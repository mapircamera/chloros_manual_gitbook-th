# การตั้งค่าโครงการ

แถบข้าง **การตั้งค่าโครงการ** (<img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line">

) ในChloros

ช่วยให้คุณสามารถกำหนดค่าทุกด้านของการประมวลผลภาพ การตรวจจับเป้าหมายการปรับเทียบ การคำนวณดัชนีมัลติสเปกตรัม และตัวเลือกการส่งออกสำหรับโครงการของคุณ การตั้งค่าเหล่านี้จะถูกบันทึกพร้อมกับโครงการของคุณ และสามารถบันทึกเป็นแม่แบบเพื่อใช้ซ้ำในโครงการต่าง ๆ ได้

## การแสดงผล

### ความละเอียดของภาพขนาดย่อ

* **ประเภท**: การเลือกจากเมนูแบบเลื่อนลง
* **ตัวเลือก**: `Default (512 px)`, `1024 px`, `2048 px`, `Full resolution`
* **ค่าเริ่มต้น**: ค่าเริ่มต้น (512 px)
* **คำอธิบาย**: ความละเอียด (ตามด้านที่ยาวที่สุด, ในพิกเซล) ที่ใช้สร้างภาพตัวอย่างแบบกริดของภาพ ค่าที่สูงขึ้นจะดูคมชัดขึ้นเมื่อซูมเข้า แต่โหลดช้าลงและใช้หน่วยความจำมากขึ้น ความละเอียดเต็มจะตรงกับขนาดภาพต้นฉบับ
* **หมายเหตุ**: แสดงผลเท่านั้น — ไม่ส่งผลต่อการประมวลผลหรือไฟล์ที่ส่งออก***

## การตรวจจับเป้าหมาย

การตั้งค่าเหล่านี้ควบคุมวิธีที่Chloros

ตรวจจับและประมวลผลเป้าหมายการปรับเทียบในภาพของคุณ ทั้งสองตัวเลือกจะทำงานได้เฉพาะเมื่อ **การปรับเทียบการสะท้อน / สมดุลสีขาว** ถูกเปิดใช้งาน (หากไม่เปิดใช้งาน ตัวเลือกเหล่านี้จะถูกทำให้เป็นสีเทา เพราะการตรวจจับเป้าหมายจะถูกข้ามไปทั้งหมด)

### พื้นที่ตัวอย่างการปรับเทียบขั้นต่ำ (px)

* **ประเภท**: ตัวเลข
* **ช่วง**: 0 ถึง 10,000 พิกเซล
* **ค่าเริ่มต้น**: 25 พิกเซล
* **คำอธิบาย**: กำหนดพื้นที่ขั้นต่ำ (ในพิกเซล) ที่จำเป็นเพื่อให้พื้นที่ที่ถูกตรวจพบถือเป็นตัวอย่างเป้าหมายการปรับเทียบที่ถูกต้อง ค่าที่เล็กกว่าจะตรวจพบเป้าหมายที่เล็กกว่า แต่อาจเพิ่มจำนวนผลบวกปลอม ค่าที่ใหญ่กว่าต้องการพื้นที่เป้าหมายที่ใหญ่และชัดเจนขึ้นสำหรับการตรวจพบ
* **เมื่อใดควรปรับ**:
  * เพิ่มค่าหากเกิดการตรวจจับผิดพลาดบนสิ่งผิดปกติขนาดเล็กในภาพ
  * ลดค่าหากเป้าหมายการปรับเทียบของคุณปรากฏในภาพขนาดเล็กและไม่ถูกตรวจจับ

### การจัดกลุ่มเป้าหมายขั้นต่ำ (0-100)

* **ประเภท**: ตัวเลข
* **ช่วง**: 0 ถึง 100
* **ค่าเริ่มต้น**: 60
* **คำอธิบาย**: ควบคุมค่าเกณฑ์การรวมกลุ่ม (clustering threshold) สำหรับการจัดกลุ่มพื้นที่ที่มีสีคล้ายกันเมื่อตรวจจับเป้าหมายการปรับเทียบ ค่าที่สูงขึ้นจะต้องการสีที่คล้ายกันมากขึ้นเพื่อจัดกลุ่มร่วมกัน ซึ่งส่งผลให้การตรวจจับเป้าหมายเป็นไปอย่างระมัดระวังมากขึ้น ค่าที่ต่ำลงจะอนุญาตให้มีความแตกต่างของสีมากขึ้นภายในกลุ่มเป้าหมายเดียวกัน
* **เมื่อใดควรปรับ**:
  * เพิ่มค่าหากเป้าหมายการปรับเทียบถูกแบ่งออกเป็นหลายการตรวจจับ
  * ลดค่าหากเป้าหมายการปรับเทียบที่มีความแตกต่างของสีไม่ถูกตรวจจับอย่างครบถ้วน

## การประมวลผล

การตั้งค่าเหล่านี้ควบคุมวิธีที่Chloros

ประมวลผลและปรับเทียบภาพของคุณ

### การแก้ไขวิเนตต์

* **ประเภท**: ช่องทำเครื่องหมาย
* **ค่าเริ่มต้น**: เปิดใช้งาน (ทำเครื่องหมาย)
* **คำอธิบาย**: ใช้การแก้ไขวิเนตต์เพื่อชดเชยความมืดของเลนส์ที่ขอบภาพ วิเนตต์เป็นปรากฏการณ์ทางแสงที่พบบ่อย ซึ่งมุมและขอบของภาพจะดูมืดกว่าส่วนกลาง เนื่องจากลักษณะของเลนส์
* **ผลข้างเคียง**: ตัวเลือกนี้ยังใช้เพื่อเลือก *ผลิตภัณฑ์สำรองที่ยังไม่ได้รับการปรับเทียบ* ที่การรันจะเขียน (ดูด้านล่าง)

### การปรับเทียบการสะท้อน / สมดุลสีขาว

* **ประเภท**: ช่องทำเครื่องหมาย
* **ค่าเริ่มต้น**: เปิด (ถูกทำเครื่องหมาย)
* **คำอธิบาย**: เปิดการปรับเทียบการสะท้อนแสง — จากเป้าหมายการปรับเทียบที่ตรวจพบในกรอบภาพและ/หรือข้อมูลแสงที่ส่องลงจากเซ็นเซอร์แสง DAQ ขึ้นอยู่กับกล้องและข้อมูลที่มีอยู่ การปรับเทียบนี้จะทำให้ค่าการสะท้อนแสงในชุดข้อมูลของคุณเป็นมาตรฐานเดียวกัน และรับประกันการวัดที่สม่ำเสมอไม่ว่าสภาพแสงจะเป็นอย่างไร
* **เมื่อปิด**: การตรวจจับเป้าหมายจะถูกข้ามไปโดยสิ้นเชิง และ**กล้องใดก็ตามจะไม่สามารถสร้างผลิตภัณฑ์ค่าสะท้อนแสงได้** — ทั้งระบบที่ขับเคลื่อนด้วยเป้าหมาย (Survey3

) และระบบที่ขับเคลื่อนด้วย DAQ LATTICE (LATTICE DAQ-driven) การตั้งค่าที่เกี่ยวข้อง (*Export reflectance*, *Minimum recalibration interval*, และเกณฑ์การตรวจจับเป้าหมาย) จะถูกทำให้เป็นสีเทา

### ผลลัพธ์สำรองเมื่อไม่มีการปรับเทียบ: ส่งออกการตอบสนองของเซ็นเซอร์ / ส่งออกภาพที่แก้ไข vignette

* **ประเภท**: กล่องเลือกสองช่อง
* **ค่าเริ่มต้น**: ทั้งสองถูกเปิด (ถูกเลือก)
* **คำอธิบาย**: เมื่อไม่สามารถปรับเทียบค่าสะท้อนแสงของเฟรมได้ (ไม่พบเป้าหมายการปรับเทียบ หรือการปรับเทียบค่าสะท้อนแสงถูกปิด) เฟรมนั้นจะถูกบันทึกเป็น *ผลิตภัณฑ์สำรองที่ยังไม่ปรับเทียบ* แทน **มีผลิตภัณฑ์สำรองเพียงหนึ่งเดียวจากสองตัวเลือกต่อการรัน สำหรับทุกรุ่นกล้อง** ซึ่งถูกเลือกโดยสวิตช์ *การแก้ไขวิเนตต์*:
  * การแก้ไขวิเนตต์ **เปิด**→ `Vignette_Corrected_Images/` (ถูกควบคุมโดย**ส่งออกที่แก้ไขวิเนตต์**)
  * การแก้ไข vignette **ปิด**→ `Sensor_Response_Images/` (ถูกควบคุมโดย**Export sensor response**)
* ผลิตภัณฑ์สำรองที่ไม่ได้ใช้งานจะถูกทำให้เป็นสีเทา การยกเลิกการเลือกผลิตภัณฑ์ที่กำลังใช้งานจะหยุดการเขียนไฟล์นั้นโดยสิ้นเชิง

### ผลิตภัณฑ์ส่งออก LATTICE

สำหรับโครงการที่มีข้อมูลจับภาพ LATTICE แต่ละเฟรม LATTICE ที่นำเข้าจะถูกกระจายไปยังทุกผลิตภัณฑ์ที่เปิดใช้งาน **และเหมาะสม**ในขั้นตอนการประมวลผลครั้งเดียว มีกล่องเลือก 4 กล่องที่ควบคุมการกระจายนี้ (ทั้งหมดตั้งเป็น**เปิด** ตามค่าเริ่มต้น):

| การตั้งค่า | โฟลเดอร์ผลลัพธ์ | สิ่งที่ส่งออก |
| --- | --- | --- |
| **ส่งออกภาพที่ถอดเดเบย์เออร์** | `Debayered_Images/` | ภาพที่ถอดเดเบย์เออร์แบบเชิงเส้น ใช้ได้กับกล้องRGB

และกล้องมัลติสเปกตรัม |
| **ส่งออกภาพตัวอย่าง** | `Preview_Images/` | ภาพตัวอย่างที่แสดงบนหน้าจอRGB

= การปรับสมดุลสีขาว (ใช้แหล่งแสง DAQ หากมี มิฉะนั้นใช้ gray-world) + gamma; multispectral = การขยายสีเท็จ |
| **ส่งออก radiance** | `Radiance_Images/` | ความส่องผ่านเชิงสเปกตรัมแบบ Float32 ในหน่วย W/m²/sr/nm ใช้ได้เฉพาะแบบมัลติสเปกตรัม (M3C/M3M) เท่านั้น — ไม่ใช้กับไฟล์ต้นแบบแบบRGB

เสมอ เขียนเป็นTIFF

แบบ 32 บิตเสมอ ไม่ว่ารูปแบบ *ภาพที่ปรับเทียบแล้ว* |
| **ค่าการสะท้อนที่ส่งออก**| `Reflectance_Calibrated_Images/` | ค่าการสะท้อน Uint16 ที่ปรับสเกลให้**32768 = ค่าการสะท้อน 1.0** (ถูกบันทึกเป็น XMP `Chloros:PixelScale`). ใช้ได้เฉพาะภาพมัลติสเปกตรัมเท่านั้น, ถูกเขียนเมื่อมีบันทึกการส่องลง (downwelling) `.daq` ที่ตรงกัน (หรือเป้าหมายในเฟรมที่ผ่านการตรวจสอบคุณภาพ QA) ครอบคลุมเฟรม |

* กล้องหลักของRGB

จะส่งข้อมูลแบบ debayered + preview; ค่า radiance/reflectance จะถูกข้ามไปเนื่องจากไม่เกี่ยวข้อง
* ความลึกของบิตของภาพที่ถอดเบย์เยอร์/ภาพตัวอย่างจะตามการตั้งค่า *Calibrated image format*; ค่า radiance เป็น float32 เสมอ
* การประมวลผล *Survey3

สวิตช์เหล่านี้ได้แทนที่แฟล็ก `--radiometric-output` เดิม ซึ่งปัจจุบันไม่มีอยู่แล้ว

{% endhint %}

### แหล่งที่มาของการสะท้อนแสง (การตั้งค่าโครงการ, ตั้งค่าผ่านCLI

/SDK

)

โครงการยังเก็บข้อมูลว่า **แหล่งอ้างอิงการสะท้อนแสง** ที่ผลิตภัณฑ์การสะท้อนแสง LATTICE ใช้ ไม่มีปุ่มควบคุมเฉพาะในแผงตั้งค่า; ค่านี้ถูกเก็บไว้ในส่วนกำหนดค่าโครงการเป็น `Processing → "Target reflectance source"` และถูกตั้งค่าด้วย `chloros-cli process --reflectance-source {auto,target,daq}` หรือพารามิเตอร์ `reflectance_source` ของSDK

:

* **`auto`** (ค่าเริ่มต้น): เป้าหมายการปรับเทียบในเฟรมที่ผ่านการตรวจสอบคุณภาพ (QA) จะกลายเป็นอ้างอิงสัมบูรณ์ โดยจะเปลี่ยนไปใช้การแบ่งแสงลงของ DAQ (ρ = πL/E) เมื่อไม่มีเป้าหมายหรือการตรวจสอบคุณภาพ (QA) ล้มเหลว
* **`target`**: ค่าการสะท้อนที่ขับเคลื่อนด้วยเป้าหมายอย่างเคร่งครัด — ไม่มีการแทนที่จาก DAQ
* **`daq`**: ค่าการสะท้อนแสงที่อ้างอิงจาก DAQ เป็นหลัก; เป้าหมายในเฟรมไม่ถูกใช้เป็นจุดอ้างอิง

ค่าที่เก็บไว้จะถูกจับคู่โดยไม่คำนึงถึงตัวพิมพ์ใหญ่-เล็ก และมีการยอมรับการสะกดบางรูปแบบเป็นชื่อเรียกแทน: `target`, `target_image`, `empirical` และ `empirical_line` ทั้งหมดหมายถึง **เป้าหมาย**; `daq`, `dls`, `light_sensor` และ `sensor` ทั้งหมดหมายถึง**daq**. สิ่งอื่นใด — รวมถึงคีย์ที่ไม่มี — จะถูกกำหนดเป็น**auto**

**การวัด**การสแกน**เป้าหมาย** ตามหน่วยจะถูกค้นหาโดยใช้หมายเลขซีเรียล/QR ของหน่วยเป้าหมาย เช่น `<serial>.csv` ในสามที่: ไดเรกทอรีที่ระบุด้วย `--target-reflectance-dir` (เก็บไว้เป็น `Processing → "Target reflectance dir"`), โฟลเดอร์ `target_reflectance/` ของโครงการเอง, และเส้นทางในตัวแปรสภาพแวดล้อม `CHLOROS_TARGET_REFLECTANCE_DIR` เมื่อไม่มีการสแกนที่วัดได้สำหรับหน่วยนั้น จะใช้เส้นโค้งมาตรฐานที่เผยแพร่สำหรับโมเดลเป้าหมายแทน

## DAQ Light Sensor

ส่วนนี้ปรากฏใน Project Settings และแสดงรายชื่อไฟล์ DAQ downwelling ทุกไฟล์ในโครงการ — การบันทึก `.daq` และ DAQ-M `.csv` downwelling logs. การบันทึกที่ทำในแท็บ Light Sensors จะถูกเพิ่มเข้าไปในโครงการที่เปิดอยู่โดยอัตโนมัติ



<!-- SCREENSHOT-NEEDED: Project Settings "DAQ Light Sensor" section of a project containing at least one .daq file, showing the "Cap override (all files)" dropdown and a per-file row with its resolved cap. -->

แต่ละแถวแสดงไฟล์ รุ่นเซ็นเซอร์ และการปรับแก้ฝาครอบดิฟฟิวเซอร์ที่ใช้อยู่จริงสำหรับไฟล์นั้น ด้านบนแถวข้อมูลมีตัวควบคุมเดียวที่ใช้กับทั้งโครงการ:

### การแทนที่ค่าฝาครอบ (ทุกไฟล์)

* **ประเภท**: การเลือกจากเมนูแบบเลื่อนลง
* **ตัวเลือก**: `Auto` พร้อมด้วยโปรไฟล์การปรับแก้ค่าฝาครอบที่ใช้ได้กับประเภทเซ็นเซอร์ที่มีอยู่ในโครงการ
* **ค่าเริ่มต้น**: อัตโนมัติ
* **เก็บเป็น**: `Processing → "DAQ cap id"` (ค่าเริ่มต้น `auto`)
* **คำอธิบาย**: `Auto` ใช้ค่า cap ที่บันทึกไว้ในแต่ละไฟล์ (หากไม่มีการบันทึกค่า cap ใดๆ จะถือว่าใช้ค่า Sunshine cap — เครื่อง DAQMAPIR

ทุกเครื่องมาพร้อมตัวปรับค่า Sunshine) การเลือกค่า cap เฉพาะจะแทนที่ **ทุก** ไฟล์ downwelling ในโครงการ: การบันทึกดิบจะถูกปรับแก้ด้วยค่านี้ และการบันทึกที่มีค่า cap อยู่แล้วจะถูกอ้างอิงใหม่ (การปรับแก้ที่บันทึกไว้จะถูกยกเลิก และค่าที่เลือกจะถูกนำไปใช้)
* **สำคัญ**: ค่า cap ที่เลือกต้องตรงกับ cap ที่ติดตั้งจริงในระหว่างการบันทึก ทั้งเซ็นเซอร์และซอฟต์แวร์ไม่สามารถตรวจจับ cap ที่ติดตั้งจริงได้ — หาก ID ของ cap ไม่ตรงกัน จะทำให้การปรับแก้สเปกตรัมผิดพลาด

มี **เพียงหนึ่ง** ตัวควบคุมสำหรับทั้งโครงการแทนที่จะมีเมนูแบบเลื่อนลงสำหรับแต่ละไฟล์: การตั้งค่านี้จะส่งผลต่อทุกแหล่งข้อมูลที่รับแสงลงในโครงการ***

## การจัดแนวอาร์เรย์

ส่วนนี้จะปรากฏ **เฉพาะ** เมื่อมีภาพอย่างน้อยหนึ่งภาพในโครงการที่มีการแปลงการจัดแนวระหว่างโมดูลต่อโมดูล ซึ่งอาร์เรย์ LATTICE บันทึกไว้ขณะถ่ายภาพ (แท็ก XMP `Chloros:Alignment*`) ส่วนนี้แสดงจำนวนภาพที่มีแท็กการจัดแนว กล้องใดเป็นกล้องอ้างอิง (`REF` badge) และตารางจำนวนภาพตามกล้องแต่ละตัว

<!-- SCREENSHOT-NEEDED: Project Settings "Array Alignment" section for an imported LATTICE array capture set, showing the tagged-image count, the per-camera rows with the REF badge, and the three controls (Apply array alignment, Crop to common overlap, Resampling). -->

### ใช้การจัดแนวอาร์เรย์

* **ประเภท**: ช่องทำเครื่องหมาย
* **ค่าเริ่มต้น**: เปิด (ถูกเลือก)
* **เก็บไว้เป็น**: `Processing → "Array alignment"`
* **คำอธิบาย**: ปรับตำแหน่งภาพทุกผลิตภัณฑ์ที่ผ่านการประมวลผล (debayered / preview / radiance / reflectance / index) ให้ตรงกับรูปทรงอ้างอิงร่วมของอาร์เรย์ โดยใช้การแปลงที่ถูกบันทึกไว้ขณะถ่ายภาพ หากปิด = ส่งออกในรูปแบบรูปทรงเฉพาะของเซ็นเซอร์แต่ละตัว

### ตัดภาพให้เหลือส่วนทับซ้อนร่วมกัน

* **ประเภท**: ช่องทำเครื่องหมาย (ทำงานได้เฉพาะเมื่อ *Apply array alignment* เปิดอยู่)
* **ค่าเริ่มต้น**: เปิด (ถูกเลือก)
* **เก็บไว้เป็น**: `Processing → "Array alignment crop"`
* **คำอธิบาย**: ตัดส่วนที่ส่งออกที่จัดแนวแล้วให้อยู่ในพื้นที่ที่โมดูลกล้องทุกตัวใช้ร่วมกัน เพื่อให้ทุกแบนด์มีพื้นที่ครอบคลุมเท่ากัน ปิดจะรักษาพื้นที่เซนเซอร์เต็ม (เติมสีดำด้านนอกแหล่งข้อมูลต้นทาง)

### การสุ่มตัวอย่างใหม่

* **ประเภท**: การเลือกจากเมนูแบบเลื่อนลง (ทำงานได้เฉพาะเมื่อ *Apply array alignment* เปิดอยู่)
* **ตัวเลือก**: `Bilinear (smooth, default)`, `Nearest (preserve exact values)`, `Cubic (sharpest)`
* **ค่าเริ่มต้น**: Bilinear
* **เก็บไว้เป็น**: `Processing → "Array alignment interpolation"`
* **คำอธิบาย**: การแทรกค่าที่ใช้ในการปรับแนวภาพ Nearest รักษาค่าต้นฉบับอย่างแม่นยำ (ไม่มีการผสมระหว่างพิกเซล) สำหรับการวิเคราะห์รังสีอย่างเคร่งครัด; Bilinear เหมาะที่สุดสำหรับการทำแผนที่และการใช้งานทางภาพ

ตัวเลือกทั้งสามนี้ยังมีอยู่ในรูปแบบที่ไม่มีส่วนหัว (headless) คือ `chloros-cli process --array-alignment`, `--array-alignment-crop` และ `--array-alignment-interp {bilinear,nearest,cubic}`

4. **การปรับเปลี่ยนด้วยมือ** - การเปลี่ยนแปลงใดๆ ที่คุณทำระหว่างเซสชันปัจจุบัน

### การตั้งค่าและการประมวลผลภาพ

การตั้งค่าการประมวลผลจะถูกอ่านเมื่อเริ่มการประมวลผล การเปลี่ยนแปลงการตั้งค่าจะไม่ส่งผลย้อนหลังต่อผลลัพธ์ที่บันทึกไว้บนดิสก์แล้ว — ต้องดำเนินการประมวลผลใหม่เพื่อใช้การตั้งค่าใหม่ การตั้งค่าบางรายการไม่ส่งผลต่อการประมวลผลเลย:

* ความละเอียดภาพขนาดย่อ (แสดงผลเท่านั้น)
* บันทึกแม่แบบโครงการ
* บันทึกโฟลเดอร์โครงการ

## แนวทางปฏิบัติที่ดีที่สุด

1. **เริ่มต้นด้วยค่าเริ่มต้น**: การตั้งค่าเริ่มต้นทำงานได้ดีสำหรับระบบกล้องMAPIR

ส่วนใหญ่และขั้นตอนการทำงานทั่วไป
2. **สร้างแม่แบบ**: เมื่อคุณปรับตั้งค่าให้เหมาะสมกับกระบวนการทำงานหรือกล้องเฉพาะแล้ว ให้บันทึกไว้เป็นแม่แบบเพื่อรักษาความสม่ำเสมอระหว่างโครงการต่างๆ
3. **ทดสอบก่อนประมวลผลทั้งหมด**: เมื่อทดลองตั้งค่าใหม่ ให้ทดสอบกับชุดภาพขนาดเล็กก่อนที่จะประมวลผลชุดข้อมูลทั้งหมด
4. **บันทึกการตั้งค่า**: ใช้ชื่อแม่แบบที่อธิบายได้ชัดเจน ซึ่งระบุระบบกล้อง ประเภทการประมวลผล และวัตถุประสงค์การใช้งาน (เช่น &quot;Survey3

\_RGB\_NDVI\_Agriculture&quot;).
5. **การเลือกรูปแบบการส่งออก**: เลือกรูปแบบการส่งออกตามวัตถุประสงค์การใช้งานสุดท้าย:
   * การวิเคราะห์ทางวิทยาศาสตร์ →TIFF

(16-bit หรือ 32-bit)
   * การประมวลผล GIS →TIFF

(16-bit)
   * การแสดงผลอย่างรวดเร็ว →PNG

(8-bit)
   * การแบ่งปันบนเว็บ → JPG (8-bit)
