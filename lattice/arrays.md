# ระบบกล้องหลายตัว

**ระบบ**LATTICE คือกล้อง LATTICE สองตัวหรือมากกว่าที่เชื่อมต่อกันเป็นหน่วยเดียวที่ทำงานพร้อมกัน กล้องหนึ่งตัวทำหน้าที่เป็น**master**: มันส่งสัญญาณทริกเกอร์ GPIO แบบฮาร์ดแวร์ผ่านสายซิงค์ที่ใช้ร่วมกัน (ค่าเริ่มต้น**Line2**), เพื่อให้ทุกกล้องในระบบจับภาพในเวลาเดียวกัน Chloros

เพิ่มการซิงค์เวลา PTP, การดูตัวอย่างสด (ในรูปแบบไทล์ต่อกล้องหรือภาพรวมหลายแถบที่จัดเรียงให้ตรงกัน) และการจับภาพแบบซิงค์ — ทุกครั้งที่จับภาพจะสร้าง **กลุ่มเฟรม** หนึ่งชุด ซึ่งกล้องทุกตัวมีเวลาประทับและ ID เฟรมเดียวกัน (แสดงเป็น `fid:N` ในผลลัพธ์การจับภาพ).

อาร์เรย์คือวิธีที่กล้องโมโน (M3M) สร้างดัชนีพืชพรรณ — กล้องหนึ่งตัวให้ข้อมูลหนึ่งแบนด์ และอาร์เรย์จัดเรียงข้อมูลเหล่านั้นเป็นสแต็กหลายแบนด์ ดู [กล้องโมโนและดัชนีพืชพรรณ](mono-indices.md).

มีสามวิธีที่เทียบเท่ากันในการเชื่อมต่ออาร์เรย์ และทุกวิธีล้วนใช้ขั้นตอน &quot;smart-prep&quot; ที่เดียวกัน:

| Surface | จุดเข้า |
| --- | --- |
| GUI | แท็บ Cameras → **Connect Array** (ปุ่มสีฟ้า) |
| CLI

| `chloros-cli lattice array-connect --serials SN1,SN2,…` (หมายเลขซีเรียลแรก = master) |
| Python

SDK

| `connect_array(serials=[…])` → `ArraySession` (ซีเรียลแรก = master) |

Smart-prep ดำเนินการ: การตรวจสอบความสามารถของเครือข่าย (ICMP DF ping + GVSP probe), การเลือกชั้นการซิงค์, การคาดการณ์อัตราเฟรมที่ขนาดเฟรมที่ร้องขอ, การตัดสินใจเกี่ยวกับการส่งข้อมูลแบบแพ็ก 12 บิต (ดู [การส่งข้อมูลแบบแพ็ก 12 บิต](#packed-12-bit-transport)), การเปิดใช้งาน PTP, การเลือกรูปแบบพิกเซลอัตโนมัติสำหรับแต่ละกล้อง, การตั้งค่าเริ่มต้นการเปิดรับแสงอัตโนมัติจากสถานะที่บันทึกไว้ของแต่ละกล้อง และการกำหนดค่าทริกเกอร์ GPIO บน Line2

**ใช้เซ็นเซอร์เต็มขนาดตามค่าเริ่มต้น (ใหม่ในเวอร์ชัน 1.3.0).** Connect จะรักษาขนาดเฟรมที่คุณขอไว้ — เซนเซอร์เต็ม 2048×1536 โดยไม่มีการรวมพิกเซล (binning) หรือการตัดภาพ (crop) เว้นแต่คุณจะเลือกอย่างอื่น — และปล่อยให้อัตราเฟรมลดลงตามความสามารถของโฮสต์และเครือข่าย มันจะไม่ทำการ binning หรือ crop ด้วยตัวเอง (ในเวอร์ชัน 1.2.0 จะทำการ binning อัตโนมัติเมื่ออัตราเฟรมต่ำกว่า 1.5 fps) การรวมพิกเซลหรือ ROI ที่เล็กลงเป็นความตัดสินใจของคุณ: ในหน้าสนทนา Connect ให้เลือกหนึ่งในนั้น และส่วน Projected Outcome จะแสดงอัตราเฟรมที่ได้; `array-connect` จะพิมพ์ตัวเลือกที่เร็วกว่าพร้อมอัตราเฟรมที่คาดการณ์ไว้

{% hint style="info" %}
กล้องต้องสามารถเข้าถึงได้ผ่านลิงก์ก่อนที่กระบวนการนี้จะทำงาน — ดู [การเชื่อมต่อกล้อง](connecting.md) เพื่อการค้นหา การกำหนดที่อยู่ และการดาวน์โหลดการปรับเทียบในการเชื่อมต่อครั้งแรก สำหรับระบบกล้องหลายตัว การตั้งค่าวงรับ (receive-ring) ของ NIC หลักมีความสำคัญไม่แพ้ความเร็วของลิงก์; ตารางอาการ→วิธีแก้ไขแบบครบถ้วนอยู่ใน [CLI

Reference § Host NIC Setup &amp; Tuning](../reference/cli-reference.md#host-nic-setup--tuning-lattice-arrays)
{% endhint %}

## กล่องโต้ตอบ Array Connect

แท็บ Cameras → **Connect Array**จะเปิดวิซาร์ด 3 ขั้นตอน:**Select → Display Mode → Settings**.

### ขั้นตอนที่ 1 — เลือกกล้องหลักและกล้องรอง

<!-- SCREENSHOT-NEEDED: Array Connect dialog, Select scene, with 3-4 LATTICE cameras discovered (an FRGB among them). กล่องโต้ตอบจะสแกนเครือข่ายทันทีที่เปิดขึ้น (&quot;Scanning network...&quot;) จากนั้นจะตรวจสอบสายซิงค์ (&quot;Probing sync cables...&quot;) เพื่อค้นหาว่ากล้องใดอยู่บนสายซิงค์ M8 คุณต้องมี **กล้องอย่างน้อย 2 ตัว** เพื่อสร้างอาร์เรย์

สายซิงค์ M8 มาบรรจบกันที่จุดต่อหนึ่งจุด ดังนั้น **กล้องใดก็ตามที่ต่อสายสามารถเป็นมาสเตอร์ได้**. ระบบจะกำหนดบทบาทไว้ล่วงหน้า — กล้องRGB

(`-FRGB`) เป็นมาสเตอร์เมื่อต่อสายแล้ว มิฉะนั้นจะเป็นกล้องที่ต่อสายตัวแรก และกล้องอื่น ๆ ที่ต่อสายเป็นสเลฟ — และแสดงหนึ่งในสามแบนเนอร์ต่อไปนี้:

| แบนเนอร์ | ความหมาย |
| --- | --- |
| &quot;พบสายซิงค์บนกล้อง {n} ตัว กล้องใดก็ได้สามารถเป็นมาสเตอร์ได้; กล้องRGB

(หรือกล้องตัวแรกหากไม่มีการเชื่อมต่อ) ถูกเลือกไว้ล่วงหน้าแล้ว&quot; (สีเขียว) | โพรบพบกล้องบนสายซิงค์แล้ว; ช่องทำเครื่องหมายสำหรับมาสเตอร์และสเลฟถูกเลือกไว้ล่วงหน้าแล้ว |
| &quot;ไม่พบมาสเตอร์ - ตรวจสอบสาย GPIO&quot; (สีส้ม) | ไม่มีกล้องใดที่ตรวจพบสัญญาณทริกเกอร์; ตรวจสอบการต่อสายซิงค์ บทบาทยังคงถูกเลือกไว้ล่วงหน้า (กล้องRGB

หรือกล้องแรกในรายการ เป็นมาสเตอร์) และคุณสามารถเปลี่ยนได้ |
| &quot;ไม่มีสายซิงค์: {serials}&quot; (สีส้ม) | กล้องที่แสดงในรายการไม่มีสายซิงค์ต่ออยู่ |

ตารางกล้องมีคอลัมน์ **กล้อง / Serial / IP / Master (วิทยุ) / Slave (ช่องทำเครื่องหมาย)**แถวถูกจัดเรียงตาม**ลำดับกล้อง** — กล้อง M3C (Bayer) ก่อน M3M (mono); ในกลุ่ม M3C มี FRGB, FRGN, FOCN แล้วตามด้วย FNGB; M3M ตามความยาวคลื่นของฟิลเตอร์ โดยเรียงจากค่าต่ำสุดก่อน (F450 ก่อน F808) รายชื่อกล้องในแถบข้างและรูปแบบเริ่มต้นของตารางใช้ลำดับเดียวกัน

* เลือก **มาสเตอร์** **หนึ่งตัว**และ**สเลฟ** **หนึ่งตัวหรือมากกว่า** เท่านั้น การคลิกที่วิทยุของมาสเตอร์ปัจจุบันอีกครั้งจะยกเลิกการเลือกนั้น การเลือกมาสเตอร์อื่นทำได้ด้วยการคลิกเพียงครั้งเดียว: มาสเตอร์ใหม่จะนำสเลฟไปด้วย และมาสเตอร์เดิมจะกลายเป็นสเลฟ (เว้นแต่ไม่มีสายซิงค์)
* กล้องที่มีเครื่องหมาย **&quot;No Sync Cable&quot;** ไม่สามารถถูกเลือกเป็น slave ได้ — slave ที่ไม่มีสายทริกเกอร์จะรออยู่บนสายซิงค์ตลอดไปและส่งสัญญาณภาพที่ไม่มีข้อมูล ให้เชื่อมต่อกล้องนั้นเป็นกล้องแบบสแตนด์อโลนแทน
* กล้องที่เชื่อมต่อแบบสแตนด์อโลนอยู่แล้ว *ไม่* ถูกปิดใช้งาน: การเชื่อมต่อแบบอาร์เรย์จะยกเลิกเซสชันสแตนด์อโลนและเปิดกล้องใหม่ภายในอาร์เรย์

**ถัดไป: โหมดแสดงผล →**จะเปิดใช้งานเมื่อเลือกมาสเตอร์และสเลฟอย่างน้อยหนึ่งตัวแล้ว**สแกนใหม่** จะรันการค้นหาและตรวจสอบการเชื่อมต่อสายใหม่

{% hint style="warning" %}
**ยกเลิก** จะถูกปิดใช้งานระหว่างการสแกนหรือการตรวจสอบ — การยกเลิกกลางทางอาจทำให้กล้องSDK

บนเฟิร์มแวร์กล้อง LATTICE ล่มได้ โปรดรอจนกว่าไอคอนหมุนจะเสร็จสิ้น
{% endhint %}

จะขอ **คำแนะนำ**จากระบบหลังบ้านและนำไปใช้:**เซ็นเซอร์เต็ม — ไม่มีการรวมพิกเซล (binning) หรือการตัด ROI — เมื่อใดก็ตามที่อัตราเฟรมสามารถรองรับได้**ไม่ว่าอัตราที่โฮสต์และสายส่งจะส่งมาเท่าใดก็ตาม เฉพาะเมื่อไม่มีอัตราใดที่สามารถส่งเซ็นเซอร์เต็มได้ คำแนะนำจึงจะลดขนาดเฟรมลง และจากนั้นจะเลือกใช้การรวมพิกเซล (binning) แทนการตัด ROI เพราะการรวมพิกเซลช่วยรักษามุมมองเต็มไว้ได้ คุณต้องแลกเปลี่ยนความละเอียดเพื่อเพิ่มความเร็วเฟรมจากจุดนี้ ทุกการเปลี่ยนแปลงที่คุณทำจะรันการวิเคราะห์แบบเรียลไทม์ใหม่และอัปเดตแผง**ผลลัพธ์ที่คาดการณ์** ทางด้านขวา

กล่องเลือก **Pin resolution** จากเวอร์ชัน 1.2.0 ได้ถูกลบออกแล้ว: ระบบจะรักษาขนาดเฟรมที่คุณเลือกไว้เสมอ และปรับลดอัตราเฟรมแทน

คอลัมน์ด้านขวา — **Projected Outcome**:

* **ระดับการซิงค์** — &quot;การบันทึกพร้อมกัน&quot; (สีเขียว), &quot;การบันทึกพร้อมกัน (FTD-staggered emit)&quot; (สีเขียว), &quot;การบันทึกแบบสลับ (100 ms drift)&quot; (สีเหลือง), หรือ &quot;การกำหนดค่าใหญ่เกินไป&quot; (สีแดง). Chloros

จะเลือกระดับการทำงาน: การบันทึกพร้อมกันเมื่อสายสามารถแบ่งปันได้ด้วยความเร็วที่กล้องสามารถปรับจังหวะได้ (อัตราเฟรมจะลดลงเมื่อส่วนแบ่งของแต่ละกล้องลดลง), และการบันทึกแบบสลับกันเฉพาะเมื่อไม่สามารถแบ่งปันได้ — ดังนั้นกลุ่มกล้องจะเชื่อมต่อบนเครือข่ายใดก็ได้ ด้วยอัตราเฟรมที่เครือข่ายนั้นอนุญาต
* **การคาดการณ์ fps** — อัตราเฟรมที่คาดว่าจะทำงานของระบบกล้อง ในการจับภาพพร้อมกัน จะเป็นค่าเดียว: อัตราเฟรมมาอยู่ก่อน และการปรับแสงอัตโนมัติจะเติมเต็มช่วงเวลาที่กำหนด จากนั้นเพิ่มค่าเกน เพื่อให้ฉากที่มืดไม่ทำให้อัตราเฟรมลดลง (ดู [วิธีที่การปรับแสงอัตโนมัติใช้การเปิดรับแสงและเกน](camera-settings.md)). ในการจับภาพแบบสลับกัน ค่านี้จะแสดงเป็นช่วง (&quot;มืด → สว่าง&quot;) เนื่องจากเวลาการเปิดรับแสงของแต่ละกล้องจะยืดระยะเวลาการสลับกันในฉากที่มืด
* **NIC line** — ความเร็วการเชื่อมต่อและปริมาณข้อมูลที่ส่งผ่านอย่างต่อเนื่อง (&quot;NIC {mbps} Mbps · sustained {N} MB/s&quot;).
* **การตรวจสอบการส่งข้อมูลแบบ Sim-emit burst** — NIC ของโฮสต์สามารถรับและดูดซับการส่งข้อมูลแบบ Burst พร้อมกันจากทุกกล้องได้หรือไม่ (&quot;Sim-emit burst: X MB · NIC ring usable: Y MB ✓/✗&quot;).
* **การตรวจสอบงบประมาณสาย** — ความต้องการรวมในสภาวะคงที่เทียบกับขีดจำกัดสายที่ปลอดภัยจากการชนกัน (&quot;Wire budget: {demand} MB/s ที่ถูกขอโดย {n} กล้อง · ceiling {ceiling} MB/s ✓/✗ ถูกจองเกิน&quot;)
* **&quot;จำนวนกล้องสูงสุดบนสายนี้: {n} — กำหนดโดยค่าขั้นต่ำของแบนด์วิธต่อกล้อง ดังนั้นการรวมกลุ่ม (binning) จะไม่เพิ่มค่านี้&quot;** — แสดงขึ้นเมื่อคุณใกล้ถึง (หรือเกิน) ขีดจำกัดจำนวนกล้อง
* **&quot;เฟรมจะถูกละทิ้ง (DROP) ที่การตั้งค่าเหล่านี้.&quot;**— คำเตือนสีแดงพร้อมเหตุผลจากระบบหลังบ้าน พร้อมรายชื่อปัจจัยที่ขัดขวาง และ**คำแนะนำการแก้ไข** สีฟ้า (&quot;เพื่อให้ชุดข้อมูลนี้พอดีกับเครือข่าย&quot; / &quot;เพื่อปลดล็อกการบันทึกพร้อมกัน&quot;).**Apply &amp; Connect** จะถูกปิดจนกว่าจะมีการคาดการณ์ และป้ายกำกับจะบอกเหตุผลที่ระบบปฏิเสธ:

| ป้ายปุ่ม | ความหมาย | สิ่งที่ช่วยได้จริง |
| --- | --- | --- |
| &quot;กำลังวิเคราะห์...&quot; | การวิเคราะห์ยังดำเนินอยู่ | รอ |
| **&quot;มีกล้องมากเกินไปสำหรับเครือข่ายนี้&quot;**| สายเครือข่ายไม่สามารถรับส่งข้อมูลของอาร์เรย์ได้แม้เพียงกล้องเดียวในแต่ละครั้ง (การตรวจสอบการรวมข้อมูลล้มเหลว): มีกล้องมากกว่าที่เครือข่ายสามารถจัดการได้ หรือมีกล้องอื่นกำลังสตรีมผ่านเครือข่ายนี้ | ลดจำนวนกล้อง ใช้เฟรมจัมโบ้แบบ end-to-end หรือใช้ NIC ที่เร็วขึ้น**การลด ROI จะไม่ช่วย** — ดูด้านล่าง |
| **&quot;ลด ROI เพื่อเปิดใช้งาน&quot;** | เฟรมจะหลุดออกในการตั้งค่านี้ (การตรวจสอบ burst/ring ล้มเหลว) | ลด ROI, เพิ่ม binning, หรือแก้ไขวงรับของ NIC |

ระหว่างการเชื่อมต่อ **แผงดาวน์โหลดการปรับเทียบ** สีเขียวอาจปรากฏขึ้นพร้อมแถบความคืบหน้าตามแต่ละพอร์ตอนุกรม: เมื่อกล้องถูกเชื่อมต่อกับเครื่องเป็นครั้งแรก Chloros

จะดึงแพ็กการปรับเทียบจากโรงงานขนาด ~3.8 MB จากกล้องผ่าน GigE (ประมาณ 70 วินาทีต่อกล้อง) กล้องที่เก็บไว้ในแคชจะไม่แสดงแผงนี้เลย; หากมีกล้องมากกว่าหกตัว แถวในแผงจะเลื่อนไปมา ดู [การเชื่อมต่อกล้อง](connecting.md).

### การส่งข้อมูลแบบ Packed 12-bit

รูปแบบ 12-bit (`BayerRG12`, `Mono12`) โดยปกติจะถูกส่งเป็นคำ 16-bit **การส่งข้อมูลแบบบีบอัด**จะส่ง 12 บิตเดียวกันใน 1.5 ไบต์ต่อพิกเซล และทำการคลายบีบอัดบนเครื่องโฮสต์ ดังนั้นแต่ละเฟรมจะใช้เวลาส่งน้อยลง 25% — เมื่อใช้เซ็นเซอร์เต็มความเร็ว จะส่งเฟรมได้มากขึ้นประมาณหนึ่งในสามต่อวินาที**ข้อมูลที่บันทึกไว้จะเหมือนกันทุกประการ** Array Connect จะตัดสินใจโดยอัตโนมัติ (`auto`): มันจะทำการแพ็กข้อมูลเฉพาะเมื่อมีประโยชน์ และเครื่องโฮสต์มี CPU เหลือพอสำหรับการแกะแพ็ก GUI ไม่มีตัวเลือกสำหรับเรื่องนี้; จากCLI

ให้ใช้ `array-connect --packed {auto,on,off}` (ค่าเริ่มต้น `auto`) รูปแบบ 8 บิตและ 16 บิตจะไม่ถูกบีบอัดเลย

## แบนด์วิธ: จำนวนกล้องที่รองรับได้

ความสามารถในการรับส่งข้อมูลของอาร์เรย์ขึ้นอยู่กับคุณสมบัติของสายสัญญาณ ไม่ใช่ของChloros

ดังนั้นข้อมูลการวางแผนจึงอยู่ในคู่มือฮาร์ดแวร์: **[การวางแผนแบนด์วิธของอาร์เรย์](https://mapir.gitbook.io/lattice-camera/setup/array-bandwidth-planning)**.

Chloros

ใช้ข้อมูลเหล่านี้อย่างไร: หน้าต่างการเชื่อมต่อจะดำเนินการตรวจสอบเครือข่าย (network probe) คาดการณ์อัตราเฟรมที่สามารถบรรลุได้ และเลือกระดับ (tier) ที่เหมาะสม อาร์เรย์สามารถเชื่อมต่อได้บนเครือข่ายใดก็ได้: บนลิงก์ที่ช้า แต่ละกล้องจะถูกปรับให้สอดคล้องกับส่วนแบ่งของสายสัญญาณ และอัตราเฟรมจะลดลง แทนที่จะถูกปฏิเสธการเชื่อมต่อหรือเฟรมถูกลดขนาด เพียงแต่ระบบอาร์เรย์ที่สายเครือข่ายไม่สามารถรองรับกล้องได้แม้แต่ตัวเดียวในแต่ละครั้งเท่านั้นที่จะถูกปฏิเสธ (**มีกล้องมากเกินไปสำหรับเครือข่ายนี้**) แทนที่จะทิ้งแพ็กเก็ตไปอย่างเงียบๆ — ดูแผงผลลัพธ์ที่คาดการณ์ไว้ตามที่อธิบายไว้ข้างต้น

## การซิงโครไนซ์เวลา PTP

การ *ซิงโครไนซ์* เฟรมเกิดจากทริกเกอร์ของฮาร์ดแวร์; **PTP** (IEEE 1588 PTPv2) ให้ *timestamps* ที่เทียบเท่ากันในทุกอุปกรณ์ คุณสมบัตินี้ถูกเปิดใช้งานโดยค่าเริ่มต้นเมื่อเชื่อมต่ออาร์เรย์:

* **แบ็กเอนด์โฮสต์ Chloros** ทำหน้าที่เป็น PTP grandmaster. กล้อง LATTICE และเซ็นเซอร์แสง DAQ-E จะทำงานเป็น slave ในโดเมน 0 ดังนั้นเวลาประทับของภาพและสเปกตรัม DAQ จะอยู่ในนาฬิกาเดียวกัน (~1 ms).
* `--no-ptp` (CLI

) ปิดใช้งานคุณสมบัตินี้สำหรับการทำงานบนโต๊ะทดลอง — ซึ่งทำให้ **ไม่สามารถ** เปรียบเทียบเวลาประทับระหว่างกล้องได้
* ตรวจสอบสถานะการซิงค์ผ่าน CLI

:

```bash
chloros-cli time-sync status     # grandmaster state, clock identity, health (OK, or why its packets are not reaching the network)
chloros-cli time-sync peers      # slaves seen (cameras + DAQ-E sensors)
chloros-cli time-sync cameras    # per-camera PtpStatus / PtpOffsetFromMaster / PtpMeanPathDelay
```

แท็บ Cameras เองไม่มีตัวบ่งชี้ PTP; ข้อมูลการซิงค์ต่อกล้องที่แสดงอยู่ที่นั่นคือ **Role**(Master/Slave) ที่อ่านได้เท่านั้น,**Sync Line**, และระดับ Capabilities ของอาร์เรย์ สถานะ PTP ของ DAQ-E แสดงอยู่ในรายละเอียดเซ็นเซอร์ของแท็บ Light Sensors

อาร์เรย์แบบเรียลไทม์ พื้นที่แสดงผลหลักมีสองรูปแบบ (สลับได้ที่แถบด้านบน): **มุมมองกริด**(ทุกไทล์คือเซลล์; ลากเพื่อจัดเรียงใหม่เมื่อล็อกกริดถูกปลดล็อก) และ**มุมมองแบบรายการ**(แถวความกว้างเต็ม: อาร์เรย์**รวม**เป็นหนึ่งแถว — เป็นไทล์รวม — ในขณะที่อาร์เรย์**แยก**ให้**สมาชิกแต่ละตัวมีแถวของตัวเอง**พร้อมฟีดสดและตาราง Calibration Target ของตัวเอง; ด้านล่างของอาร์เรย์ มีกล้องเดี่ยวหนึ่งตัว — กล้องที่กำลังใช้งานอยู่). ตัวเลื่อน**Feed Zoom** ใช้ปรับขนาดของไทล์; เมื่อความกว้างของเซลล์ต่ำกว่า 200 px การซ้อนทับชื่อ/fps จะซ่อนอัตโนมัติ กล้องสมาชิกจะปรากฏในแถบด้านข้างและในเลย์เอาต์เริ่มต้นของกริดตามลำดับกล้อง (M3C ก่อน M3M, FRGB ก่อน, กล้องโมโนโครมตามความยาวคลื่น); การปลดล็อกกริดและลากยังคงมีผลเหนือกว่าลำดับของกริด



<!-- SCREENSHOT-NEEDED: list view of a connected SEPARATE array (1.3.0): one full-width row per member camera, each with its live feed and its own Calibration Target table below it. -->

**โหมดแยก** แสดงไทล์หนึ่งต่อกล้องหนึ่ง แต่ละไทล์มีข้อมูลทับซ้อน:

* ชื่อกล้อง (มุมบนซ้าย),
* **ค่า fps** (มุมบนขวา) — นี่คือ *อัตราการจับภาพจริง* ของกล้องที่รายงานโดยระบบหลังบ้าน ไม่ใช่ความถี่การสำรวจภาพตัวอย่าง (ภาพตัวอย่างสดถูกจำกัดไว้ที่ 30 fps ไม่ว่าอัตราการจับภาพจริงจะเป็นเท่าใด),
* จุดแสดงสถานะ — สีเขียว (กำลังสตรีม) / สีเหลืองอำพัน (กำลังโหลด) / สีแดง (เกิดข้อผิดพลาด),
* **ไอคอนหมุนแสดงเฟรมเก่า** เมื่อไม่มีเฟรมใหม่เข้ามาเป็นเวลา 2 วินาที — เป็นเรื่องปกติที่จะเกิดขึ้นประมาณ 5 วินาทีหลังการเชื่อมต่อ/ตัดการเชื่อมต่อใดๆ ในขณะที่ระบบหลังบ้านกำลังปรับสมดุลงบประมาณการส่งข้อมูลระหว่างกล้องต่างๆ**โหมดรวม**แสดงไทล์รวมเดียว: ระบบหลังบ้านจะทำการเดเบย์เออร์, ปรับขนาด, จัดแนว, ลดสัญญาณรบกวน, แปลงเป็นความสว่างต่อแถบ (บวกกับการสะท้อน DLS เมื่อมีเซ็นเซอร์แสงที่ผูกไว้), ประเมินนิพจน์ดัชนีของอาร์เรย์, ใช้ LUT และส่งผลลัพธ์เป็น MJPEG จนกว่าเฟรมที่จัดแนวแล้วเฟรมแรกจะแสดงผล ไทล์จะแสดงสถานะของมันว่า: &quot;Preparing array…&quot;, &quot;กำลังปรับเทียบการจัดแนว…&quot;, &quot;รอเฟรมแรก…&quot;, หรือ — หากการลองใหม่การจัดแนวอัตโนมัติของไทล์ (ประมาณหนึ่งนาที) หมดเวลา — &quot;ต้องจัดแนว&quot; พร้อมปุ่ม**ปรับเทียบการจัดแนว**.

การแสดงค่า fps ของไทล์อาร์เรย์ยังรายงานสถานะของสตรีมด้วย:**&quot;กำลังปรับใช้การตั้งค่า…&quot;**เมื่อมีการเปลี่ยนแปลงการตั้งค่า (รูปแบบ, การรวมพิกเซล, ROI) ซึ่งทำให้กล้องเริ่มต้นใหม่,**&quot;หยุดชั่วคราว&quot;**เมื่ออาร์เรย์ยังทำงานอยู่แต่หยุดส่งกลุ่มเฟรม, และ**&quot;หยุดแล้ว&quot;**เมื่อการสตรีมหยุดลง — ในกรณีนี้ ให้เชื่อมต่ออาร์เรย์ใหม่ เมื่อการแยกสเปกตรัมต้องจำกัดแบนด์ที่แสดงในภาพรวมบนส่วนมากของพิกเซล (25% หรือมากกว่า) แผ่นไทล์จะแสดง**&quot;ข้อมูลแบนด์ความมั่นใจต่ำ · N%&quot;**: ค่าดัชนีที่สร้างขึ้นจากแถบนั้นอาจไม่ถูกต้อง (โดยทั่วไปเป็นเพราะแถบหนึ่งรับแสงน้อยเกินไป)

ข้อมูลสำคัญเกี่ยวกับโหมดรวม:

* ภาพรวมถูกจดทะเบียนกับเฟรมของกล้อง **หลัก**การกำหนดเป้าหมาย AE-ROI และการวัดแสงแบบจุดบนภาพรวมจะแม่นยำสำหรับกล้องหลักและประมาณการสำหรับกล้องรอง; ใช้**Split View** (การตั้งค่าอาร์เรย์ → &quot;Show member cameras&quot;) เพื่อดูไทล์ที่แม่นยำระดับพิกเซลต่อกล้องแต่ละตัวโดยไม่ต้องเปิดการเชื่อมต่อกล้องเพิ่มเติม
* **Display Layers**(การตั้งค่าอาร์เรย์; ปิดตามค่าเริ่มต้น) ช่วยให้คุณเลือกระดับพื้นหน้าและพื้นหลัง — กล้องสมาชิกใดก็ได้หรือ**Index** เมื่อตั้งค่าพื้นหน้า = Index พิกเซลที่อยู่นอกช่วง LUT Min/Max จะแสดงระดับพื้นหลัง
* **ความละเอียดการเรนเดอร์** (ค่าเริ่มต้น 720p) กำหนดความสูงของสตรีมสด *และ* ขนาดการส่งออกภาพรวมที่บันทึกไว้ ภาพจากกล้องแต่ละตัวจะถูกส่งออกเสมอด้วยความละเอียดเต็ม
* การจัดแนวจะถูกคำนวณต่อเซสชันและไม่ถูกบันทึกไว้Chloros

จะจัดแนว **ทุกอาร์เรย์โดยอัตโนมัติหลังการเชื่อมต่อ ในทั้งสองโหมดการแสดง**เมื่อการปรับแสงอัตโนมัติของสมาชิกได้คงที่แล้ว (ระบบจะพยายามต่อไปสูงสุด 5 นาที). ส่วน**การปรับแนว**ในแผงตั้งค่าอาร์เรย์จะแสดงค่า RMS residuals และปุ่ม**ปรับแนวใหม่** — รวมถึงสำหรับอาร์เรย์แยกที่ไม่มีไทล์คอมโพสิต

## การบันทึก: การเฝ้าติดตาม vs การวิเคราะห์

พื้นผิวการจับภาพของอาร์เรย์ถูกแบ่งอย่างชัดเจนเป็น **ระดับการติดตาม**(บันทึกสิ่งที่เห็น) และ**ระดับการวิเคราะห์** (บันทึกข้อมูลดิบ, ปรับเทียบภายหลัง):

| กระบวนการทำงาน | ระดับ | สิ่งที่บันทึก | GUI | CLI

|
| --- | --- | --- | --- | --- |
| **การบันทึก**(ภาพนิ่ง) | การวิเคราะห์ | กลุ่มเฟรมที่ซิงค์กันหนึ่งกลุ่มต่อรอบการบันทึก; ไฟล์ต่อกล้องที่ทุกระดับการส่งออกที่เลือก (ดิบ/เดเบเยอร์/เรเดียนซ์/รีเฟลกเทนซ์/พรีวิว/ดัชนี) + `.daq` sidecar |**ปุ่ม **Capture All** + การตั้งค่าการจับภาพ | `lattice array-capture` |
| **บันทึกวิดีโอดัชนี** | การตรวจสอบ | ภาพรวมดัชนีแบบรวมที่แสดงแบบสด — 8 บิต, ความละเอียดแบบพรีวิว, LUT ถูกฝังไว้แล้ว จากCLI

โดยไม่มีหน้า GUI เปิดอยู่ ระบบหลังจะเรนเดอร์ค่าNDVI

(หรือ `--expr`) ของอาร์เรย์ทันทีที่อาร์เรย์ถูกจัดแนว; การบันทึกที่ไม่เขียนเฟรมใด ๆ จะล้มเหลว | ● บันทึกวิดีโอดัชนี (อาร์เรย์รวม) | `lattice array-record` |
| **Raw burst → สร้างวิดีโอ**| การวิเคราะห์ | เฟรมเซ็นเซอร์ดิบที่อัตราการจับภาพเต็ม + manifest + `.daq`, จากนั้นสร้างใหม่แบบออฟไลน์เป็นวิดีโอ radiance / reflectance / index ที่ได้รับการปรับเทียบแล้ว, จับคู่เวลาให้ตรงกับค่าอ่านจาก DAQ | ⦿ บันทึก raw burst →**สร้างวิดีโอ** | `lattice array-burst` → `lattice array-build-video` |

หลักการทั่วไป: หากพิกเซลจะส่ง *ค่าการวัด* ให้ใช้โหมด capture หรือ burst (ระดับการวิเคราะห์); หากต้องการเพียง *ดูหรือแสดง* สิ่งที่อาร์เรย์เห็น ให้บันทึกวิดีโอดัชนี (ระดับการเฝ้าติดตาม)

### การตั้งค่าการจับภาพ (GUI)

ไอคอนรูปเฟืองข้าง **Capture All** จะเปิดหน้าต่างการตั้งค่าการจับภาพ (ต้องเปิดโครงการไว้ — ภาพที่จับจะถูกบันทึกไว้ในโครงการนั้น):

* **โหมดการจับภาพ**:**Single**(หนึ่งรอบ) /**Continuous**(ต่อเนื่อง; จำกัดด้วยจำนวนการจับภาพ (ค่าเริ่มต้น 1) หรือระยะเวลา (ค่าเริ่มต้น 10 วินาที)) /**Interval** (timelapse: N ภาพทุก X ช่วงเวลารวม Y ครั้ง, ค่าเริ่มต้น 1 ภาพทุก 5 วินาที เป็นเวลา 1 นาที)
* **ประเภทการส่งออกต่อกล้อง**: Raw, Debayered, Radiance, Reflectance, Preview, Index — ทุกตัวเลือกที่ใช้งานได้จะถูกเปิดโดยค่าเริ่มต้น Radiance/Reflectance จะถูกซ่อนสำหรับกล้องที่ใช้ฟิลเตอร์RGB

; **Reflectance จะปรากฏขึ้นเฉพาะเมื่อกล้องมีเซ็นเซอร์แสง DAQ** (ของตัวกล้องเองหรือรับมาจากอาร์เรย์); Index ต้องมีการกำหนดนิพจน์ดัชนีไว้
* **จัดแนว**(ต่ออาร์เรย์, ค่าเริ่มต้น**เปิด**): ปรับการส่งออกของสมาชิกให้สอดคล้องกับโปรไฟล์การจัดแนวของอาร์เรย์ เพื่อให้การส่งออกมีการลงทะเบียนพิกเซลที่ตรงกัน Raw จะไม่ถูกปรับรูปทรงเสมอ แต่จะเก็บการแปลงไว้ในเมตาดาต้า ไฟล์สมาชิกของอาร์เรย์จะถูกบันทึกในทิศทางดั้งเดิมของแต่ละกล้อง (การตั้งค่า Mirror/Rotation ใดๆ จะถูกบันทึกในไฟล์ แต่ไม่ถูกนำไปใช้).
* **Fastest Capture** (สลับ): ใช้เฉพาะ raw + ค่าอ่าน DAQ ที่กำหนด + ภาพรวมดัชนีแบบรวมฟรี โดยข้ามการคำนวณการปรับเทียบขณะจับภาพเพื่อความเร็วสูงสุด — สร้างค่า radiance/reflectance/index ใหม่ในภายหลังจากไฟล์ `.daq` ที่บันทึกไว้
* การเลือกจะคงอยู่ร่วมกับโครงการ กล้องที่ซ่อนหรือถูกหยุดชั่วคราวจะถูกข้ามไป
* **Continuous** บนอาร์เรย์ทำงานภายในแบ็กเอนด์Chloros

(ใหม่ในเวอร์ชัน 1.3.0): เมื่อกล้องทุกตัวในรายการเป็นส่วนหนึ่งของอาร์เรย์ แบ็กเอนด์จะรันลูปการจับภาพเอง โดยเขียนข้อมูลของกลุ่มหนึ่งขณะเลือกกลุ่มถัดไป โดยไม่มีการส่งคำขอต่อการจับภาพแต่ละครั้ง ไดรฟ์เต็มจะหยุดการทำงาน (&quot;Stopped: drive full. Saved N, F failed&quot;). ดู [การตั้งค่าและโหมดการจับภาพ](capture.md#capture-modes) สำหรับหมายเหตุของ Microsoft Defender เกี่ยวกับอัตราการจับภาพสูง

CLI

ที่เทียบเท่า (จุดปลายทาง backend เดียวกัน, ความหมายเดียวกัน):

```bash
# One synced group, every applicable export level per camera (the default)
chloros-cli lattice array-capture -o output/

# Interval timelapse: one reflectance pass every 10 s for 5 minutes
chloros-cli lattice array-capture --interval 10 --duration 300 --processing reflectance -o timelapse/

# Fastest grab for a moving rig — raw + .daq now, calibrate later
chloros-cli lattice array-capture --fastest -o flightline/

# 30-second monitoring clip of the combined index view, plus a GIF
chloros-cli lattice array-record --duration 30 --fps 10 --gif -o monitoring/

# 5-second analysis-grade raw burst, then build the combined index video
chloros-cli lattice array-burst --duration 5 --build --products combined:index --fps 10 -o capture/
```

## การจับคู่เซ็นเซอร์แสง DAQ

ภาพตัวอย่างที่ปรับค่าการสะท้อนแสงและแสงส่องต้องใช้ข้อมูลแสงที่ส่องลงจากเซ็นเซอร์ DAQ (ที่เชื่อมต่อในแท็บ **Light Sensors**):

* แถว **array row**ในแถบด้านข้างจะแสดง**ปุ่ม &quot;DAQ · on/off&quot;** — *เปิด* เมื่อตั้งค่าเซ็นเซอร์แสงระดับอาร์เรย์ **หรือ** กล้องสมาชิกใดก็ตามมีเซ็นเซอร์แสงของตัวเอง; คำอธิบายในเครื่องมือจะระบุอย่างชัดเจนว่าเซ็นเซอร์ใดส่งข้อมูลไปยังกล้องใด
* กำหนดค่าสำหรับทั้งอาร์เรย์ในตั้งค่าอาร์เรย์ → **เซ็นเซอร์แสงรอบตัว**→ เมนูแบบเลื่อนลง**เซ็นเซอร์แสง** การเลือกนี้จะคงอยู่ตามโครงการ แพร่กระจายไปยังกล้องทุกตัวในอาร์เรย์ และกล้องแต่ละตัวยังสามารถแทนที่ด้วยเซ็นเซอร์ของตัวเองได้
* แถบสถานะด้านล่างจะรายงานสถานะแบบเรียลไทม์: **ปิด**→ &quot;รอสเปกตรัมแรก…&quot; →**&quot;เปิด — กล้องทุกตัวในอาร์เรย์ได้รับการปรับแก้แสงแล้ว&quot;** → หรือ หากไม่มีสเปกตรัมใหม่เข้ามาใน 3 วินาทีที่ผ่านมา จะแสดงข้อความแจ้งเตือนว่าข้อมูลเก่า — ค่าอ่านล่าสุดยังคงถูกใช้ต่อไป (ค่าอ่านไม่เคยหมดอายุในเส้นทางจับภาพ)

เมื่อกำหนดเซ็นเซอร์แล้ว: ประเภทการส่งออก Reflectance จะใช้งานได้, การดูตัวอย่างแบบเรียลไทม์จะได้รับการปรับแก้การส่องสว่าง, การปรับแสงอัตโนมัติแบบคาดการณ์สามารถใช้สเปกตรัมได้, และการจับภาพสะท้อนทุกครั้งจะบันทึกค่าอ่าน DAQ ที่ใช้จริงเป็น **ไฟล์ `.daq`** ในโฟลเดอร์ `daq/` เพื่อสามารถประมวลผลใหม่ได้ในภายหลัง นอกจากนี้ ยังมีไฟล์ `.daq.cameras.json` ที่ระบุชื่อกล้องที่ภาพเฟรมนั้นสอดคล้องกับค่าการอ่านดังกล่าว; เมื่อประมวลผลใหม่ Chloros

จะจับคู่ค่าการอ่านกับภาพจากกล้องเหล่านั้นเท่านั้น
