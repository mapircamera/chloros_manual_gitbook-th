# ระบบกล้องหลายตัว

**ระบบ**LATTICE คือกล้อง LATTICE สองตัวหรือมากกว่าที่เชื่อมต่อกันเป็นหน่วยเดียวที่ทำงานพร้อมกัน กล้องหนึ่งตัวทำหน้าที่เป็น**master**: มันส่งสัญญาณทริกเกอร์ GPIO แบบฮาร์ดแวร์ผ่านสายซิงค์ที่ใช้ร่วมกัน (ค่าเริ่มต้น**Line2**) เพื่อให้ทุกกล้องถ่ายภาพในเวลาเดียวกัน Chloros เพิ่มการซิงโครไนซ์เวลา PTP, การดูตัวอย่างสด (ในรูปแบบไทล์ต่อกล้องหรือภาพรวมหลายแถบที่จัดแนวแล้ว), และการถ่ายภาพที่ซิงโครไนซ์ — ทุกครั้งที่มีการถ่ายภาพจะสร้าง**กลุ่มเฟรม** หนึ่งกลุ่ม ซึ่งกล้องทุกตัวมีเวลาประทับและ ID เฟรมเดียวกัน (แสดงเป็น `fid:N` ในผลลัพธ์การถ่ายภาพ)

อาร์เรย์คือวิธีที่กล้องโมโน (M3M) ใช้ในการสร้างดัชนีพืชพรรณ — กล้องหนึ่งตัวให้ข้อมูลหนึ่งแบนด์ และอาร์เรย์จะจัดเรียงข้อมูลเหล่านั้นเป็นสแต็กหลายแบนด์ ดู [กล้องโมโนและดัชนีพืชพรรณ](mono-indices.md).

มีสามวิธีที่เทียบเท่ากันในการเชื่อมต่ออาร์เรย์ และทั้งหมดนี้ใช้ขั้นตอน &quot;smart-prep&quot; ที่เหมือนกัน:

| พื้นผิว | จุดเข้า |
| --- | --- |
| GUI | แท็บกล้อง → **Connect Array** (ปุ่มสีฟ้า) |
| CLI | `chloros-cli lattice array-connect --serials SN1,SN2,…` (หมายเลขซีเรียลแรก = master) |
| Python SDK | `connect_array(serials=[…])` → `ArraySession` (หมายเลขซีเรียลแรก = master) |

Smart-prep ดำเนินการตามลำดับดังนี้: การตรวจสอบความสามารถของเครือข่าย (ICMP DF ping + GVSP probe), การเลือกชั้นการซิงค์, การปรับขนาดเฟรมให้เหมาะสมกับสายสัญญาณโดยอัตโนมัติ, การเปิดใช้งาน PTP, การเลือกรูปแบบพิกเซลอัตโนมัติสำหรับแต่ละกล้อง, การตั้งค่าการเปิดรับแสงอัตโนมัติจากสถานะที่บันทึกไว้ของแต่ละกล้อง และการกำหนดค่าทริกเกอร์ GPIO บน Line2.

{% hint style="info" %}
กล้องต้องสามารถติดต่อได้ผ่านลิงก์ก่อนที่กระบวนการใด ๆ จะทำงาน — ดู [การเชื่อมต่อกล้อง](connecting.md) สำหรับการค้นพบ การกำหนดที่อยู่ และการดาวน์โหลดการปรับเทียบในการเชื่อมต่อครั้งแรก สำหรับระบบกล้องหลายตัว การตั้งค่าวงรับ (receive-ring) ของ NIC ฝั่งโฮสต์มีความสำคัญไม่แพ้ความเร็วของลิงก์; ตารางอาการ→วิธีแก้ไขแบบครบถ้วนอยู่ใน [เอกสารอ้างอิง CLI § การตั้งค่าและปรับแต่ง NIC ฝั่งโฮสต์](../reference/cli-reference.md#host-nic-setup--tuning-lattice-arrays).
{% endhint %}

## กล่องโต้ตอบ Array Connect

แท็บ Cameras → **Connect Array**จะเปิดวิซาร์ดสามขั้นตอน:**Select → Display Mode → Settings**.

### ขั้นตอนที่ 1 — เลือกกล้องหลักและกล้องรอง



<!-- SCREENSHOT-NEEDED: Array Connect dialog, Select scene, with 3-4 LATTICE cameras discovered. Table showing Camera / Serial / IP / Master radio / Slave checkbox columns, with the green "GPIO master detected — selections pre-populated" probe banner visible above the table. -->กล่องโต้ตอบจะสแกนเครือข่ายทันทีที่เปิดขึ้น (&quot;Scanning network...&quot;) จากนั้นจะตรวจสอบการต่อสายทริกเกอร์ GPIO (&quot;Probing GPIO wiring...&quot;). คุณต้องมี **กล้องอย่างน้อย 2 ตัว** เพื่อสร้างอาร์เรย์

การตรวจสอบการต่อสายจะกรอกตัวเลือกบทบาทไว้ล่วงหน้าเมื่อเป็นไปได้ และแสดงหนึ่งในสามข้อความต่อไปนี้:

| ข้อความ | ความหมาย |
| --- | --- |
| &quot;ตรวจพบมาสเตอร์ GPIO — ตัวเลือกถูกกรอกไว้ล่วงหน้า&quot; (สีเขียว) | การตรวจสอบพบโครงสร้างการทริกเกอร์แล้ว; ช่องทำเครื่องหมายของมาสเตอร์และสเลฟถูกกรอกไว้แล้ว |
| &quot;ไม่พบมาสเตอร์ — ตรวจสอบสาย GPIO&quot; (สีส้ม) | ไม่มีกล้องใดตรวจพบสัญญาณทริกเกอร์; ตรวจสอบสายซิงค์ คุณสามารถเลือกบทบาทด้วยตนเองได้ |
| &quot;ไม่มีสายซิงค์: {serials}&quot; (สีส้ม) | กล้องที่แสดงในรายการไม่มีสายซิงค์ต่ออยู่ |

ตารางกล้องมีคอลัมน์ **กล้อง / Serial / IP / Master (วิทยุ) / Slave (ช่องทำเครื่องหมาย)**:

* เลือก **Master หนึ่งตัว**และ**Slave หนึ่งตัวหรือมากกว่า** เท่านั้น การคลิกที่วิทยุของ Master ปัจจุบันอีกครั้งจะลบการเลือกนั้น |
* กล้องที่มีเครื่องหมาย **&quot;ไม่มีสายซิงค์&quot;** ไม่สามารถเลือกเป็นสเลฟได้ — สเลฟที่ไม่มีสายทริกเกอร์จะรออยู่บนสายซิงค์ตลอดไปและส่งสัญญาณภาพที่ไม่มีประโยชน์ ให้เชื่อมต่อกล้องนั้นเป็นกล้องแบบสแตนด์อโลนแทน
* กล้องที่เชื่อมต่อแบบสแตนด์อโลนอยู่แล้ว *ไม่* ถูกปิดใช้งาน: การเชื่อมต่อในอาร์เรย์จะยกเลิกเซสชันสแตนด์อโลนและเปิดกล้องนั้นใหม่ภายในอาร์เรย์

**ถัดไป: โหมดแสดงผล →**จะเปิดใช้งานเมื่อเลือกมาสเตอร์และสเลฟอย่างน้อยหนึ่งตัวแล้ว**สแกนใหม่** จะรันการค้นหาและตรวจสอบการเชื่อมต่อสายใหม่

{% hint style="warning" %}
**ยกเลิก** จะถูกปิดใช้งานระหว่างการสแกนหรือการตรวจสอบ — การยกเลิกกลางกระบวนการตรวจสอบอาจทำให้กล้องSDKบนเฟิร์มแวร์กล้อง LATTICE ล่มได้ โปรดรอจนกว่าไอคอนหมุนจะเสร็จสิ้น
{% endhint %}

### ขั้นตอนที่ 2 — โหมดการแสดงผล



<!-- SCREENSHOT-NEEDED: Array Connect dialog, Display Mode scene, showing the two selectable cards ("Separate Cameras" and "Combined Cameras") with Combined selected/highlighted as the default. -->| โหมด | ผลลัพธ์ |
| --- | --- |
| **กล้องแยก** | หนึ่งไทล์สดต่อกล้องหนึ่งตัว ทุกกล้องถูกทริกเกอร์พร้อมกันเพื่อให้เฟรมยังคงซิงค์กัน แต่ละกล้องรักษาสีและตั้งค่าของตัวเอง |
| **กล้องรวม** *(ค่าเริ่มต้น)* | ไทล์เดียวที่แสดงภาพรวมหลายแถบที่จัดแนวแล้ว NDVI /index กล้องทั้งหมดใช้สีของอาร์เรย์ร่วมกัน |

โหมดการแสดงผลจะเปลี่ยนเฉพาะการแสดงตัวอย่างสดเท่านั้น — พฤติกรรมการจับภาพยังคงเหมือนเดิมในทั้งสองโหมด

### ขั้นตอนที่ 3 — การตั้งค่าอาร์เรย์และผลลัพธ์

<!-- SCREENSHOT-NEEDED: Array Connect dialog, Settings scene, healthy state: left column with ROI / Binning / Pin resolution / Trigger Rate controls, right "Projected Outcome" column showing green "Simultaneous capture" tier, an fps range, the NIC line, the "Sim-emit burst" line, and the "Wire budget" line with a checkmark. -->ที่คาดการณ์

เมื่อเข้าสู่ฉากนี้ Chloros จะขอ **คำแนะนำ**จากระบบหลังบ้าน และใช้การรวม ROI + binning ที่เหมาะสมกับวงรับสัญญาณของ NIC ของคุณโดยอัตโนมัติ (ระบบจะเลือก binning แทนการตัด ROI เพราะ binning ช่วยรักษาสนามมองทั้งหมด) ทุกการเปลี่ยนแปลงที่คุณทำจะรันการวิเคราะห์ใหม่แบบเรียลไทม์ และอัปเดต**ผลลัพธ์ที่คาดการณ์** ทางด้านขวา

คอลัมน์ซ้าย — การตั้งค่า:

| การควบคุม | ตัวเลือก | ค่าเริ่มต้น | หมายเหตุ |
| --- | --- | --- | --- |
| **ROI (มุมมอง)** | เต็ม (2048×1536) / ครึ่ง (1024×768) / หนึ่งในสี่ (512×384) | เต็ม | การตัดภาพจากเซ็นเซอร์: ตัดภาพครึ่ง/หนึ่งในสี่ลงสู่พื้นที่ที่เล็กกว่าที่ความละเอียดพิกเซลดั้งเดิม |
| **Binning** | 1× / 2× (รวม 2×2) / 4× (รวม 4×4) | 1× | การรวมพิกเซลด้วยฮาร์ดแวร์: 2×2 = FoV เต็มที่ค่าใช้จ่ายสายสัญญาณ 1/4; 4×4 = FoV เต็มที่ค่าใช้จ่ายสายสัญญาณ 1/16. ถูกซ่อนหากกล้องไม่สนับสนุนการรวมพิกเซล |
| **ภาพด้านสาย** (การอ่านข้อมูล) | — | — | ความกว้าง×ความสูงหลังการรวมพิกเซลที่ส่งผ่านสายจริง ๆ ซึ่งถูกปรับให้ลงเป็นจำนวนเท่าของ 16 (ขั้นต่ำ 64) |
| **ความละเอียดพิน**| ช่องทำเครื่องหมาย | ปิด | Chloros โดยปกติจะเพิ่มการรวมพิกเซลอัตโนมัติเมื่อเชื่อมต่อ หากอัตราการส่งข้อมูลที่คาดการณ์ไว้ต่ำกว่า**

1.5 fps** การตั้งค่าพินจะรักษาขนาดเฟรมที่เลือกไว้และยอมรับอัตราการส่งข้อมูลที่ต่ำลง — และเปลี่ยนการตั้งค่าที่มีการใช้งานเกินขีดจำกัดให้เป็นการปฏิเสธการเชื่อมต่ออย่างเด็ดขาด แทนที่จะลดความละเอียดลงอัตโนมัติ |
| **อัตราการทริกเกอร์** | 0.5–60 fps, ขั้น 0.1 | ว่าง = อัตโนมัติ | อัตราการยิงทริกเกอร์ของมาสเตอร์ ปล่อยให้ว่างเพื่อให้ Chloros คำนวณค่านี้ |
| **Wire Budget**| 20–2000 MB/s, ขั้น 10 | ว่าง = อัตโนมัติ | ปริมาณที่โฮสต์สามารถรับได้จริง ในหน่วย MB/s —**ตัวเลขเดียวที่การจัดสรรอาร์เรย์ทั้งหมดขึ้นอยู่กับ** ตรวจจับอัตโนมัติจากอะแดปเตอร์เครือข่าย ลดค่าลงหากอาร์เรย์รายงานเฟรมที่เสียหาย: ค่าที่ตรวจจับได้อาจสูงเกินจริงสำหรับอะแดปเตอร์ USB และสวิตช์ที่ใช้ร่วมกัน การเปลี่ยนแปลงค่านี้จะทำให้การคาดการณ์ทำงานใหม่แบบเรียลไทม์ |

คอลัมน์ขวา — **ผลลัพธ์ที่คาดการณ์**:

* **ระดับการซิงค์** — &quot;การจับภาพพร้อมกัน&quot; (สีเขียว), &quot;การจับภาพพร้อมกัน (FTD-staggered emit)&quot; (สีเขียว), &quot;การจับภาพแบบสลับ (100 ms drift)&quot; (สีเหลือง), หรือ &quot;การกำหนดค่าใหญ่เกินไป&quot; (สีแดง).
* **การคาดการณ์ fps** — แสดงเป็นช่วง (&quot;มืด → สว่าง&quot;) เนื่องจากอัตราการถ่ายของกลุ่มกล้องที่ซิงโครไนซ์ถูกจำกัดโดยเวลาเปิดรับแสงของกล้องที่ช้าที่สุด
* **บรรทัด NIC** — ความเร็วการเชื่อมต่อและปริมาณข้อมูลที่ส่งผ่านอย่างต่อเนื่อง (&quot;NIC {mbps} Mbps · sustained {N} MB/s&quot;).
* **การตรวจสอบการส่งข้อมูลแบบ Sim-emit burst** — NIC ของโฮสต์สามารถรับข้อมูลแบบ ring absorb ได้หรือไม่ สำหรับการส่งข้อมูลแบบ burst พร้อมกันจากกล้องทั้งหมด (&quot;Sim-emit burst: X MB · NIC ring usable: Y MB ✓/✗&quot;).
* **การตรวจสอบงบประมาณสาย** — ความต้องการรวมในสภาวะคงที่เทียบกับขีดจำกัดสายที่ปลอดภัยจากการชนกัน (&quot;Wire budget: {demand} MB/s ที่ถูกขอโดย {n} กล้อง · ceiling {ceiling} MB/s ✓/✗ ถูกจองเกิน&quot;)
* **&quot;จำนวนกล้องสูงสุดบนสายนี้: {n} — กำหนดโดยขีดจำกัดแบนด์วิดท์ขั้นต่ำต่อกล้อง ดังนั้นการรวมข้อมูล (binning) จะไม่เพิ่มค่านี้&quot;** — แสดงขึ้นเมื่อคุณใกล้ถึง (หรือเกิน) ขีดจำกัดจำนวนกล้องสูงสุด
* **&quot;เฟรมจะหลุดที่การตั้งค่าเหล่านี้&quot;**— คำเตือนสีแดงพร้อมเหตุผลจากระบบหลังบ้าน รวมถึงรายชื่อปัจจัยที่ขัดขวาง และ**คำแนะนำการแก้ไข** สีฟ้า (&quot;เพื่อให้อาร์เรย์นี้พอดีกับเครือข่าย&quot; / &quot;เพื่อปลดล็อกการบันทึกพร้อมกัน&quot;)**Apply &amp; Connect** จะถูกปิดจนกว่าจะมีการคาดการณ์ และป้ายกำกับจะบอกเหตุผลที่ระบบปฏิเสธ:

| ป้ายกำกับปุ่ม | ความหมาย | วิธีแก้ไข |
| --- | --- | --- |
| &quot;Analyzing...&quot; | การวิเคราะห์ยังดำเนินอยู่ | รอ |
| **&quot;มีกล้องมากเกินไปสำหรับเครือข่ายนี้&quot;**| ชุดกล้องใช้แบนด์วิธเกินขีดจำกัด (การตรวจสอบรวมล้มเหลว) | ลดจำนวนกล้อง, ใช้เฟรมจัมโบ้แบบ end-to-end, หรือใช้ NIC ที่เร็วขึ้น**การลด ROI จะไม่ช่วย** — ดูด้านล่าง |
| **&quot;ลด ROI เพื่อเปิดใช้งาน&quot;** | เฟรมจะหลุดออกในการตั้งค่านี้ (การตรวจสอบ burst/ring ล้มเหลว) | ลด ROI, เพิ่ม binning หรือแก้ไข ring รับของ NIC |

## แบนด์วิธ: จำนวนกล้องที่รองรับได้

ความจุที่อาร์เรย์สามารถรองรับได้ขึ้นอยู่กับคุณสมบัติของสายสัญญาณ ไม่ใช่ของ Chloros ดังนั้นข้อมูลการวางแผนจึงอยู่ในคู่มือฮาร์ดแวร์: **[การวางแผนแบนด์วิธของอาร์เรย์](https://mapir.gitbook.io/lattice-camera/setup/array-bandwidth-planning)**.

Chloros ทำงานกับข้อมูลเหล่านี้อย่างไร: หน้าต่างการเชื่อมต่อจะดำเนินการตรวจสอบเครือข่าย (network probe), คาดการณ์อัตราเฟรมที่สามารถบรรลุได้, และเลือกระดับ (tier) ที่เหมาะสม หากอาร์เรย์ใช้แบนด์วิดท์เกินขีดจำกัดของสายสัญญาณ ระบบจะปฏิเสธการเชื่อมต่อแทนที่จะทิ้งแพ็กเก็ตไปอย่างเงียบๆ — ดูแผงผลลัพธ์ที่คาดการณ์ไว้ (projected-outcome panel) ที่อธิบายไว้ข้างต้น

| สิ่งที่เกิดขึ้น | ความหมาย | จุดที่ควรตรวจสอบ |
| --- | --- | --- |
| **Corrupt**— เฟรมมาถึงแต่มีโครงสร้างผิดปกติ | การสูญเสียแพ็กเก็ต GVSP บนเส้นทางเครือข่าย |**wire budget**, วงรับของ NIC, เฟรมจัมโบ้, สวิตช์ |

### อะแดปเตอร์เครือข่าย USB ถูกจำกัดความเร็วสูงสุดที่ 200 MB/s

อะแดปเตอร์อีเทอร์เน็ต USB จะประกาศอัตราความเร็ว *อีเทอร์เน็ต* ของมัน แต่สิ่งที่มันสามารถ
รักษาได้จริง ๆ นั้นถูกจำกัดโดยบัส USB และไดรเวอร์ของมัน อะแดปเตอร์ USB 10GbE เคยถูกระบุ
ว่ามีอัตราการส่งข้อมูลประมาณ 1000 MB/s — ตัวเลขที่ยังไม่เคยมีอุปกรณ์ใดวัดได้ — และการปรับความเร็ว
กล้องสี่ตัวตามพื้นที่ว่างที่ไม่มีอยู่จริงนั้น ทำให้เฟรมเสียหาย 6–18 % ในขณะที่ระบบ
ยังคงรายงานอัตราเฟรมเป้าหมายที่ปกติ อะแดปเตอร์ที่เชื่อมต่อผ่าน USB ปัจจุบันถูกจำกัดไว้ที่
**200 MB/s** การจำกัดนี้เป็นค่าสัมบูรณ์ ไม่ใช่เปอร์เซ็นต์ เนื่องจากข้อจำกัดอยู่ที่
บัส: อะแดปเตอร์ USB 1 GbE สามารถดึงความเร็วได้ประมาณ 80 MB/s และไม่ได้รับผลกระทบ

หากเครื่องโฮสต์ของคุณมีความเร็วจริงที่สูงกว่าขีดจำกัด ให้เพิ่ม **Wire Budget** เพื่อระบุให้ชัดเจน

## การซิงโครไนซ์เวลา PTP

การ *ซิงโครไนซ์* เฟรมเกิดจากทริกเกอร์ของฮาร์ดแวร์; **PTP** (IEEE 1588 PTPv2) ให้ *timestamps* ที่เทียบเท่ากันในทุกอุปกรณ์ มันถูกเปิดใช้งานโดยค่าเริ่มต้นเมื่อเชื่อมต่ออาร์เรย์:

* **แบ็กเอนด์โฮสต์ Chloros**ทำงานเป็น PTP grandmaster**。กล้อง LATTICE และเซ็นเซอร์แสง DAQ-E จะทำงานเป็น slave ในโดเมน 0 ดังนั้นเวลาประทับของภาพและสเปกตรัม DAQ จะถูกกำหนดโดยนาฬิกาเดียว (~1 ms)。
* `--no-ptp` (CLI) ปิดใช้งาน PTP สำหรับงานบนโต๊ะทดลอง — ซึ่งทำให้ **ไม่สามารถ** เปรียบเทียบเวลาประทับระหว่างกล้องได้
* ตรวจสอบสถานะการซิงค์ด้วย CLI:

```bash
chloros-cli time-sync status     # grandmaster state, clock identity
chloros-cli time-sync peers      # slaves seen (cameras + DAQ-E sensors)
chloros-cli time-sync cameras    # per-camera PtpStatus / PtpOffsetFromMaster / PtpMeanPathDelay
```

แท็บ Cameras เองไม่มีตัวบ่งชี้ PTP; พื้นผิวการซิงค์ต่อกล้องมี **Role**(Master/Slave) ที่อ่านได้เท่านั้น,**Sync Line**, และระดับ Capabilities ของอาร์เรย์ สถานะ PTP ของ DAQ-E แสดงอยู่ในรายละเอียดเซ็นเซอร์ของแท็บ Light Sensors

## มุมมอง

<!-- SCREENSHOT-NEEDED: Cameras tab with a connected combined array: sidebar showing the ARRAY row (color badge, array name, "DAQ · on" pill) with indented member camera rows, and the main area showing the combined index composite tile with the LUT-colored NDVI render, top-left array name pill, and top-right fps readout. -->อาร์เรย์แบบเรียลไทม์

พื้นที่แสดงภาพหลักมีสองรูปแบบ (สลับได้ในแถบด้านบน): **มุมมองแบบกริด**(ทุกไทล์คือเซลล์; ลากเพื่อจัดเรียงใหม่เมื่อล็อกกริดถูกปลดล็อก) และ**มุมมองรายการ**(อาร์เรย์แสดงเต็มความกว้างด้านบน, กล้องที่ใช้งานอยู่หนึ่งตัวด้านล่าง) ตัวเลื่อน**Feed Zoom** ใช้ปรับขนาดไทล์; เมื่อความกว้างเซลล์ต่ำกว่า 200 px ชื่อ/fps ที่แสดงทับจะซ่อนอัตโนมัติ**โหมดแยก** แสดงหนึ่งไทล์ต่อกล้องหนึ่งตัว แต่ละไทล์แสดงข้อมูลทับซ้อน:

* ชื่อกล้อง (มุมซ้ายบน),
* **ค่า fps** (มุมขวาบน) — นี่คือ *อัตราการจับภาพจริง* ของกล้องที่ระบบหลังบ้านรายงานมา ไม่ใช่ความถี่การสำรวจของภาพตัวอย่าง (ภาพตัวอย่างสดถูกจำกัดไว้ที่ 30 fps ไม่ว่าอัตราการจับภาพจริงจะเป็นเท่าใด),
* จุดแสดงสถานะ — สีเขียว (กำลังสตรีม) / สีเหลือง (กำลังโหลด) / สีแดง (เกิดข้อผิดพลาด),
* **ไอคอนหมุนแสดงเฟรมเก่า** เมื่อไม่มีเฟรมใหม่เข้ามาเป็นเวลา 2 วินาที — เป็นเรื่องปกติที่จะเกิดขึ้นประมาณ 5 วินาทีหลังการเชื่อมต่อ/ตัดการเชื่อมต่อใดๆ ในขณะที่ระบบหลังบ้านกำลังปรับสมดุลงบประมาณการส่งข้อมูลระหว่างกล้องต่างๆ**โหมดรวม**แสดงไทล์คอมโพสิตเดียว: ระบบหลังจะทำการเดเบเยอร์, ปรับขนาด, จัดแนว, ลดสัญญาณรบกวน, แปลงเป็นความสว่างต่อแถบ (บวกกับการสะท้อนแสง DLS เมื่อมีเซ็นเซอร์แสงที่ผูกไว้), ประเมินนิพจน์ดัชนีของอาร์เรย์, ใช้ LUT, และสตรีมผลลัพธ์เป็น MJPEG. จนกว่าเฟรมที่จัดแนวแล้วจะแสดงผลครั้งแรก แผ่นไทล์จะแสดงสถานะของมัน: &quot;Preparing array…&quot;, &quot;ปรับเทียบการจัดแนว…&quot;, &quot;รอเฟรมแรก…&quot;, หรือ — หากงบประมาณการลองจัดแนวอัตโนมัติ (~30 วินาที) หมด — &quot;ต้องจัดแนว&quot; พร้อมปุ่ม**ปรับเทียบการจัดแนว**

ข้อมูลสำคัญเกี่ยวกับโหมดรวม:

* ภาพรวมถูกจัดตำแหน่งให้ตรงกับเฟรมของกล้อง **หลัก**การกำหนดพื้นที่ AE-ROI และการวัดแสงแบบจุดบนภาพรวมจะแม่นยำสำหรับกล้องหลักและประมาณการสำหรับกล้องรอง; ใช้**Split View** (การตั้งค่าอาร์เรย์ → &quot;แสดงกล้องสมาชิก&quot;) เพื่อดูไทล์ที่แม่นยำระดับพิกเซลสำหรับแต่ละกล้องโดยไม่ต้องเปิดการเชื่อมต่อกล้องเพิ่มเติม
* **Display Layers**(การตั้งค่าอาร์เรย์; ปิดตามค่าเริ่มต้น) ช่วยให้คุณเลือกชั้นหน้าและชั้นหลัง — กล้องสมาชิกใดก็ได้หรือ**Index** เมื่อชั้นหน้า = Index พิกเซลที่อยู่นอกช่วง LUT Min/Max จะแสดงชั้นหลัง
* **ความละเอียดการเรนเดอร์** (ค่าเริ่มต้น 720p) กำหนดความสูงของสตรีมสด *และ* ขนาดไฟล์ส่งออกของภาพรวมที่บันทึกไว้ ภาพจากกล้องแต่ละตัวจะส่งออกด้วยความละเอียดเต็มเสมอ
* การจัดแนวถูกคำนวณต่อเซสชันและไม่ถูกบันทึกไว้ — ดูส่วนการจัดแนวในหน้าต่างการตั้งค่าอาร์เรย์เพื่อดูค่า RMS residuals และปุ่ม Recalibrate

## การจับภาพ: การเฝ้าติดตาม vs การวิเคราะห์

พื้นผิวการจับภาพของอาร์เรย์แบ่งอย่างชัดเจนเป็น **ระดับการเฝ้าติดตาม**(บันทึกสิ่งที่คุณเห็น) และ**ระดับการวิเคราะห์** (บันทึกข้อมูลดิบ, ปรับเทียบในภายหลัง):

| กระบวนการทำงาน | ระดับ | สิ่งที่บันทึก | GUI | CLI |
| --- | --- | --- | --- | --- |
| **การบันทึก**(ภาพนิ่ง) | การวิเคราะห์ | กลุ่มเฟรมที่ซิงค์หนึ่งกลุ่มต่อครั้ง; ไฟล์ต่อกล้องที่ทุกระดับการส่งออกที่เลือก (raw/debayered/radiance/reflectance/preview/index) + `.daq` sidecar | ปุ่ม**Capture All** + การตั้งค่าการจับภาพ | `lattice array-capture` |
| **บันทึกวิดีโอดัชนี** | การเฝ้าติดตาม | ภาพรวมดัชนีแบบรวมที่แสดงแบบสด — 8 บิต, ความละเอียดแบบพรีวิว, LUT ถูกฝังไว้; ต้องเปิดสตรีมสด | ● บันทึกวิดีโอดัชนี (อาร์เรย์รวม) | `lattice array-record` |
| **ชุดภาพดิบ → สร้างวิดีโอ**| การวิเคราะห์ | เฟรมภาพดิบจากเซ็นเซอร์ที่อัตราการจับภาพเต็ม + manifest + `.daq`, จากนั้นสร้างใหม่แบบออฟไลน์เป็นวิดีโอความสว่าง / ความสะท้อน / ดัชนีที่ปรับเทียบแล้ว, จับเวลาให้ตรงกับค่าอ่านจาก DAQ | ⦿ บันทึกชุดภาพดิบ →**สร้างวิดีโอ** | `lattice array-burst` → `lattice array-build-video` |

หลักการทั่วไป: หากพิกเซลจะส่ง *ค่าการวัด*, ให้ใช้โหมด capture หรือ burst (ระดับการวิเคราะห์); หากต้องการเพียง *ดูหรือแสดง* สิ่งที่อาร์เรย์จับภาพได้ ให้บันทึกวิดีโอดัชนี (ระดับการเฝ้าติดตาม)

### การตั้งค่าการจับภาพ (GUI)



<!-- SCREENSHOT-NEEDED: Capture Settings pane (gear next to Capture All) with a connected array: capture-mode buttons (Single/Continuous/Interval), the bulk export-type toggle row, the Fastest Capture toggle, and the per-array group card showing the Aligned checkbox and the "Record index video" / "Record raw burst" buttons. -->ไอคอนรูปเฟืองข้าง **Capture All** จะเปิดหน้าต่างการตั้งค่าการจับภาพ (ต้องเปิดโครงการไว้ — ภาพที่จับจะถูกบันทึกไว้ในโครงการนั้น):

* **โหมดการจับภาพ**:**Single**(หนึ่งรอบ) /**ต่อเนื่อง**(ถ่ายต่อเนื่อง; จำกัดด้วยจำนวนการถ่าย (ค่าเริ่มต้น 1) หรือระยะเวลา (ค่าเริ่มต้น 10 วินาที)) /**ช่วงเวลา** (timelapse: ถ่าย N ครั้งทุก X ช่วงเวลา รวม Y ครั้ง, ค่าเริ่มต้น 1 ครั้งทุก 5 วินาที เป็นเวลา 1 นาที).
* **ประเภทการส่งออกต่อกล้อง**: Raw, Debayered, Radiance, Reflectance, Preview, Index — ทุกตัวเลือกที่ใช้งานได้จะถูกเปิดไว้เป็นค่าเริ่มต้น Radiance/Reflectance จะถูกซ่อนสำหรับกล้องที่ใช้ตัวกรองRGB;**Reflectance จะปรากฏเฉพาะเมื่อกล้องมีเซ็นเซอร์แสง DAQ** (เป็นของตัวเองหรือรับมาจากอาร์เรย์); Index ต้องการนิพจน์ดัชนีที่ตั้งค่าไว้แล้ว
* **จัดแนว**(ต่ออาร์เรย์, ค่าเริ่มต้น**เปิด**): ปรับการส่งออกของสมาชิกให้สอดคล้องกับโปรไฟล์การจัดแนวของอาร์เรย์ เพื่อให้การส่งออกมีการลงทะเบียนพิกเซล Raw จะไม่ถูกปรับแต่งเสมอ แต่จะเก็บการแปลงไว้ในเมตาดาต้า
* **Fastest Capture** (สลับ): raw-only + ค่าอ่าน DAQ ที่กำหนด + ภาพรวมดัชนีแบบรวมฟรี โดยข้ามการคำนวณการปรับเทียบขณะจับภาพเพื่อความเร็วสูงสุด — สร้าง radiance/reflectance/index ใหม่ในภายหลังจากไฟล์ `.daq` ที่บันทึกไว้
* การเลือกจะคงอยู่ร่วมกับโครงการ กล้องที่ถูกซ่อนหรือหยุดชั่วคราวจะถูกข้ามไป

CLI ที่เทียบเท่า (จุดปลายทางแบ็กเอนด์เดียวกัน, ความหมายเดียวกัน):

```bash
# One synced group, every applicable export level per camera (the default)
chloros-cli lattice array-capture -o output/

# Interval timelapse: one reflectance pass every 10 s for 5 minutes
chloros-cli lattice array-capture --interval 10 --duration 300 --processing reflectance -o timelapse/

# Fastest grab for a moving rig — raw + .daq now, calibrate later
chloros-cli lattice array-capture --fastest -o flightline/

# 30-second monitoring clip of the combined index view, plus a GIF
chloros-cli lattice array-record --duration 30 --fps 10 --gif -o monitoring/

# 5-second analysis-grade raw burst, then build the combined index video
chloros-cli lattice array-burst --duration 5 --build --products combined:index --fps 10 -o capture/
```

TIFF การบีบอัดสำหรับการจับภาพคือ `deflate` (ไม่สูญเสียข้อมูล, ค่าเริ่มต้น) หรือ `none` — ตารางแฟล็กเต็มรูปแบบ, โครงสร้างโฟลเดอร์การจับภาพ และกฎการประมวลผลใหม่มีอยู่ใน [CLI Reference](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).

## การจับคู่เซ็นเซอร์แสง DAQ

ภาพตัวอย่างที่ปรับค่าการสะท้อนแสงและแสงส่องต้องใช้ข้อมูลแสงที่ส่องลงจากเซ็นเซอร์ DAQ (เชื่อมต่อในแท็บ **Light Sensors**):

* แถว **array row**ในแถบด้านข้างจะแสดง**ปุ่ม &quot;DAQ · on/off&quot;** — *เปิด* เมื่อตั้งเซ็นเซอร์แสงระดับอาร์เรย์ **หรือ** กล้องสมาชิกใดก็ตามมีเซ็นเซอร์แสงของตัวเอง; คำอธิบายในเครื่องมือจะระบุอย่างชัดเจนว่าเซ็นเซอร์ใดส่งข้อมูลไปยังกล้องใด
* กำหนดค่าสำหรับทั้งอาร์เรย์ในตั้งค่าอาร์เรย์ → **เซ็นเซอร์แสงรอบตัว**→ เมนูแบบเลื่อนลง**เซ็นเซอร์แสง** การเลือกนี้จะคงอยู่ตามโครงการ แพร่กระจายไปยังกล้องทุกตัวในอาร์เรย์ และกล้องแต่ละตัวยังสามารถแทนที่ด้วยเซ็นเซอร์ของตัวเองได้
* แถบสถานะด้านล่างจะแสดงสถานะแบบเรียลไทม์: **ปิด**→ &quot;รอสเปกตรัมแรก…&quot; →**&quot;กำลังทำงาน — กล้องทุกตัวในอาร์เรย์ได้รับการปรับแก้แสงแล้ว&quot;** → หรือ หากไม่มีสเปกตรัมใหม่เข้ามาใน 3 วินาทีที่ผ่านมา จะแสดงข้อความแจ้งเตือนว่าข้อมูลเก่า — ค่าอ่านล่าสุดยังคงถูกใช้อยู่ (ค่าอ่านไม่เคยหมดอายุในเส้นทางจับภาพ)

เมื่อกำหนดเซ็นเซอร์แล้ว: ประเภทการส่งออก Reflectance จะใช้งานได้, การดูตัวอย่างแบบเรียลไทม์จะได้รับการปรับแก้การส่องสว่าง, การปรับค่าการเปิดรับแสงอัตโนมัติแบบคาดการณ์สามารถใช้สเปกตรัมได้, และการจับภาพ reflectance ทุกครั้งจะบันทึกค่าการอ่าน DAQ ที่ใช้จริงเป็น **`.daq` sidecar** ข้างๆ ภาพ เพื่อให้สามารถประมวลผลการจับภาพใหม่ได้ในภายหลัง

## `array-connect` ตัวเลือก CLI

| ตัวเลือก | ค่าเริ่มต้น | คำอธิบาย |
| --- | --- | --- |
| `--serials SN1,SN2,…` | ค้นหาอัตโนมัติกล้อง LATTICE ทั้งหมด (ต้องมี ≥2) | **กล้องที่มีหมายเลขซีเรียลแรกคือ MASTER.** |
| `--line {Line0,Line2,Line3}` | `Line2` | สายซิงค์ GPIO |
| `--target-fps F` | auto | อัตราการยิงของ Master |
| `--binning {1,2,4}` | อัตโนมัติ | การจัดกลุ่มฮาร์ดแวร์ |
| `--force-tier {sim-capture-sim-emit, sim-capture-ftd-stagger, slip-emit-and-capture}` | อัตโนมัติ | การแทนที่โดยผู้เชี่ยวชาญของตัวเลือกระดับการซิงค์ |
| `--wire-ceiling-mbps MB_PER_S` | ตรวจจับอัตโนมัติ | งบประมาณสายของโฮสต์ใน MB/s — รูปแบบCLIของสนาม **Wire Budget** ลดค่านี้ลงหากอาร์เรย์รายงานเฟรมที่เสียหาย ค่านี้จะถูกบันทึกพร้อมกับโครงการ ดังนั้นการเชื่อมต่อใหม่ในภายหลังจะคืนค่าเดิม |
| `--no-recommend` | ปิด | ข้ามขั้นตอนการวิเคราะห์เครือข่าย |
| `--no-ptp` | ปิด | ปิดใช้งาน PTP (ทำให้เวลาประทับของกล้องต่างกันไม่สามารถเปรียบเทียบได้) |

`lattice array-list`, `array-status` และ `array-disconnect` จัดการเซสชันที่คงอยู่ รายการอ้างอิงคำสั่งย่อยทั้งหมด รวมถึงการจัดแนว (`align-calibrate` / `align-apply`) และเครื่องมือเครือข่าย อยู่ใน [CLI Reference § chloros-cli lattice](../reference/cli-reference.md#chloros-cli-lattice); ส่วนที่เทียบเท่าในSDK (`connect_array`, `ArraySession`, `attach_array`, `analyze_array_network`) อยู่ใน [SDK Reference](../reference/sdk-reference.md). จาก Python งบประมาณสายคือ `connect_array(..., wire_ceiling_mbps=120)` และการแบ่งข้อมูลที่เสียหายขณะใช้งาน/ไม่ได้รับเลยอยู่ที่ [`/api/camera/array/<id>/capability`](../reference/sdk-reference.md#array-health--which-subsystem-is-losing-frames).
