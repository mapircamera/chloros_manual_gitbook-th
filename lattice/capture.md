# การตั้งค่าและโหมดการถ่ายภาพ

การถ่ายภาพในแท็บ “กล้อง” ควบคุมโดยปุ่ม **Capture All**สีแดงหนึ่งปุ่ม และส่วน**Capture Settings** หนึ่งส่วน ซึ่งกำหนดผลลัพธ์ที่ปุ่มดังกล่าวสร้างขึ้น ได้แก่ กล้องใดจะเข้าร่วมการถ่ายภาพ ประเภทไฟล์ส่งออกที่แต่ละกล้องจะบันทึก และว่าชัตเตอร์จะทำงานครั้งเดียว ต่อเนื่อง หรือตามช่วงเวลา หน้านี้อธิบายขั้นตอนทั้งหมด — การตั้งค่า การถ่ายภาพเอง ตำแหน่งที่ไฟล์ถูกบันทึกบนดิสก์ และวิธีการประมวลผลไฟล์เหล่านั้นใหม่เพื่อสร้างผลิตภัณฑ์ที่ผ่านการปรับเทียบในภายหลัง ส่วนการควบคุมกล้องและระบบกล้องแบบอาร์เรย์นั้นอยู่ที่ [การตั้งค่ากล้อง](camera-settings.md)

{% hint style="info" %}
**การถ่ายภาพต้องเปิดโครงการไว้ก่อน** ปุ่ม "Capture All" และไอคอนรูปเกียร์ "Capture Settings" จะถูกปิดใช้งานจนกว่าจะมีโครงการเปิดอยู่ ("สร้างหรือเปิดโครงการเพื่อบันทึกการถ่ายภาพ") ทุกการถ่ายภาพจะถูกบันทึกไว้ในโฟลเดอร์โครงการใน `captures/`
{% endhint %}

## แผงการตั้งค่าการจับภาพ

เปิดมันด้วย **ไอคอนรูปเกียร์ข้างปุ่ม "จับภาพทั้งหมด"**ในรายการกล้องบนแถบด้านข้าง หรือด้วย**ปุ่ม "เปิดการตั้งค่าการจับภาพ…"** ที่ด้านล่างของแผงการตั้งค่าสำหรับกล้องแต่ละตัว ส่วนหัวแสดงข้อความ "การตั้งค่าการจับภาพ" พร้อมปุ่มย้อนกลับ ←

ของคุณที่นี่ — กล้องที่รวมไว้ กล่องเลือกตามประเภท และโหมดการบันทึก — จะถูกบันทึก **ตามโครงการ** และถูกกู้คืนเมื่อคุณเปิดใหม่

### โหมดการบันทึก

ปุ่มโหมดสามปุ่มที่ส่วนบนของหน้าต่าง:

| โหมด | หน้าที่ | การตั้งค่าย่อย (ค่าเริ่มต้น) |
| --- | --- | --- |
| **ครั้งเดียว** *(ค่าเริ่มต้น)* | ถ่ายภาพครั้งเดียวจากทุกกล้องที่เลือก | — |
| **ต่อเนื่อง**| ถ่ายภาพต่อเนื่องจนกว่าจะถึงเงื่อนไขหยุด | | หยุดตาม**จำนวนการถ่ายภาพ** (ค่าเริ่มต้น 1) *หรือ* **ระยะเวลาการถ่ายภาพ** (ค่าเริ่มต้น 10 วินาที; หน่วย: วินาที / นาที / ชั่วโมง / วัน) |
| **Interval**(timelapse) | ถ่ายภาพเป็นชุดตามตัวจับเวลา |**จำนวนภาพ / ช่วง**(ค่าเริ่มต้น 1) ·**ทุก**N หน่วย (ค่าเริ่มต้น 5 วินาที) ·**เป็น** N หน่วย (ค่าเริ่มต้น 1 นาที). |

ในโหมดต่อเนื่องหรือโหมดช่วงเวลา ปุ่ม "Capture All" จะเปลี่ยนเป็นปุ่ม **Stop (N)** ระหว่างการทำงาน โดยนับจำนวนการถ่ายภาพตามลำดับที่บันทึกได้ เมื่อพื้นที่จัดเก็บข้อมูลเต็ม ระบบจะหยุดการทำงาน (ดู [กระบวนการ Capture All](#the-capture-all-flow)).**โหมดต่อเนื่องบนอาร์เรย์ทำงานภายในแบ็กเอนด์ (ใหม่ในเวอร์ชัน 1.3.0)** เมื่อกล้องทุกตัวในรายการเป็นส่วนหนึ่งของอาร์เรย์ (กล้องแบบสแตนด์อโลนถูกซ่อนหรือถูกยกเว้น) โหมดต่อเนื่องจะไม่ส่งคำขอหนึ่งครั้งต่อการจับภาพอีกต่อไป: เบ็กเอนด์Chloros จะรันลูปการจับภาพด้วยตัวเอง โดยเขียนกลุ่มที่ซิงค์แล้วหนึ่งกลุ่มขณะเลือกกลุ่มถัดไป และปุ่มจะตรวจสอบจำนวนการจับภาพที่เกิดขึ้น สำหรับกล้องแบบสแตนด์อโลนในรายการ Chloros จะจับภาพทีละผ่านเหมือนเดิม

{% hint style="warning" %}
**การจับภาพเร็วบนWindows: ให้คงไว้ซึ่งการยกเว้นแบ็กเอนด์Chloros จากการสแกนของ Microsoft Defender** การสแกนแบบเรียลไทม์ของทุกไฟล์ที่การจับภาพความเร็วสูงเขียนลง ใช้เวลาประมาณ 30% ของอัตราการจับภาพ ในการทดสอบของMAPIR (หลายร้อยไฟล์ต่อวินาทีใน ROI ขนาดเล็ก) ตัวติดตั้งของWindows มีตัวเลือก **"ยกเว้นแบ็กเอนด์ของChloros จากการสแกนของ Microsoft Defender (การจับภาพจากกล้องเร็วขึ้นมาก; แนะนำ)"** ซึ่งถูกเลือกไว้เป็นค่าเริ่มต้น และจะยกเลิกการยกเว้นนี้เมื่อถอนการติดตั้ง หากคุณได้ยกเลิกการเลือกตัวเลือกนี้ ให้ติดตั้งโปรแกรมใหม่โดยเลือกตัวเลือกนี้ไว้ หรือเพิ่มการยกเว้นกระบวนการของ Defender สำหรับ `chloros-backend.exe` (ในโฟลเดอร์ `backend` ของโฟลเดอร์ติดตั้งChloros) เมื่อ Defender ใช้ CPU core หนึ่งหรือมากกว่านั้นระหว่างการจับภาพต่อเนื่องของอาร์เรย์ (Continuous capture) เบ็กเอนด์ของChloros จะบันทึกเหตุการณ์นี้ลงในล็อกเพียงครั้งเดียว พร้อมเสนอวิธีแก้ไขสองวิธีเดียวกันนี้
{% endhint %}

### การเลือกกล้องและประเภทการส่งออก

ข้อความช่วยเหลือในหน้าต่างนี้สรุปไว้อย่างชัดเจน: เลือกกล้องและประเภทการส่งออกที่ "Capture All" จะสร้างขึ้น — ทุกอย่างถูกเปิดไว้ตามค่าเริ่มต้น และตัวเลือกเหล่านี้จะถูกบันทึกไว้กับโครงการนี้

* **ปุ่ม “เลือกทั้งหมด / ไม่เลือกอะไรเลย”** จะสลับสถานะกล่องเลือกของกล้องทุกตัวพร้อมกัน
* **ปุ่มสลับประเภทการส่งออกแบบกลุ่ม**(สองแถวของปุ่ม):**All Raw / All Debayered / All Preview / All Radiance / All Reflectance / All Index**. แต่ละตัวเลือกมีสีสามสถานะ: สีเขียว ✓ = เปิดสำหรับกล้องทุกตัวที่รองรับ, สีเหลือง – = เปิดสำหรับบางตัว, สีเทา = ไม่มีตัวใดรองรับ. ปุ่มสลับจะถูกปิดใช้งานหากไม่มีกล้องที่เชื่อมต่อใดที่สนับสนุนประเภทนั้น ปุ่มทั้งหมดจะกลายเป็นสีเทาเมื่อโหมด Fastest Capture เปิดอยู่
* **แถวสำหรับแต่ละกล้อง**: ช่องทำเครื่องหมายเพื่อรวมภาพ พร้อมด้วยรายการที่ขยายได้ (▸/▾) ของประเภทการส่งออกที่กล้องนั้นรองรับ พร้อมช่องทำเครื่องหมายแยกสำหรับแต่ละประเภท แถวจะแสดงจำนวนที่เปิดใช้งาน เช่น "4/6"

### ประเภทการส่งออกและกล้องที่รองรับ

มีประเภทการส่งออกทั้งหมด 6 ประเภท: **Raw, Debayered, Radiance, Reflectance, Preview, Index**. เฉพาะประเภทที่ใช้งานได้เท่านั้นที่จะปรากฏในแถวของกล้องแต่ละตัว:

| ประเภทการส่งออก | เนื้อหา | RGB (FRGB) | Bayer multispectral (FRGN/FOCN/FNGB) | Mono (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | โมเสก Bayer (โมโน: แบนด์เดียว) ที่ส่งตรงจากเซ็นเซอร์ | ✓ | ✓ | ✓ |
| **Debayered** | การถอดโมเสคแบบเชิงเส้น: ลบค่าออฟเซ็ตความมืด (DSNU) จากไฟล์ดิบในชุดการปรับเทียบ จากนั้นทำการถอดโมเสคที่คำนึงถึงขอบ — ไม่มีการแก้ไขความเชิงเส้น, ฟิลด์แบน หรือการแยกสี เก็บเป็นไฟล์ RGB TIFF 3 ช่อง (mono: 1 ช่อง เกรย์สเกล) | ✓ | ✓ | ✓ |
| **Preview** | โซ่การแสดงผลเต็ม (สมดุลสีขาว + แกมมาตามโปรไฟล์ของกล้อง, พร้อมกับการตั้งค่า Highlights ของกล้องRGB; มัลติสเปกตรัม: การขยายสีเท็จ) | ✓ | ✓ | ✓ |
| **ความส่อง** | float32 W/m²/sr/nm ผ่านห่วงโซ่รังสีวัดเต็ม | — (ไม่มี) | ✓ | ✓ |
| **ความสะท้อน** | uint16 ρ (32768 = 1.0) | — (ไม่มี) | ✓ — แสดงเฉพาะเมื่อกล้องมีเซ็นเซอร์แสง DAQ (ของตัวเองหรือรับมาจากอาร์เรย์) | เหมือนกับมัลติสเปกตรัม |
| **ดัชนี** | การเรนเดอร์ดัชนีพืชพรรณ (LUT) | — | ✓ — ต้องมีนิพจน์ดัชนีที่เปิดใช้งานและไม่ว่างเปล่าบนกล้อง และไม่ให้บริการแก่สมาชิกของอาร์เรย์รวม (อาร์เรย์มีดัชนีที่ใช้ร่วมกันหนึ่งตัว) | — (ดัชนีต้องมี ≥2 แบนด์; ดู [กล้องโมโนและดัชนีพืชพรรณ](mono-indices.md)) |

ค่าความส่องสว่าง (radiance) และค่าการสะท้อน (reflectance) ไม่เคยถูกเสนอสำหรับกล้องRGB — ค่าความส่องสว่างต่อ Bayer ไม่มีความหมายสำหรับเซ็นเซอร์โฟโตเมตริกแบบแบนด์กว้าง

### การจับภาพเร็วที่สุด

สวิตช์ **⚡ Fastest Capture — raw only**(สีส้มเมื่อเปิด) จะแทนที่การเลือกส่งออกทั้งหมดเป็น**raw-only** — พร้อมด้วยภาพรวมดัชนีรวมฟรีสำหรับอาร์เรย์ — เพื่อให้เฟรมถูกบันทึกได้เร็วที่สุดเท่าที่เป็นไปได้: การคำนวณความเรเดียนซ์/การสะท้อนแสง/การแสดงผลจะถูกข้ามไปทั้งหมดในเวลาบันทึก

{% hint style="info" %}
**ไฟล์ `.daq` ยังคงถูกบันทึกไว้** เมื่อกำหนดเซ็นเซอร์แสงแล้ว การจับภาพเร็วที่สุด (Fastest Capture) จะยังคงบันทึกค่าการอ่าน DAQ ที่ส่องลง (ลงในโฟลเดอร์ `daq/` ของภาพที่จับได้) — ดังนั้นผลิตภัณฑ์ความส่องสว่าง ความสะท้อน และดัชนีสามารถสร้างขึ้นได้ทั้งหมดในภายหลังโดยการประมวลผลใหม่ (ดู [การประมวลผลใหม่ของข้อมูลที่บันทึก](#re-processing-captures-into-calibrated-products)). Fastest Capture ยังไม่ส่งผลต่อการเลือกในช่องทำเครื่องหมายของคุณ: ปิดมันลงแล้วการเลือกจะกลับมาตามเดิม
{% endhint %}

### การควบคุมตามอาร์เรย์

อาร์เรย์แต่ละตัวที่เชื่อมต่อจะมีบัตรกลุ่มของตัวเองในหน้าต่าง:

* **กล่องเลือก Include** (มี 3 สถานะสำหรับสมาชิกทั้งหมด) และชื่อของอาร์เรย์พร้อมโหมดแสดงผล: "(รวม | แยก)"
* **กล่องเลือก Aligned**(ตั้งค่าเริ่มต้น**เปิด**): ปรับการส่งออกของสมาชิกให้สอดคล้องกับโปรไฟล์การจัดแนวของอาร์เรย์ เพื่อให้การส่งออกมีการจัดตำแหน่งพิกเซลที่ตรงกันระหว่างกล้องต่างๆ ไฟล์ Raw จะไม่ถูกปรับแนว แต่จะเก็บข้อมูลการแปลงไว้ในเมตาดาต้า (โปรไฟล์เองถูกคำนวณใน [หน้าต่างการตั้งค่าอาร์เรย์](camera-settings.md#alignment-co-registration)) ไฟล์สมาชิกของอาร์เรย์จะถูกบันทึกในทิศทางดั้งเดิมของแต่ละกล้อง โดยตั้งค่า Mirror/Rotation จะถูกบันทึกไว้ในไฟล์แทนที่จะถูกนำไปใช้
* แถวของกล้องสมาชิกถูกจัดวางซ้อนกันภายในบัตรอาร์เรย์

บัตรอาร์เรย์ยังรองรับเครื่องบันทึกสองเครื่อง ให้คิดถึงพวกมันในลักษณะ **การเฝ้าติดตาม vs การวิเคราะห์**:

| เครื่องบันทึก | ระดับ | สิ่งที่บันทึก |
| --- | --- | --- |
| **● บันทึกวิดีโอดัชนีรวม / ■ หยุดบันทึก** *(เฉพาะอาร์เรย์รวมเท่านั้น)* | **การเฝ้าติดตาม** | วิดีโอคอมโพสิตดัชนีรวมแบบสดที่ 10 fps — 8-bit, ความละเอียดแบบพรีวิว, LUT ถูกฝังไว้แล้ว ต้องเปิดโครงการและเปิดมุมมองสตรีมสด แสดงเฟรมและเวลาที่ผ่านไปแล้วระหว่างการบันทึก |
| **⦿ บันทึกภาพดิบแบบบัร์สต์ / ■ หยุดบันทึกแบบ raw burst** *(อาร์เรย์ใดก็ได้)* | **วิเคราะห์**| เฟรม Bayer แบบ raw ที่อัตราการจับภาพสด (ไม่ผ่านกระบวนการประมวลผล) พร้อมด้วย manifest ต่อเฟรมและค่าอ่าน `.daq`, ส่งเข้า `captures/bursts/`. หลังการถ่ายภาพต่อเนื่อง ปุ่ม**สร้างวิดีโอ** จะปรากฏขึ้น: ปุ่มนี้จะประมวลผลชุดภาพต่อเนื่องแบบออฟไลน์เป็นวิดีโอที่ปรับเทียบแล้ว — รวมดัชนีและ/หรือค่าความส่องสว่าง / ความสะท้อน / ดัชนีต่อกล้อง — พร้อมไฟล์ TIFF ตามตัวเลือก การสร้างวิดีโอแบบรวมดัชนีจะเริ่มอัตโนมัติเมื่อคุณหยุดการถ่ายภาพต่อเนื่อง |

## กระบวนการ

<!-- SCREENSHOT-NEEDED: the sidebar during a capture — Capture All showing live "Capturing… 3/6" progress text, and (second capture) the result flash "Saved N files". -->

Capture All

กด **Capture All** ในรายการกล้องบนแถบด้านข้าง:

1. ทุกกล้องที่ถูกรวมไว้, ที่มองเห็นได้, และไม่ได้หยุดชั่วคราว จะบันทึกภาพตามประเภทการส่งออกที่เลือกไว้ **กลุ่มกล้องจะทำงานพร้อมกันด้วยทริกเกอร์ที่ซิงโครไนซ์** (กลุ่มเดียวที่ซิงโครไนซ์กันสำหรับสมาชิกทั้งหมด — ดู [Multi-Camera Arrays](arrays.md)); ส่วนกล้องเดี่ยวจะบันทึกภาพแบบแยกกัน
2. กล้องที่ซ่อน (ตา) หรือถูกหยุดชั่วคราวจะถูกข้ามไป อาร์เรย์จะถูกบล็อกอย่างสมบูรณ์ก็ต่อเมื่อ *ทุก* สมาชิกในอาร์เรย์นั้นถูกซ่อนหรือหยุดชั่วคราว
3. ทุกครั้งที่มีการกำหนดเซ็นเซอร์แสง ค่าการอ่าน DAQ downwelling ที่ตรงกันจะถูกบันทึกเป็นไฟล์ `.daq` ในโฟลเดอร์ `daq/` ของการบันทึก — แม้สำหรับการบันทึกแบบ raw เท่านั้น — เพื่อให้สามารถสร้างผลิตภัณฑ์รังสีได้เสมอในภายหลัง
4. ปุ่มจะแสดงความคืบหน้าแบบเรียลไทม์ — "กำลังบันทึก… เสร็จ/รวม" — และในโหมดต่อเนื่อง/ช่วงเวลาจะเปลี่ยนเป็น **หยุด (N)** แต่ละรายการบันทึกมีเวลาหมดอายุ 300 วินาที
5. เมื่อการบันทึกเสร็จสิ้น จะมีข้อความแจ้งผลแบบแฟลชแสดง **"บันทึก N ไฟล์"**หรือ**"บันทึก N, F ล้มเหลว"**พร้อมด้วย "(S ถูกซ่อน/หยุดชั่วคราว/ข้าม)" เมื่อกล้องถูกข้ามไป หากพื้นที่จัดเก็บข้อมูลเต็ม การทำงานจะหยุดลงและแสดงข้อความ**"หยุด: พื้นที่จัดเก็บข้อมูลเต็ม. บันทึก N, F ล้มเหลว"** — ทุกไฟล์ที่ไม่สามารถเขียนได้จะนับเป็นล้มเหลว

## สถานที่จัดเก็บข้อมูลที่จับภาพ

ข้อมูลที่จับภาพจะถูกบันทึกไว้ในโครงการที่เปิดอยู่ภายใต้ `<project>/captures/` แต่ละประเภทการส่งออกจะถูกจัดเก็บใน **โฟลเดอร์ย่อยของตัวเอง** ดังนั้นการจับภาพหลายระดับจะไม่มีการผสมประเภทกัน:

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── clamp_masks/   radiance/…_clampmask.tif, reflectance/…, index/… — unmix clamp masks,
│                  one subfolder per product folder, only when a band was clamped
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── daq/           the downwelling reading(s) matched to each capture (.daq), each with a
                   .daq.cameras.json naming the cameras it describes
```

* `<ts>` เป็นเวลาประทับของข้อมูลที่จับได้ และ `<serial>` เป็นหมายเลขซีเรียลของกล้อง การจับภาพแบบสแตนด์อโลนจะถูกตั้งชื่อเป็น `capture_<ts>_SN<serial>_<level>`; การจับภาพแบบอาร์เรย์จากทริกเกอร์ที่ซิงค์กันหนึ่งตัวจะถูกตั้งชื่อเป็น `sync_<ts>_SN<serial>_<level>` และ **ใช้ตราประทับเวลาเดียวกันสำหรับกล้องทุกตัวในกลุ่ม** (ส่วนต่อท้ายระดับจะถูกลบออกเมื่อกล้องบันทึกเพียงระดับเดียวเท่านั้น)
* **จุดไม่สมมาตรที่ควรทราบ:** ระดับการแสดงผลถูกเก็บไว้ในโฟลเดอร์ชื่อ `preview/` ในขณะที่ไฟล์ยังคงมีชื่อ `_display` — โฟลเดอร์และส่วนท้ายชื่อจะต่างกันเฉพาะสำหรับระดับนั้นเท่านั้น
* ระดับที่ไม่รู้จักจะกลับไปยังโฟลเดอร์ที่มีชื่อของตัวเอง; หากไม่สามารถสร้างโฟลเดอร์ย่อยได้ ไฟล์จะถูกเขียนไปยังรากของ capture แทนที่จะสูญหาย
* ไฟล์ TIFF ของ capture ถูกบีบอัดแบบไม่สูญเสียข้อมูล (DEFLATE) ตามค่าเริ่มต้น และเก็บข้อมูลเมตาดาต้าการปรับเทียบและการประมวลผลทั้งหมด **ภายใน XMP ของไฟล์** — ข้อมูลที่จับภาพสามารถอธิบายตัวเองได้ โดยไม่มีไฟล์เสริมอื่นใดนอกจากไฟล์ `.daq` (และไฟล์ `.daq.cameras.json` ที่เกี่ยวข้อง)
* **หน้ากาก Clamp (ใหม่ในเวอร์ชัน 1.3.0)**ในกรณีที่การแยกสเปกตรัม 3×3 ต้องจำกัดแถบความยาวคลื่นให้เหลือ 0 บนพิกเซลอย่างน้อยหนึ่งพิกเซล ผลิตภัณฑ์ radiance, reflectance และ index จะได้รับหน้ากากแบบต่อพิกเซล, `clamp_masks/<product folder>/<product name>_clampmask.tif` (bit 0 = แบนด์ในช่อง R ของผลิตภัณฑ์, bit 1 = G, bit 2 = B); แท็ก XMP ของผลิตภัณฑ์ `Chloros:UnmixClampMask` จะชี้ไปยังไฟล์นี้ หน้ากากเหล่านี้อยู่**ข้างๆ** โฟลเดอร์ผลิตภัณฑ์ ไม่เคยอยู่ภายในโฟลเดอร์ ดังนั้น โฟลเดอร์ผลิตภัณฑ์ เช่น `reflectance/` จึงสามารถส่งไปยังซอฟต์แวร์โฟโตแกรมเมตรีได้โดยตรง ส่วนฟังก์ชันนำเข้าของ Chloros จะข้ามหน้ากากเหล่านี้ไป
* **ทิศทาง (1.3.0).** ผลิตภัณฑ์ Preview, Radiance, Reflectance และ Index ของกล้องแบบสแตนด์อโลนจะถูกหมุนตามการตั้งค่า Mirror/Rotation ของกล้องนั้น; ส่วน Raw และ Debayered จะคงไว้ตามค่าที่เซ็นเซอร์อ่านมา ไฟล์สมาชิกในอาร์เรย์ทั้งหมดจะคงอยู่ในรูปแบบต้นฉบับ ทุกไฟล์บันทึกการตั้งค่าไว้ใน XMP ของตัวเอง ดังนั้นการประมวลผลใหม่จะนำไปใช้ในลักษณะเดียวกัน
* **กล้องที่ `.daq` สังกัดอยู่ (1.3.0).** `.daq` ของการจับภาพจะถูกจับคู่ ในขณะประมวลผล เฉพาะกับภาพจากกล้องที่ระบุในชื่อ `.daq.cameras.json` ของมันเท่านั้น ดังนั้น กล้องแบบสแตนด์อโลนที่ไม่มีเซ็นเซอร์แสงของตัวเอง จึงไม่ใช้ค่าอ่านจากกล้องอื่นอีกต่อไป — ให้ผูกเซ็นเซอร์กับกล้องนั้น หรือบันทึกเซ็นเซอร์ในแท็บ Light Sensors การบันทึกข้อมูลจากเซ็นเซอร์แสง (และ `.daq` ใดก็ตามที่ไม่มีไฟล์ดังกล่าว รวมถึงการจับภาพเก่า) ยังคงให้บริการกล้องทุกตัว

นี่คือโครงสร้างเดียวกันที่ `chloros-cli lattice capture` / `array-capture` เขียนลงในโฟลเดอร์ `-o` ของพวกมัน — ซึ่งได้รับการบันทึกไว้ใน [CLI Reference § What a captures folder looks like](../reference/cli-reference.md#what-a-captures-folder-looks-like)

## การประมวลผลภาพที่จับได้ใหม่เป็นผลิตภัณฑ์ที่ปรับเทียบแล้ว

ภาพดิบที่จับได้พร้อมกับไฟล์ `.daq` ที่บันทึกไว้คือทุกสิ่งที่กระบวนการประมวลผลต้องการ — นี่คือเหตุผลที่ Fastest Capture ปลอดภัยสำหรับการทำงานจริง

* **GUI**: เพิ่มโฟลเดอร์ captures เข้าสู่โครงการ ([การเพิ่มไฟล์เข้าสู่โครงการ](../processing-images-gui/adding-files-to-a-project.md)) และดำเนินการตามปกติ
* **CLI**: กำหนด `process` ให้ชี้ไปยัง **รากของ captures**:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

`process` โดยปกติจะนำเข้าเฉพาะโฟลเดอร์ที่คุณระบุชื่อเท่านั้น แต่เมื่อโฟลเดอร์นั้นไม่มีภาพและยังมีโฟลเดอร์ย่อย มันจะค้นหาโฟลเดอร์ย่อยโดยอัตโนมัติ — ดังนั้นโฟลเดอร์ย่อยระดับต่าง ๆ และโฟลเดอร์ `daq/` จะถูกนำเข้าพร้อมกันในครั้งเดียว การจับภาพทุกครั้งจะถูกนำเข้าเป็น **ภาพเดียว** โดยระดับอื่นๆ จะถูกแนบมาในรูปแบบโหมดการดู ไม่ใช่ภาพหนึ่งภาพต่อระดับ

การตั้งชื่อโฟลเดอร์ลูกในระดับโดยตรง (เช่น `…/captures/raw/`) ก็ทำงานได้เช่นกัน แต่จะทิ้งโฟลเดอร์ `daq/` ไว้ — ให้คัดลอกโฟลเดอร์นั้นมาพร้อมกันเมื่อคุณ-สร้างผลิตภัณฑ์รังสีวัดจาก `raw/` มิฉะนั้นการจับคู่เวลาจะไม่มีข้อมูลอ้างอิงเพื่อแก้ไข

{% hint style="warning" %}
**การประมวลผลจะเริ่มจาก `raw` เสมอ.** ในแต่ละการจับภาพ เฟรมดิบเป็นแหล่งข้อมูลของระบบประมวลผล; `debayered`, `radiance`, `reflectance`, และ `preview` เป็นโหมดที่แสดงผลได้ แต่ไม่เคยถูกส่งกลับผ่านท่อประมวลผล — การประมวลผลซ้ำผลิตภัณฑ์ที่ได้มาจะนำไปใช้การปรับ vignette, สี และการคำนวณ radiance ที่ถูกฝังไว้ในพิกเซลแล้ว ดังนั้นChloros จึงปฏิเสธการประมวลผลแทนที่จะประมวลผลซ้ำ การเรนเดอร์ `index/` และ `composite/` ไม่ได้รับการประมวลผลเลย (พวกมันเป็นผลลัพธ์ ไม่ใช่การจับภาพ) โฟลเดอร์ captures ที่บันทึก **โดยไม่** นำเข้าข้อมูลดิบจะแสดงผลตามปกติ แต่ `process` จะข้ามมันไปและแจ้งให้ทราบ; `--input-level {raw,debayered,processed}` เป็นทางออกที่ตั้งใจสร้างขึ้นเพื่อบังคับให้มีจุดเข้า ดู [คู่มือ [CLI]](../reference/cli-reference.md#what-a-captures-folder-looks-like) เพื่อดูข้อความข้ามที่แม่นยำ
{% endhint %}

พฤติกรรมอีกสองอย่างที่ควรรู้เมื่อเขียนสคริปต์เพื่อประมวลผลใหม่:

* การรัน `chloros-cli process` ที่ขอผลิตภัณฑ์แต่ **ไม่เขียนผลิตภัณฑ์ภาพ**จะล้มเหลวอย่างชัดเจนและออกด้วยค่าที่ไม่ใช่ศูนย์** — คุณจะไม่เคยได้รับการรันที่ว่างเปล่าอย่างเงียบๆ การรันที่สำเร็จจะรายงานจำนวนผลิตภัณฑ์ (การรันที่ตั้งใจให้ใช้เฉพาะเมตาดาต้าเท่านั้นยังคงนับว่าสำเร็จ)
* การนำเข้าใหม่ของไฟล์ส่งออกที่ผ่านการประมวลผลแล้วจะไม่ใช้สล็อต raw ของการจับภาพ — raw ต้นฉบับจะยังคงเป็นแหล่งข้อมูลของ pipeline เสมอ

## คำสั่งเทียบเท่าในCLI



ทุกสิ่งบนหน้านี้สามารถทำงานได้แบบ headless โหมดการจับภาพใน GUI จะตรงกับ `chloros-cli lattice array-capture`:

| GUI | CLI |
| --- | --- |
| Single | `chloros-cli lattice array-capture` |
| Continuous | `array-capture --continuous [--count N] [--duration S]` |
| ตามช่วงเวลา | `array-capture --interval S [--duration S]` |
| การจับภาพเร็วที่สุด | `array-capture --fastest` |
| ช่องทำเครื่องหมายการจัดแนว | `--aligned / --no-aligned` |
| ช่องทำเครื่องหมายประเภทการส่งออก | `--processing LEVEL` หรือ `--levels L1,L2,…` (ค่าเริ่มต้น `all`) |
| บันทึกวิดีโอแบบดัชนี | `chloros-cli lattice array-record` |
| บันทึกภาพต่อเนื่องแบบดิบ / สร้างวิดีโอ | `chloros-cli lattice array-burst` / `array-build-video` |

ตารางธงเต็ม ตัวเลือกการจับภาพแบบ smart-AE settled-capture (`--smart`) และโมเดลอัตราคงที่ (sustained-rate) อยู่ใน [CLI Reference § Capture Modes, Recorders & Offline Reprocess](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).
