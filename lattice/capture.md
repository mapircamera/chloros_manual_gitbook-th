# การตั้งค่าและโหมดการถ่ายภาพ

การถ่ายภาพในแท็บ Cameras ควบคุมโดยปุ่ม **Capture All**สีแดงหนึ่งปุ่ม และส่วน**Capture Settings** หนึ่งส่วน ซึ่งกำหนดผลลัพธ์ที่ปุ่มดังกล่าวสร้างขึ้น: กล้องใดจะเข้าร่วม, ประเภทการส่งออกที่กล้องแต่ละตัวบันทึก, และว่าชัตเตอร์จะทำงานครั้งเดียว, แบบต่อเนื่อง, หรือตามช่วงเวลา หน้านี้อธิบายขั้นตอนทั้งหมด — การตั้งค่า การถ่ายภาพจริง ตำแหน่งที่ไฟล์ถูกบันทึกบนดิสก์ และวิธีการประมวลผลไฟล์เหล่านั้นใหม่เพื่อสร้างผลิตภัณฑ์ที่ผ่านการปรับเทียบในภายหลัง ส่วนการควบคุมกล้องและระบบกล้องนั้นอยู่ที่ [การตั้งค่ากล้อง](camera-settings.md)

{% hint style="info" %}
**การถ่ายภาพต้องเปิดโครงการไว้ก่อน** ตัวเลือก &quot;Capture All&quot; และไอคอนรูปเกียร์ &quot;Capture Settings&quot; จะถูกปิดใช้งานจนกว่าจะมีโครงการเปิดอยู่ (&quot;สร้างหรือเปิดโครงการเพื่อบันทึกภาพที่ถ่าย&quot;) ทุกภาพที่ถ่ายจะถูกบันทึกไว้ในโฟลเดอร์โครงการใน `captures/`.
{% endhint %}

## แผงการตั้งค่าการจับภาพ

เปิดแผงนี้ด้วย **ไอคอนรูปเกียร์ข้างปุ่ม Capture All**ในรายการกล้องบนแถบด้านข้าง หรือด้วย**ปุ่ม &quot;Open Capture Settings…&quot;** ที่ด้านล่างของแผงการตั้งค่าสำหรับกล้องแต่ละตัว ส่วนหัวแสดงข้อความ &quot;Capture Settings&quot; พร้อมปุ่มย้อนกลับ ← การเลือก

ของคุณที่นี่ — กล้องที่รวมไว้, ช่องทำเครื่องหมายตามประเภท, และโหมดการจับภาพ — จะถูกบันทึก **ตามโครงการ** และถูกกู้คืนเมื่อคุณเปิดโครงการนั้นอีกครั้ง

ปุ่มโหมดสามปุ่มที่ส่วนบนของหน้าต่าง:

| --- | --- | --- |

| **ต่อเนื่อง**| ถ่ายภาพต่อเนื่องจนกว่าจะถึงเงื่อนไขหยุด | หยุดตาม**จำนวนภาพ** (ค่าเริ่มต้น 1) *หรือ* **ระยะเวลาการถ่ายภาพ** (ค่าเริ่มต้น 10 วินาที; หน่วย: วินาที / นาที / ชั่วโมง / วัน) |

### การเลือกกล้องและประเภทการส่งออก

ข้อความช่วยเหลือในหน้าต่างนี้สรุปไว้อย่างชัดเจน: เลือกกล้องและประเภทการส่งออกที่ &quot;Capture All&quot; จะสร้างขึ้น — ทุกอย่างถูกเปิดไว้เป็นค่าเริ่มต้น และตัวเลือกเหล่านี้จะถูกบันทึกไว้กับโครงการนี้

* **ปุ่ม**เลือกทั้งหมด / ไม่เลือก** จะสลับกล่องเลือกของกล้องทุกตัวพร้อมกัน
* **ปุ่มสลับประเภทการส่งออกแบบกลุ่ม**(สองแถวของปุ่ม):**ทั้งหมด Raw / ทั้งหมด Debayered / ทั้งหมด Preview / ทั้งหมด Radiance / ทั้งหมด Reflectance / ทั้งหมด Index**. แต่ละตัวเลือกมีสีสามสถานะ: สีเขียว ✓ = เปิดสำหรับทุกกล้องที่รองรับ, สีเหลือง – = เปิดสำหรับบางกล้อง, สีเทา = ไม่มีกล้องใดรองรับ สวิตช์จะถูกปิดใช้งานเมื่อไม่มีกล้องที่เชื่อมต่อใดรองรับประเภทนั้น ทุกตัวเลือกจะกลายเป็นสีเทาเมื่อเปิดใช้งาน Fastest Capture
* **แถวสำหรับแต่ละกล้อง**: มีช่องทำเครื่องหมายเพื่อรวม (include) พร้อมรายการที่ขยายได้ (▸/▾) ของประเภทการส่งออกที่กล้องนั้นรองรับ พร้อมช่องทำเครื่องหมายแยกแต่ละประเภท แถวจะแสดงจำนวนที่เปิดใช้งาน เช่น &quot;4/6&quot;

### ประเภทการส่งออกและกล้องที่รองรับ

มีประเภทการส่งออกทั้งหมด 6 ประเภท: **Raw, Debayered, Radiance, Reflectance, Preview, Index**. เฉพาะประเภทที่ใช้งานได้เท่านั้นที่จะปรากฏในแถวของกล้องแต่ละตัว:

| ประเภทการส่งออก | เนื้อหา |RGB

(FRGB) | Bayer multispectral (FRGN/FOCN/FNGB) | Mono (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | โมเสก Bayer (โมโน: แบนด์เดียว) จากเซ็นเซอร์โดยตรง | ✓ | ✓ | ✓ |
| **Debayered** | การถอดโมเสกแบบเชิงเส้น (โมโน: เกรย์สเกล 1 ช่อง) | ✓ | ✓ | ✓ |
| **Preview** | โซ่การแสดงผลเต็มรูปแบบ (การปรับสมดุลสีขาว + แกมมาตามโปรไฟล์ของกล้อง; มัลติสเปกตรัม: การขยายสีเทียม) | ✓ | ✓ | ✓ |
| **Radiance** | float32 W/m²/sr/nm ผ่านห่วงโซ่รังสีวัดเต็ม | — (ไม่มี) | ✓ | ✓ |
| **Reflectance** | uint16 ρ (32768 = 1.0) | — (ไม่มีให้บริการ) | ✓ — แสดงเฉพาะเมื่อกล้องมีเซ็นเซอร์แสง DAQ (ของตัวเองหรือรับมาจากอาร์เรย์) | เหมือนกับมัลติสเปกตรัม |
| **ดัชนี** | การเรนเดอร์ดัชนีพืชพรรณ (LUT) | — | ✓ — ต้องมีนิพจน์ดัชนีที่เปิดใช้งานและไม่ว่างเปล่าบนกล้อง และไม่ให้บริการสำหรับสมาชิกในอาร์เรย์รวม (อาร์เรย์มีดัชนีที่ใช้ร่วมกันหนึ่งตัว) | — (ดัชนีต้องมี ≥2 แบนด์; ดู [กล้องโมโนและดัชนีพืชพรรณ](mono-indices.md)) |

ค่าความส่องสว่าง (radiance) และค่าการสะท้อน (reflectance) ไม่เคยถูกเสนอสำหรับกล้องแบบหลายแถบ (RGB

) — ค่าความส่องสว่างต่อ Bayer ไม่มีความหมายสำหรับเซ็นเซอร์โฟโตเมตริกแบบแถบกว้าง

### การจับภาพเร็วที่สุด

สวิตช์ **⚡ Fastest Capture — raw only**(สีส้มเมื่อเปิด) จะแทนที่การเลือกส่งออกทั้งหมดเป็น**raw-only** — พร้อมด้วยภาพรวมดัชนีแบบรวมฟรีสำหรับอาร์เรย์ — เพื่อให้เฟรมถูกบันทึกได้เร็วที่สุดเท่าที่เป็นไปได้: การคำนวณความเรเดียนซ์/การสะท้อนแสง/การแสดงผลจะถูกข้ามไปทั้งหมดในเวลาบันทึก

{% hint style="info" %}
**`.daq` ยังคงถูกบันทึกไว้** เมื่อกำหนดเซ็นเซอร์แสงแล้ว Fastest Capture จะยังคงบันทึกค่าการอ่าน DAQ ของแสงที่ส่องลงข้างๆ เฟรม raw — ดังนั้นผลิตภัณฑ์ radiance, reflectance และ index ทั้งหมดสามารถสร้างขึ้นได้ในภายหลังโดยการประมวลผลใหม่ (ดู [การประมวลผลใหม่ของข้อมูลที่จับภาพ](#re-processing-captures-into-calibrated-products)). Fastest Capture ยังไม่ทำลายการเลือกในช่องทำเครื่องหมายของคุณ: ปิดมันลงแล้วการเลือกเหล่านั้นจะกลับมา
{% endhint %}

### การควบคุมตามอาร์เรย์

อาร์เรย์แต่ละตัวที่เชื่อมต่อจะได้รับบัตรกลุ่มของตัวเองในหน้าต่าง:

* **กล่องเลือก Include** (มีสามสถานะสำหรับสมาชิกทั้งหมด) และชื่อของอาร์เรย์พร้อมโหมดแสดงผล: &quot;(รวม | แยก)&quot;
* **กล่องเลือก Aligned**(ตั้งค่าเริ่มต้น**เปิด**): ปรับการส่งออกของสมาชิกให้สอดคล้องกับโปรไฟล์การจัดแนวของอาร์เรย์ เพื่อให้การส่งออกมีการลงทะเบียนพิกเซลที่ตรงกันระหว่างกล้องต่างๆ ไฟล์ Raw จะไม่ถูกปรับแนว แต่จะเก็บข้อมูลการแปลงไว้ในเมตาดาต้า (โปรไฟล์นี้ถูกคำนวณใน [หน้าต่างการตั้งค่าอาร์เรย์](camera-settings.md#alignment-co-registration-combined-only))
* แถวของกล้องสมาชิกถูกจัดวางซ้อนกันภายในบัตร

บัตรอาร์เรย์ยังรองรับเครื่องบันทึกสองเครื่อง ให้คิดถึงพวกมันในลักษณะ **การเฝ้าติดตาม vs การวิเคราะห์**:

| เครื่องบันทึก | ระดับ | สิ่งที่บันทึก |
| --- | --- | --- |
| **● บันทึกวิดีโอดัชนีรวม / ■ หยุดบันทึก** *(เฉพาะอาร์เรย์รวมเท่านั้น)* | **การเฝ้าติดตาม** | วิดีโอคอมโพสิตดัชนีรวมแบบสดที่ 10 fps — 8 บิต, ความละเอียดแบบพรีวิว, LUT ถูกฝังไว้แล้ว ต้องมีโครงการที่เปิดอยู่และมุมมองสดแบบสตรีมมิ่ง แสดงเฟรม + เวลาที่ผ่านไประหว่างการบันทึก |
| **⦿ บันทึกภาพแบบ raw burst / ■ หยุดการบันทึกแบบ raw burst** *(อาร์เรย์ใดก็ได้)* | **การวิเคราะห์**| เฟรม Bayer แบบ raw ที่อัตราการจับภาพสด (ไม่มีการประมวลผล) พร้อมด้วย manifest ต่อเฟรมและค่าอ่าน `.daq`, ส่งเข้า `captures/bursts/`. หลังการถ่ายภาพต่อเนื่อง ปุ่ม**สร้างวิดีโอ** จะปรากฏขึ้น: ปุ่มนี้จะประมวลผลชุดภาพต่อเนื่องแบบออฟไลน์เป็นวิดีโอที่ปรับเทียบแล้ว — รวมดัชนีและ/หรือค่าความส่อง / ความสะท้อน / ดัชนีต่อกล้อง — พร้อมไฟล์ TIFF ตามตัวเลือก การสร้างวิดีโอแบบรวมดัชนีจะเริ่มอัตโนมัติเมื่อคุณหยุดการถ่ายภาพต่อเนื่อง |

## กระบวนการ

<!-- SCREENSHOT-NEEDED: the sidebar during a capture — Capture All showing live "Capturing… 3/6" progress text, and (second capture) the result flash "Saved N files". -->

Capture All กด **Capture All** ในรายการกล้องที่แถบด้านข้าง:

1. ทุกกล้องที่ถูกรวมไว้, ที่มองเห็นได้, และที่ยังไม่ถูกหยุดชั่วคราว จะบันทึกภาพตามประเภทการส่งออกที่เลือกไว้ **อาร์เรย์จะทำงานพร้อมกันเป็นทริกเกอร์ที่ซิงโครไนซ์** (กลุ่มเดียวที่ซิงโครไนซ์กันสำหรับสมาชิกทั้งหมด — ดู [Multi-Camera Arrays](arrays.md)); ส่วนกล้องเดี่ยวจะบันทึกภาพทีละตัว
2. กล้องที่ซ่อน (ตา) หรือถูกหยุดชั่วคราวจะถูกข้ามไป อาร์เรย์จะถูกบล็อกอย่างสมบูรณ์ก็ต่อเมื่อ *ทุก* สมาชิกในอาร์เรย์นั้นถูกซ่อนหรือหยุดชั่วคราว
3. ทุกครั้งที่มีเซ็นเซอร์แสงถูกกำหนด ค่าการอ่าน DAQ ที่สอดคล้องกันจะถูกบันทึกเป็นไฟล์ `.daq` พร้อมกับภาพ — แม้สำหรับการบันทึกแบบ raw เท่านั้น — เพื่อให้สามารถสร้างผลิตภัณฑ์รังสีวัดได้ในภายหลังเสมอ
4. ปุ่มแสดงความคืบหน้าแบบเรียลไทม์ — &quot;กำลังบันทึก… เสร็จ/รวม&quot; — และในโหมดต่อเนื่อง/ช่วงเวลาระยะจะเปลี่ยนเป็น **หยุด (N)** แต่ละรายการบันทึกมีเวลาหมดอายุ 300 วินาที
5. เมื่อการผ่านรอบเสร็จสิ้น จะมีข้อความแจ้งผลแบบแฟลชว่า **&quot;บันทึกไฟล์ N ไฟล์&quot;**หรือ**&quot;บันทึก N ไฟล์, F ล้มเหลว&quot;** พร้อมทั้ง &quot;(S ถูกซ่อน/หยุดชั่วคราว/ข้ามไป)&quot; เมื่อกล้องถูกข้ามไป

## สถานที่จัดเก็บข้อมูลที่จับภาพ

ข้อมูลที่จับภาพจะถูกบันทึกไว้ในโครงการที่เปิดอยู่ภายใต้ชื่อ `<project>/captures/` แต่ละประเภทการส่งออกจะถูกจัดเก็บใน **โฟลเดอร์ย่อยของตัวเอง** ดังนั้นการจับภาพหลายระดับจะไม่มีการผสมประเภทข้อมูล:

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── *.daq          the downwelling reading matched to the capture
```

* `<ts>` คือเวลาบันทึก และ `<serial>` คือหมายเลขซีเรียลของกล้อง การจับภาพแบบสแตนด์อโลนจะถูกตั้งชื่อว่า `capture_<ts>_SN<serial>_<level>`; การจับภาพแบบอาร์เรย์จากทริกเกอร์ที่ซิงค์กันหนึ่งตัวจะถูกตั้งชื่อว่า `sync_<ts>_SN<serial>_<level>` และ **ใช้ตราประทับเวลาเดียวกันสำหรับกล้องทั้งหมดในกลุ่ม** (ส่วนต่อท้ายระดับจะถูกลบออกเมื่อกล้องบันทึกเพียงระดับเดียวเท่านั้น)
* **จุดไม่สมมาตรที่ควรทราบ:** ระดับการแสดงผลถูกเก็บไว้ในโฟลเดอร์ชื่อ `preview/` ในขณะที่ไฟล์ยังคงใช้ชื่อ `_display` — โฟลเดอร์และส่วนท้ายชื่อจะแตกต่างกันเฉพาะสำหรับระดับนั้นเท่านั้น
* ระดับที่ไม่รู้จักจะกลับไปใช้โฟลเดอร์ที่มีชื่อของตัวเอง; หากไม่สามารถสร้างโฟลเดอร์ย่อยได้ ไฟล์จะถูกเขียนลงในรากของ captures แทนที่จะสูญหาย
* ไฟล์ TIFF ที่จับภาพจะถูกบีบอัดแบบไม่สูญเสียข้อมูล (DEFLATE) ตามค่าเริ่มต้น และเก็บข้อมูลเมตาดาต้าการปรับเทียบและการประมวลผลทั้งหมด **ภายใน XMP ของไฟล์** — ภาพที่จับได้สามารถอธิบายตัวเองได้ โดยไม่มีไฟล์เสริมอื่นใดนอกจากไฟล์ `.daq` ที่ใช้สำหรับการอ่าน

นี่คือโครงสร้างเดียวกันที่ `chloros-cli lattice capture` / `array-capture` ที่เขียนลงในโฟลเดอร์ `-o` — ซึ่งได้บันทึกไว้ใน [CLI

Reference § What a captures folder looks like](../reference/cli-reference.md#what-a-captures-folder-looks-like).

## การประมวลผลภาพที่จับได้ใหม่เป็นผลิตภัณฑ์ที่ปรับเทียบแล้ว

ภาพดิบที่จับได้พร้อมกับไฟล์ `.daq` ที่บันทึกไว้คือทุกสิ่งที่ท่อประมวลผลต้องการ — นี่คือเหตุผลที่ Fastest Capture ปลอดภัยสำหรับการใช้งานจริง

* **GUI**: เพิ่มโฟลเดอร์ captures เข้าสู่โครงการ ([การเพิ่มไฟล์เข้าสู่โครงการ](../processing-images-gui/adding-files-to-a-project.md)) และดำเนินการตามปกติ
* **CLI**: ตั้งค่า `process` ให้ชี้ไปยัง **รากของโฟลเดอร์ captures**:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

`process` โดยปกติจะนำเข้าเฉพาะโฟลเดอร์ที่คุณตั้งชื่อไว้เท่านั้น แต่เมื่อโฟลเดอร์นั้นไม่มีภาพและยังมีโฟลเดอร์ย่อยอยู่ มันจะค้นหาโฟลเดอร์ย่อยโดยอัตโนมัติ — ดังนั้น โฟลเดอร์ย่อยระดับต่าง ๆ และไฟล์ใน **captures root**`.daq` จะถูกนำเข้าพร้อมกันในครั้งเดียว การจับภาพทุกครั้งจะนำเข้าเป็น**ภาพเดียว** โดยระดับอื่น ๆ จะถูกแนบมาในรูปแบบที่สามารถดูได้ ไม่ใช่ภาพหนึ่งภาพต่อระดับ

การตั้งชื่อโฟลเดอร์ลูกของระดับโดยตรง (เช่น `…/captures/raw/`) ก็ทำงานได้เช่นกัน, แต่จะทำให้ไฟล์ `.daq` ที่อยู่ในระดับรากถูกทิ้งไว้ — ให้คัดลอกไฟล์เหล่านั้นมาพร้อมกันเมื่อคุณสร้างผลิตภัณฑ์รังสีวัดใหม่จาก `raw/` มิฉะนั้น การจับคู่เวลาประทับจะไม่มีข้อมูลอ้างอิงเพื่อแก้ไข

{% hint style="warning" %}
**การประมวลผลจะเริ่มจาก `raw` เสมอ** ในแต่ละการจับภาพ เฟรมดิบคือแหล่งข้อมูลของระบบประมวลผล; `debayered`, `radiance`, `reflectance`, และ `preview` เป็นโหมดที่แสดงผลได้ แต่ไม่เคยถูกส่งกลับผ่านท่อประมวลผล — การประมวลผลซ้ำผลิตภัณฑ์ที่ได้มาจะนำไปใช้การปรับ vignette, สี และการคำนวณ radiance ที่ถูกฝังไว้ในพิกเซลแล้ว ดังนั้นChloros

จึงปฏิเสธการประมวลผลแทนที่จะประมวลผลซ้ำ การเรนเดอร์ `index/` และ `composite/` ไม่ได้รับการประมวลผลเลย (พวกมันเป็นผลลัพธ์ ไม่ใช่การจับภาพ) โฟลเดอร์ captures ที่บันทึก **โดยไม่** นำเข้าไฟล์ raw จะแสดงผลตามปกติ แต่ `process` จะข้ามมันไปและแจ้งให้ทราบ; `--input-level {raw,debayered,processed}` เป็นทางออกที่ตั้งใจสร้างขึ้นเพื่อบังคับให้มีจุดเริ่มต้น ดู [CLI

Reference](../reference/cli-reference.md#what-a-captures-folder-looks-like) เพื่อดูข้อความข้ามที่แม่นยำ
{% endhint %}

พฤติกรรมอีกสองอย่างที่ควรรู้เมื่อเขียนสคริปต์เพื่อประมวลผลใหม่:

* การรัน `chloros-cli process` ที่ขอผลิตภัณฑ์แต่ **ไม่เขียนผลิตภัณฑ์ภาพ**จะล้มเหลวอย่างชัดเจนและออกด้วยค่าที่ไม่เป็นศูนย์** — คุณจะไม่เคยได้รับการรันที่ว่างเปล่าอย่างเงียบๆ การรันที่สำเร็จจะรายงานจำนวนผลิตภัณฑ์ (การรันที่ตั้งใจให้ใช้เมตาดาต้าเท่านั้นยังคงนับว่าสำเร็จ)
* การนำเข้าใหม่ของไฟล์ส่งออกที่ผ่านการประมวลผลแล้วจะไม่ใช้สล็อต raw ของการจับภาพ — raw ต้นฉบับจะยังคงเป็นแหล่งข้อมูลของ pipeline เสมอ

## สิ่งที่เทียบเท่าในCLI



ทุกสิ่งบนหน้านี้สามารถทำงานได้แบบ headless โหมดการจับภาพใน GUI จะตรงกับ `chloros-cli lattice array-capture`:

| GUI |CLI

|
| --- | --- |
| Single | `chloros-cli lattice array-capture` |
| Continuous | `array-capture --continuous [--count N] [--duration S]` |
| ตามช่วงเวลา | `array-capture --interval S [--duration S]` |
| การจับภาพเร็วที่สุด | `array-capture --fastest` |
| ช่องทำเครื่องหมายที่จัดแนว | `--aligned / --no-aligned` |
| ช่องเลือกประเภทการส่งออก | `--processing LEVEL` หรือ `--levels L1,L2,…` (ค่าเริ่มต้น `all`) |
| บันทึกวิดีโอแบบดัชนี | `chloros-cli lattice array-record` |
| บันทึกภาพต่อเนื่องแบบดิบ / สร้างวิดีโอ | `chloros-cli lattice array-burst` / `array-build-video` |

ตารางธงเต็ม, ตัวเลือกการถ่ายภาพแบบ smart-AE settled-capture (`--smart`), และแบบอัตราคงที่ (sustained-rate) อยู่ใน [CLI

Reference § Capture Modes, Recorders &amp; Offline Reprocess](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).
