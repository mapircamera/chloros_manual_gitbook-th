# กล้องโมโนโครมและดัชนีพืชพรรณ

## กล้องหนึ่งตัว = แบนด์หนึ่ง

กล้อง **M3M**เป็นรุ่นโมโนโครมของ**M3C** แบบ Bayer: ใช้เซ็นเซอร์ IMX265 โมโนโครมที่ติดตั้งอยู่หลังฟิลเตอร์แทรกสอดแบนด์แคบตัวเดียว ชื่อรุ่นระบุชื่อแถบ — `M3M-<lens>-F<wavelength>`, เช่น `M3M-L87-F685` (แสดงในChloros

เป็น `LATT-M3M-L87-F685`) เซ็นเซอร์นี้ให้ **แถบสีเทาเดียว** โดยไม่มีโมเสกแบบ Bayer: จึงไม่มีขั้นตอนการถอดโมเสก (demosaic) ไม่มีสัญญาณรบกวนระหว่างช่องสัญญาณ (inter-channel crosstalk) ที่ต้องแยกออก และไม่จำเป็นต้องตั้งค่าสมดุลสีขาว (white balance)

ผลที่ควรทราบก่อนวางแผนระบบโมโนโครม:

* **ความส่องสว่างและความสะท้อนถูกกำหนดอย่างครบถ้วนต่อแต่ละแถบ**นี่คือแผนที่รังสีวัดค่าตามแต่ละแบนด์ ดังนั้นกล้อง M3M หนึ่งตัวจะสร้างค่าความส่องสว่าง (radiance) แบบ float32 ที่ได้รับการปรับเทียบ (W/m²/sr/nm) และค่าการสะท้อน (reflectance) แบบ uint16 (`32768` = ρ 1.0) ได้อย่างแม่นยำ เหมือนกับที่แบนด์ M3C ทำ เฟรม Mono นำ**เมทริกซ์การตอบสนองของเซ็นเซอร์**แบบ**identity** — ไม่จำเป็นต้องใช้หรือประยุกต์ใช้การแยกผสม 3×3
* **กล้อง Mono เดี่ยวไม่สามารถสร้างดัชนีพืชพรรณได้** ดัชนีพืชพรรณ (NDVI

), ดัชนีความชื้นพืช (NDRE

) และดัชนีอื่น ๆ จำเป็นต้องมีอย่างน้อยสองแบนด์ เพื่อคำนวณดัชนีจากฮาร์ดแวร์ Mono คุณต้องรวมกล้อง M3M หลายตัว — ดูรายละเอียดด้านล่าง
* กล้อง M3M ส่งข้อมูล **Mono12** (12 บิต, 2 ไบต์/พิกเซลบนสายสัญญาณ) ซึ่งมีความสำคัญต่อ [การจัดสรรถ่ายความกว้างแบนด์วิดท์ของอาร์เรย์](arrays.md#bandwidth-the-rules-of-thumb).

## สิ่งที่Chloros

ข้ามไปสำหรับโมโน — และวิธีที่มันแจ้งให้คุณทราบ

ขั้นตอนในสายการประมวลผลสี (colour pipeline) ไม่สามารถนำไปใช้กับเซ็นเซอร์แบบแถบเดียวได้Chloros

**จะข้ามขั้นตอนเหล่านี้ด้วยข้อความเพียงหนึ่งบรรทัด** แทนที่จะแสดงข้อผิดพลาด และยังคงดำเนินการตามปกติสำหรับกล้อง M3C (Bayer) ใด ๆ ในเซสชันเดียวกัน:

| ขั้นตอน | พฤติกรรม Mono (M3M) | พฤติกรรม M3C |
| --- | --- | --- |
| Demosaic / debayer | ข้าม — ระดับการส่งออก `debayered` เป็นภาพสีเทา 1 ช่องสัญญาณ | Demosaic 3 ช่อง |
| White balance (`lattice white-balance`) | ข้ามไปพร้อมข้อความหนึ่งบรรทัด | ทำงานตามปกติ |
| โปรไฟล์สี (`lattice color-profile`) | ข้ามไปพร้อมข้อความหนึ่งบรรทัด | ทำงานปกติ |
| ความอิ่มตัว/ความคมชัด (`lattice color`) | ข้ามไปพร้อมข้อความหนึ่งบรรทัด | | ทำงานปกติ |
| การแยกสัญญาณครอสทอล์กสเปกตรัม | ตัวตน (ไม่มีเมทริกซ์ 3×3) | ใช้เมทริกซ์ 3×3 สำหรับแต่ละกล้อง |
| ความสว่าง / ความสะท้อน | **ทำงาน** — ตามแต่ละแถบ, ปรับเทียบอย่างสมบูรณ์ | ทำงานตามแต่ละแถบ |

GUI ใช้การจำกัดแบบเดียวกัน: สำหรับกล้องโมโน แผงตั้งค่าต่อกล้องจะซ่อนแถวที่เกี่ยวข้องกับRGB

เท่านั้น (White Balance, Gamma, Color Profile, Saturation, Contrast, channel splits), และฮิสโตแกรมแบบเรียลไทม์ถูกล็อกไว้ที่เส้น **MONO** เดียว ตัวระบุ (discriminator) ในทั้งสแต็กคือโทเคน `M3M` ในสตริงโมเดล ซึ่งแสดงบน GUI/SDK

ในรูปแบบ `is_mono`

## ดัชนีต้องใช้ ≥ 2 แบนด์: จัดแนว → สแต็ก → ดัชนี

ขั้นตอนการทำงานของดัชนีโมโนมีสามขั้นตอนที่เหมือนกันเสมอ:

1. **จัดแนว** — ตั้งกล้อง M3M หลายตัวที่ความยาวคลื่นต่างกัน (เช่น F650 &quot;Red

&quot; และ F850 &quot;NIR

&quot;), เชื่อมต่อพวกมันเป็น [อาร์เรย์กล้องหลายตัว](arrays.md) และให้Chloros

คำนวณการปรับตำแหน่งร่วม (co-registration warp) ระหว่างกล้อง
2. **Stack** — ภาพที่จัดตำแหน่งแล้วจะรวมเป็นภาพหลายแถบเดียว (กล้องแต่ละตัวให้แถบที่มีชื่อหนึ่งแถบ)
3. **Index** — คำนวณสูตรดัชนีบนแถบสีของชุดภาพที่จัดเรียงแล้ว โดยสามารถเรนเดอร์ผ่าน LUT ได้ตามต้องการ

ใน GUI ห่วงโซ่ทั้งหมดนี้คือโหมดแสดงผลแบบ **Combined Cameras**: ภาพรวมแบบเรียลไทม์ได้รับการจัดเรียงแล้ว และ**Index Calculator**ของอาร์เรย์ (ด้านล่าง) กำหนดสูตรที่ใช้ในการเรนเดอร์ ไฟล์ที่ส่งออกจากการบันทึกสามารถปรับให้ตรงกับตำแหน่งเดียวกันได้โดยใช้ตัวเลือก**Aligned** ในการบันทึก

## เครื่องคำนวณดัชนี

เครื่องคำนวณดัชนีสร้างนิพจน์ดัชนีที่ใช้ในมุมมองสดและการส่งออกดัชนีตามกล้องแต่ละตัว มันเป็นพื้นผิวที่ใช้ร่วมกัน ซึ่งสามารถเปิดได้จากสองตำแหน่งในแถบด้านข้างของแท็บ Cameras:

* **ต่อกล้อง**— Live Preview →**Index** (เฉพาะกล้อง Bayer ที่ใช้RGN

/OCN

/NGB

; กล้องโมโนเดี่ยวไม่มีตัวเลือกควบคุมดัชนี เนื่องจากแถบเดียวไม่สามารถสร้างดัชนีได้)
* **ตามอาร์เรย์**— การตั้งค่าอาร์เรย์ → Live Preview →**Index**(ไอคอนรูปเฟือง). นี่คือเส้นทางสำหรับกล้องโมโนโครม: รายการแถบครอบคลุม**กล้องสมาชิกทั้งหมด** ดังนั้นคู่กล้องโมโนโครมจึงส่งแถบทั้งสองของมันมาที่นี่

ปุ่มควบคุมจากบนลงล่าง:

* **ชิปแถบ** (&quot;แถบ — คลิกเพื่อเพิ่มลงในนิพจน์&quot;) — ปุ่มหนึ่งต่อแถบที่มีอยู่ แต่ละปุ่มมีชื่อสี + ความยาวคลื่นในหน่วย nm (ชื่อสีที่ซ้ำกันจะถูกแยกความหมาย เช่น &quot;Color 850&quot;) การคลิกจะแทรกโทเค็นแถบที่ตำแหน่งเคอร์เซอร์ แถบจากกล้องที่ไม่สามารถสร้าง radiance ตามแถบได้ (RGB

/FRGB) จะถูกกรองออก
* **ปุ่มตัวดำเนินการและฟังก์ชัน** — `+ - * / ( ) ^ ,` และ `abs() sqrt() log() log10() exp() min() max() pow()`.
* **พื้นที่ข้อความสำหรับนิพจน์** — สูตรที่พิมพ์ได้อิสระ; ตัวแทนแสดงรูปแบบคลาสสิกของNDVI

`(NIR - Red) / (NIR + Red)`. การแสดงตัวอย่างแบบอ่านอย่างเดียวที่ถูกแบ่งเป็นโทเคนด้านบนจะแสดงชิปแถบ, ตัวเลข, และธงเป็นโทเคนที่ยังไม่ทราบ
* **แถบสถานะความถูกต้อง**— สีเทา &quot;ว่าง — ไม่มีการใช้ดัชนี&quot;; สีเขียว &quot;นิพจน์ถูกต้อง&quot;; สีแดงพร้อมข้อผิดพลาดการวิเคราะห์เฉพาะ (แถบไม่รู้จัก, แถบไม่ชัดเจนจากกล้องหลายตัว, ขาดวงเล็บ, …); หรือสีเหลืองอำพันเมื่อนิพจน์ถูกต้องแต่**ค่าคงที่** (เช่น `X/X` หรือตัวหารของNDVI

ที่ถูกพิมพ์เป็น `−` แทน `+`) — ค่าคงที่จะทำให้เฟรมทั้งหมดถูกแปลงเป็นสีเดียว
* คำเตือนสีเหลืองอำพันแยกต่างหากจะปรากฏขึ้นหากนิพจน์ที่นำไปใช้ถูกต้อง แต่ **เฟรมสดมีสีสม่ำเสมอ** (ฉากที่ราบเรียบหรืออิ่มตัว) — ระบบจะตรวจพบการยุบตัวของฮิสโตแกรมให้คุณ
* **Apply LUT**(เปิดตามค่าเริ่มต้น; ปิด = การขยายสเกลสีเทา),**Level**2/3/5/7-stop (ค่าเริ่มต้น 7-stop), และ**Min / Max**ที่อยู่ด้านข้างของแถบไล่ระดับสี ค่า Min ตั้งค่าเริ่มต้นเป็น**

0.2**— ซึ่งช่วยซูมช่วงสีให้อยู่ในช่วงที่เกี่ยวข้องกับพืชพรรณ ในขณะที่ค่าที่ต่ำกว่าจะแสดงเป็นสีเทา; ตั้งค่า Min เป็น −1 เพื่อแสดงช่วงดัชนีทั้งหมด (ปุ่ม**Reset** จะคืนค่าเป็น −1…+1) ค่า Max ตั้งค่าเริ่มต้นเป็น 1.
* **ฮิสโตแกรมแบบเรียลไทม์** ของการแจกแจงดัชนี — แถบที่ปรับสเกลด้วยรากที่สอง, เส้นเปอร์เซ็นไทล์ p2/p98 สีเหลืองอำพัน, เส้นมัธยฐานสีขาว, และค่าแสดงผลส่วนท้ายที่อยู่นอกช่วง (&quot;◀ N% &lt; lo&quot; / &quot;hi &lt; N% ▶&quot;) ที่เปลี่ยนเป็นสีเหลืองอำพันเมื่อเกิน 1% เพื่อเป็นสัญญาณให้ขยายหน้าต่าง Min/Max
* **Apply**ส่งนิพจน์ไปยังสตรีมสด; การปรับแต่ง LUT มีผลทันทีโดยไม่ต้องกด Apply นิพจน์ถูกออกแบบให้เป็น**เฉพาะเซสชัน** — ไม่ถูกเก็บไว้ระหว่างเซสชัน

## เส้นทางCLI



ห่วงโซ่ align → stack → index เดียวกัน ซึ่งสามารถเขียนสคริปต์ได้ตั้งแต่ต้นจนจบ:

```bash
chloros-cli lattice array-connect --serials SN_RED,SN_NIR
chloros-cli lattice index --live --profile align.json \
  --preset NDVI --channel red=Red_660 --channel nir=NIR_850 \
  --save-multiband -o output/
```

`--channel` แปลงสัญลักษณ์ของ preset ให้ตรงกับชื่อแบนด์ของ stack สองกฎนี้จะช่วยคุณหลีกเลี่ยงการรันที่ล้มเหลว:

* **สัญลักษณ์มีความไวต่อตัวพิมพ์ใหญ่-เล็ก** และต้องตรงกับชื่อช่องของพรีเซ็ตอย่างแม่นยำ — พรีเซ็ตใช้ตัวพิมพ์เล็ก (ของNDVI

คือ `red`, `nir`; ตรวจสอบ `--list-presets`). `--channel red=Red_660` ทำงานได้; `--channel RED=660` ล้มเหลวพร้อมข้อผิดพลาด `channel_map missing entries`.
* ด้าน band ต้องระบุชื่อ band ใน stack ที่จัดเรียงแล้ว (`lattice align-info --profile align.json` แสดงรายการเหล่านั้น) โหมดออฟไลน์ยังรับดัชนี band ที่เริ่มจาก 0 ได้ เช่น `--channel red=0 --channel nir=1`

`lattice index` ยังทำงานแบบออฟไลน์อย่างเต็มรูปแบบกับชุดภาพหลายแถบที่จัดเรียงและบันทึกไว้แล้วTIFF

:

```bash
chloros-cli lattice index --input aligned.tif --preset NDVI \
  --output ndvi.tif --colorize --gradient RdYlGn
```

## การจับภาพผลิตภัณฑ์ดัชนีจากอาร์เรย์โมโน

เมื่ออาร์เรย์ถูกเชื่อมต่อและมีการใช้สูตรดัชนีแล้ว `array-capture` (หรือ GUI **Capture All**) จะบันทึกระดับการส่งออกของแต่ละกล้อง *และ* การเรนเดอร์ดัชนี — `--index`/`--no-index` ใช้เพื่อเปิด/ปิดฟังก์ชันนี้ในหน้าต่างการตั้งค่า (CLI

) และการบันทึกค่าเริ่มต้นจะรวมทุกระดับที่เกี่ยวข้อง ส่วนที่กล้องโมโนมีส่วนร่วมในแต่ละกลุ่มการจับภาพคือแถบเดียวของมันที่ระดับ raw/debayered (grayscale)/radiance/reflectance พร้อมทั้งภาพรวมดัชนีที่รวมกันเมื่ออาร์เรย์ทำงานในโหมดรวม ดู [Multi-Camera Arrays § Capturing](arrays.md#capturing-monitoring-vs-analysis).
