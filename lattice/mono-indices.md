# กล้องโมโนโครมและดัชนีพืชพรรณ

## กล้องหนึ่งตัว = แบนด์หนึ่ง

กล้อง **M3M**เป็นรุ่นโมโนโครมของกล้อง Bayer**M3C**: ใช้เซ็นเซอร์ IMX265 โมโนโครมที่ติดตั้งอยู่หลังฟิลเตอร์แทรกสอดแบนด์แคบเพียงตัวเดียว ชื่อรุ่นจะระบุชื่อแถบ — `M3M-<lens>-F<wavelength>`, เช่น `M3M-L87-F685` (แสดงใน Chloros

เป็น `LATT-M3M-L87-F685`) เซ็นเซอร์นี้ให้ **แถบสีเทาเดียว** โดยไม่มีโมเสก Bayer: ไม่มีอะไรต้องทำการเดโมเสก ไม่มีสัญญาณรบกวนระหว่างช่องที่ต้องแยกออก และไม่จำเป็นต้องตั้งค่าสมดุลสีขาว

ผลที่ควรทราบก่อนวางแผนระบบโมโนโครม:

* **ความส่องสว่างและความสะท้อนถูกกำหนดอย่างครบถ้วนต่อแต่ละแบนด์**นี่คือแผนที่รังสีวัดค่าตามแต่ละแบนด์ ดังนั้นกล้อง M3M หนึ่งตัวจะสร้างค่าความส่องสว่างที่ผ่านการปรับเทียบในรูปแบบ float32 (W/m²/sr/nm) และค่าการสะท้อนในรูปแบบ uint16 (`32768` = ρ 1.0) ได้อย่างแม่นยำเช่นเดียวกับแบนด์ของ M3C เฟรม Mono มี**เมทริกซ์การตอบสนองของเซ็นเซอร์**แบบ**identity** — ไม่จำเป็นต้องใช้หรือประยุกต์ใช้การแยกผสม 3×3
* **กล้อง Mono เดี่ยวไม่สามารถสร้างดัชนีพืชพรรณได้** NDVI

, NDRE

และดัชนีอื่น ๆ ต้องการอย่างน้อยสองแบนด์ เพื่อคำนวณดัชนีจากฮาร์ดแวร์ Mono คุณต้องรวมกล้อง M3M หลายตัว — ดูด้านล่าง
* กล้อง M3M ส่งข้อมูล **Mono12** (12 บิต: 2 ไบต์/พิกเซลบนสาย หรือ 1.5 ไบต์/พิกเซลเมื่ออาร์เรย์ใช้ [การส่งข้อมูลแบบ packed 12 บิต](arrays.md#packed-12-bit-transport)) ซึ่งมีความสำคัญต่อ [การจัดสรรถ่ายทอดแบนด์วิดท์ของอาร์เรย์](arrays.md#bandwidth-how-many-cameras-fit).

## สิ่งที่Chloros

ข้ามไปสำหรับโหมดโมโน — และวิธีที่มันแจ้งให้คุณทราบ

ขั้นตอนใน pipeline สีไม่ถูกนำไปใช้กับเซ็นเซอร์แบบแถบเดียว Chloros

**ข้ามขั้นตอนเหล่านี้ด้วยข้อความหนึ่งบรรทัด** แทนที่จะแสดงข้อผิดพลาด และยังคงดำเนินการขั้นตอนเหล่านี้ตามปกติสำหรับกล้อง M3C (Bayer) ใดก็ตามในเซสชันเดียวกัน:

| ขั้นตอน | พฤติกรรม Mono (M3M) | พฤติกรรม M3C |
| --- | --- | --- |
| Demosaic / debayer | ข้าม — ระดับการส่งออก `debayered` เป็นภาพเกรดสเกล 1 ช่อง | Demosaic 3 ช่อง |
| การปรับสมดุลสีขาว (`lattice white-balance`) | ข้ามไปพร้อมข้อความหนึ่งบรรทัด | ทำงานตามปกติ |
| โปรไฟล์สี (`lattice color-profile`) | ข้ามไปพร้อมข้อความหนึ่งบรรทัด | ทำงานตามปกติ |
| ความอิ่มตัว/ความคมชัด (`lattice color`) | ถูกข้ามไปพร้อมข้อความหนึ่งบรรทัด | ทำงานปกติ |
| การแยกสัญญาณข้ามสเปกตรัม | ตัวตน (ไม่มีเมทริกซ์ 3×3) | ใช้เมทริกซ์ 3×3 สำหรับแต่ละกล้อง |
| ความสว่าง / ความสะท้อน | **ทำงาน** — ตามแต่ละแถบ, ปรับเทียบอย่างสมบูรณ์ | ทำงานตามแต่ละแถบ |

GUI ใช้การจำกัดแบบเดียวกัน: สำหรับกล้องโมโน แผงตั้งค่าต่อกล้องจะซ่อนแถวที่เกี่ยวข้องกับRGB

เท่านั้น (White Balance, Gamma, Color Profile, Saturation, Contrast, channel splits) และฮิสโตแกรมแบบเรียลไทม์ถูกล็อกไว้ที่เส้น **MONO** เดียว ตัวแยกแยะ (discriminator) ในทั้งสแต็กคือโทเค็น `M3M` ในสตริงโมเดล ซึ่งแสดงบน GUI/SDK

เป็น `is_mono`

## ดัชนีต้องใช้ ≥ 2 แบนด์: จัดแนว → สแต็ก → ดัชนี

ขั้นตอนการทำงานของดัชนีโมโนมีสามขั้นตอนที่เหมือนกันเสมอ:

1. **จัดแนว** — ตั้งกล้อง M3M หลายตัวที่ความยาวคลื่นต่างกัน (เช่น F650 &quot;Red

&quot; และ F850 &quot;NIR

&quot;), เชื่อมต่อพวกมันเป็น [อาร์เรย์กล้องหลายตัว](arrays.md) และให้Chloros

คำนวณการบิดเบือนการลงทะเบียนร่วมระหว่างกล้อง
2. **การซ้อนภาพ** — ภาพที่จัดแนวแล้วจะกลายเป็นภาพหลายแถบเดียว (กล้องแต่ละตัวให้แถบที่มีชื่อหนึ่งแถบ)
3. **Index** — คำนวณสูตรดัชนีบนแถบสีของภาพที่จัดเรียงแล้ว โดยสามารถเรนเดอร์ผ่าน LUT ได้ตามต้องการ

ใน GUI ห่วงโซ่กระบวนการทั้งหมดนี้คือโหมดแสดงผล **Combined Cameras**: ภาพรวมแบบเรียลไทม์ได้รับการจัดเรียงแล้ว และ**Index Calculator**ของอาร์เรย์ (ด้านล่าง) กำหนดสูตรที่ใช้ในการเรนเดอร์ ไฟล์ที่ส่งออกจากการจับภาพสามารถปรับให้ตรงกับการจัดแนวเดียวกันได้โดยใช้ตัวเลือกการจับภาพ**Aligned**

## เครื่องคำนวณดัชนี

เครื่องคำนวณดัชนีสร้างนิพจน์ดัชนีที่ใช้ในมุมมองสดและการส่งออกดัชนีต่อกล้องแต่ละตัว มันเป็นพื้นผิวที่ใช้ร่วมกัน ซึ่งสามารถเปิดได้จากสองจุดในแถบด้านข้างของแท็บ Cameras:

* **ต่อกล้อง**— Live Preview →**Index** (เฉพาะกล้อง RGN

/OCN

/NGB

Bayer; กล้องโมโนเดี่ยวไม่มีตัวเลือกควบคุมดัชนี เนื่องจากแถบเดียวไม่สามารถสร้างดัชนีได้)
* **ตามอาร์เรย์**— การตั้งค่าอาร์เรย์ → Live Preview →**Index**(ไอคอนรูปเฟือง). นี่คือเส้นทางสำหรับกล้องโมโนโครม: รายการแถบครอบคลุม**กล้องทุกตัวในอาร์เรย์** ดังนั้นคู่กล้องโมโนโครมจึงส่งแถบทั้งสองของมันมาที่นี่

ปุ่มควบคุมจากบนลงล่าง:

* **ชิปแถบ** (&quot;แถบ — คลิกเพื่อเพิ่มลงในนิพจน์&quot;) — ปุ่มหนึ่งต่อแถบที่มีอยู่ แต่ละปุ่มมีชื่อสี + ความยาวคลื่นในหน่วย nm (ชื่อสีที่ซ้ำกันจะถูกแยกความหมาย เช่น &quot;Color 850&quot;) การคลิกจะแทรกโทเค็นแถบที่ตำแหน่งเคอร์เซอร์ แถบจากกล้องที่ไม่สามารถสร้างค่าความสว่างต่อแถบได้ (RGB

/FRGB) จะถูกกรองออก
* **ปุ่มตัวดำเนินการและฟังก์ชัน** — `+ - * / ( ) ^ ,` และ `abs() sqrt() log() log10() exp() min() max() pow()`.
* **พื้นที่ข้อความสำหรับสูตร** — สูตรที่พิมพ์ได้อิสระ; ตัวแทนแสดงรูปแบบNDVI

แบบคลาสสิก `(NIR - Red) / (NIR + Red)`. ส่วนแสดงตัวอย่างแบบอ่านอย่างเดียวที่แบ่งเป็นโทเคนด้านบนจะแสดงชิปแถบ, ตัวเลข และธงสำหรับโทเคนที่ยังไม่ทราบ
* **แถบแสดงความถูกต้อง**— สีเทา &quot;ว่าง — ไม่มีการใช้ดัชนี&quot;; สีเขียว &quot;นิพจน์ถูกต้อง&quot;; สีแดงพร้อมข้อผิดพลาดการวิเคราะห์เฉพาะ (แถบไม่รู้จัก, แถบไม่ชัดเจนจากกล้องหลายตัว, ขาดวงเล็บ, …); หรือสีเหลืองอำพันเมื่อนิพจน์ถูกต้องแต่**ค่าคงที่** (เช่น `X/X` หรือตัวหารNDVI

ที่พิมพ์ด้วย `−` แทน `+`) — ค่าคงที่จะทำให้เฟรมทั้งหมดถูกแปลงเป็นสีเดียว
* คำเตือนสีเหลืองอำพันแยกต่างหากจะปรากฏขึ้นหากนิพจน์ที่นำไปใช้ถูกต้อง แต่ **เฟรมสดมีสีสม่ำเสมอ** (ฉากที่ราบเรียบหรืออิ่มตัว) — ระบบจะตรวจพบการยุบตัวของฮิสโตแกรมให้คุณ
* **Apply LUT**(เปิดตามค่าเริ่มต้น; ปิด = ขยายสเกลสีเทา),**Level**2/3/5/7-stop (ค่าเริ่มต้น 7-stop), และ**Min / Max**ที่อยู่ด้านข้างของแถบไล่ระดับสี ค่า Min ตั้งค่าเริ่มต้นเป็น**

0.2**— ซึ่งช่วยซูมช่วงสีให้อยู่ในช่วงที่เกี่ยวข้องกับพืชพรรณ ส่วนค่าที่ต่ำกว่าจะแสดงเป็นสีเทา; ตั้งค่า Min เป็น −1 เพื่อแสดงช่วงดัชนีทั้งหมด (ปุ่ม**Reset** จะคืนค่าเป็น −1…+1) ค่า Max ตั้งค่าเริ่มต้นเป็น 1.
* **ฮิสโตแกรมแบบเรียลไทม์** ของการแจกแจงค่าดัชนี — แถบที่ปรับสเกลด้วยรากที่สอง, เส้นเปอร์เซ็นไทล์ p2/p98 สีเหลืองอำพัน, เส้นมัธยฐานสีขาว, และค่าแสดงผลส่วนท้ายที่อยู่นอกช่วง (&quot;◀ N% &lt; lo&quot; / &quot;hi &lt; N% ▶&quot;) ซึ่งจะเปลี่ยนเป็นสีเหลืองอำพันเมื่อเกิน 1% เพื่อเป็นสัญญาณให้ขยายหน้าต่าง Min/Max
* **Apply** ใช้สูตรกับสตรีมสด; การปรับแต่ง LUT จะมีผลทันทีโดยไม่ต้องกด Apply เมื่อเปิดโครงการไว้ การตั้งค่าสูตรและ LUT จะถูกบันทึกพร้อมกับโครงการและคืนค่าเมื่อเปิดโครงการใหม่; หากไม่มีโครงการ การตั้งค่าเหล่านี้จะมีผลเฉพาะในเซสชันนั้นเท่านั้น

## เส้นทางCLI



ห่วงโซ่ align → stack → index เดียวกัน ซึ่งสามารถเขียนสคริปต์ได้ตั้งแต่ต้นจนจบ:

```bash
chloros-cli lattice align-calibrate --serials SN_RED,SN_NIR --save align.json
chloros-cli lattice index --live --profile align.json \
  --preset NDVI --channel red=Red_660 --channel nir=NIR_850 \
  --save-multiband -o output/
```

`align-calibrate` ใช้ array ที่เชื่อมต่อกันเพื่อเก็บกล้องไว้ หรือเปิดกล้องเองสำหรับการทำงานครั้งเดียว `index --live` จะเปิดกล้องเองเสมอ (เป็น [transient array](../reference/cli-reference.md#multi-camera-transient-sessions)) และไม่มี `--serials`: มันจะเปิดกล้องทุกตัวในเครือข่าย ดังนั้น ให้ปล่อยกล้องทุกตัวที่Chloros

ถืออยู่ก่อน — GUI, `cam-connect`, `array-connect` (`chloros-cli lattice array-disconnect --all`): การเปิดกล้องที่ถูกถือครองเป็นครั้งที่สองอาจทำให้สตรีมของผู้ถือหยุดลงหรือทำให้ระบบหลังบ้านล่ม กล้องที่ไม่ส่งเฟรมจะทำให้การรันล้มเหลว และไม่มีการเขียนสแต็กหรือดัชนี

`--channel` แปลงสัญลักษณ์ของพรีเซ็ตให้เป็นชื่อแบนด์ของสแต็ก มีสองกฎที่จะช่วยคุณหลีกเลี่ยงการรันที่ล้มเหลว:

* **สัญลักษณ์มีความไวต่อตัวพิมพ์ใหญ่-เล็ก** และต้องตรงกับชื่อช่องของพรีเซ็ตอย่างแม่นยำ — พรีเซ็ตใช้ตัวพิมพ์เล็ก (ของ NDVI

คือ `red`,`nir`; ดู `--list-presets`). `--channel red=Red_660` ทำงานได้; `--channel RED=660` ล้มเหลวพร้อมข้อผิดพลาด `channel_map missing entries`.
* ด้าน band ต้องระบุชื่อ band ในชุดภาพที่จัดเรียงแล้ว (`lattice align-info --profile align.json` แสดงรายการไว้) โหมดออฟไลน์ยังรับดัชนี band ที่เริ่มจาก 0 ได้ เช่น `--channel red=0 --channel nir=1`.

`lattice index` ยังสามารถทำงานแบบออฟไลน์ได้กับไฟล์TIFF

หลายแบนด์ที่จัดเรียงแล้วและถูกบันทึกไว้ ทุกแบบฟอร์มทำงานบนระบบหลังบ้าน ดังนั้นระบบต้องกำลังทำงานและเข้าสู่ระบบในแพ็กเกจ Chloros

+ ที่ชำระเงินแล้ว; `--input` หรือ `--output` ที่เกี่ยวข้องจะอ้างอิงไปยังโฟลเดอร์ที่คุณเรียกใช้คำสั่งจาก:

```bash
chloros-cli lattice index --input aligned.tif --preset NDVI \
  --output ndvi.tif --colorize --gradient RdYlGn
```

### การตั้งค่าล่วงหน้าของดัชนี

`lattice index --preset` (และ [Index/LUT sandbox](../image-viewer-gui/index-lut-sandbox.md) ในแท็บ Image ซึ่งใช้เอนจินเดียวกัน) มาพร้อมกับ **22 การตั้งค่าล่วงหน้า** ดังนี้:

`NDVI, GNDVI, BNDVI, NDRE, ENDVI, SAVI, OSAVI, MSAVI, EVI, EVI2, CVI, MSR, TDVI, LAI, GLI, NGRDI, VARI, TGI, EXG, CIRE, CIGREEN, NDWI`

เรียกใช้ `chloros-cli lattice index --list-presets` เพื่อดูสูตรและสัญลักษณ์ช่องสัญญาณของแต่ละค่าตั้งล่วงหน้า และ `--list-gradients` เพื่อดูการไล่ระดับสีที่มีอยู่ สูตรที่กำหนดเองใช้ `--formula EXPR` ด้วยไวยากรณ์เดียวกันกับ Index Calculator หมายเหตุ: รายการพรีเซ็ตนี้เฉพาะสำหรับ LATTICE index engine — รายการในเมนูแบบเลื่อนลง &quot;Project Settings processing&quot; สำหรับภาพที่นำเข้าเป็นรายการที่ต่างกัน (ดู [สูตรดัชนีมัลติสเปกตรัม](../project-settings/multispectral-index-formulas.md)).

## การจับภาพผลิตภัณฑ์ดัชนีจากอาร์เรย์โมโน

เมื่อเชื่อมต่ออาร์เรย์และใช้สูตรดัชนีแล้ว `array-capture` (หรือ GUI **Capture All**) จะบันทึกระดับการส่งออกของแต่ละกล้อง *และ* การเรนเดอร์ดัชนี — `--index`/`--no-index` ใช้เพื่อเปิด/ปิดฟังก์ชันนี้ในCLI

และการบันทึกจะตั้งค่าเริ่มต้นให้รวมทุกระดับที่ applicable ส่วนที่กล้องโมโนแต่ละตัวมีส่วนร่วมในแต่ละกลุ่มการบันทึกคือแถบเดียวของมันในระดับ raw/debayered (grayscale)/radiance/reflectance รวมถึงภาพรวมดัชนีที่รวมกันเมื่ออาร์เรย์ทำงานในโหมดรวม ดู [กลุ่มกล้องหลายตัว § การบันทึก](arrays.md#capturing-monitoring-vs-analysis).
