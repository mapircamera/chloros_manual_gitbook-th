# เริ่มต้น

<div data-full-width="false"><figure><img src=".gitbook/assets/chloros_logo_transparent.png" alt=""><figcaption></figcaption></figure></div>

Chloros
เป็นแอปพลิเคชันซอฟต์แวร์จาก [MAPIR
](https://www.mapir.camera) ที่ใช้เพื่อประมวลผลภาพมัลติสเปกตรัม ควบคุมอุปกรณ์ MAPIR
แบบเรียลไทม์ และบันทึกข้อมูลเซ็นเซอร์ Chloros
1.3.0 รองรับผลิตภัณฑ์ MAPIR
ทั้งหมด:

* **กล้อง Survey3** — ประมวลผลภาพ RAW+JPG ที่ถ่ายได้เป็นแผนที่การสะท้อนแสงที่ปรับเทียบแล้วและแผนที่ดัชนีพืชพรรณ ดู [กล้องที่รองรับ](supported-cameras.md).
* **กล้อง LATTICE** — เชื่อมต่อโมดูลกล้องมัลติสเปกตรัม GigE แบบเรียลไทม์ ทั้งแบบเดี่ยวหรือเป็นกลุ่มกล้องหลายตัวที่ซิงโครไนซ์: ดูตัวอย่างภาพ, ถ่ายภาพ และประมวลผลเป็นผลิตภัณฑ์ความสว่างและความสะท้อนที่ได้รับการปรับเทียบ ดู [ส่วน LATTICE](lattice/README.md).
* **เซ็นเซอร์แสง DAQ** — DAQ-U (USB), DAQ-M (Bluetooth), และ DAQ-E และ DAQ-E-S (Ethernet) เซ็นเซอร์สเปกตรัม: สเปกตรัมที่ปรับเทียบแบบเรียลไทม์, `.daq` การบันทึกข้อมูล และแสงที่ส่องลงสำหรับการประมวลผลค่าการสะท้อน ดู [ส่วน DAQ](daq/README.md)

## สิ่งใหม่ในChloros
1.3.0

* **ผู้ช่วย AI สามารถควบคุม Chloros
ได้** `chloros-mcp` ซึ่งเป็นเซิร์ฟเวอร์ MCP ที่ติดตั้งพร้อมกับ Python
SDK
ช่วยให้ Claude Desktop, Claude Code, Cursor และไคลเอนต์ MCP อื่นๆ สามารถประมวลผลภาพและควบคุมกล้อง LATTICE, อาร์เรย์ และเซ็นเซอร์แสง DAQ ได้ ดู [การใช้ Chloros
กับผู้ช่วย AI](ai-assistants.md).
* **CLI
(CLI
), SDK
(SDK
) และ `chloros-mcp` มีคุณสมบัติที่เหมือนกัน** เพื่อความปลอดภัย การลงชื่อเข้าใช้ การตั้งค่า DAQ-E และเซิร์ฟเวอร์ DAQ โดยตรงยังคงอยู่เฉพาะใน CLI
เท่านั้น สคริปต์บางตัวในเวอร์ชัน 1.2.0 จำเป็นต้องปรับเปลี่ยน: ดู **Changed in 1.3.0** ที่ส่วนบนของ [CLI
Reference](reference/cli-reference.md) และ [SDK
Reference](reference/sdk-reference.md).
* **ผลิตภัณฑ์ดัชนี LATTICE ที่ได้รับการปรับปรุง** NDVI
และผลิตภัณฑ์ดัชนีอื่น ๆ ที่ส่งออกจากการจับภาพ LATTICE ได้รับการปรับปรุงในทุกโหมดการประมวลผล
* **ตัวเลือกตัวติดตั้ง Windows**ในส่วน **การตั้งค่าระบบ**ตัวติดตั้งมีตัวเลือก**เปิดใช้งานเส้นทางยาวของ Windows
**และ**ยกเว้นระบบหลังบ้าน Chloros
จากการสแกนของ Microsoft Defender** ซึ่งทั้งสองตัวเลือกถูกเลือกไว้เป็นค่าเริ่มต้น ตัวเลือกแรกช่วยให้โฟลเดอร์โครงการสามารถมีชื่อยาวเกิน 260 ตัวอักษรได้; ตัวเลือกที่สองป้องกันไม่ให้การสแกนแบบเรียลไทม์ทำให้การจับภาพของกล้องช้าลง (ประมาณ 30% ของอัตราการจับภาพเมื่อใช้ความเร็วสูง). โปรแกรมติดตั้งยังเพิ่มโฟลเดอร์CLI
เข้าสู่ `PATH` เพียงครั้งเดียว และลบรายการซ้ำที่โปรแกรมติดตั้งเวอร์ชันก่อนหน้าทิ้งไว้ ดู [Download](download.md).
* **โฟลเดอร์โครงการที่ลึกเกินไปจะถูกปฏิเสธตั้งแต่ต้น** เมื่อปิดใช้งานเส้นทางยาวของWindows
(ค่าเริ่มต้นของWindows
) โฟลเดอร์โครงการที่ลึกเกินขีดจำกัด 260 ตัวอักษรของเส้นทางจะถูกปฏิเสธก่อนที่โปรแกรมจะทำงาน โดยจะแสดงโฟลเดอร์โครงการที่ยาวที่สุดที่ยังอยู่ในขีดจำกัด และวิธีเปิดใช้งานเส้นทางยาว ก่อนหน้านี้ การทำงานดังกล่าวจะไม่บันทึกผลิตภัณฑ์ใดๆ เมื่อเปิดใช้งานเส้นทางยาวแล้ว ผลิตภัณฑ์ในโฟลเดอร์ที่ลึกมากจะรักษาข้อมูลเมตา (แท็ก GPS และ XMP) ของมันไว้
* **การตัดค่าหน้ากาก (mask)** เมื่อการแยกแบนด์ (band unmix) ของผลิตภัณฑ์ radiance หรือ reflectance จาก LATTICE ให้ค่าแบนด์เป็นค่าลบ ค่าดังกล่าวจะถูกตัดเป็นศูนย์ และหน้ากากต่อพิกเซล (per-pixel mask) ในโฟลเดอร์ `clamp_masks/` ที่อยู่ข้างโฟลเดอร์ผลิตภัณฑ์ จะบันทึกว่าพิกเซลและแบนด์ใดได้รับผลกระทบ ผลิตภัณฑ์จะตั้งชื่อมาสก์ในแท็ก `Chloros:UnmixClampMask` การแสดงผลแบบเรียลไทม์ (Live views) จะตัดค่าให้ตรงกับการส่งออก (export) ดู [รูปแบบภาพผลลัพธ์](output-image-formats.md)
* **ผลิตภัณฑ์อธิบายตัวเอง** ผลิตภัณฑ์ดัชนีมีแท็กการประมวลผลของตัวเอง (`Chloros:ProcessingLevel=index`, นิพจน์ดัชนี, และว่าถูกคำนวณจาก radiance หรือ reflectance) แทนที่จะใช้แท็กของไฟล์ดิบต้นทาง ผลิตภัณฑ์Survey3
มีแท็กการประมวลผลของChloros
ในทุกโหมดการประมวลผล ไฟล์ดิบและไฟล์ที่ถอดเบย์เออร์ของ LATTICE ยังคงรักษาทิศทางดั้งเดิมของเซ็นเซอร์และบันทึกทิศทางนั้นใน XMP; Image Viewer จะหมุนไฟล์เหล่านั้นเพื่อแสดงผลเท่านั้น
* **แพ็กเกจLinux
ถูกจัดส่งในสภาพที่ยังไม่ถูกคลายซิป** ส่วนหลัง (backend) และ CLI
ถูกติดตั้งเป็นโฟลเดอร์ภายใต้ `/usr/lib/chloros/` ดังนั้นจึงไม่จำเป็นต้องคลายซิปตัวเองทุกครั้งที่เปิดใช้งาน บน x86_64 ส่วนหลัง (backend) ไม่ใช้เวลาราว 100 วินาทีในการเริ่มต้นอีกต่อไป และ `.deb` มีขนาดประมาณครึ่งหนึ่งของเดิม ExifTool ที่มาพร้อมแพ็กเกจสามารถทำงานได้บนระบบ Ubuntu ที่ติดตั้งใหม่ `.deb` ยังติดตั้ง Python
SDK
สำหรับระบบ `python3` (ติดตั้งด้วย `sudo apt install ./chloros_1.3.0_<arch>.deb`), เพิ่มขนาดบัฟเฟอร์รับซ็อกเก็ตของเคอร์เนลที่สตรีมจากกล้องต้องการ และเพิ่มบริการแบ็กเอนด์ที่ทำงานในฐานะผู้ใช้ของคุณ แพ็กเกจ Jetson, `chloros_1.3.0_arm64_jp6.deb`, ถูกสร้างขึ้นสำหรับ JetPack 6 และประมวลผลบน GPU ของ Jetson ด้วย PyTorch เวอร์ชัน CUDA ของ JetPack บนระบบ Linux
ภาพที่ส่งออกแต่ละภาพจะเข้าถึงดิสก์เพียงครั้งเดียว (ถูกเขียนและติดแท็กในหน่วยความจำ ก่อนที่จะถูกคัดลอกไปยังตำแหน่งที่ถูกต้อง): บน Jetson ซึ่งความเร็วถูกกำหนดโดยดิสก์ การรัน LATTICE 288 ภาพจะใช้เวลา 14 นาที แทนที่จะเป็น 24 นาที ดู [การติดตั้งบน Linux
](linux/linux-installation.md).
* **กล้อง LATTICE OCN
อ่านค่าได้แม่นยำยิ่งขึ้นในแสงแดด** ค่าความส่องสว่าง (Radiance), ค่าการสะท้อน (reflectance) และค่าดัชนี (indices) ได้รับการปรับแก้แบบกลุ่มหลังการแยกแบนด์ (band unmix) ทำให้เป้าหมายสีเทาอ่านค่าได้ใกล้เคียงกับค่า NDVI
ที่เป็นกลางในแสงแดด กล้อง RGN
ยังคงไม่เปลี่ยนแปลง
* **รายงานข้อผิดพลาดในแอป** ไอคอนข้อผิดพลาดที่ด้านบนของแท็บ Debug Log จะส่งคำอธิบาย ภาพสูงสุด 10 ภาพ บันทึก และรายละเอียดระบบไปยัง MAPIR
ดู [GUI : Navigation](navigation.md).
* **อาร์เรย์ LATTICE**อาร์เรย์จะเก็บข้อมูลเซ็นเซอร์เต็มรูปแบบตามค่าเริ่มต้น และการส่งข้อมูลแบบแพ็ก 12 บิต (`--packed`, ค่าเริ่มต้น `auto`) จะเพิ่มความเร็วเฟรมของเซ็นเซอร์เต็มรูปแบบขึ้นประมาณหนึ่งในสาม; อาร์เรย์ทำงานได้บนเครือข่ายใดก็ตามด้วยความเร็วเฟรมที่เครือข่ายนั้นรองรับ (การเชื่อมต่อที่ช้าจะลดความเร็วเฟรมแทนที่จะปฏิเสธอาร์เรย์หรือลดขนาดเฟรม); อาร์เรย์ที่กล้องเกิดการรีสตาร์ทจะฟื้นตัวได้เองเมื่อ PTP กลับมาทำงาน; การปรับแสงอัตโนมัติไม่ลดความเร็วเฟรมในสภาพแสงน้อยอีกต่อไป (ระบบจะเติมช่วงเวลาให้เต็มก่อนแล้วจึงเพิ่มเกน); การถ่ายภาพต่อเนื่องสามารถตามทันกับอาร์เรย์ความเร็วสูง; การควบคุม**Highlights** สำหรับกล้องRGB
; และ `ArraySession` ของSDK
ได้เพิ่ม `grab()`, `frame_stream()` และ `continuous()` ดู [ส่วน LATTICE](lattice/README.md)
* **การปรับแสงอัตโนมัติที่เสถียรยิ่งขึ้น** การปรับแสงจะคงที่เมื่อแสงคงที่ และปรับตัวให้เหมาะสมภายในไม่กี่วินาทีหลังมีการเปลี่ยนแปลง จุดสว่างเล็กๆ จะไม่ทำให้ภาพโดยรวมมืดลงอีกต่อไป การปรับแสงแบบแมนนวลจะคงค่าเกนไว้ที่โหมดอัตโนมัติ และกล้องที่หยุดตอบสนองในแสงแดดจ้าจะคงระดับการปรับแสงตามแสงที่รับได้ ซึ่งวัดโดยเซ็นเซอร์แสง หรือหากไม่มีการเชื่อมต่อเซ็นเซอร์แสง จะวัดจากเฟรมของกล้องเอง ดู [การตั้งค่ากล้อง](lattice/camera-settings.md).
* **เซ็นเซอร์แสง** **การสนับสนุน DAQ-E-S:** ดิฟฟิวเซอร์แบบคงที่ของมันไม่รับการปรับค่าแคป และแต่ละค่าที่อ่านได้จะรวมข้อมูลการเอียง (tilt), การหมุน (roll) และการก้ม (pitch) ของอุปกรณ์ ไฟล์บันทึกจะระบุว่าการเลือกฝาครอบเป็นแบบกำหนดเองหรือแบบสมมติ และระบบประมวลผลจะแจ้งเตือนเมื่อใช้แบบสมมติ: DAQ-U, DAQ-M และ DAQ-E ส่งมาโดยไม่มีฝาครอบ ดังนั้นโปรดระบุชื่อฝาครอบที่ติดตั้งไว้ การบันทึกแบบเรียลไทม์ของ `.daq` จะยังคงอยู่แม้เกิดการตัดไฟ (เก็บไฟล์ `.daq-journal` ไว้พร้อมกับ `.daq`), และ DAQ-E ที่หยุดส่งข้อมูลจะถูกเชื่อมต่อใหม่โดยช่องว่างจะถูกทำเครื่องหมายในบันทึกของมัน โครงการที่เก็บเฉพาะการบันทึกจากเซ็นเซอร์แสงจะแสดงรายการและประมวลผลข้อมูลจากแอปและCLI
และการบันทึกที่สร้างด้วย `chloros_scripts` จะถูกแสดงเป็น DAQ ที่สร้างการบันทึกนั้น พร้อมด้วยขีดจำกัดที่คุณสามารถตั้งค่าได้ ทุกการบันทึกจะเก็บค่าการอ่านของ DAQ ที่ใช้ในการบันทึกนั้น ดู [ส่วน DAQ](daq/README.md)
* **การประมวลผล**เฟรม LATTICE เริ่มการประมวลผลระหว่างการตรวจจับเป้าหมาย การอ้างอิงเป้าหมายและ DAQ ถูกกำหนดตามแต่ละแบนด์ โครงการที่เคลื่อนย้ายจะเชื่อมโยงไฟล์ใหม่ การส่งออกจากการจับภาพ 8 บิตจะเป็น 8 บิต ด้วยรูปแบบ**TIFF
(8 บิต)** ใหม่ การรันSurvey3
ที่ไม่มีเป้าหมายการปรับเทียบจะถูกจัดเก็บเป็นผลิตภัณฑ์สำรอง (`Vignette_Corrected_Images` หรือ `Sensor_Response_Images`) ไม่ใช่เป็นภาพสะท้อน แท็ก DLS ต่อแถบความถี่ของภาพสะท้อนจะเป็นของเฟรมนั้นเองเสมอ Texture Aware ถูกปฏิเสธสำหรับการจับภาพ LATTICE ซึ่งจะใช้การ debayer มาตรฐานเสมอ
* **CLI
&amp; SDK
** เส้นทางออกสัมพัทธ์จะอยู่ในโฟลเดอร์ที่คุณเรียกใช้คำสั่งหรือสคริปต์ (แบ็กเอนด์ที่ติดตั้งไว้เคยพยายามแก้ไขเส้นทางในโฟลเดอร์ติดตั้งของตัวเองและล้มเหลว) แบ็กเอนด์จะทำงานต่อเนื่องระหว่างคำสั่งและสคริปต์ และจะหยุดทำงานเองหลังจากไม่ถูกใช้งานเป็นเวลา 30 นาที; `chloros-cli backend status` และ `backend stop` เป็นผู้จัดการกระบวนการนี้ คำสั่ง Capture จะระบุชื่อทุกไฟล์ที่เขียนไม่ได้และออกด้วยรหัส 1 และการจับภาพที่ซ้ำกันจะหยุดลงเมื่อพื้นที่เก็บข้อมูลเต็ม การเรียกใช้ `process` ที่สำเร็จจะรายงาน `Image products written: N (plus M clamp masks)` บนระบบWindows
`ChlorosLocal` / `process_folder` ของ SDK จะค้นหา backend ที่ติดตั้งไว้ (และใช้ backend ที่กำลังทำงานอยู่) ส่วน `read_image_audit_tags` จะทำงานจาก `pip install` แบบธรรมดา

## สิ่งใหม่ในChloros
1.2.0

* **การควบคุมกล้องแบบเรียลไทม์ — แท็บ Cameras ใหม่** เชื่อมต่อกล้อง LATTICE ได้ทั้งแบบทีละตัวหรือเป็นกลุ่มกล้องหลายตัวที่ทำงานพร้อมกัน (การซิงค์เวลา PTP, การจับภาพที่ทริกเกอร์ด้วยฮาร์ดแวร์), พร้อมด้วยภาพพรีวิวสดแบบโอเวอร์เลย์, ฮิสโตแกรมตามแต่ละแบนด์, การปรับแสงอัตโนมัติแบบอัจฉริยะ, เครื่องคำนวณดัชนีแบบสด และการอัปเดตเฟิร์มแวร์กล้องภายในแอป
* **เซ็นเซอร์แสง — แท็บ Light Sensors ใหม่** เชื่อมต่อเซ็นเซอร์ DAQ-U (USB), DAQ-M (Bluetooth) และ DAQ-E (Ethernet); ดูสเปกตรัมที่ปรับเทียบแบบเรียลไทม์ (W/m²/nm), บันทึกไฟล์ `.daq` ลงในโครงการของคุณ, เลือกโปรไฟล์การปรับแก้ cap, และอัปเดตเฟิร์มแวร์ DAQ-E ผ่านเครือข่าย
* **โหมดการจับภาพและเครื่องบันทึก** โหมดการจับภาพแบบเดี่ยว / ต่อเนื่อง / ตามช่วงเวลา พร้อมโหมดการจับภาพเร็วที่สุด (Fastest Capture) ที่บันทึกเฉพาะข้อมูลดิบ; การเลือกกล้องและประเภทการส่งออกที่ &quot;Capture All&quot; จะสร้างขึ้นตามแต่ละโครงการ; เครื่องบันทึกแบบอาร์เรย์สำหรับวิดีโอแบบดัชนีระดับการเฝ้าติดตาม และชุดข้อมูลดิบแบบ Burst ระดับการวิเคราะห์ พร้อมการสร้างวิดีโอแบบออฟไลน์
* **ท่อประมวลผล LATTICE** นำเข้าโฟลเดอร์การจับภาพ LATTICE และแยกแต่ละเฟรมดิบออกเป็นผลิตภัณฑ์ที่ผ่านการถอดเบย์เออร์ (debayered), ภาพตัวอย่าง (preview), ค่าความส่องสว่างแบบ float32 (W/m²/sr/nm), และค่าการสะท้อน พร้อมตัวเลือกเปิด/ปิดสำหรับแต่ละผลิตภัณฑ์ ค่าการสะท้อนสามารถมาจากเป้าหมายการปรับเทียบในเฟรมหรือสัญญาณ DAQ ที่ส่งลง; การจัดแนวอาร์เรย์จะถูกนำไปใช้กับไฟล์ที่ส่งออก; การปรับเทียบจากโรงงานที่ขาดหายไปจะถูกดาวน์โหลดอัตโนมัติตามหมายเลขซีเรียลของกล้อง
* **โครงการจะจดจำอุปกรณ์ฮาร์ดแวร์** กล้องและเซ็นเซอร์แสงที่เชื่อมต่อจะถูกบันทึกไว้กับโครงการ (`cameras.json` / `sensors.json`) และจะเชื่อมต่อใหม่ด้วยตั้งค่าที่บันทึกไว้เมื่อคุณเปิดโครงการอีกครั้ง ดู [GUI : โครงการ](projects.md).
* **การอัปเกรดโปรแกรมดูภาพ** การอ่านค่าพิกเซล/ดัชนีของเคอร์เซอร์พร้อมการปรับสเกลการสะท้อนแสงที่ถูกต้องตามไฟล์แต่ละไฟล์, ฮิสโตแกรมของชั้น, สไลเดอร์การรวม GSD, โหมดกริด Per Trigger / Per Camera, มุมมองผลิตภัณฑ์ LATTICE, และการส่งออกดัชนี/LUT จากแซนด์บ็อกซ์ไปยังดิสก์
* **CLI
&amp; SDK
, ขยายอย่างมาก.** กลุ่มคำสั่งใหม่ `lattice`, `daq pool-*`, `project` และ `time-sync`; ตัวเลือก `process` ใหม่ (`--input-level`, สวิตช์สำหรับแต่ละผลิตภัณฑ์, `--reflectance-source`, ธงการจัดแนวอาร์เรย์); ตัวจัดการ smart-connect ของ SDK
(`connect_camera` / `connect_array` / `connect_daq_sensor`) ที่เริ่มต้นระบบหลัง (backend) โดยอัตโนมัติ; `open_project()` การทำงานอัตโนมัติ; SDK
wheel ถูกบรรจุรวมกับตัวติดตั้งและเผยแพร่ไปยัง PyPI ในชื่อ `chloros-sdk`.
* **เซมานติกส์ความล้มเหลวที่ตรงไปตรงมา** การรัน `chloros-cli process` ที่ขอผลิตภัณฑ์แต่ไม่เขียนอะไรเลย จะล้มเหลวอย่างชัดเจนและออกค่าไม่เท่ากับศูนย์; การรันที่สำเร็จจะรายงานจำนวนผลิตภัณฑ์ภาพที่เขียนได้
* **รูปแบบผลลัพธ์ใหม่** ผลิตภัณฑ์จะถูกจัดเก็บในโฟลเดอร์ `<project>/<camera>/<format>/<Product>_Images/` และรักษาชื่อไฟล์ต้นฉบับไว้ — โฟลเดอร์ (ไม่ใช่ส่วนต่อท้ายชื่อไฟล์) เป็นตัวระบุผลิตภัณฑ์ ดู [รูปแบบภาพผลลัพธ์](output-image-formats.md).
* **ข้อมูลนำเข้า แผน และภาษาเพิ่มเติม** รองรับข้อมูลนำเข้า `.dng`; ภาษาอินเทอร์เฟซทั้ง 38 ภาษาได้รับการจัดเตรียมครบถ้วน; ข้อจำกัดฮาร์ดแวร์ตามแผน พร้อมการใช้งานฟรี (ไม่ต้องเข้าสู่ระบบ) ได้สูงสุด 4 กล้องและ 2 เซนเซอร์แสง
* **ความน่าเชื่อถือ** การหยุดการประมวลผล (Stop Processing) จะหยุดอย่างสมบูรณ์พร้อมสรุปการทำงานที่ชัดเจน โครงการที่มีหลายกล้องจะส่งออกข้อมูลจากทุกกล้อง และโปรแกรมติดตั้ง (installer) เมื่ออัปเกรดจะไม่ทำให้คุณถูกออกจากระบบอีกต่อไป***
