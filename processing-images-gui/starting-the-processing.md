# เริ่มการประมวลผล

หลังจากที่คุณได้นำเข้าภาพ กำหนดจุดอ้างอิงสำหรับการปรับเทียบ และตั้งค่าโครงการแล้ว คุณก็พร้อมที่จะเริ่มการประมวลผลแล้ว หน้านี้จะนำคุณผ่านขั้นตอนการเริ่มต้นกระบวนการประมวลผลChloros

## รายการตรวจสอบก่อนการประมวลผล

ก่อนที่จะคลิกปุ่ม Start ให้ตรวจสอบให้แน่ใจว่าทุกอย่างพร้อมแล้ว:

* [ ] **ไฟล์ถูกนำเข้า** - ภาพทั้งหมดปรากฏใน File Browser
* [ ] **ภาพเป้าหมายถูกทำเครื่องหมาย** - คอลัมน์ Target ถูกทำเครื่องหมายสำหรับภาพการปรับเทียบ (หรือไฟล์บันทึก `.daq` ที่นำเข้าสำหรับ LATTICE)
* [ ] **ตรวจพบรุ่นกล้อง** - คอลัมน์ &quot;รุ่นกล้อง&quot; แสดงรุ่นกล้องที่ถูกต้อง
* [ ] **ตั้งค่าเรียบร้อย** - ตรวจสอบและปรับตั้งค่าโครงการแล้ว
* [ ] **เลือกดัชนี** - เพิ่มดัชนีมัลติสเปกตรัมที่ต้องการ (หากจำเป็น)
* [ ] **เลือกรูปแบบการส่งออก** - รูปแบบผลลัพธ์ที่เหมาะสมกับขั้นตอนการทำงานของคุณ

{% hint style="info" %}
**เคล็ดลับ**: คลิกผ่านภาพบางภาพใน File Browser เพื่อตรวจสอบว่าภาพถูกโหลดอย่างถูกต้องก่อนการประมวลผล
{% endhint %}

***

## เริ่มการประมวลผล

### ค้นหาปุ่ม Start

ปุ่ม Start/Play ตั้งอยู่ในแถบหัวเรื่องด้านบนของ Chloros:

* ตำแหน่ง: ตรงกลางด้านบนของหน้าต่าง
* ไอคอน: **ปุ่ม Play/Start** <img src="../.gitbook/assets/image (2) (1) (1).png" alt="" data-size="line">
* สถานะ: ปุ่มจะเปิดใช้งาน (สว่าง) เมื่อพร้อมที่จะประมวลผล

### คลิกเพื่อเริ่ม

1. คลิก **ปุ่ม Play/Start** ในแถบหัวเรื่องด้านบน
2. การประมวลผลจะเริ่มทันที
3. ปุ่มจะเปลี่ยนเป็น **ปุ่ม Stop** ระหว่างการประมวลผล
4. แถบความคืบหน้าจะอัปเดต แสดงสถานะการประมวลผล

{% hint style="success" %}
**การประมวลผลเริ่มแล้ว**: เมื่อคลิกแล้ว Chloros จะจัดการขั้นตอนการประมวลผลทั้งหมดโดยอัตโนมัติ - การตรวจจับเป้าหมาย การลบเดย์เออร์ การปรับเทียบ การคำนวณดัชนี และการส่งออก มันจะตรวจจับอัตโนมัติว่าโครงการของคุณเป็น Survey3 LATTICE หรือการผสมผสาน และใช้ขั้นตอนการประมวลผลที่เหมาะสมกับกล้องแต่ละตัว
{% endhint %}

## การเข้าใจโหมดการประมวลผล

Chloros ทำงานในสองโหมดการประมวลผลที่แตกต่างกัน ขึ้นอยู่กับใบอนุญาตของคุณ:

### โหมดฟรี (การประมวลผลแบบลำดับ)

**ใช้ได้สำหรับผู้ใช้ทุกคน**

**วิธีการทำงาน:**

* ประมวลผลภาพทีละภาพ ตามลำดับ
* การทำงานแบบเธรดเดียว
* การใช้หน่วยความจำน้อย

**แถบความคืบหน้าแสดง 2 ขั้นตอน:**

1.**การตรวจจับเป้าหมาย** - สแกนหาเป้าหมายการปรับเทียบ
2. **การประมวลผล** - ปรับเทียบและส่งออกภาพ**เวลาการประมวลผล:**

* ช้ากว่ามากเมื่อเทียบกับโหมดขนานของChloros+
* เหมาะสำหรับชุดข้อมูลขนาดเล็กถึงกลาง (&lt; 200 ภาพ)

### โหมด Chloros+ (การประมวลผลแบบขนาน)

**ต้องใช้ใบอนุญาต Chloros+**

**วิธีการทำงาน:**

* ประมวลผลภาพหลายภาพพร้อมกันโดยใช้ [ท่อประมวลผล 4 เธรด](../processing-architecture/processing-pipeline.md)
* [การปรับการคำนวณแบบไดนามิก](../processing-architecture/dynamic-compute-adaptation.md) จะเลือกกลยุทธ์ที่เหมาะสมที่สุดสำหรับฮาร์ดแวร์ของคุณโดยอัตโนมัติเมื่อเริ่มการทำงาน
* การเร่งความเร็วด้วย GPU (CUDA) สำหรับการ์ดกราฟิก NVIDIA
* **จำนวนเวิร์กเกอร์ปรับตามฮาร์ดแวร์**: กลยุทธ์ GPU จะรัน**2-4 เวิร์กเกอร์พร้อมกัน** (ปรับตาม VRAM — 3 เวิร์กเกอร์บน GPU 2-12GB, 2 ถึง 4 เวิร์กเกอร์บน GPU 12GB ขึ้นไป); ระบบที่ใช้ CPU เท่านั้นจะทำงานด้วย worker หนึ่งตัวต่อคอร์ทางกายภาพ ลบหนึ่ง**แถบความคืบหน้าแสดง 4 ขั้นตอน** (สอดคล้องกับ 4 เธรดใน pipeline):

1. **การตรวจจับ** (Thread 1) - ค้นหาเป้าหมายการปรับเทียบ
2. **วิเคราะห์** (Thread 2) - ตรวจสอบข้อมูลเมตาดาต้าของภาพและคำนวณการปรับเทียบ
3. **ปรับเทียบ** (Thread 3) - การแยกพิกเซล (Debayering), การแก้ไขวิเนตต์, การปรับเทียบ, การคำนวณดัชนี
4. **ส่งออก** (Thread 4) - การบันทึกภาพที่ประมวลผลแล้วและดัชนี**การโต้ตอบกับแถบความคืบหน้า:*** **นำเมาส์ไปวาง** เหนือแถบเพื่อดูแผงดรอปดาวน์รายละเอียด 4 ขั้นตอน
* **คลิก** แถบความคืบหน้าเพื่อตรึงแผงดรอปดาวน์ไว้ที่ตำแหน่งนั้น
* **คลิกอีกครั้ง** เพื่อปลดตรึงและซ่อนแผง**เวลาการประมวลผล:**

* เร็วกว่าโหมดฟรีอย่างเห็นได้ชัด
* การเร่งความเร็วด้วย GPU ช่วยเพิ่มความเร็วได้อีก

{% hint style="info" %}
**ความเร็ว Chloros+**: การประมวลผลแบบขนานสามารถเร็วกว่าโหมดลำดับถึง 5-10 เท่าสำหรับชุดข้อมูลขนาดใหญ่ โครงการที่มีภาพ 500 ภาพ ซึ่งใช้เวลากว่า 2 ชั่วโมงในโหมดฟรี อาจเสร็จสิ้นภายใน 15-20 นาทีด้วย Chloros+
{% endhint %}

## สิ่งที่เกิดขึ้นระหว่างการประมวลผล

### ขั้นตอนที่ 1: การตรวจจับเป้าหมาย

**Chloros ทำอะไร:**

* สแกนภาพที่คุณได้ทำเครื่องหมายในคอลัมน์ Target (หากไม่มีการทำเครื่องหมาย จะสแกนภาพทั้งหมด)
* ระบุแผงการปรับเทียบในแต่ละเป้าหมาย
* สกัดค่าการสะท้อนแสงจากแผงเป้าหมาย
* บันทึกเวลาของเป้าหมายเพื่อจัดตารางการปรับเทียบ

**ระยะเวลา:** 1-30 วินาที (เมื่อมีเป้าหมายที่ถูกทำเครื่องหมาย), 5-30+ นาที (เมื่อไม่มีเครื่องหมาย)

### ขั้นตอนที่ 2: การแยกเบย์เออร์ (การแปลง RAW)

**Chloros ทำอะไร:**

* แปลงข้อมูลแบบ Bayer RAW เป็นภาพ 3 ช่องสัญญาณเต็ม (โมดูล LATTICE mono ยังคงเป็นช่องสัญญาณเดียว — การแยก Bayer จะถูกข้ามไปสำหรับโมดูลเหล่านี้ พร้อมบันทึกหมายเหตุในล็อก)
* ใช้ขั้นตอนการแยก Bayer ที่เลือก
* รักษาคุณภาพภาพและรายละเอียดสูงสุด

**ระยะเวลา:** ขึ้นอยู่กับจำนวนภาพและความเร็วของ CPU/GPU

### ขั้นตอนที่ 3: การปรับเทียบ

**Chloros ทำอะไร:*** **การแก้ไข vignette**: ลบความมืดของเลนส์ที่ขอบภาพ
* **การปรับเทียบการสะท้อน**: ปรับให้เป็นมาตรฐานโดยใช้ค่าการสะท้อนเป้าหมายและ/หรือข้อมูลแสงลงจาก DAQ
* ใช้การปรับแก้กับทุกแถบ/ช่อง
* ใช้ข้อมูลอ้างอิงการปรับเทียบที่เหมาะสมสำหรับภาพแต่ละภาพตามเวลาที่บันทึก

**ระยะเวลา:** ส่วนใหญ่ของเวลาการประมวลผล

### ขั้นตอนที่ 4: การคำนวณดัชนี

**Chloros ทำอะไร:**

* คำนวณดัชนีมัลติสเปกตรัมที่ตั้งค่าไว้ (NDVI, NDRE, เป็นต้น)
* นำการคำนวณทางคณิตศาสตร์ของแถบมาประยุกต์ใช้กับภาพที่ปรับเทียบแล้ว
* สร้างภาพดัชนีสำหรับแต่ละดัชนีที่เลือก

**ระยะเวลา:** ไม่กี่วินาทีต่อภาพ

### ขั้นตอนที่ 5: ส่งออก

**Chloros ทำอะไร:**

* บันทึกภาพที่ผ่านการประมวลผลในรูปแบบที่เลือก
* **LATTICE fan-out**: แต่ละเฟรม LATTICE ดิบจะถูกส่งออกเป็นผลิตภัณฑ์ที่เปิดใช้งานทั้งหมดในครั้งเดียว — debayered, preview, radiance (เสมอ float32), reflectance
* เขียนไฟล์ลงในโครงสร้างโฟลเดอร์ผลลัพธ์ของโครงการ: `<project>/<camera>/<format>/<Product>_Images/`
* **รักษาชื่อไฟล์ต้นฉบับ** — โฟลเดอร์ระบุผลิตภัณฑ์ ไม่มีการเพิ่มส่วนท้าย**ระยะเวลา:** ขึ้นอยู่กับรูปแบบการส่งออกและขนาดไฟล์***

## พฤติกรรมการประมวลผล

### สายการประมวลผลอัตโนมัติ

เมื่อเริ่มทำงานแล้ว สายการประมวลผลทั้งหมดจะทำงานอัตโนมัติ:

* ไม่จำเป็นต้องมีการโต้ตอบจากผู้ใช้
* ทุกขั้นตอนที่ตั้งค่าไว้จะทำงานตามลำดับ
* แสดงความคืบหน้าแบบเรียลไทม์
* ไฟล์ที่ส่งออกจะถูกเขียนลงดิสก์ทันทีที่เสร็จสิ้น — คุณสามารถเปิดผลลัพธ์ที่เสร็จแล้วได้ขณะที่การประมวลผลยังคงดำเนินอยู่

### การใช้ทรัพยากรคอมพิวเตอร์ระหว่างการประมวลผล

**โหมดฟรี:**

* การใช้ CPU ต่ำพอสมควร (แบบ single-threaded)
* คอมพิวเตอร์ยังคงตอบสนองได้สำหรับงานอื่น ๆ
* สามารถลด Chloros ลงได้และทำงานในแอปพลิเคชันอื่น ๆ ได้อย่างปลอดภัย

**โหมด Chloros+ Parallel:**

* การใช้ CPU สูงในทั้งกลุ่ม worker ของกลยุทธ์
* เมื่อใช้การเร่งความเร็วด้วย GPU: การใช้ GPU สูง
* คอมพิวเตอร์อาจตอบสนองได้ช้าลงระหว่างการประมวลผล
* หลีกเลี่ยงการเริ่มงานอื่นที่ใช้ CPU มาก

{% hint style="warning" %}
**เคล็ดลับประสิทธิภาพ**: เพื่อประสิทธิภาพ Chloros+ ที่ดีที่สุด ให้ปิดแอปพลิเคชันอื่น ๆ และให้ Chloros ใช้ทรัพยากรระบบอย่างเต็มที่
{% endhint %}

### ไม่สามารถหยุดการประมวลผลได้ (แต่การหยุดทำงานจะเสร็จสิ้นอย่างสมบูรณ์)

* เมื่อเริ่มการประมวลผลแล้ว ไม่สามารถหยุดชั่วคราวและกลับมาดำเนินการต่อได้
* การคลิก **Stop** จะหยุดการประมวลผลอย่างสมบูรณ์ตั้งแต่คลิกครั้งแรก
* ผลลัพธ์ที่ส่งออกมาก่อนการหยุดจะยังคงอยู่บนดิสก์
* การประมวลผลที่หยุดลงจะรายงานอย่างตรงไปตรงมาว่าได้เสร็จสิ้นส่วนใด (ดูบรรทัด `[RUN-SUMMARY]` ในไฟล์บันทึก)
* การรันใหม่จะเริ่มกระบวนการตั้งแต่ต้น

**เคล็ดลับการวางแผน:** สำหรับโครงการที่มีขนาดใหญ่มาก ให้พิจารณาการประมวลผลแบบเป็นชุด หรือใช้ CLI เพื่อควบคุมได้ดีขึ้น***

## การติดตามการประมวลผล

ระหว่างการประมวลผล คุณสามารถ:

* **ดูแถบความคืบหน้า** - ดูเปอร์เซ็นต์การเสร็จสิ้นโดยรวม
* **ดูขั้นตอนปัจจุบัน** - การตรวจจับ, การวิเคราะห์, การปรับเทียบ, หรือการส่งออก
* **ตรวจสอบแท็บบันทึก** - ดูข้อความและคำเตือนการประมวลผลอย่างละเอียด
* **ดูตัวอย่างภาพที่เสร็จสิ้น** - ไฟล์ที่ส่งออกจะปรากฏบนดิสก์ระหว่างการประมวลผล

สำหรับข้อมูลรายละเอียดเกี่ยวกับการติดตามผล โปรดดู [การติดตามผลกระบวนการประมวลผล](monitoring-the-processing.md).

## การหยุดกระบวนการประมวลผล

หากต้องการหยุดกระบวนการประมวลผล:

### วิธีหยุด

1. ค้นหา **ปุ่มหยุด** (แทนที่ปุ่ม Start ระหว่างการประมวลผล)
2. คลิกหนึ่งครั้ง — แถบจะแสดง **&quot;Stopping...&quot;** จนกว่าภาพที่กำลังประมวลผลอยู่จะเสร็จสิ้น
3. การประมวลผลจะสิ้นสุดในสถานะหยุดอย่างสมบูรณ์ และบันทึกจะแสดงผล `[RUN-SUMMARY]` ที่ชัดเจนเกี่ยวกับสิ่งที่ได้เสร็จสิ้น

### เมื่อใดควรหยุด

**เหตุผลที่สมควรหยุด:**

* พบว่าใช้การตั้งค่าผิด
* ลืมทำเครื่องหมายภาพเป้าหมาย
* นำเข้าภาพผิด
* ระบบทำงานช้าเกินไปหรือไม่ตอบสนอง

**หลังจากหยุด:**

* ผลิตภัณฑ์ที่ส่งออกก่อนการหยุดจะยังคงอยู่บนดิสก์
* ตรวจสอบและแก้ไขปัญหา ปรับการตั้งค่าตามความจำเป็น
* เริ่มการประมวลผลใหม่ — การประมวลผลจะเริ่มจากต้น

***

## การประมาณเวลาการประมวลผล

เวลาการประมวลผลจริงอาจแตกต่างกันอย่างมากขึ้นอยู่กับ:

* จำนวนภาพ
* ความละเอียดของภาพ
* รูปแบบข้อมูลเข้า RAW หรือ JPG
* โหมดการประมวลผล (Free vs Chloros+)
* ความเร็ว CPU และจำนวนคอร์
* ความพร้อมใช้งานของ GPU (Chloros+ เท่านั้น)
* จำนวนดัชนีที่ต้องคำนวณ
* จำนวนผลิตภัณฑ์ส่งออกที่เปิดใช้งาน (LATTICE)

### การประมาณการคร่าวๆ (Chloros+, ภาพ 12MP, CPU รุ่นใหม่)

| จำนวนภาพ | โหมดฟรี | Chloros+ (CPU) | Chloros+ (GPU) |
| ----------- | --------- | -------------- | -------------- |
| 50 ภาพ   | 15-20 นาที | 5-8 นาที        | 3-5 นาที        |
| 100 ภาพ  | 30-40 นาที | 10-15 นาที      | 5-8 นาที        |
| 200 ภาพ   | 1-1.5 ชั่วโมง | 20-30 นาที      | 10-15 นาที      |
| 500 ภาพ   | 2-3 ชั่วโมง   | 45-60 นาที      | 20-30 นาที      |
| 1000 ภาพ | 4-6 ชั่วโมง   | 1.5-2 ชั่วโมง      | 40-60 นาที      |

{% hint style="info" %}
**การรันครั้งแรก**: การประมวลผลครั้งแรกอาจใช้เวลานานขึ้น เนื่องจาก Chloros กำลังสร้างแคชและโปรไฟล์ การประมวลผลชุดข้อมูลที่คล้ายกันในครั้งต่อไปจะเร็วขึ้น
{% endhint %}

## ปัญหาทั่วไปเมื่อเริ่มต้น

### ปุ่มเริ่มต้นถูกปิดใช้งาน (สีเทา)

**สาเหตุที่อาจเกิดขึ้น:**

* ยังไม่มีการนำเข้าภาพ
* ระบบหลังบ้านยังไม่เริ่มต้นอย่างสมบูรณ์
* การประมวลผลครั้งก่อนยังทำงานอยู่
* โครงการยังไม่โหลดเสร็จสมบูรณ์

**วิธีแก้ไข:**

1. รอให้ระบบหลังบ้านเริ่มต้นอย่างสมบูรณ์ (ตรวจสอบไอคอนเมนูหลัก)
2. ตรวจสอบว่าภาพได้ถูกนำเข้าใน File Browser แล้ว
3. เริ่มต้น Chloros ใหม่หากปุ่มยังคงถูกปิดใช้งาน
4. ตรวจสอบ Debug Log เพื่อหาข้อความข้อผิดพลาด

### การประมวลผลเริ่มแล้วล้มเหลวทันที

**สาเหตุที่อาจเกิดขึ้น:**

* ไม่มีภาพที่ถูกต้องในโครงการ
* ไฟล์ภาพถูกเสียหาย
* พื้นที่ดิสก์ไม่เพียงพอ
* หน่วยความจำ (RAM) ไม่เพียงพอ

**วิธีแก้ไข:**

1. ตรวจสอบ Debug Log <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line"> เพื่อหาข้อความข้อผิดพลาด
2. ตรวจสอบพื้นที่ดิสก์ที่ว่าง
3. ลองประมวลผลชุดภาพที่มีขนาดเล็กกว่า
4. ตรวจสอบว่าภาพไม่เสียหาย

### การประมวลผลเสร็จสิ้นแต่ไม่เขียนภาพใด

การประมวลผลที่ขอผลิตภัณฑ์ภาพแต่ไม่เขียนภาพใดเลย จะถูกพิจารณาเป็น **ความล้มเหลว ไม่ใช่ความสำเร็จ** — Chloros จะแจ้งเตือนอย่างชัดเจน:

* บันทึกใน GUI จะแสดงข้อความ `[RUN-SUMMARY]` ที่ชี้ให้เห็นสาเหตุที่เป็นไปได้ — ไม่มีการนำเข้าภาพ ไม่พบเป้าหมาย หรือผลิตภัณฑ์ที่ขอทั้งหมดถูกข้ามไปเนื่องจากไม่เหมาะสม (เช่น การขอค่า radiance/reflectance จากกล้องที่มีเพียงRGB เท่านั้น)
* ส่วนที่เทียบเท่าในCLI (`chloros-cli process`) จะแสดงข้อความ `Processing finished but wrote no image products.` และ **ออกด้วยค่าที่ไม่ใช่ศูนย์** ทำให้สคริปต์สามารถตรวจจับได้
* การรันที่ตั้งใจให้ใช้เฉพาะเมตาดาต้า (ปิดการใช้งานผลิตภัณฑ์ส่งออกทั้งหมด และไม่มีดัชนี) ยังคงนับเป็นความสำเร็จ

ดู [คู่มืออ้างอิง CLI](../reference/cli-reference.md#a-run-that-writes-no-images-fails) เพื่อดูความหมายอย่างครบถ้วน

### โฟลเดอร์โครงการลึกเกินไปสำหรับคอมพิวเตอร์นี้

**เฉพาะ Windows, ใหม่ในเวอร์ชัน 1.3.0.**Windows มาพร้อมกับตัวเลือกเส้นทางยาวที่ถูกปิดไว้ และเส้นทางไฟล์ใด ๆ ก็ไม่สามารถยาวเกิน 260 ตัวอักษรได้ ผลิตภัณฑ์ของ Chloros จะถูกจัดเก็บอยู่ใต้โฟลเดอร์โครงการประมาณ 130 ตัวอักษร ดังนั้น โฟลเดอร์โครงการที่ลึกกว่านั้นจะไม่สามารถรับผลิตภัณฑ์ได้ แทนที่จะทำงานแล้วไม่เขียนข้อมูลใด ๆ Chloros จะตรวจสอบก่อนเริ่มการประมวลผล:

* การคลิก Start จะไม่เริ่มการประมวลผล: แถบความคืบหน้าจะแสดงเหตุผล และ Debug Log จะแสดง `[PROCESS] refused: The project folder is too deep for this computer…` ข้อความนี้จะระบุความยาวของโฟลเดอร์โครงการและโฟลเดอร์โครงการที่ยาวที่สุดที่ยังเหมาะสม
* การสร้างหรือเปิดโครงการในโฟลเดอร์ที่ลึกเกินไป แม้แต่สำหรับไฟล์ของโครงการเอง ก็จะถูกปฏิเสธเช่นกัน กล่องข้อความจะแสดงเหตุผล พร้อมทั้งชื่อโฟลเดอร์โครงการที่ยาวที่สุดที่ยังเหมาะสม และวิธีเปิดใช้งานเส้นทางที่ยาว; ไม่มีไฟล์ใดถูกสร้างหรือเปิด; Debug Log บันทึกเหตุการณ์นี้ด้วยรหัส `[PROJECT] refused: …` การคัดลอกโครงการภายใต้ชื่อที่ยาวขึ้นอาจทำให้เกินขีดจำกัดได้เช่นกัน: การคัดลอกจะสำเร็จแต่ไม่เปิดโครงการ และข้อความเดียวกันจะอธิบายเหตุผล

**วิธีแก้ไข:**

1. เก็บโครงการไว้ในโฟลเดอร์ที่มีชื่อสั้นกว่า — เปลี่ยน**Working Directory** ใน [Project Settings](../project-settings/project-settings.md) แล้วสร้างโครงการใหม่ หรือ
2. เปิดใช้งานเส้นทางยาวของWindows และรีสตาร์ทChloros: ติดตั้งChloros ใหม่โดยทำเครื่องหมายที่ **Enable Windows long paths** (ถูกทำเครื่องหมายไว้โดยค่าเริ่มต้น) หรือใช้ Group Policy: *Computer Configuration &gt; Administrative Templates &gt; System &gt; Filesystem &gt; Enable Win32 long paths*.

### คำเตือน &quot;ไม่พบเป้าหมาย&quot;

**สาเหตุที่อาจเกิดขึ้น:**

* ลืมทำเครื่องหมายภาพเป้าหมาย
* ภาพเป้าหมายไม่ประกอบด้วยเป้าหมายที่มองเห็นได้
* การตั้งค่าการตรวจจับเป้าหมายเข้มงวดเกินไป

**วิธีแก้ไข:**

1. ตรวจสอบ [การเลือกภาพเป้าหมาย](choosing-target-images.md)
2. ทำเครื่องหมายภาพที่เหมาะสมในคอลัมน์ Target
3. ตรวจสอบว่าเป้าหมายปรากฏอยู่ในภาพที่ทำเครื่องหมายแล้ว
4. ปรับการตั้งค่าการตรวจจับเป้าหมายหากจำเป็น

## เคล็ดลับเพื่อให้การประมวลผลสำเร็จ

### ก่อนเริ่ม

1. **ทดสอบกับชุดข้อมูลขนาดเล็กก่อน** - ประมวลผลภาพ 10-20 ภาพเพื่อตรวจสอบการตั้งค่า
2. **ตรวจสอบพื้นที่ว่างบนดิสก์** - ตรวจสอบให้แน่ใจว่ามีพื้นที่ว่าง 2-3 เท่าของขนาดชุดข้อมูล (มากขึ้นหากเปิดใช้งานผลิตภัณฑ์ LATTICE ทั้งหมด)
3. **ปิดแอปพลิเคชันที่ไม่จำเป็น** - เพื่อปลดปล่อยทรัพยากรระบบ
4. **ตรวจสอบภาพเป้าหมาย** - ดูตัวอย่างเป้าหมายที่เลือกไว้เพื่อตรวจสอบคุณภาพ
5. **บันทึกโครงการ** - โครงการจะบันทึกอัตโนมัติ แต่ควรบันทึกด้วยตนเองเพื่อความปลอดภัย

### ระหว่างการประมวลผล

1. **หลีกเลี่ยงการให้ระบบเข้าสู่โหมดสลีป** - ปิดโหมดประหยัดพลังงาน
2. **รักษาChloros ให้อยู่ในเบื้องหน้า** - หรืออย่างน้อยให้ปรากฏในแถบงาน
3. **ตรวจสอบความคืบหน้าเป็นระยะ** - ตรวจสอบคำเตือนหรือข้อผิดพลาด
4. **อย่าเปิดแอปพลิเคชันหนักอื่น ๆ** - โดยเฉพาะเมื่อใช้โหมดขนานของChloros+

### การเร่งความเร็วด้วย GPU ของChloros+

หากใช้การเร่งความเร็วด้วย GPU ของ NVIDIA:

1. อัปเดตไดรเวอร์ NVIDIA เป็นเวอร์ชันล่าสุด
2. ตรวจสอบให้แน่ใจว่า GPU มี VRAM 4GB ขึ้นไป (7GB ขึ้นไป สำหรับการ debayering แบบ Texture Aware ที่ทำงานพร้อมกัน)
3. ปิดแอปพลิเคชันที่ใช้ GPU หนัก (เกม, การตัดต่อวิดีโอ)
4. ตรวจสอบอุณหภูมิ GPU (ตรวจสอบให้แน่ใจว่ามีระบบระบายความร้อนที่เพียงพอ)
