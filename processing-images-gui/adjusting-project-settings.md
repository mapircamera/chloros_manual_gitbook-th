# การปรับตั้งค่าโครงการ

ก่อนที่จะประมวลผลภาพของคุณ การตั้งค่าโครงการให้สอดคล้องกับความต้องการของกระบวนการทำงานของคุณเป็นสิ่งสำคัญ แผงควบคุม Project Settings <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> ให้คุณควบคุมได้อย่างครบถ้วนเกี่ยวกับการปรับเทียบ (calibration) ตัวเลือกการประมวลผล ดัชนีมัลติสเปกตรัม และรูปแบบการส่งออก

## การเข้าถึงการตั้งค่าโครงการ

1. เปิดโครงการของคุณใน Chloros
2. คลิกไอคอน **Project Settings** <img src="../.gitbook/assets/icon_project-settings.JPG" alt="" data-size="line"> ในแถบด้านซ้าย
3. แผง Project Settings จะแสดงตัวเลือกการตั้งค่าทั้งหมด

<figure><img src="../.gitbook/assets/image (28).png" alt=""><figcaption><p>แผงการตั้งค่าโครงการ — การแสดงผล การตรวจจับเป้าหมาย และการประมวลผล</p></figcaption></figure>

{% hint style="info" %}
**การตั้งค่าจะถูกบันทึกอัตโนมัติ** พร้อมกับโครงการของคุณ เมื่อคุณเปิดโครงการอีกครั้ง การตั้งค่าทั้งหมดจะถูกกู้คืน
{% endhint %}

***

## การตั้งค่าอย่างรวดเร็วสำหรับขั้นตอนการทำงานทั่วไป

### การตั้งค่าเริ่มต้น (แนะนำสำหรับผู้ใช้ส่วนใหญ่)

การตั้งค่าเริ่มต้นทำงานได้ดีสำหรับขั้นตอนการทำงานทั่วไปของSurvey3 และ LATTICE:

* ✅ **การแก้ไขวิเนตต์**: เปิด
* ✅ **การปรับเทียบการสะท้อนแสง / สมดุลสีขาว**: เปิด (ใช้เป้าหมายMAPIR และ/หรือข้อมูลเซ็นเซอร์แสง DAQ)
* ✅ **วิธี Debayer**: มาตรฐาน (เร็ว, คุณภาพปานกลาง)
* ✅ **รูปแบบการส่งออก**: TIFF (16 บิต) (TIFF (8 บิต) สำหรับโครงการที่ใช้ 8 บิตทั้งหมด)
* ✅ **ผลิตภัณฑ์ส่งออกทั้งหมด**: เปิดใช้งาน (LATTICE จะจับภาพ fan out และแปลงเป็น debayered, preview, radiance และ reflectance โดยอัตโนมัติ)

เพียงนำเข้าภาพของคุณและเริ่มประมวลผลด้วยค่าเริ่มต้นเหล่านี้

***

## ภาพรวมการตั้งค่าโครงการ

แผงการตั้งค่าโครงการถูกจัดเป็นส่วนต่าง ๆ ดังต่อไปนี้ ส่วนเพิ่มเติมอีกสองส่วน — **เซ็นเซอร์แสง DAQ**และ**การจัดแนวอาร์เรย์** — จะปรากฏขึ้นอัตโนมัติเมื่อโครงการของคุณมีไฟล์ที่เกี่ยวข้อง สำหรับเอกสารประกอบที่ครบถ้วน โปรดดู [การตั้งค่าโครงการ](../project-settings/project-settings.md).

### การแสดงผล

* **ความละเอียดของภาพขนาดย่อ**: ความละเอียดของภาพขนาดย่อในตารางภาพ ตัวเลือก:**ค่าเริ่มต้น (512 px)**,**1024 px**,**2048 px**,**ความละเอียดเต็ม**. ใช้สำหรับการแสดงผลเท่านั้น — ไม่ส่งผลต่อการประมวลผล ค่าที่สูงขึ้นจะดูคมชัดขึ้นเมื่อซูมเข้า แต่โหลดช้าลง

### การตรวจจับเป้าหมาย

ควบคุมวิธีที่Chloros ใช้เพื่อระบุเป้าหมายการปรับเทียบในภาพของคุณ

**การตั้งค่าหลัก:*** **พื้นที่ตัวอย่างการปรับเทียบขั้นต่ำ (px)**: ค่าเกณฑ์ขนาดสำหรับการตรวจจับเป้าหมาย (ค่าเริ่มต้น:**25**, ช่วง 0–10000)
* **ค่าความคล้ายคลึงขั้นต่ำสำหรับการจัดกลุ่มเป้าหมาย (0-100)**: ค่าเกณฑ์ความคล้ายคลึงสำหรับการจัดกลุ่มพื้นที่เป้าหมาย (ค่าเริ่มต้น:**60**)**เมื่อใดควรปรับ:**

* เพิ่มพื้นที่ตัวอย่างหากเกิดการตรวจจับผิดพลาด
* ลดลงหากไม่ตรวจจับเป้าหมายได้
* ปรับค่าการกลุ่มเป้าหมายหากเป้าหมายถูกแบ่งออกเป็นหลายจุดตรวจจับ

{% hint style="info" %}
การตั้งค่าเหล่านี้จะถูกทำให้เป็นสีเทาเมื่อ **การปรับเทียบการสะท้อน / สมดุลสีขาว** ถูกปิด — เมื่อปิดการตั้งค่านี้ การตรวจจับเป้าหมายจะไม่ทำงานเลย
{% endhint %}

### การประมวลผล

ตัวเลือกหลักสำหรับการประมวลผลภาพและการปรับเทียบ

**การตั้งค่าสำคัญ:*** **การแก้ไข vignette**: ชดเชยความมืดของเลนส์ที่ขอบภาพ ✅ แนะนำ
* **การปรับเทียบการสะท้อน / สมดุลสีขาว**: ปรับเทียบภาพโดยใช้เป้าหมายที่ตรวจพบ (Survey3) และ/หรือข้อมูลจากเซ็นเซอร์แสง DAQ (LATTICE) ✅ แนะนำ
* **วิธี Debayer**: อัลกอริทึมสำหรับการแปลงไฟล์ RAW เป็นภาพมัลติสเปกตรัม 3 ช่อง
* **ช่วงเวลาการปรับเทียบใหม่ขั้นต่ำ**: เวลาขั้นต่ำเป็นวินาทีระหว่างการใช้เป้าหมายการปรับเทียบ (ค่าเริ่มต้น:**0** = ใช้ทั้งหมด, ช่วง 0–3600)**ผลิตภัณฑ์สำรองเมื่อไม่มีการปรับเทียบ:**เมื่อไม่สามารถปรับเทียบการสะท้อนแสงของเฟรมได้ (ไม่มีเป้าหมาย หรือการปรับเทียบถูกปิดใช้งาน) เฟรมนั้นจะถูกส่งออกเป็นหนึ่งในสองผลิตภัณฑ์สำรอง —**มีเพียงหนึ่งผลิตภัณฑ์จากคู่ดังกล่าวต่อการรัน** ซึ่งถูกเลือกโดยสวิตช์การแก้ไข Vignette:

* **ส่งออกการตอบสนองของเซ็นเซอร์**: เขียน `Sensor_Response_Images` — ใช้เมื่อการแก้ไข Vignette**ปิด*** **ส่งออกหลังการแก้ไข vignette**: เขียน `Vignette_Corrected_Images` — ใช้เมื่อการแก้ไข vignette**เปิด**ช่องทำเครื่องหมายที่ไม่ได้ใช้งานจะถูกทำให้เป็นสีเทา การยกเลิกการเลือกช่องที่ใช้งานอยู่จะหยุดการเขียนไฟล์นั้นโดยสิ้นเชิง**ผลิตภัณฑ์ส่งออก LATTICE** (แสดงสำหรับทุกโครงการ; ใช้กับการจับภาพ LATTICE):

* **ส่งออกแบบ debayered**: ภาพที่ผ่านกระบวนการเดเบเยอร์แบบเชิงเส้น (`Debayered_Images`): ได้ลบค่าออฟเซ็ตความมืดจากชุดการปรับเทียบแล้ว จากนั้นผ่านกระบวนการเดโมไซซิ่ง โดยไม่ใช้ไฟล์แฟลตฟิลด์หรือการแยกสี — เป็นไฟล์เดียวกันที่การจับภาพบันทึกไว้ที่ระดับเดเบเยอร์ — ในทิศทางดั้งเดิมของเซ็นเซอร์ ใช้ได้กับโมดูลRGB และมัลติสเปกตรัม
* **ส่งออกภาพตัวอย่าง**: ภาพตัวอย่างที่แสดงบนหน้าจอ (`Preview_Images`) RGB = การปรับสมดุลสีขาว (ใช้แหล่งแสง DAQ หากมี มิฉะนั้นใช้ gray-world) + แกมมา; มัลติสเปกตรัม = การขยายสีเทียม
* **ส่งออก radiance**: ความส่องผ่านสเปกตรัมแบบ float32 (`Radiance_Images`, W/m²/sr/nm). เฉพาะโมดูลมัลติสเปกตรัม — ไม่ใช้กับไฟล์RGB master
* ****ส่งออกค่าสะท้อน**: ค่าสะท้อนแบบ uint16 (`Reflectance_Calibrated_Images`, DN 32768 = ρ 1.0) เมื่อการอ่านค่าแสงลง (downwelling) ของ `.daq` หรือเป้าหมายภายในเฟรมครอบคลุมเฟรมทั้งหมด เฉพาะโมดูลมัลติสเปกตรัมเท่านั้น

ทั้งสี่ตัวเลือก **เปิดโดยค่าเริ่มต้น**— เฟรมดิบ LATTICE ที่นำเข้าหนึ่งเฟรมจะถูกกระจายไปยังทุกผลิตภัณฑ์ที่เปิดใช้งานและเหมาะสมในขั้นตอนการประมวลผลครั้งเดียว ช่องทำเครื่องหมาย**ส่งออกค่าสะท้อน** จะถูกทำให้เป็นสีเทาเมื่อการปรับเทียบค่าสะท้อนถูกปิด การตั้งค่าที่สวิตช์หลักทำให้ไม่สามารถใช้งานได้ จะถูกทำให้เป็นสีเทาเสมอ พร้อมด้วยข้อความชี้แนะที่ระบุชื่อสวิตช์ที่ต้องปรับเปลี่ยน**การตั้งค่าขั้นสูง:*** **การปรับเวลาโซนของเซ็นเซอร์แสง**: จำนวนชั่วโมงจาก UTC สำหรับการปรับเวลาของเซ็นเซอร์แสง (ค่าเริ่มต้น: 0, ช่วง −12 ถึง +12)
* **ใช้การแก้ไข PPK**: ใช้ข้อมูล GPS/จุดกำหนดการเปิดรับแสงจากไฟล์ `.daq` (ค่าเริ่มต้น: ปิด)
* **จุดกำหนดการเปิดรับแสง 1/2**: กำหนดกล้องให้สอดคล้องกับจุดกำหนดการเปิดรับแสงสำหรับการตั้งค่ากล้องคู่

{% hint style="info" %}
**ระดับการป้อนข้อมูล LATTICE เป็นอัตโนมัติ** การจับภาพ LATTICE จะเก็บระดับการประมวลผลไว้ในข้อมูลเมตาดาต้า XMP และการประมวลผลจะเข้าสู่กระบวนการเสมอที่เฟรมดิบ — ไม่มีอะไรต้องตั้งค่าใน GUI (มีแฟล็ก `--input-level` ใน CLI สำหรับผู้ใช้ขั้นสูงเพื่อแทนที่การตั้งค่าสำหรับการบันทึกที่สูญเสียเมตาดาต้า; ดู [CLI Reference](../reference/cli-reference.md).)
{% endhint %}

### วิธีเดเบเยอร์

ปัจจุบันเรามี 2 วิธีเดเบเยอร์ในChloros:

#### Standard (เร็ว, คุณภาพระดับกลาง)

วิธีเดเบเยอร์ Standard ทำงานเร็ว แต่แสดงสัญญาณรบกวนสีจากการเดเบเยอร์ ซึ่งส่งผลให้ภาพมีความแม่นยำน้อยลงและมีสัญญาณรบกวนมากขึ้น

#### Texture Aware (ช้า, คุณภาพสูงสุด) \[เฉพาะChloros+ เท่านั้น]

Texture Aware ใช้การเดเบย์เออร์คุณภาพสูงที่รับรู้ขอบภาพ ร่วมกับโมเดลลดสัญญาณรบกวน AI/ML ซึ่งสามารถกำจัดสัญญาณรบกวนจากการเดเบย์เออร์ได้เกือบทั้งหมด โมเดลนี้ต้องการหน่วยความจำ GPU (VRAM) เพื่อทำงาน: ด้วย **VRAM 7 GB หรือมากกว่า** สามารถประมวลผลภาพหลายภาพพร้อมกันได้; หากต่ำกว่า 7 GB จะประมวลผลภาพทีละภาพ (ช้าลงอย่างเห็นได้ชัด) ดู [Dynamic Compute Adaptation](../processing-architecture/dynamic-compute-adaptation.md).

{% hint style="info" %}
**ภาพที่ถ่ายด้วย LATTICE จะใช้การเดโมซิกแบบมาตรฐานเสมอ** เนื่องจากไม่มีโมเดล Texture Aware ที่ได้รับการฝึกอบรมสำหรับ LATTICE ดังนั้นตัวเลือกนี้จึงไม่ปรากฏสำหรับภาพ LATTICE — แต่ภาพSurvey3 ในโครงการเดียวกันยังสามารถใช้ตัวเลือกนี้ได้
{% endhint %}

### ดัชนี (ดัชนีมัลติสเปกตรัม)

กำหนดดัชนีพืชพันธุ์ที่จะคำนวณและส่งออก เมนูแบบเลื่อนลงใน GUI มี **สูตรดัชนีที่กำหนดไว้ล่วงหน้า 27 สูตร**

**วิธีเพิ่มดัชนี:**

1. คลิกปุ่ม**"Add index"**

2. เลือกดัชนีจากเมนูแบบเลื่อนลง (NDVI, NDRE, GNDVI, เป็นต้น)
3. ตั้งค่าการแสดงผล (สี LUT, ช่วงค่า)
4. เพิ่มดัชนีหลายตัวตามความต้องการ

**ดัชนียอดนิยม:*** **NDVI**: สุขภาพพืชพรรณทั่วไป (ใช้บ่อยที่สุด)
* **NDRE**: การตรวจจับความเครียดในระยะเริ่มต้นด้วย RedEdge
* **GNDVI**: ไวต่อความเข้มข้นของคลอโรฟิลล์
* **OSAVI**: ทำงานได้ดีกับดินที่มองเห็นได้
* **EVI**: พื้นที่ที่มีดัชนีพื้นที่ใบ (LAI) สูง

**สูตรกำหนดเอง:**

* สร้างสูตรดัชนีมัลติสเปกตรัมกำหนดเองด้วยการคำนวณระหว่างช่องสัญญาณภาพทั้งหมด
* บันทึกสูตรกำหนดเองเพื่อใช้ซ้ำ
* สูตรที่กำหนดเองเป็นคุณสมบัติของChloros+; ความพร้อมใช้งานขึ้นอยู่กับระดับแผนบริการของคุณ

สำหรับดัชนีและสูตรทั้งหมดที่มีอยู่ — รวมถึงชื่อใดที่ใช้ได้เฉพาะใน GUI และชื่อใดที่ใช้งานได้ทั้งใน CLI/SDK — ดู [สูตรดัชนีมัลติสเปกตรัม](../project-settings/multispectral-index-formulas.md).

### ส่งออก

ควบคุมรูปแบบไฟล์ผลลัพธ์

**รูปแบบที่มีอยู่**(การตั้งค่า:**รูปแบบภาพที่ปรับเทียบ**, ค่าเริ่มต้น**TIFF (16-bit)**):

* **TIFF (16-bit)**: แนะนำสำหรับ GIS และการวิเคราะห์ทางวิทยาศาสตร์
* **TIFF (8-bit)**: TIFF 8 บิต* **TIFF (32-bit, Percent)**: ค่าแบบจุดลอย
* **PNG (8-bit)**: การบีบอัดแบบไม่สูญเสียข้อมูลสำหรับการแสดงผล
* **JPG (8-bit)**: ไฟล์ขนาดเล็กที่สุด, การบีบอัดแบบสูญเสียข้อมูล

รายการนี้แสดงถึงรูปแบบไฟล์ที่ภาพในโครงการสามารถรองรับได้: Chloros ไม่เพิ่มระดับความลึกของบิต ภาพทั้งหมดที่ใช้ 8 บิตมีเพียง TIFF (8 บิต), PNG (8 บิต) และ JPG (8 บิต) เท่านั้น และตั้งค่าเริ่มต้นเป็น TIFF (8 บิต) ในโครงการแบบผสม แต่ละการจับภาพจะถูกส่งออกด้วยความลึกของสีตามต้นฉบับหรือต่ำกว่า Radiance จะคงอยู่ที่ 32-bit float

ไฟล์ที่ส่งออกจะถูกบันทึกไว้ในโฟลเดอร์ของโครงการ โดยจัดกลุ่มตามกล้องและรูปแบบ: `<project>/<camera>/<format>/<Product>_Images/` Radiance **จะถูกบันทึก**เป็น float32 ในโฟลเดอร์ `tiff32`**เสมอ** ไม่ว่าการตั้งค่านี้จะเป็นอย่างไร ไฟล์ที่ส่งออกจะรักษาชื่อไฟล์ต้นฉบับ — โฟลเดอร์จะระบุผลิตภัณฑ์ LATTICE multispectral ที่ส่งออกยังสามารถเขียนมาสก์จำกัดค่าต่อพิกเซลลงในโฟลเดอร์ `clamp_masks/` ที่อยู่ข้างๆ โฟลเดอร์ผลิตภัณฑ์ ดู [การเสร็จสิ้นการประมวลผล](finishing-the-processing.md) เพื่อดูโครงสร้างไฟล์ผลลัพธ์อย่างครบถ้วน

{% hint style="warning" %}
**การอ่านค่าการสะท้อน**: ค่า DN ที่หมายถึง ρ = 1.0 ขึ้นอยู่กับกล้องต้นทาง — LATTICE ใช้ 32768 (ถูกบันทึกเป็น XMP `Chloros:PixelScale`), ส่วนSurvey3 ใช้ 65535. อ่านแท็กแทนที่จะสมมติว่าเป็นค่าคงที่ ดู [รูปแบบภาพผลลัพธ์](../output-image-formats.md).
{% endhint %}

### เซ็นเซอร์แสง DAQ

ส่วนนี้แสดงรายการไฟล์ DAQ downwelling ทุกไฟล์ (`.daq` / `.csv`) ในโครงการของคุณ โดยแต่ละไฟล์มีหนึ่งแถว แสดงรุ่นเซ็นเซอร์ ชื่อไฟล์ และ **cap** ของตัวกระจายแสง ที่ใช้กับไฟล์นั้น

* **การแทนที่ค่า Cap (ทุกไฟล์)**: เมนูแบบเลื่อนลงเดียวที่ใช้กับทั้งโครงการ**Auto** (ค่าเริ่มต้น) ใช้ค่า cap ที่บันทึกไว้ในแต่ละไฟล์ — หากไม่มีการบันทึกค่า cap จะถือว่าเป็นการวัดแสงแดด แต่ DAQ-U, DAQ-M และ DAQ-E มาพร้อมโดยไม่มีการตั้งค่า cap และChloros ไม่สามารถตรวจจับค่าที่ปรับได้ ดังนั้นระบบประมวลผลจะแจ้งเตือนเมื่อใช้ค่า cap ที่สมมติ: ให้เลือกค่า cap ที่ได้ปรับแล้ว การเลือกค่าขีดจำกัดจะแทนที่ค่าขีดจำกัดของทุกไฟล์ ยกเว้นไฟล์ของ DAQ-E-S ซึ่งดิฟฟิวเซอร์เป็นส่วนหนึ่งของการสอบเทียบ: การบันทึกข้อมูลดิบจะถูกปรับแก้ด้วยค่านี้ และการบันทึกข้อมูลที่มีค่าขีดจำกัดอยู่แล้วจะถูกอ้างอิงใหม่ (การปรับแก้ที่บันทึกไว้จะถูกยกเลิก และค่าขีดจำกัดที่เลือกจะถูกนำไปใช้)
* ระบบจะแสดงคำเตือนเมื่อค่าตัวเก็บประจุที่บันทึกไว้เป็นค่าเริ่มต้นที่ฮับสมมติขึ้นแทนที่จะได้รับการยืนยันจากผู้ใช้งาน และเมื่อค่าตัวเก็บประจุที่เลือกไม่มีโปรไฟล์สำหรับรุ่นอุปกรณ์นั้น (การแทนที่จะถูกปฏิเสธสำหรับไฟล์นั้น)

การบันทึก DAQ ที่ทำในแท็บ Light Sensors จะถูกเพิ่มเข้าไปในโครงการที่เปิดอยู่โดยอัตโนมัติ และไฟล์ `.daq` / `.csv` ที่นำเข้าจะปรากฏที่นี่ทันทีที่เพิ่มเข้าไป

<figure><img src="../.gitbook/assets/image (32).png" alt=""><figcaption><p>การตั้งค่าโครงการส่วนล่าง — ดัชนี, รูปแบบการส่งออก, ส่วน DAQ Light Sensor, และตัวควบคุมแม่แบบ/โฟลเดอร์โครงการ</p></figcaption></figure>### การจัดแนวอาร์เรย์

ส่วนนี้จะปรากฏ **เฉพาะ** เมื่อมีภาพอย่างน้อยหนึ่งภาพในโครงการที่มีการแปลงการจัดแนวระหว่างโมดูล ซึ่งอาร์เรย์ LATTICE บันทึกไว้ขณะจับภาพ (`Chloros:Alignment*` XMP) ส่วนนี้แสดงจำนวนภาพที่มีแท็กและกล้องใดเป็นอ้างอิง พร้อมด้วยตัวเลือกควบคุมดังต่อไปนี้:

* **ใช้การจัดแนวอาร์เรย์** (ค่าเริ่มต้น: เปิด): ปรับรูปทรงของผลิตภัณฑ์ที่ประมวลผลทุกชนิด (debayered / preview / radiance / reflectance / index) ให้สอดคล้องกับรูปทรงอ้างอิงร่วมของอาร์เรย์ ปิด = ส่งออกในรูปแบบรูปทรงเซนเซอร์ต้นฉบับ
* **ตัดให้เหลือพื้นที่ทับซ้อนร่วมกัน** (ค่าเริ่มต้น: เปิด): ตัดส่วนที่ส่งออกที่จัดแนวแล้วให้เหลือเฉพาะพื้นที่ที่ทุกโมดูลใช้ร่วมกัน เพื่อให้ทุกแบนด์มีพื้นที่ทับซ้อนเท่ากัน ปิดจะรักษาพื้นที่เซนเซอร์เต็ม (เติมสีดำนอกพื้นที่ต้นทาง)
* **การสุ่มตัวอย่างใหม่**:**Bilinear (เรียบเนียน, ค่าเริ่มต้น)**,**Nearest (รักษาค่าที่แม่นยำ)**— ไม่มีการผสมระหว่างพิกเซล สำหรับการวิเคราะห์รังสีอย่างเคร่งครัด — หรือ**Cubic (คมชัดที่สุด)**.

## การตั้งค่า PPK (Post-Processed Kinematic)

หากใช้เครื่องบันทึกMAPIR DAQ ที่มี GPS เพื่อกำหนดตำแหน่งทางภูมิศาสตร์อย่างแม่นยำ:

### ข้อกำหนดเบื้องต้น

* เครื่องบันทึกMAPIR DAQ พร้อมโมดูล GPS (GNSS)
* ไฟล์บันทึก .daq ที่มีข้อมูลพินการเปิดรับแสง
* กล้องที่เชื่อมต่อกับพินการเปิดรับแสงของ DAQ ระหว่างการบันทึก

### ขั้นตอนการตั้งค่า

1. วางไฟล์บันทึก .daq ในโฟลเดอร์โครงการของคุณ
2. ใน Project Settings (การตั้งค่าโครงการ), ทำเครื่องหมายในช่อง **"Apply PPK corrections"**

3. ตั้งค่า**"Light sensor timezone offset"** หากจำเป็น (ค่าเริ่มต้น: 0 สำหรับ UTC)
4. กำหนดกล้องให้ตรงกับพินการเปิดรับแสง:
   * **กล้องเดียว**: กำหนดอัตโนมัติให้พิน 1
   * **กล้องคู่**: กำหนดกล้องแต่ละตัวให้พินที่ถูกต้องด้วยตนเอง**การจัดสรรพินการรับแสง:*** **พินการรับแสง 1**: เลือกแบบกล้องจากเมนูแบบเลื่อนลง
* **พินการรับแสง 2**: เลือกกล้องตัวที่สอง หรือ "ไม่ใช้"
* ไม่สามารถจัดสรรรุ่นกล้องเดียวกันให้กับทั้งสองพินได้

{% hint style="warning" %}
**สำคัญ**: ต้องกำหนดพินการรับแสงให้ถูกต้องกับกล้องแต่ละตัว การกำหนดที่ผิดจะส่งผลให้ข้อมูลตำแหน่งทางภูมิศาสตร์ไม่ถูกต้อง
{% endhint %}

## สถานการณ์ขั้นสูง

### โครงการหลายกล้อง

เมื่อประมวลผลภาพจากกล้อง MAPIR หลายตัวในโครงการเดียว:

1. Chloros จะตรวจจับรุ่นกล้องแต่ละตัวโดยอัตโนมัติ (ทั้ง Survey3 และ LATTICE)
2. กล้องแต่ละตัวจะได้รับโปรไฟล์การประมวลผลที่เหมาะสม และแต่ละตัวจะมีโครงสร้างโฟลเดอร์ผลลัพธ์เป็นของตัวเอง
3. PPK: กำหนดพินการรับแสง (Survey3) ของกล้องแต่ละตัวให้ถูกต้องด้วยตนเอง
4. กล้องทั้งหมดใช้รูปแบบการส่งออกและดัชนีเดียวกัน

**ตัวอย่าง**: ชุดกล้องคู่ Survey3W RGN + Survey3N OCN หรือชุดกล้อง LATTICE ที่ผสมผสานกล้องหลัก RGB กับโมดูลแถบแคบ

### การสำรวจแบบ Time-Lapse หรือหลายวัน

สำหรับการสำรวจพื้นที่เดียวกันซ้ำๆ ตามช่วงเวลา:

1. สร้างแม่แบบด้วยตั้งค่ามาตรฐานของคุณ
2. ใช้การตั้งค่าเป้าหมายการปรับเทียบที่สม่ำเสมอในทุกเซสชัน
3. ประมวลผลแต่ละวันที่เป็นโครงการแยกกัน
4. ใช้การตั้งค่าที่เหมือนกันเพื่อให้ได้ผลลัพธ์ที่สามารถเปรียบเทียบได้
5. ส่งออกในรูปแบบเดียวกันเพื่อการวิเคราะห์ตามเวลา

### ชุดข้อมูลขนาดใหญ่

สำหรับโครงการที่มีภาพจำนวนมาก (500+):

* พิจารณาแบ่งเป็นโครงการย่อยตามวันที่หรือพื้นที่
* ใช้การประมวลผลแบบขนานของChloros+ เพื่อผลลัพธ์ที่เร็วขึ้น
* พิจารณาใช้CLI หรือAPI เพื่อการทำงานอัตโนมัติแบบแบทช์
* ปรับช่วงเวลาการปรับเทียบใหม่ขั้นต่ำเพื่อลดเวลาการตรวจจับเป้าหมาย
