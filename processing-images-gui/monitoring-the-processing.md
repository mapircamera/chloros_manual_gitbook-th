## ภาพรวมของแถบความคืบหน้า

แถบความคืบหน้าที่อยู่ในส่วนหัวด้านบนแสดงสถานะการประมวลผลแบบเรียลไทม์และเปอร์เซ็นต์การเสร็จสิ้น ความคืบหน้าถูกส่งมาแบบสดจากระบบหลังบ้านผ่าน Server-Sent Events (SSE) ดังนั้นแถบความคืบหน้าจึงสะท้อนสิ่งที่ระบบประมวลผลกำลังดำเนินการอยู่จริง

### แถบความคืบหน้าในโหมดฟรี

สำหรับผู้ใช้ที่ไม่มีใบอนุญาตChloros

+:

**การแสดงความคืบหน้า 2 ขั้นตอน:**

1.**การตรวจจับเป้าหมาย** - ค้นหาเป้าหมายการปรับเทียบในภาพ
2. **การประมวลผล** - การปรับแก้ไขและส่งออก**แถบความคืบหน้าแสดง:**

* เปอร์เซ็นต์การเสร็จสิ้นโดยรวม (0-100%)
* ชื่อขั้นตอนปัจจุบัน
* การแสดงผลแบบแถบแนวนอนอย่างง่าย

### แถบความคืบหน้าChloros

+

สำหรับผู้ใช้ที่มีใบอนุญาตChloros

+:

**การแสดงความคืบหน้า 4 ขั้นตอน:**

1.**การตรวจจับ** - ค้นหาเป้าหมายการปรับเทียบ
2. **การวิเคราะห์** - ตรวจสอบภาพและเตรียมขั้นตอนการทำงาน

* แต่ละขั้นตอนแสดงความคืบหน้าแยกกัน (0-100%)

## การเข้าใจแต่ละขั้นตอนการประมวลผล

{% hint style="info" %}
**สถาปัตยกรรมท่อประมวลผล**: ขั้นตอน GUI 4 ขั้นตอนนี้สอดคล้องกับ [ท่อประมวลผล 4 เธรด](../processing-architecture/processing-pipeline.md). ในระบบที่มีการเร่งความเร็วด้วย GPU, Thread 3 (การปรับเทียบ) จะได้รับประโยชน์จาก [การปรับการคำนวณแบบไดนามิก](../processing-architecture/dynamic-compute-adaptation.md) ซึ่งช่วยปรับการประมวลผลให้เหมาะสมกับฮาร์ดแวร์ของคุณ
{% endhint %}

### ขั้นตอนที่ 1: การตรวจจับ (การตรวจจับเป้าหมาย)

**สิ่งที่เกิดขึ้น:**

*Chloros

สแกนภาพที่คุณได้ทำเครื่องหมายในช่อง Target (สแกนภาพทั้งหมดหากไม่มีการเลือกเป้าหมายใด)
* อัลกอริทึมการมองเห็นของคอมพิวเตอร์จะระบุแผงการปรับเทียบ
* ค่าการสะท้อนแสงถูกสกัดจากแต่ละแผง
* เวลาที่ตรวจพบเป้าหมายถูกบันทึกไว้เพื่อกำหนดตารางการปรับเทียบอย่างถูกต้อง

**ระยะเวลา:**

* มีเป้าหมายที่ระบุ: 10-60 วินาที
* ไม่มีเป้าหมายที่ระบุ: 5-30+ นาที (สแกนภาพทั้งหมด)

**ตัวบ่งชี้ความคืบหน้า:**

* กำลังตรวจจับ: 0% → 100%
* จำนวนภาพที่สแกนแล้ว (นับเฉพาะภาพที่กำลังสแกนอยู่จริง)
* จำนวนเป้าหมายที่พบ

**สิ่งที่ควรสังเกต:**

* ควรเสร็จสิ้นอย่างรวดเร็วหากเป้าหมายถูกทำเครื่องหมายอย่างถูกต้อง
* หากใช้เวลานานเกินไป เป้าหมายอาจไม่ถูกทำเครื่องหมาย
* ตรวจสอบบันทึกการดีบัก (Debug Log) เพื่อหาข้อความ &quot;Target found&quot;

### ขั้นตอนที่ 2: การวิเคราะห์

**สิ่งที่กำลังเกิดขึ้น:**

* อ่านข้อมูลเมตาดาต้า EXIF ของภาพ (เวลาประทับ, การตั้งค่าการเปิดรับแสง)
* กำหนดกลยุทธ์การปรับเทียบตามเวลาประทับของเป้าหมายและข้อมูล DAQ downwelling ที่มีอยู่
* จัดเรียงคิวการประมวลผลภาพ
* เตรียมตัวประมวลผลแบบขนาน (เฉพาะChloros

ขึ้นไป)

**ระยะเวลา:** 5-30 วินาที**ตัวบ่งชี้ความคืบหน้า:**

* กำลังวิเคราะห์: 0% → 100%
* ขั้นตอนนี้รวดเร็ว โดยทั่วไปจะเสร็จสิ้นอย่างรวดเร็ว

**สิ่งที่ควรสังเกต:**

* ความคืบหน้าควรเป็นไปอย่างสม่ำเสมอโดยไม่มีการหยุดชะงัก
* คำเตือนเกี่ยวกับข้อมูลเมตาดาต้าที่ขาดหายไปจะปรากฏใน Debug Log

### ขั้นตอนที่ 3: การปรับเทียบ

**สิ่งที่กำลังเกิดขึ้น:*** **Debayering**: แปลงรูปแบบ Bayer RAW เป็น 3 ช่อง (ถูกข้ามไปสำหรับโมดูล LATTICE mono พร้อมหมายเหตุ)
* **การแก้ไข vignette**: ลบความมืดที่ขอบเลนส์
* **การปรับเทียบการสะท้อน**: ปรับให้เป็นมาตรฐานด้วยค่าเป้าหมายและ/หรือการวัดแสงลงจาก DAQ
* **การคำนวณดัชนี**: คำนวณดัชนีมัลติสเปกตรัม
* ประมวลผลภาพแต่ละภาพผ่านกระบวนการทั้งหมด

**ระยะเวลา:** ส่วนใหญ่ของเวลาประมวลผลทั้งหมด (60-80%)**ตัวบ่งชี้ความคืบหน้า:**

* การปรับเทียบ: 0% → 100%
* ภาพปัจจุบันกำลังถูกประมวลผล
* ภาพที่เสร็จสิ้น / จำนวนภาพทั้งหมด

**พฤติกรรมการประมวลผล:*** **โหมดอิสระ**: ประมวลผลภาพหนึ่งภาพต่อครั้งตามลำดับ
* **โหมดChloros

+**: ทำงานกับกลุ่มงานที่ปรับตัวตามฮาร์ดแวร์ — 1-4 งานพร้อมกันบนระบบ GPU (ตาม VRAM), หนึ่งงานต่อคอร์ทางกายภาพ (ลบหนึ่ง) บนระบบที่ใช้ CPU เท่านั้น ดู [Dynamic Compute Adaptation](../processing-architecture/dynamic-compute-adaptation.md)
* **การเร่งความเร็วด้วย GPU**: ช่วยเพิ่มความเร็วขั้นตอนนี้อย่างมีนัยสำคัญ**สิ่งที่ควรสังเกต:**

* ความคืบหน้าที่สม่ำเสมอตามจำนวนภาพ
* ตรวจสอบ Debug Log เพื่อดูข้อความแจ้งการเสร็จสิ้นของแต่ละภาพ
* คำเตือนเกี่ยวกับปัญหาคุณภาพภาพหรือการปรับเทียบ

### ขั้นตอนที่ 4: การส่งออก

**สิ่งที่กำลังเกิดขึ้น:**

* การเขียนภาพที่ประมวลผลแล้วลงดิสก์ในรูปแบบที่เลือกไว้ เมื่อภาพแต่ละภาพเสร็จสิ้น
* **LATTICE**: แต่ละเฟรมจะถูกกระจายไปยังผลิตภัณฑ์ที่เปิดใช้งานทั้งหมด (debayered / preview / radiance / reflectance)
* ส่งออกภาพดัชนีมัลติสเปกตรัมพร้อมสี LUT
* สร้างโครงสร้างโฟลเดอร์ผลลัพธ์ `<project>/<camera>/<format>/<Product>_Images/` — ไฟล์ที่ส่งออกจะรักษาชื่อไฟล์ต้นฉบับไว้; โฟลเดอร์จะระบุผลิตภัณฑ์

**ระยะเวลา:** 10-20% ของเวลาประมวลผลทั้งหมด**ตัวบ่งชี้ความคืบหน้า:**

* กำลังส่งออก: 0% → 100%
* กำลังเขียนไฟล์
* รูปแบบการส่งออกและจุดหมายปลายทาง

**สิ่งที่ควรสังเกต:**

* คำเตือนเกี่ยวกับพื้นที่ดิสก์
* ข้อผิดพลาดในการเขียนไฟล์
* การเสร็จสิ้นของผลลัพธ์ทั้งหมดที่ตั้งค่าไว้

## แท็บบันทึกการดีบัก

บันทึกการดีบักให้ข้อมูลรายละเอียดเกี่ยวกับความคืบหน้าของการประมวลผลและปัญหาที่พบเจอ ข้อความเริ่มต้นของระบบแบ็กเอนด์จะถูกบันทึกซ้ำในคอนโซลบันทึกด้วย ดังนั้นบันทึกนี้จะให้ภาพรวมทั้งหมดแม้คุณจะเปิดมันในภายหลัง

### การเข้าถึงบันทึกการดีบัก

1. คลิกไอคอน **Debug Log**<img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

ในแถบด้านซ้าย
2. แผงบันทึกจะเปิดขึ้นแสดงข้อความการประมวลผลแบบเรียลไทม์
3. ระบบจะเลื่อนอัตโนมัติเพื่อแสดงข้อความล่าสุด

### การเข้าใจข้อความในบันทึก

Chloros

บรรทัดในบันทึกจะมีแท็กในวงเล็บที่ระบุชื่อระบบย่อย — เช่น `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`. สิ่งสำคัญที่สุดที่ควรรู้คือ **สรุปการรัน** ซึ่งแสดงขึ้นที่ท้ายการรันทุกครั้ง (รวมถึงการรันที่ถูกหยุด):

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

บรรทัดคำชี้แจงเพิ่มเติม `[RUN-SUMMARY]` จะปรากฏขึ้นเมื่อใดก็ตามที่จำเป็นต้องอธิบาย — เช่น การรันที่ไม่ได้ผลลัพธ์ใดๆ หรือกล้องที่ผลิตภัณฑ์ที่ร้องขอถูกข้ามไปเนื่องจากไม่เหมาะสม บรรทัด `[EXPORT-CHECK]` อธิบายการข้ามขั้นตอนสำหรับกล้องแต่ละตัว (เช่น เหตุผลที่กล้องRGB

ไม่ได้รับผลิตภัณฑ์ radiance)

ระดับความรุนแรงของข้อความทั่วไป (ตัวอย่างด้านล่างเป็นเพียงการอธิบาย ไม่ใช่ข้อความต้นฉบับ):

#### ข้อความข้อมูล (สีขาว/สีเทา)

การอัปเดตการประมวลผลปกติ: การประมวลผลเริ่มแล้ว, ตรวจพบเป้าหมาย (พร้อมจำนวนแผง), ความคืบหน้าการปรับเทียบต่อภาพ, ส่งออกไฟล์แล้ว, การประมวลผลเสร็จสิ้น

#### ข้อความเตือน (สีเหลือง)

ปัญหาที่ไม่รุนแรงและไม่ทำให้การประมวลผลหยุดลง — เช่น ข้อมูล GPS ขาดในเฟรมหนึ่ง, ช่องว่างของเวลาที่กว้างระหว่างภาพเป้าหมาย, หรือความต่างระดับสีต่ำในแผงปรับเทียบ

**การดำเนินการ:** ตรวจสอบข้อความเตือนหลังการประมวลผล แต่ไม่ควรหยุดการประมวลผล

#### ข้อความแสดงข้อผิดพลาด (Red

)

ปัญหาสำคัญที่อาจทำให้การประมวลผลล้มเหลว — เช่น ดิสก์เต็ม, ไฟล์ภาพเสียหาย, หรือไม่พบเป้าหมายขณะที่มีการร้องขอการปรับเทียบการสะท้อนแสง

**การดำเนินการ:** หยุดการประมวลผล, แก้ไขข้อผิดพลาด, เริ่มใหม่

3. วางลงในไฟล์ข้อความหรืออีเมล
4. ส่งไปยังทีมสนับสนุนMAPIR

หากจำเป็น

## การตรวจสอบทรัพยากรระบบ

### การใช้ CPU

**โหมดฟรี:**

* 1 คอร์ CPU อยู่ที่ประมาณ 100%
* คอร์อื่นๆ อยู่ในสถานะว่างหรือพร้อมใช้งาน
* ระบบยังคงตอบสนองได้

**โหมดChloros

+ Parallel:**

* หลายคอร์มีการใช้งานสูง — จำนวนขึ้นอยู่กับกลยุทธ์ที่เลือกโดย [Dynamic Compute Adaptation](../processing-architecture/dynamic-compute-adaptation.md)
* ระบบอาจรู้สึกตอบสนองช้าลง

**วิธีตรวจสอบ:**

*Windows

Task Manager (Ctrl+Shift+Esc)
* แท็บ Performance → ส่วน CPU
* ค้นหากระบวนการ &quot;Chloros

&quot; หรือ &quot;chloros-backend&quot;

### การใช้หน่วยความจำ (RAM)

**การใช้ทั่วไป:**

* โครงการขนาดเล็ก (&lt; 100 ภาพ): 2-4 GB
* โครงการขนาดกลาง (100-500 ภาพ): 4-8 GB
* โครงการขนาดใหญ่ (500+ ภาพ): 8-16 GB
* โหมดขนานChloros

+ ใช้ RAM มากขึ้น

**หากหน่วยความจำเหลือน้อย:**

* ประมวลผลเป็นชุดที่เล็กกว่า
* ปิดแอปพลิเคชันอื่น ๆ
* อัปเกรด RAM หากต้องประมวลผลชุดข้อมูลขนาดใหญ่เป็นประจำ

### การใช้ GPU (Chloros

+ ด้วย CUDA)

เมื่อเปิดใช้งานการเร่งความเร็วด้วย GPU:

* GPU NVIDIA แสดงการใช้งานสูง (60-90%)
* การใช้ VRAM เพิ่มขึ้น (ต้องการ VRAM 4GB+; 7GB+ สำหรับการ debayering แบบ Texture Aware ที่ทำงานพร้อมกัน)
* ขั้นตอนการปรับเทียบเร็วขึ้นอย่างมีนัยสำคัญ

**เพื่อตรวจสอบ:**

* ไอคอน NVIDIA ใน System Tray
* Task Manager → Performance → GPU
* GPU-Z หรือเครื่องมือตรวจสอบที่คล้ายกัน

### I/O ของดิสก์

**สิ่งที่ควรคาดการณ์:**

* การอ่านดิสก์สูงในช่วงขั้นตอนการวิเคราะห์
* การเขียนดิสก์สูงในช่วงขั้นตอนการส่งออก
* SSD เร็วกว่า HDD อย่างมีนัยสำคัญ

**เคล็ดลับด้านประสิทธิภาพ:**

* ใช้ SSD สำหรับโฟลเดอร์โครงการเมื่อเป็นไปได้
* หลีกเลี่ยงการใช้ไดรฟ์เครือข่ายสำหรับชุดข้อมูลขนาดใหญ่
* ตรวจสอบให้แน่ใจว่าดิสก์ไม่ใกล้เต็มความจุ (ส่งผลต่อความเร็วการเขียน)

## การตรวจหาปัญหาระหว่างการประมวลผล

### สัญญาณเตือน

**ความคืบหน้าหยุดนิ่ง (ไม่มีการเปลี่ยนแปลงเป็นเวลา 5 นาทีขึ้นไป):**

* ตรวจสอบบันทึกการดีบัก (Debug Log) เพื่อหาข้อผิดพลาด
* ตรวจสอบพื้นที่ว่างบนดิสก์
* ตรวจสอบ Task Manager เพื่อยืนยันว่าChloros

กำลังทำงานอยู่

**ข้อความผิดพลาดปรากฏขึ้นบ่อยครั้ง:**

* หยุดการประมวลผลและตรวจสอบข้อผิดพลาด
* สาเหตุทั่วไป: พื้นที่ดิสก์, ไฟล์เสียหาย, ปัญหาหน่วยความจำ
* ดูส่วนการแก้ไขปัญหาด้านล่าง

**ระบบไม่ตอบสนอง:**

*Chloros

+ โหมดขนานใช้ทรัพยากรมากเกินไป
* พิจารณาลดจำนวนงานที่ทำงานพร้อมกันหรืออัปเกรดฮาร์ดแวร์
* โหมดฟรีใช้ทรัพยากรน้อยกว่า

### เมื่อใดควรหยุดการประมวลผล

หยุดการประมวลผลหากพบ:

* ❌ ข้อผิดพลาด &quot;ดิสก์เต็ม&quot; หรือ &quot;ไม่สามารถเขียนไฟล์ได้&quot;
* ❌ ข้อผิดพลาดไฟล์ภาพเสียหายซ้ำๆ
* ❌ ระบบค้างสนิท (ไม่ตอบสนอง)
* ❌ พบว่ามีการตั้งค่าผิด
* ❌ นำเข้าภาพผิด

**วิธีหยุด:**

1. คลิก**ปุ่มหยุด** (แทนที่ปุ่มเริ่ม) — คลิกครั้งเดียวก็พอ
2. แถบแสดงความคืบหน้าจะแสดง &quot;Stopping...&quot; จนกว่าภาพที่กำลังประมวลผลจะเสร็จสิ้น จากนั้นกระบวนการจะสิ้นสุดในสถานะหยุด
3. ผลิตภัณฑ์ที่ส่งออกแล้วจะยังคงอยู่บนดิสก์; ไฟล์บันทึกจะแสดงรหัส `[RUN-SUMMARY]` ที่ระบุอย่างชัดเจนว่าส่วนใดเสร็จสิ้น
4. แก้ไขปัญหาและเริ่มใหม่ — กระบวนการจะเริ่มต้นจากต้น

## การแก้ไขปัญหาขณะประมวลผล

### การประมวลผลช้ามาก

**สาเหตุที่อาจเกิดขึ้น:**

* ภาพเป้าหมายที่ยังไม่ถูกทำเครื่องหมาย (กำลังสแกนภาพทั้งหมด)
* ใช้ HDD แทน SSD เป็นพื้นที่จัดเก็บข้อมูล
* ทรัพยากรระบบไม่เพียงพอ
* ตั้งค่าดัชนีจำนวนมาก
* การเข้าถึงไดรฟ์เครือข่าย

**วิธีแก้ไข:**

1. หากเพิ่งเริ่มและอยู่ในขั้นตอน Detecting: หยุด, ทำเครื่องหมายเป้าหมาย, เริ่มใหม่
2. สำหรับในอนาคต: ใช้ SSD, ลดจำนวนดัชนี, อัปเกรดฮาร์ดแวร์
3. พิจารณาใช้CLI

สำหรับการประมวลผลชุดข้อมูลขนาดใหญ่แบบแบทช์

### คำเตือน &quot;พื้นที่ดิสก์&quot;

**วิธีแก้ไข:**

1. ปล่อยพื้นที่ดิสก์ทันที
2. ย้ายโครงการไปยังไดรฟ์ที่มีพื้นที่ว่างมากขึ้น
3. ลดจำนวนดัชนีที่จะส่งออก
4. ปิดการใช้งานผลิตภัณฑ์ส่งออก LATTICE ที่ไม่จำเป็น (Project Settings → Processing)
5. ใช้รูปแบบ JPG แทนTIFF

(ไฟล์มีขนาดเล็กกว่า)

### ข้อความ &quot;ไฟล์เสียหาย&quot; ที่ปรากฏบ่อยครั้ง

**วิธีแก้ไข:**

1. คัดลอกภาพจากบัตร SD ใหม่เพื่อตรวจสอบความสมบูรณ์
2. ตรวจสอบบัตร SD เพื่อหาข้อผิดพลาด
3. ลบไฟล์ที่เสียหายออกจากโครงการ
4. ดำเนินการประมวลผลภาพที่เหลือต่อ

### ระบบร้อนเกินไป / การลดความเร็ว

**วิธีแก้ไข:**

1. ตรวจสอบให้แน่ใจว่ามีระบบระบายอากาศที่เพียงพอ
2. ทำความสะอาดฝุ่นจากช่องระบายอากาศของคอมพิวเตอร์
3. ลดภาระการประมวลผล (ใช้โหมด Free แทนChloros

+)
4. ประมวลผลในช่วงเวลาที่อากาศเย็นกว่า

## แจ้งเตือนการประมวลผลเสร็จสิ้น

เมื่อการประมวลผลเสร็จสิ้น:

* แถบความคืบหน้าถึง 100%
* บรรทัด `[RUN-SUMMARY]` จะปรากฏใน Debug Log พร้อมจำนวนสุดท้าย
* ปุ่ม Start จะกลับมาใช้งานได้อีกครั้ง
* ไฟล์ผลลัพธ์ทั้งหมดจะอยู่ในโครงสร้างโฟลเดอร์ผลลัพธ์ตามกล้องของแต่ละโครงการ: `<project>/<camera>/<format>/<Product>_Images/`

***

## ขั้นตอนต่อไป

เมื่อการประมวลผลเสร็จสิ้น:

1. **ตรวจสอบผลลัพธ์** - ดู [การเสร็จสิ้นการประมวลผล](finishing-the-processing.md)
2. **ตรวจสอบโฟลเดอร์ผลลัพธ์** - ตรวจสอบว่าไฟล์ทั้งหมดถูกส่งออกอย่างถูกต้อง
3. **ตรวจสอบบันทึกการดีบัก** - ตรวจสอบว่ามีคำเตือนหรือข้อผิดพลาดใด ๆ หรือไม่
4. **ดูตัวอย่างภาพที่ผ่านการประมวลผล** - ใช้ Image Viewer หรือซอฟต์แวร์ภายนอก

สำหรับข้อมูลเกี่ยวกับการตรวจสอบและการใช้ผลลัพธ์ที่ผ่านการประมวลผลแล้ว ดู [การเสร็จสิ้นการประมวลผล](finishing-the-processing.md).
