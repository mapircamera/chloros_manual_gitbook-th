# การติดตามการประมวลผล

เมื่อการประมวลผลเริ่มขึ้นแล้ว Chloros ให้หลายวิธีเพื่อติดตามความคืบหน้า ตรวจสอบปัญหา และเข้าใจว่าข้อมูลของคุณกำลังเกิดอะไรขึ้น หน้านี้อธิบายวิธีติดตามการประมวลผลและตีความข้อมูลที่ Chloros ให้

## ภาพรวมของแถบความคืบหน้า

แถบความคืบหน้าในส่วนหัวด้านบนแสดงสถานะการประมวลผลแบบเรียลไทม์และเปอร์เซ็นต์การเสร็จสิ้น ความคืบหน้าถูกส่งแบบสดจากระบบหลังบ้านผ่าน Server-Sent Events (SSE) ดังนั้นแถบนี้จึงสะท้อนสิ่งที่ pipeline กำลังดำเนินการอยู่จริง

### แถบความคืบหน้าในโหมดฟรี

สำหรับผู้ใช้ที่ไม่มีใบอนุญาตChloros+:

**การแสดงความคืบหน้า 2 ขั้นตอน:**

1.**การตรวจจับเป้าหมาย** - การค้นหาเป้าหมายการปรับเทียบในภาพ
2. **การประมวลผล** - การปรับแก้ไขและส่งออก**แถบความคืบหน้าแสดง:**

* เปอร์เซ็นต์การเสร็จสิ้นโดยรวม (0-100%)
* ชื่อขั้นตอนปัจจุบัน
* การแสดงผลด้วยแถบแนวนอนแบบเรียบง่าย

### แถบความคืบหน้า Chloros+

สำหรับผู้ใช้ที่มีใบอนุญาต Chloros+:

**การแสดงความคืบหน้า 4 ขั้นตอน:**

1.**การตรวจจับ** - ค้นหาเป้าหมายการปรับเทียบ
2. **การวิเคราะห์** - ตรวจสอบภาพและเตรียมระบบประมวลผล
3. **การปรับเทียบ** - การปรับแก้ vignette และ reflectance
4. **การส่งออก** - การบันทึกไฟล์ที่ผ่านการประมวลผล

**คุณสมบัติเชิงโต้ตอบ:**

* **นำเมาส์ไปวางเหนือ** แถบความคืบหน้าเพื่อดูแผง 4 ขั้นตอนที่ขยายออก
* **คลิก** แถบความคืบหน้าเพื่อตรึง/ยึดแผงที่ขยายออก
* **คลิกอีกครั้ง** เพื่อยกเลิกการตรึงและซ่อนอัตโนมัติเมื่อนำเมาส์ออก
* แต่ละขั้นตอนแสดงความคืบหน้าแยกกัน (0-100%)

{% hint style="info" %}
**ความสอดคล้องของ CLI**: ระหว่างการรัน `chloros-cli process` สี่เธรดเดียวกันจะรายงานสถานะเป็น "Detecting", "Analyzing", "Processing", "Exporting" และ `chloros-cli export-status` จะแสดงความคืบหน้าการส่งออกของเธรดที่ 4 แบบเรียลไทม์จากเทอร์มินัลอื่น ดู [คู่มืออ้างอิง CLI](../reference/cli-reference.md)
{% endhint %}

## การเข้าใจแต่ละขั้นตอนการประมวลผล

{% hint style="info" %}
**สถาปัตยกรรมท่อประมวลผล**: ขั้นตอน GUI 4 ขั้นตอนนี้สอดคล้องกับ [ท่อประมวลผล 4 เธรด](../processing-architecture/processing-pipeline.md) บนระบบที่มีการเร่งความเร็วด้วย GPU, Thread 3 (การปรับเทียบ) จะได้รับประโยชน์จาก [การปรับการคำนวณแบบไดนามิก](../processing-architecture/dynamic-compute-adaptation.md) ซึ่งช่วยปรับการประมวลผลให้เหมาะสมกับฮาร์ดแวร์ของคุณ
{% endhint %}

### ขั้นตอนที่ 1: การตรวจจับ (การตรวจจับเป้าหมาย)

**สิ่งที่เกิดขึ้น:**

* Chloros สแกนภาพที่คุณได้ทำเครื่องหมายด้วยช่องทำเครื่องหมาย Target (สแกนภาพทั้งหมดหากไม่มีการทำเครื่องหมายใด)
* อัลกอริทึมการมองเห็นด้วยคอมพิวเตอร์ระบุแผงการปรับเทียบ
* ค่าการสะท้อนแสงถูกสกัดจากแต่ละแผง
* เวลาของเป้าหมายถูกบันทึกเพื่อจัดตารางการปรับเทียบอย่างถูกต้อง

**ระยะเวลา:**

* มีเป้าหมายที่ระบุไว้: 10-60 วินาที
* ไม่มีเป้าหมายที่ระบุไว้: 5-30+ นาที (สแกนภาพทั้งหมด)

**ตัวชี้วัดความคืบหน้า:**

* กำลังตรวจจับ: 0% → 100%
* จำนวนภาพที่สแกน (นับเฉพาะภาพที่กำลังสแกนอยู่จริง)
* จำนวนเป้าหมายที่พบ

**สิ่งที่ควรสังเกต:**

* ควรเสร็จสิ้นอย่างรวดเร็วหากเป้าหมายถูกทำเครื่องหมายอย่างถูกต้อง
* หากใช้เวลานานเกินไป เป้าหมายอาจไม่ถูกทำเครื่องหมาย
* ตรวจสอบ Debug Log เพื่อหาข้อความ "Target found"

### ขั้นตอนที่ 2: การวิเคราะห์

**สิ่งที่กำลังเกิดขึ้น:**

* อ่านข้อมูลเมตาดาต้า EXIF ของภาพ (เวลาประทับ, การตั้งค่าการเปิดรับแสง)
* กำหนดกลยุทธ์การปรับเทียบตามเวลาประทับของเป้าหมายและข้อมูล DAQ ที่ส่งลงจากด้านบนที่มีอยู่
* จัดเรียงคิวการประมวลผลภาพ
* เตรียมตัวประมวลผลแบบขนาน (เฉพาะ Chloros+)

**ระยะเวลา:** 5-30 วินาที**ตัวชี้วัดความคืบหน้า:**

* กำลังวิเคราะห์: 0% → 100%
* ขั้นตอนนี้เร็ว โดยทั่วไปจะเสร็จสิ้นอย่างรวดเร็ว

**สิ่งที่ควรสังเกต:**

* ความคืบหน้าควรเป็นไปอย่างสม่ำเสมอโดยไม่มีการหยุดชะงัก
* คำเตือนเกี่ยวกับข้อมูลเมตาที่ขาดหายไปจะปรากฏใน Debug Log

### ขั้นตอนที่ 3: การปรับเทียบ

**สิ่งที่กำลังเกิดขึ้น:**

* **Debayering**: การแปลงรูปแบบ Bayer RAW เป็น 3 ช่อง (ข้ามขั้นตอนนี้สำหรับโมดูล LATTICE mono พร้อมหมายเหตุ)
* **การแก้ไข vignette**: การลบความมืดที่ขอบเลนส์
* **การปรับเทียบการสะท้อน**: การปรับให้เป็นมาตรฐานด้วยค่าเป้าหมายและ/หรือการลดสัญญาณ DAQ
* **การคำนวณดัชนี**: การคำนวณดัชนีมัลติสเปกตรัม
* การประมวลผลภาพแต่ละภาพผ่านกระบวนการทั้งหมด

**ระยะเวลา:** ส่วนใหญ่ของเวลาประมวลผลทั้งหมด (60-80%)**ตัวชี้วัดความคืบหน้า:**

* การปรับเทียบ: 0% → 100%
* ภาพปัจจุบันกำลังถูกประมวลผล
* ภาพที่เสร็จสิ้น / จำนวนภาพทั้งหมด

**พฤติกรรมการประมวลผล:**

* **โหมดฟรี**: ประมวลผลภาพหนึ่งภาพต่อครั้งตามลำดับ
* **โหมด Chloros+**: ทำงานกับกลุ่มงานที่ปรับตัวตามฮาร์ดแวร์ — 1-4 งานพร้อมกันบนระบบ GPU (ตาม VRAM), หนึ่งงานต่อแกนกายภาพ (ลบหนึ่ง) บนระบบที่ใช้ CPU เท่านั้น ดู [Dynamic Compute Adaptation](../processing-architecture/dynamic-compute-adaptation.md)
* **การเร่งความเร็วด้วย GPU**: ช่วยเพิ่มความเร็วขั้นตอนนี้อย่างมีนัยสำคัญ**สิ่งที่ควรสังเกต:**

* ความคืบหน้าที่สม่ำเสมอตามจำนวนภาพ
* ตรวจสอบ Debug Log เพื่อดูข้อความแจ้งการเสร็จสิ้นของแต่ละภาพ
* คำเตือนเกี่ยวกับคุณภาพภาพหรือปัญหาการปรับเทียบ

### ขั้นตอน 4: การส่งออก

**สิ่งที่กำลังเกิดขึ้น:**

* การเขียนภาพที่ผ่านการประมวลผลลงดิสก์ในรูปแบบที่เลือกไว้ เมื่อแต่ละภาพเสร็จสิ้น
* **LATTICE**: แต่ละเฟรมจะถูกกระจายไปยังทุกผลิตภัณฑ์ที่เปิดใช้งาน (debayered / preview / radiance / reflectance)
* ส่งออกภาพดัชนีมัลติสเปกตรัมด้วยสี LUT
* สร้างโครงสร้างโฟลเดอร์ผลลัพธ์ `<project>/<camera>/<format>/<Product>_Images/` — ไฟล์ที่ส่งออกจะรักษาชื่อไฟล์ต้นฉบับไว้; โฟลเดอร์ระบุผลิตภัณฑ์

**ระยะเวลา:** 10-20% ของเวลาประมวลผลรวม**ตัวชี้วัดความคืบหน้า:**

* การส่งออก: 0% → 100%
* กำลังเขียนไฟล์
* รูปแบบการส่งออกและจุดหมายปลายทาง

**สิ่งที่ควรสังเกต:**

* คำเตือนพื้นที่ดิสก์
* ข้อผิดพลาดในการเขียนไฟล์
* การเสร็จสิ้นของผลลัพธ์ทั้งหมดที่ตั้งค่าไว้

## แท็บบันทึกการดีบัก

บันทึกการดีบักให้ข้อมูลรายละเอียดเกี่ยวกับความคืบหน้าของการประมวลผลและปัญหาที่พบเจอ ข้อความเริ่มต้นของระบบหลังบ้านจะถูกบันทึกซ้ำในคอนโซลบันทึกด้วย ดังนั้นบันทึกนี้จะให้ภาพรวมทั้งหมด แม้คุณจะเปิดมันในภายหลัง

### การเข้าถึงบันทึกการดีบัก

1. คลิกไอคอน **Debug Log** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

ในแถบด้านซ้าย
2. แผงบันทึกจะเปิดขึ้นและแสดงข้อความการประมวลผลแบบเรียลไทม์
3. ระบบจะเลื่อนอัตโนมัติเพื่อแสดงข้อความล่าสุด

### การเข้าใจข้อความในบันทึก บรรทัดบันทึกของ

Chloros มีแท็กในวงเล็บที่ระบุชื่อระบบย่อย — เช่น `[PROCESSING]`, `[RUN-SUMMARY]`, `[LATTICE-EXPORT]`, `[EXPORT-CHECK]`, `[IMPORT-LEVEL]`. สิ่งสำคัญที่สุดที่ควรรู้คือ **สรุปการรัน** ซึ่งแสดงขึ้นที่ท้ายการรันทุกครั้ง (รวมถึงการรันที่ถูกหยุด):

```
[RUN-SUMMARY] 49 image(s) in 2 camera group(s); 4 target(s) detected; 45 image(s) calibrated; 180 file(s) written.
```

จะมีบรรทัดคำอธิบายเพิ่มเติม `[RUN-SUMMARY]` ตามมาทุกครั้งที่มีสิ่งใดต้องการคำอธิบาย — เช่น การรันที่ไม่ได้ผลลัพธ์ใดๆ, หรือกล้องที่ผลิตภัณฑ์ที่ขอถูกข้ามไปเนื่องจากไม่เหมาะสม บรรทัด `[EXPORT-CHECK]` อธิบายการข้ามไปสำหรับแต่ละกล้อง (เช่น เหตุผลที่กล้องRGB ไม่ได้รับผลิตภัณฑ์ radiance)

ระดับความรุนแรงของข้อความทั่วไป (ตัวอย่างด้านล่างเป็นตัวอย่างเพื่ออธิบาย ไม่ใช่ข้อความต้นฉบับ):

#### ข้อความข้อมูล (สีขาว/สีเทา)

การอัปเดตการประมวลผลปกติ: การประมวลผลเริ่มแล้ว, ตรวจพบเป้าหมาย (พร้อมจำนวนแผง), ความคืบหน้าการปรับเทียบต่อภาพ, ส่งออกไฟล์แล้ว, การประมวลผลเสร็จสิ้น.

#### ข้อความเตือน (สีเหลือง)

ปัญหาที่ไม่รุนแรงและไม่ทำให้การประมวลผลหยุดลง — เช่น ข้อมูล GPS ขาดในเฟรมหนึ่ง ช่องว่างของเวลาที่กว้างระหว่างภาพเป้าหมาย หรือความต่างระดับสีต่ำในแผงปรับเทียบ

**การดำเนินการ:** ตรวจสอบข้อความเตือนหลังการประมวลผล แต่ไม่ต้องหยุดการประมวลผล

#### ข้อความข้อผิดพลาด (Red)

ปัญหาสำคัญที่อาจทำให้การประมวลผลล้มเหลว — เช่น ดิสก์เต็ม, ไฟล์ภาพเสียหาย, หรือไม่พบเป้าหมายขณะที่มีการร้องขอการปรับเทียบการสะท้อนแสง

**การดำเนินการ:** หยุดการประมวลผล, แก้ไขข้อผิดพลาด, เริ่มใหม่

### สถานการณ์บันทึกทั่วไป

| สถานการณ์                             | ความหมาย                                       | การดำเนินการที่จำเป็น                                         |
| ------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| พบเป้าหมายใน \[filename]        | พบเป้าหมายการปรับเทียบสำเร็จ         | ไม่มี - ปกติ                                         |
| แถบความคืบหน้าต่อภาพ              | อัปเดตความคืบหน้าปัจจุบัน                       | ไม่มี - ปกติ                                         |
| ไม่พบเป้าหมาย                      | ไม่ตรวจพบเป้าหมายการปรับเทียบ               | ทำเครื่องหมายภาพเป้าหมายหรือปิดการปรับเทียบการสะท้อน |
| พื้นที่ดิสก์ไม่เพียงพอ               | ไม่มีพื้นที่จัดเก็บเพียงพอสำหรับผลลัพธ์                 | ปลดปล่อยพื้นที่ดิสก์                                    |
| ข้ามไฟล์ที่เสียหาย               | ไฟล์ภาพถูกเสียหาย                         | คัดลอกไฟล์ใหม่จากบัตร SD                             |
| `[IMPORT-LEVEL] Skipping ... no raw source` | การถ่ายภาพที่ไม่มีเฟรมดิบไม่สามารถประมวลผลได้ | ถ่ายภาพใหม่พร้อมเฟรมดิบ, หรือใช้CLI `--input-level`  |

### การคัดลอกข้อมูลบันทึก

เพื่อคัดลอกบันทึกสำหรับการแก้ไขปัญหาหรือขอความช่วยเหลือ:

1. เปิดแผงบันทึกการดีบัก
2. คลิกปุ่ม **คัดลอก**(คัดลอกบันทึกไปยังคลิปบอร์ด) หรือ**ดาวน์โหลด** เพื่อบันทึกเป็นไฟล์ข้อความ
3. วางลงในไฟล์ข้อความหรืออีเมล
4. ส่งไปยังทีมสนับสนุน MAPIR หากจำเป็น

### รายงานข้อผิดพลาดจากแท็บบันทึก

คุณสมบัติใหม่ในเวอร์ชัน 1.3.0: ไอคอนข้อผิดพลาด (**รายงานข้อผิดพลาด**) ที่ด้านบนของแท็บบันทึกการดีบัก จะส่งรายงานโดยตรงไปยัง MAPIR



1. คลิกไอคอนข้อผิดพลาดที่ด้านบนของแท็บบันทึกการดีบัก
2. อธิบายปัญหา: คุณกำลังทำอะไร, ผลที่คาดหวัง และสิ่งที่เกิดขึ้นจริง (จำเป็น)
3. หากต้องการ ให้ทำเครื่องหมายที่ **เพิ่มรูปภาพไม่กี่รูป (สูงสุด 10 รูป)**และเลือกรูปภาพจากโครงการที่เปิดอยู่ หรือใช้**เรียกดู...** สำหรับไฟล์รูปภาพอื่น ๆ
4. คลิก **ส่ง**

รายงานจะรวมคำอธิบายของคุณ รูปภาพที่แนบมา บันทึกของ Chloros และรายละเอียดระบบ (เวอร์ชัน Chloros ระบบปฏิบัติการ GPU และการตั้งค่าโครงการ) คุณต้องเข้าสู่ระบบ Chloros (แท็บ User) เพื่อส่งรายงาน คุณสามารถปิดหน้าต่างได้ระหว่างการส่ง; เมื่อการส่งเสร็จสิ้น รหัสอ้างอิง เช่น `Bug report sent. Reference: BR-…` จะถูกบันทึกลงในบันทึก — โปรดระบุรหัสนี้เมื่อติดต่อ MAPIR หากไม่สามารถอัปโหลดรายงานได้ (เช่น ไม่มีการเชื่อมต่ออินเทอร์เน็ต), Chloros จะบันทึกมันไว้บนคอมพิวเตอร์ของคุณและแสดงเส้นทางเพื่อให้คุณสามารถส่งอีเมลไปยัง support@mapir.camera ได้

## การติดตามทรัพยากรระบบ

### การใช้ CPU

**โหมดฟรี:**

* 1 คอร์ CPU ที่ \~100%
* คอร์อื่นๆ อยู่ในสถานะว่างหรือพร้อมใช้งาน
* ระบบยังคงตอบสนองได้

**โหมด Chloros+ Parallel:**

* คอร์หลายตัวถูกใช้งานในระดับสูง — จำนวนขึ้นอยู่กับกลยุทธ์ที่เลือกโดย [Dynamic Compute Adaptation](../processing-architecture/dynamic-compute-adaptation.md)
* ระบบอาจตอบสนองได้ช้าลง

**วิธีตรวจสอบ:**

* Windows Task Manager (Ctrl+Shift+Esc)
* แท็บ Performance → ส่วน CPU
* ค้นหากระบวนการ "Chloros" หรือ "chloros-backend"

### การใช้หน่วยความจำ (RAM)

**การใช้งานทั่วไป:**

* โครงการขนาดเล็ก (< 100 ภาพ): 2-4 GB
* โครงการขนาดกลาง (100-500 ภาพ): 4-8 GB
* โครงการขนาดใหญ่ (500+ ภาพ): 8-16 GB
* โหมดขนานของChloros+ ใช้ RAM มากขึ้น

**หากหน่วยความจำเหลือน้อย:**

* ประมวลผลชุดข้อมูลขนาดเล็ก
* ปิดแอปพลิเคชันอื่น ๆ
* อัปเกรด RAM หากต้องประมวลผลชุดข้อมูลขนาดใหญ่เป็นประจำ

### การใช้ GPU (Chloros+ กับ CUDA)

เมื่อเปิดใช้งานการเร่งความเร็วด้วย GPU:

* GPU ของ NVIDIA จะแสดงการใช้งานสูง (60-90%)
* การใช้ VRAM เพิ่มขึ้น (ต้องการ VRAM 4 GB ขึ้นไป; 7 GB ขึ้นไป สำหรับการ debayering แบบ Texture Aware ที่ทำงานพร้อมกัน)
* ขั้นตอนการปรับเทียบเร็วขึ้นอย่างมีนัยสำคัญ

**เพื่อติดตาม:**

* ไอคอน NVIDIA ใน System Tray
* Task Manager → Performance → GPU
* GPU-Z หรือเครื่องมือติดตามที่คล้ายกัน

### I/O ของดิสก์

**สิ่งที่ควรคาดหวัง:**

* การอ่านดิสก์สูงในช่วงขั้นตอนการวิเคราะห์
* การเขียนดิสก์สูงในช่วงขั้นตอนการส่งออก
* SSD เร็วกว่า HDD อย่างมีนัยสำคัญ

**เคล็ดลับด้านประสิทธิภาพ:**

* ใช้ SSD สำหรับโฟลเดอร์โครงการเมื่อเป็นไปได้
* หลีกเลี่ยงการใช้ไดรฟ์เครือข่ายสำหรับชุดข้อมูลขนาดใหญ่
* ตรวจสอบให้แน่ใจว่าพื้นที่ดิสก์ไม่ใกล้เต็ม (ส่งผลต่อความเร็วการเขียน)

## การตรวจหาปัญหาระหว่างการประมวลผล

### สัญญาณเตือน

**ความคืบหน้าหยุดนิ่ง (ไม่มีการเปลี่ยนแปลงเป็นเวลา 5+ นาที):**

* ตรวจสอบบันทึกการดีบัก (Debug Log) เพื่อหาข้อผิดพลาด
* ตรวจสอบพื้นที่ว่างบนดิสก์
* ตรวจสอบ Task Manager เพื่อยืนยันว่า Chloros กำลังทำงาน

**ข้อความผิดพลาดปรากฏบ่อยครั้ง:**

* หยุดการประมวลผลและตรวจสอบข้อผิดพลาด
* สาเหตุทั่วไป: พื้นที่ดิสก์ไม่เพียงพอ, ไฟล์เสียหาย, ปัญหาหน่วยความจำ
* ดูส่วนการแก้ไขปัญหา (Troubleshooting) ด้านล่าง

**ระบบไม่ตอบสนอง:**

* โหมดขนานของChloros+ ใช้ทรัพยากรมากเกินไป
* พิจารณาลดจำนวนงานที่ทำงานพร้อมกันหรืออัปเกรดฮาร์ดแวร์
* โหมดฟรีใช้ทรัพยากรน้อยกว่า

### เมื่อใดควรหยุดการประมวลผล

หยุดการประมวลผลหากพบ:

* ❌ ข้อผิดพลาด "ดิสก์เต็ม" หรือ "ไม่สามารถเขียนไฟล์ได้"
* ❌ ข้อผิดพลาดไฟล์ภาพเสียหายซ้ำๆ
* ❌ ระบบค้างสนิท (ไม่ตอบสนอง)
* ❌ พบว่าตั้งค่าผิด
* ❌ นำเข้าภาพผิด

**วิธีหยุด:**

1. คลิก**ปุ่ม Stop** (แทนที่ปุ่ม Start) — คลิกครั้งเดียวก็พอ
2. แถบแสดงความคืบหน้าจะแสดง "Stopping..." จนกว่าไฟล์ภาพที่กำลังประมวลผลจะเสร็จสิ้น จากนั้นกระบวนการจะสิ้นสุดในสถานะหยุด
3. ผลิตภัณฑ์ที่ส่งออกแล้วจะยังคงอยู่บนดิสก์; บันทึกจะแสดงรหัส `[RUN-SUMMARY]` ที่ระบุอย่างชัดเจนว่าส่วนใดเสร็จสิ้น
4. แก้ไขปัญหาและเริ่มต้นใหม่ — การประมวลผลจะเริ่มจากต้น

## การแก้ไขปัญหาขณะประมวลผล

### การประมวลผลช้ามาก

**สาเหตุที่อาจเกิดขึ้น:**

* ภาพเป้าหมายที่ยังไม่ถูกทำเครื่องหมาย (กำลังสแกนภาพทั้งหมด)
* ใช้ HDD แทน SSD เป็นพื้นที่จัดเก็บข้อมูล
* ทรัพยากรระบบไม่เพียงพอ
* มีการกำหนดดัชนีจำนวนมาก
* การเข้าถึงไดรฟ์เครือข่าย

**วิธีแก้ไข:**

1. หากเพิ่งเริ่มและอยู่ในขั้นตอน Detecting: หยุด, กำหนดเป้าหมาย, เริ่มใหม่
2. สำหรับในอนาคต: ใช้ SSD, ลดจำนวนดัชนี, อัปเกรดฮาร์ดแวร์
3. พิจารณาใช้ CLI สำหรับการประมวลผลชุดข้อมูลขนาดใหญ่แบบแบทช์

### คำเตือน "พื้นที่ดิสก์"

**วิธีแก้ไข:**

1. ปลดปล่อยพื้นที่ดิสก์ทันที
2. ย้ายโครงการไปยังไดรฟ์ที่มีพื้นที่ว่างมากขึ้น
3. ลดจำนวนดัชนีที่จะส่งออก
4. ปิดการใช้งานผลิตภัณฑ์ส่งออก LATTICE ที่ไม่จำเป็น (Project Settings → Processing)
5. ใช้รูปแบบ JPG แทนTIFF (ไฟล์มีขนาดเล็กกว่า)

### ข้อความ "ไฟล์เสียหาย" ที่ปรากฏบ่อยครั้ง

**วิธีแก้ไข:**

1. คัดลอกภาพจากบัตร SD ใหม่เพื่อตรวจสอบความสมบูรณ์
2. ตรวจสอบบัตร SD เพื่อหาข้อผิดพลาด
3. ลบไฟล์ที่เสียหายออกจากโครงการ
4. ดำเนินการประมวลผลภาพที่เหลือต่อ

### ระบบร้อนเกินไป / การลดความเร็ว

**วิธีแก้ไข:**

1. ตรวจสอบให้แน่ใจว่ามีระบบระบายอากาศที่เพียงพอ
2. ทำความสะอาดฝุ่นจากช่องระบายอากาศของคอมพิวเตอร์
3. ลดภาระการประมวลผล (ใช้โหมด Free แทนChloros+)
4. ประมวลผลในช่วงเวลาที่อากาศเย็นกว่า

## การแจ้งเตือนการประมวลผลเสร็จสิ้น

เมื่อการประมวลผลเสร็จสิ้น:

* แถบความคืบหน้าถึง 100%
* บรรทัด `[RUN-SUMMARY]` จะปรากฏใน Debug Log พร้อมจำนวนสุดท้าย
* ปุ่ม Start จะกลับมาใช้งานได้อีกครั้ง
* ไฟล์ผลลัพธ์ทั้งหมดจะอยู่ในโครงสร้างโฟลเดอร์ผลลัพธ์ตามกล้องของแต่ละกล้องในโครงการ: `<project>/<camera>/<format>/<Product>_Images/`

***

## ขั้นตอนต่อไป

เมื่อการประมวลผลเสร็จสิ้น:

1. **ตรวจสอบผลลัพธ์** - ดู [การเสร็จสิ้นการประมวลผล](finishing-the-processing.md)
2. **ตรวจสอบโฟลเดอร์ผลลัพธ์** - ตรวจสอบว่าไฟล์ทั้งหมดถูกส่งออกอย่างถูกต้อง
3. **ตรวจสอบบันทึกการดีบัก** - ตรวจสอบว่ามีคำเตือนหรือข้อผิดพลาดใด ๆ หรือไม่
4. **ดูตัวอย่างภาพที่ผ่านการประมวลผล** - ใช้ Image Viewer หรือซอฟต์แวร์ภายนอก

สำหรับข้อมูลเกี่ยวกับการตรวจสอบและใช้ผลลัพธ์ที่ผ่านการประมวลผลแล้ว ดู [การเสร็จสิ้นการประมวลผล](finishing-the-processing.md).
