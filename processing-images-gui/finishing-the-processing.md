# การเสร็จสิ้นการประมวลผล

เมื่อChloros
เสร็จสิ้นการประมวลผลแล้ว ก็ถึงเวลาตรวจสอบผลลัพธ์ ตรวจสอบคุณภาพผลลัพธ์ และเตรียมภาพที่ผ่านการประมวลผลเพื่อใช้ในกระบวนการทำงานของคุณ หน้านี้จะนำคุณผ่านขั้นตอนสุดท้ายและขั้นตอนต่อไป

## สัญญาณการเสร็จสิ้นการประมวลผล

เมื่อการประมวลผลเสร็จสิ้นอย่างสำเร็จ คุณจะเห็นสัญญาณหลายอย่าง:

* ✅ **แถบความคืบหน้า**: ถึง 100%
* ✅ **บันทึกการดีบัก**: แสดงบรรทัด `[RUN-SUMMARY]` สุดท้ายพร้อมจำนวน (ภาพ, กลุ่มกล้อง, เป้าหมาย, ภาพที่ปรับเทียบแล้ว, ไฟล์ที่เขียน)
* ✅ **ปุ่มเริ่ม**: กลับมาใช้งานได้อีกครั้ง (พร้อมสำหรับการประมวลผลครั้งต่อไป)
* ✅ **ไฟล์ผลลัพธ์**: ภาพทั้งหมดที่ผ่านการประมวลผลจะถูกบันทึกไว้ในโครงสร้างโฟลเดอร์ผลลัพธ์ของโครงการ (ด้านล่าง)

{% hint style="warning" %}
**การประมวลผลที่ไม่บันทึกภาพใดเลยถือว่าล้มเหลว** หากคุณได้ขอผลิตภัณฑ์ภาพ แต่การประมวลผลไม่บันทึกภาพใดเลย ระบบChloros
จะรายงานว่าล้มเหลว — `[RUN-SUMMARY]` จะให้คำใบ้ในชื่อบันทึกเกี่ยวกับสาเหตุที่เป็นไปได้ (ไม่มีการนำเข้าข้อมูล, ไม่พบเป้าหมาย, หรือผลิตภัณฑ์ที่ร้องขอทั้งหมดถูกข้ามไปเนื่องจากไม่เหมาะสม) ส่วนเวอร์ชันที่เทียบเท่าในCLI
จะออกค่าที่ไม่เป็นศูนย์ การรันที่ตั้งใจให้ใช้เฉพาะเมตาดาต้า (ปิดผลิตภัณฑ์ส่งออกทั้งหมด, ไม่มีดัชนี) ยังคงถือว่าสำเร็จ ดู [เอกสารอ้างอิงCLI
](../reference/cli-reference.md#a-run-that-writes-no-images-fails).
{% endhint %}

## การค้นหาภาพที่ผ่านการประมวลผล

### การเปิดโฟลเดอร์ผลลัพธ์

1. คลิกไอคอน **Main Menu**<img src="../.gitbook/assets/image (1) (1) (1) (1).png" alt="" data-size="line">
(มุมซ้ายบน)
2. เลือก **&quot;Open Project Folder&quot;**

3. โปรแกรมจัดการไฟล์จะเปิดไปยังไดเรกทอรีของโครงการ
4. ค้นหาโครงการของคุณตามชื่อ

### โครงสร้างโฟลเดอร์ผลลัพธ์

ผลิตภัณฑ์จะถูกบันทึก **ภายในโฟลเดอร์โครงการ โดยจัดกลุ่มตามกล้องและตามรูปแบบไฟล์**:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **โฟลเดอร์กล้อง**: `LATT-<sensor>-<lens>-F<filter>` สำหรับ LATTICE (ตรงกับ EXIF ของภาพที่ถ่าย `Model`), `<model>_<filter>` สำหรับSurvey3
(เช่น `Survey3N_RGN`) กล้องสองตัวที่ใช้เซ็นเซอร์และฟิลเตอร์เดียวกันแต่มีเลนส์ต่างกันจะมีโครงสร้างโฟลเดอร์แยกกัน — เนื่องจาก vignette, มุมมอง และ distortion แตกต่างกัน
* **โฟลเดอร์รูปแบบ**: ตามการตั้งค่ารูปแบบการส่งออกของคุณ — `tiff16`, `tiff8`, `png8`, `jpg8` หรือ `tiff32` สำหรับTIFF
(32-bit, Percent) ค่า radiance เป็น float32 เสมอ และถูกจัดเก็บภายใต้ `tiff32` เสมอ
* **โฟลเดอร์ผลิตภัณฑ์**:
  * `Reflectance_Calibrated_Images/` — ค่าสะท้อนที่ปรับเทียบแล้ว
  * `Debayered_Images/` — การแยกพิกเซลแบบเชิงเส้น (LATTICE)
  * `Preview_Images/` — พรีวิวบนหน้าจอ (LATTICE)
  * `Radiance_Images/` — ความส่องสว่างเชิงสเปกตรัมแบบ float32, W/m²/sr/nm (LATTICE multispectral)
  * `Vignette_Corrected_Images/` **หรือ** `Sensor_Response_Images/` — ค่าสำรองที่ยังไม่ได้รับการปรับเทียบสำหรับเฟรมที่ไม่มีข้อมูลอ้างอิงการสะท้อนแสง; ในแต่ละรอบการประมวลผลจะมีเพียงหนึ่งในสองค่านี้เท่านั้น ซึ่งถูกเลือกโดยตั้งค่าการแก้ไข Vignette
  * `<INDEX>_Index_Images/` — โฟลเดอร์หนึ่งต่อดัชนีที่เลือก (เช่น `NDVI_Index_Images`)

{% hint style="info" %}
**ทุกผลิตภัณฑ์ที่ส่งออกจะรักษาชื่อไฟล์ต้นฉบับไว้**การส่งออก radiance ของ `capture_..._raw.tif` จะยังคงมีชื่อว่า `capture_..._raw.tif` — แต่จะอยู่ใน `tiff32/Radiance_Images/`**โฟลเดอร์คือตัวระบุผลิตภัณฑ์ ไม่ใช่ชื่อไฟล์** ดังนั้นการค้นหา `*radiance*.tif` จะไม่พบอะไร; ให้ค้นหาตามชื่อโฟลเดอร์แทน
{% endhint %}

### ควรมีไฟล์กี่ไฟล์?

อย่านับตามสูตร — จำนวนไฟล์ผลลัพธ์ขึ้นอยู่กับผลิตภัณฑ์ใดที่ถูกเปิดใช้งานและผลิตภัณฑ์ใดที่นำไปใช้กับกล้องแต่ละตัว (เช่น กล้องRGB
ไม่ได้รับข้อมูล radiance/reflectance). จำนวนที่ถูกต้องอยู่ในไฟล์บันทึก: บรรทัดสุดท้ายของ `[RUN-SUMMARY]` จะรายงานจำนวนไฟล์ที่ถูกเขียนอย่างแม่นยำ และบรรทัดคำอธิบายจะชี้แจงสิ่งที่ถูกข้ามไป

## การอ่านค่าพิกเซลการสะท้อนแสง (GIS / Pix4D / Scripts)

การสะท้อนแสงถูกเก็บไว้เป็นค่า DN แบบจำนวนเต็ม และ **ค่า DN ที่หมายถึง ρ = 1.0 ขึ้นอยู่กับกล้องต้นทาง**:

| แหล่งที่มา          | ρ = 1.0 คือ | วิธีตรวจสอบ                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768** (มีพื้นที่ว่างจนถึง ρ 2.0) | แท็ก XMP `Chloros:PixelScale=32768` ถูกบันทึกไว้ในไฟล์ |
|Survey3
         | **65535** (ถูกตัดที่ ρ 1.0)     | ไม่มีแท็ก XMP `Chloros:*` — การไม่มีแท็กนี้คือสัญญาณ |

**อ่านแท็ก `Chloros:PixelScale` และหารด้วยค่านั้น** แทนที่จะสมมติค่า 65535 แบบเหมารวม — การหารค่าการสะท้อน LATTICE ด้วย 65535 จะลดค่าทุกตัวลงครึ่งหนึ่งโดยไม่มีข้อความแจ้งเตือน มีกรณีพิเศษหนึ่งที่ไม่มีการปรับสเกลตามการออกแบบ: การจับภาพจากแหล่ง 8 บิตที่เขียนเป็นผลลัพธ์ 8 บิตจะถูกตัดค่า (clipped) ไม่ใช่ปรับสเกลใหม่ และไม่ได้รับแท็กสเกลโดยเจตนา — ให้ส่งออกใหม่ที่ 16 บิตหรือ 32 บิต แทนที่จะหารด้วยค่าดังกล่าว ดู [รูปแบบภาพออก](../output-image-formats.md) เพื่อทราบรายละเอียดทั้งหมด***

## ข้อมูลเมตาที่ส่งต่อไปยังไฟล์ส่งออก

ทุกผลิตภัณฑ์จะเก็บ **บล็อก GPS**และ**EXIF sub-IFD** ของภาพต้นฉบับไว้ ดังนั้น
ไฟล์ที่ส่งออกจะนำ **`FocalLength`**,**`FNumber`**,**`ExposureTime`**, `ISO`, `DateTimeOriginal` และ
`CameraSerialNumber` รวมถึงข้อมูลการอ้างอิงตำแหน่งทางภูมิศาสตร์ด้วย

{% hint style="warning" %}
**หากออร์โธโมเสกมีสเกลที่ผิดปกติ ให้ตรวจสอบ `FocalLength` ก่อน**
Pix4D คำนวณระยะตัวอย่างพื้นดิน (GSD) จากความยาวโฟกัสบวกกับความสูง หากไม่มีแท็กนี้
ระบบจะกลับสู่สเกลที่ผิดพลาดอย่างรุนแรง — ในการบินวัดผล 49 ภาพหนึ่งครั้ง สวนส้มขนาด 411 m × 160 m
ถูกสร้างใหม่เป็น 47.8 km × 13 km ซึ่งสร้างออร์โธโมเสก 455 เมกะพิกเซลที่ส่วนใหญ่เป็น
พื้นที่ว่างเปล่า การแบ่งภาพเป็นไทล์ที่ช้าและไฟล์ที่มีขนาดใหญ่เกินคาดเป็นอาการของปัญหานี้ ไม่ใช่
ปัญหาที่แยกกัน

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

ไม่ใช่ *ทุก* แท็กที่ถูกคัดลอก แท็กโครงสร้างของ IFD0 ถูกทิ้งไว้โดยเจตนา (การคัดลอก
แท็กเหล่านี้จะทำให้ผลลัพธ์ของ LATTICE เสียหาย) และ `ExifImageWidth` / `ExifImageHeight` ถูกยกเว้น
เนื่องจากพวกมันอธิบายการจับภาพต้นฉบับ — การส่งออกที่ถูกปรับขนาดใหม่จะ
อ้างถึงขนาดที่ขัดแย้งกับภาพแรสเตอร์ของตัวเอง

## การตรวจสอบบันทึกการดีบัก

### ตรวจสอบคำเตือนหรือข้อผิดพลาด

## ปัญหาผลลัพธ์ที่พบบ่อยและวิธีแก้ไข

### ปัญหา: ไฟล์ผลลัพธ์ขาดหายไป

**สาเหตุที่อาจเกิดขึ้น:**

* ผลิตภัณฑ์ไม่เหมาะสมกับกล้องนั้น (เช่น radiance/reflectance สำหรับกล้องRGB
— บันทึกจะระบุไว้)
* ขาดข้อมูลอ้างอิงที่จำเป็น (เช่น ค่า reflectance ที่ไม่มี target และไม่มี `.daq` downwelling)
* ช่องทำเครื่องหมายส่งออกของผลิตภัณฑ์ถูกปิดใช้งานใน Project Settings
* พื้นที่ดิสก์ไม่เพียงพอระหว่างการส่งออก

**วิธีแก้ไข:**

1. ตรวจสอบคำแนะนำ `[RUN-SUMMARY]` และบรรทัด `[EXPORT-CHECK]` ในบันทึกการดีบัก — ซึ่งอธิบายการข้ามข้อมูลตามกล้องแต่ละตัว
2. ตรวจสอบช่องทำเครื่องหมายส่งออกผลิตภัณฑ์ใน [การตั้งค่าโครงการ](adjusting-project-settings.md)
3. ตรวจสอบว่าพื้นที่ดิสก์มีเพียงพอ
4. ประมวลผลใหม่หลังจากแก้ไขสาเหตุ

### ปัญหา: ขอบมืดหรือสว่าง (Vignetting ยังคงปรากฏ)

**สาเหตุที่อาจเกิดขึ้น:**

* การแก้ไข vignetting ถูกปิด
* กล้อง/เลนส์ไม่อยู่ในฐานข้อมูลโปรไฟล์ของChloros

* Vignetting รุนแรงเกินความสามารถในการแก้ไข

**วิธีแก้ไข:**

1. ตรวจสอบว่าการแก้ไข vignetting ถูกเปิดใช้งานใน Project Settings
2. ตรวจสอบว่ารุ่นกล้องถูกตรวจจับอย่างถูกต้อง
3. ติดต่อฝ่ายสนับสนุนMAPIR
หาก vignetting ยังคงปรากฏ

### ปัญหา: สีหรือค่าไม่ถูกต้อง

**สาเหตุที่เป็นไปได้:**

* ไม่ตรวจพบเป้าหมายการปรับเทียบ
* เลือกแบบเป้าหมายการปรับเทียบผิด
* การปรับเทียบการสะท้อนถูกปิด
* ภาพเป้าหมายมีคุณภาพต่ำ

**วิธีแก้ไข:**

1. ตรวจสอบว่าการปรับเทียบการสะท้อนแสงถูกเปิดใช้งานแล้ว
2. ตรวจสอบข้อความ &quot;Target found&quot; ใน Debug Log
3. ตรวจสอบคุณภาพภาพเป้าหมาย
4. ประมวลผลใหม่โดยทำเครื่องหมายเป้าหมายที่ถูกต้อง

### ปัญหา: ค่าNDVI
ดูเหมือนไม่ถูกต้อง

**ช่วงค่าNDVI
ที่คาดหมาย:*** **น้ำ, หิน, ดิน**: -0.1 ถึง 0.2
* **พืชพรรณที่บาง/ไม่สมบูรณ์**: 0.2 ถึง 0.4
* **พืชพรรณระดับปานกลาง**: 0.4 ถึง 0.6
* **พืชพรรณที่สมบูรณ์และหนาแน่น**: 0.6 ถึง 0.9**หากค่าอยู่นอกช่วงดังกล่าว:**

1. ตรวจสอบว่าได้ทำการปรับเทียบค่าสะท้อนแล้ว
2. ตรวจสอบว่าได้รวมบันทึกข้อมูลจากเซ็นเซอร์แสงแล้ว
3. ตรวจสอบว่าได้ตรวจพบเป้าหมายการปรับเทียบแล้ว
4. ตรวจสอบว่าได้ตรวจพบรุ่นกล้องที่ถูกต้องแล้ว
5. ตรวจสอบเวลาและสภาพการถ่ายภาพเป้าหมาย
6. หากคำนวณดัชนีด้วยตนเองจากไฟล์การสะท้อนแสง ให้ยืนยันว่าได้หารด้วยค่า `Chloros:PixelScale` ของไฟล์ (ดูข้างต้น)

## การใช้ภาพที่ผ่านการประมวลผล

### สำหรับการสร้างภาพโฟโตแกรมเมตรี / ออร์โธโมเสก

**ขั้นตอนการทำงานที่แนะนำ:**

1.**นำเข้าภาพสะท้อนแสงที่ผ่านการปรับเทียบ** เข้าสู่ซอฟต์แวร์โฟโตแกรมเมตรี:
   * Pix4Dmapper
   * Agisoft Metashape
   * DroneDeploy
   * WebODM
2. **รักษาข้อมูลเมตาดาต้า EXIF**: ตรวจสอบให้แน่ใจว่าข้อมูล GPS ถูกรักษาไว้เพื่อการติดแท็กตำแหน่งทางภูมิศาสตร์
3. **ขั้นตอนการทำงานที่ผ่านการปรับเทียบ**: ใช้ภาพสะท้อนแสงเพื่อความแม่นยำทางวิทยาศาสตร์ — ภาพสะท้อนแสง LATTICE มีแท็กการปรับเทียบ XMP ที่ Pix4D สามารถอ่านได้
4. **ประมวลผลภาพโมเสกดัชนี**: สร้างภาพออร์โธโมเสกแบบดัชนี (NDVI
) จากภาพดัชนีแต่ละภาพ
5. **ส่งออกภาพโมเสกออร์โธที่อ้างอิงตำแหน่งทางภูมิศาสตร์ (GeoTIFF
)**: เพื่อใช้ในแอปพลิเคชัน GIS

### สำหรับการวิเคราะห์ GIS

**ขั้นตอนการทำงานที่แนะนำ:**

1.**โหลดเข้า QGIS, ArcGIS หรือโปรแกรมที่คล้ายกัน**

2.**ใช้ภาพสะท้อนแสง 16-bitTIFF
** สำหรับการวิเคราะห์หลายแถบ (แบ่งด้วยค่า `Chloros:PixelScale` ของไฟล์)
3. **ใช้ภาพดัชนี** (NDVI
,NDRE
) เป็นชั้นข้อมูลพืชที่พร้อมใช้งาน
4. **เครื่องคำนวณราสเตอร์**: รวมแถบเพื่อวิเคราะห์ตามความต้องการ
5. **ส่งออก**: สร้างแผนที่การจัดประเภท, การตรวจจับการเปลี่ยนแปลง, และแผนที่สุขภาพพืช

### สำหรับการวิเคราะห์โดยตรง / การรายงาน

**ขั้นตอนการทำงานที่แนะนำ:**

1.**ใช้ภาพดัชนีพร้อมสี LUT** สำหรับรายงานแบบภาพ
2. **สกัดข้อมูลสถิติ**: ค่าเฉลี่ยNDVI
ต่อพื้นที่/แปลง
3. **ชุดข้อมูลตามเวลา**: เปรียบเทียบดัชนีระหว่างหลายช่วงเวลา
4. **สร้างรายงาน**: รวมแผนที่ ข้อมูลสถิติ และการแสดงผลแบบภาพ***

## การเก็บรักษาและสำรองข้อมูล

### กลยุทธ์การสำรองข้อมูลที่แนะนำ

**สิ่งที่ควรเก็บ:*** ✅ **ภาพ RAW/JPG ต้นฉบับหรือภาพดิบ LATTICE** - เก็บไว้ในไดรฟ์/คลาวด์แยกต่างหาก; ภาพดิบเป็นแหล่งข้อมูลของกระบวนการ และข้อมูลอื่น ๆ สามารถสร้างขึ้นใหม่ได้จากภาพดิบนี้
* ✅ **ไฟล์เซ็นเซอร์แสง `.daq` / `.csv`** - จำเป็นสำหรับการคำนวณค่าสะท้อนแสงใหม่ในภายหลัง
* ✅ **ผลลัพธ์ที่ผ่านการประมวลผล** - เก็บภาพที่ผ่านการปรับเทียบและดัชนี
* ✅ **โฟลเดอร์โครงการ** (`project.json` และไฟล์ที่เกี่ยวข้อง) - ประกอบด้วยตั้งค่าทั้งหมดสำหรับการประมวลผลใหม่หากจำเป็น
* ✅ **บันทึกการดีบัก** - บันทึกรายละเอียดการประมวลผล
* ✅ **ภาพเป้าหมายการปรับเทียบ** - เพื่อการตรวจสอบและประมวลผลใหม่**คำแนะนำในการจัดเก็บ:*** **การสำรองข้อมูลทันที**: ฮาร์ดดิสก์ภายนอก
* **การเก็บถาวรระยะยาว**: การจัดเก็บข้อมูลบนคลาวด์ (Google Drive, Dropbox, เป็นต้น)
* **ข้อมูลสำคัญ**: เก็บสำเนา 2-3 ชุดไว้ในสถานที่ต่างกัน***

## การประมวลผลครั้งต่อไป

## การแก้ไขปัญหาในการประมวลผลหลังการถ่าย

### การประมวลผลใหม่ด้วยตั้งค่าต่าง ๆ

หากผลลัพธ์ไม่เป็นที่พอใจ:

1. เก็บภาพต้นฉบับไว้ (อย่าลบเด็ดขาด)

3. ปรับตั้งค่าในแผง Project Settings
4. ประมวลผลใหม่ — ผลลัพธ์จะถูกจัดเก็บในโฟลเดอร์ผลิตภัณฑ์เดียวกัน ดังนั้นไฟล์ที่มีชื่อเดียวกันจากการประมวลผลครั้งก่อนจะถูกแทนที่

เพื่อประมวลผลใหม่เฉพาะภาพที่ต้องการ:

1. สร้างโครงการใหม่
2. นำเข้าเฉพาะภาพที่ต้องการประมวลผลใหม่
3. ใช้แม่แบบการตั้งค่าเดิม
4. ประมวลผลชุดข้อมูลที่เล็กลง
