# การเสร็จสิ้นการประมวลผล

เมื่อChloros
เสร็จสิ้นการประมวลผลแล้ว ก็ถึงเวลาตรวจสอบผลลัพธ์ ตรวจสอบคุณภาพผลลัพธ์ และเตรียมภาพที่ผ่านการประมวลผลเพื่อใช้ในกระบวนการทำงานของคุณ หน้านี้จะนำคุณผ่านขั้นตอนสุดท้ายและขั้นตอนต่อไป

## สัญญาณการเสร็จสิ้นการประมวลผล

เมื่อการประมวลผลเสร็จสิ้นอย่างสำเร็จ คุณจะเห็นสัญญาณหลายอย่าง:

* ✅ **แถบความคืบหน้า**: ถึง 100% เสร็จสมบูรณ์
* ✅ **บันทึกการดีบัก**: แสดงบรรทัด `[RUN-SUMMARY]` สุดท้ายพร้อมจำนวน (ภาพ, กลุ่มกล้อง, เป้าหมาย, ภาพที่ปรับเทียบแล้ว, ไฟล์ที่เขียน)
* ✅ **ปุ่มเริ่ม**: กลับมาใช้งานได้อีกครั้ง (พร้อมสำหรับการประมวลผลครั้งต่อไป)
* ✅ **ไฟล์ผลลัพธ์**: ภาพทั้งหมดที่ผ่านการประมวลผลถูกบันทึกไว้ในโครงสร้างโฟลเดอร์ผลลัพธ์ของโครงการ (ด้านล่าง)

{% hint style="warning" %}
**การประมวลผลที่ไม่บันทึกภาพใด ๆ ถือเป็นการล้มเหลว.** หากคุณขอผลิตภัณฑ์ภาพแต่การรันไม่เขียนภาพใดเลย Chloros
จะรายงานว่าเป็นการล้มเหลว — ชื่อล็อก `[RUN-SUMMARY]` จะชี้ให้เห็นสาเหตุที่เป็นไปได้ (ไม่มีการนำเข้าข้อมูล ไม่พบเป้าหมาย หรือผลิตภัณฑ์ที่ขอทั้งหมดถูกข้ามไปเนื่องจากไม่เหมาะสม) คำสั่ง CLI
ที่เทียบเท่าจะออกค่าที่ไม่เท่ากับศูนย์ การรันที่ตั้งใจให้สร้างเฉพาะเมตาดาต้า (ปิดผลิตภัณฑ์ส่งออกทั้งหมด, ไม่มีดัชนี) ยังคงถือว่าสำเร็จ ดู [คู่มืออ้างอิงCLI
](../reference/cli-reference.md#a-run-that-writes-no-images-fails).
{% endhint %}

## การค้นหาภาพที่ผ่านการประมวลผล

### การเปิดโฟลเดอร์ผลลัพธ์

1. คลิกไอคอน **เมนูหลัก** <img src="../.gitbook/assets/image (1) (1) (1) (1).png" alt="" data-size="line">
(มุมซ้ายบน)
2. เลือก **&quot;เปิดโฟลเดอร์โครงการ&quot;**

3. โปรแกรมจัดการไฟล์จะเปิดไปยังไดเรกทอรีโครงการ
4. ค้นหาโครงการของคุณตามชื่อ

### โครงสร้างโฟลเดอร์ผลลัพธ์

ไฟล์ผลลัพธ์จะถูกบันทึก **ภายในโฟลเดอร์โครงการ โดยจัดกลุ่มตามกล้อง และตามรูปแบบไฟล์**:

```
<project>/
└── LATT-M3M-L41-F550/                  # one folder per camera
    ├── tiff16/
    │   ├── Reflectance_Calibrated_Images/
    │   ├── Debayered_Images/
    │   ├── Preview_Images/
    │   └── NDVI_Index_Images/           # one folder per selected index
    └── tiff32/
        └── Radiance_Images/             # float32 radiance always lands here
```

* **โฟลเดอร์กล้อง**: `LATT-<sensor>-<lens>-F<filter>` สำหรับ LATTICE (ตรงกับ EXIF ของภาพที่ถ่าย `Model`), `<model>_<filter>` สำหรับSurvey3
(เช่น `Survey3N_RGN`). กล้องสองตัวที่ใช้เซ็นเซอร์และฟิลเตอร์ร่วมกัน แต่มีเลนส์ต่างกัน จะเก็บไว้ในโครงสร้างโฟลเดอร์แยกกัน — เนื่องจากมีผลวินเนตต์ มุมมองภาพ และความบิดเบือนที่แตกต่างกัน
* **รูปแบบโฟลเดอร์**: ตามการตั้งค่ารูปแบบการส่งออกของคุณ — `tiff16`, `tiff8`, `png8`, `jpg8`, หรือ `tiff32` สำหรับTIFF
(32 บิต, เปอร์เซ็นต์) ค่าความส่องสว่าง (Radiance) เป็น float32 เสมอ และถูกจัดเก็บภายใต้ `tiff32` เสมอ
* **โฟลเดอร์ผลิตภัณฑ์**:
  * `Reflectance_Calibrated_Images/` — ค่าการสะท้อนที่ผ่านการปรับเทียบ
  * `Debayered_Images/` — การถอดเบย์เออร์แบบเชิงเส้น (LATTICE): ได้ลบค่าออฟเซ็ตความมืดและถอดเบย์เออร์แล้ว โดยไม่ใช้ฟิลด์แบนหรือการแยกสี (unmix) ในทิศทางดั้งเดิมของเซ็นเซอร์
  * `Preview_Images/` — การแสดงตัวอย่างบนหน้าจอ (LATTICE)
  * `Radiance_Images/` — ความส่องสว่างสเปกตรัมแบบ float32, W/m²/sr/nm (LATTICE multispectral)
  * `Vignette_Corrected_Images/` **หรือ** `Sensor_Response_Images/` — ตัวเลือกสำรองที่ยังไม่ได้รับการปรับเทียบ สำหรับเฟรมที่ไม่มีข้อมูลอ้างอิงการสะท้อนแสง; มีเพียงหนึ่งตัวจากสองตัวนี้ต่อการรันหนึ่งครั้ง ซึ่งถูกเลือกโดยตั้งค่าการแก้ไข Vignette
  * `<INDEX>_Index_Images/` — โฟลเดอร์หนึ่งต่อดัชนีที่เลือก (เช่น `NDVI_Index_Images`)
* **`clamp_masks/`** (ใหม่ในเวอร์ชัน 1.3.0, เฉพาะกล้อง LATTICE multispectral M3C): ปรากฏในโฟลเดอร์รูปแบบ (format folder) ข้างๆ โฟลเดอร์ผลิตภัณฑ์ เมื่อการแยกแบนด์ (band unmix) ตัดค่าลบที่เกินขอบเขตให้เป็นศูนย์ในผลิตภัณฑ์ radiance หรือ reflectance มันเก็บมาสก์ต่อพิกเซลหนึ่งชิ้นต่อผลิตภัณฑ์ที่ได้รับผลกระทบ เช่น `tiff16/clamp_masks/Reflectance_Calibrated_Images/<name>_clampmask.tif` มาสก์ไม่เคยอยู่ภายในโฟลเดอร์ผลิตภัณฑ์ ดังนั้นโฟลเดอร์ผลิตภัณฑ์จึงสามารถส่งไปยังซอฟต์แวร์โฟโตแกรมเมตรีได้โดยตรง ดู [Clamp masks](../output-image-formats.md#clamp-masks).

{% hint style="info" %}
**ทุกผลิตภัณฑ์ที่ส่งออกจะรักษาชื่อไฟล์ต้นฉบับไว้**การส่งออก radiance ของ `capture_..._raw.tif` จะยังคงมีชื่อว่า `capture_..._raw.tif` — แต่มันจะอยู่ใน `tiff32/Radiance_Images/`**โฟลเดอร์คือตัวระบุผลิตภัณฑ์ ไม่ใช่ชื่อไฟล์** ดังนั้นการค้นหา `*radiance*.tif` จะไม่พบอะไร; ให้ค้นหาตามชื่อโฟลเดอร์แทน
{% endhint %}

### ควรมีไฟล์กี่ไฟล์?

อย่าใช้สูตรในการนับ — จำนวนผลลัพธ์ขึ้นอยู่กับผลิตภัณฑ์ที่ถูกเปิดใช้งานและผลิตภัณฑ์ใดที่นำไปใช้กับกล้องแต่ละตัว (เช่น กล้องRGB
ไม่ได้รับค่า radiance/reflectance) จำนวนที่ถูกต้องอยู่ในไฟล์บันทึก: บรรทัดสุดท้ายของ `[RUN-SUMMARY]` จะรายงานจำนวนไฟล์ที่ถูกเขียนอย่างแม่นยำ และบรรทัดคำอธิบายจะชี้แจงสิ่งที่ถูกข้ามไป

## ตรวจสอบภาพที่ผ่านการประมวลผล

### ดูตัวอย่างอย่างรวดเร็วใน File Explorer

**ฟังก์ชันดูตัวอย่างในตัวของ Windows
:**

1. ไปยังโฟลเดอร์ผลิตภัณฑ์ (เช่น `tiff16/Reflectance_Calibrated_Images/`)
2. เลือกไฟล์ภาพ
3. ภาพตัวอย่างจะปรากฏในช่องแสดงตัวอย่างของWindows
Explorer

* **IrfanView** - โปรแกรมดูภาพที่รวดเร็วและเบา (รองรับไฟล์ TIFF
)
* **Adobe Photoshop** - การแก้ไขภาพระดับมืออาชีพ (รองรับไฟล์ TIFF
)
* **GIMP** - ทางเลือกฟรีสำหรับ Photoshop
* **Windows
Photos** - การดูภาพขั้นพื้นฐาน (อาจไม่รองรับไฟล์ TIFF
16 บิต)

## การอ่านค่าพิกเซลการสะท้อนแสง (GIS / Pix4D / Scripts)

ค่าการสะท้อนถูกเก็บไว้เป็น DN แบบจำนวนเต็ม และ **ค่า DN ที่หมายถึง ρ = 1.0 ขึ้นอยู่กับกล้องต้นทาง**:

| แหล่งที่มา          | ρ = 1.0 คือ | วิธีตรวจสอบ                                        |
| --------------- | ---------- | -------------------------------------------------- |
| LATTICE (M3C/M3M) | **32768** (มีพื้นที่ว่างจนถึง ρ 2.0) | แท็ก XMP `Chloros:PixelScale=32768` ถูกบันทึกไว้ในไฟล์ |
| Survey3
         | **65535** (ถูกตัดที่ ρ 1.0)     | ไม่มีแท็ก `Chloros:PixelScale` — การไม่มีแท็กนี้คือสัญญาณ (ผลิตภัณฑ์ Survey3
มีแท็กการประมวลผล `Chloros:*` อื่นๆ) |

**อ่านแท็ก `Chloros:PixelScale` และหารด้วยค่านั้น** แทนที่จะสมมติค่า 65535 แบบเหมารวม — การหารค่าการสะท้อนแสง LATTICE ด้วย 65535 จะทำให้ค่าทุกค่าลดลงครึ่งหนึ่งโดยไม่มีข้อความแจ้งเตือน ไฟล์ค่าสะท้อนแสงจากเวอร์ชันก่อน 1.3.0 ที่เขียนในรูปแบบ 8-bit จะถูกตัดค่า (clipped) ไม่ใช่ปรับสเกลใหม่ (rescaled) และไม่มีแท็กสเกล: ให้ส่งออกใหม่ในรูปแบบ 16-bit หรือ 32-bit แทนที่จะหารด้วยค่าดังกล่าว ดู [รูปแบบภาพผลลัพธ์](../output-image-formats.md) เพื่อทราบรายละเอียดทั้งหมด***

## ข้อมูลเมตาดาต้าที่ถูกส่งต่อไปยังไฟล์ส่งออก

ทุกผลิตภัณฑ์จะเก็บ **บล็อก GPS**และ**EXIF sub-IFD** ของการจับภาพต้นฉบับไว้ ดังนั้น
การส่งออกจะนำข้อมูล `FocalLength`, `FNumber`, `ExposureTime`, `ISO`, `DateTimeOriginal` และ
`CameraSerialNumber` รวมถึงข้อมูลการอ้างอิงทางภูมิศาสตร์ด้วย

{% hint style="warning" %}
**หากออร์โธโมเสกมีสเกลที่ผิดปกติ ให้ตรวจสอบ `FocalLength` ก่อน**
Pix4D คำนวณระยะตัวอย่างพื้นดิน (GSD) จากความยาวโฟกัสบวกกับความสูง หากไม่มีแท็กนี้
ระบบจะกลับไปใช้มาตราส่วนที่ผิดอย่างมาก — ในการบินที่วัดได้ 49 ภาพหนึ่งครั้ง สวนส้มขนาด 411 ม. × 160 ม.
สวนส้มถูกสร้างใหม่เป็น 47.8 กม. × 13 กม. ทำให้ได้ออร์โธโมเสก 455 เมกะพิกเซลที่ส่วนใหญ่เป็น
พื้นที่ว่างเปล่า การจัดเรียงไทล์ที่ช้าและไฟล์ที่มีขนาดใหญ่เกินคาดเป็นอาการของปัญหานี้ ไม่ใช่
ปัญหาแยกต่างหาก

```bash
exiftool -FocalLength -GPSLatitude "YourProject/.../some_export.tif"
```
{% endhint %}

ไม่ใช่ *ทุก* แท็กที่ถูกคัดลอก แท็กโครงสร้างของ IFD0 ถูกทิ้งไว้โดยเจตนา (การคัดลอก
แท็กเหล่านี้จะทำให้ผลลัพธ์ของ LATTICE เสียหาย) และ `ExifImageWidth` / `ExifImageHeight` ถูกยกเว้น
เนื่องจากพวกมันอธิบายการจับภาพต้นฉบับ — การส่งออกที่ถูกปรับขนาดใหม่จะ
ระบุขนาดที่ขัดแย้งกับราสเตอร์ของตัวเอง

Chloros
ยังเขียนแท็ก XMP ของตัวเอง `Chloros:*` ที่อธิบายถึงสิ่งที่ได้ดำเนินการกับผลิตภัณฑ์แต่ละชิ้น
(เช่น `Chloros:ProcessingLevel`, `Chloros:CalibrationApplied`,
`Chloros:VignetteCorrected`) เนื่องจากตั้งแต่เวอร์ชัน 1.3.0 เป็นต้นไป ผลิตภัณฑ์Survey3
จะนำแท็กเหล่านี้มาใช้ในทุกขั้นตอนการประมวลผล
ผลิตภัณฑ์ดัชนีจะอธิบายดัชนีเอง (`Chloros:ProcessingLevel=index`,
สูตร และว่าถูกคำนวณจากค่าสะท้อนหรือค่าความสว่าง) แทนที่จะซ้ำ
แท็กของข้อมูลดิบต้นทาง และผลิตภัณฑ์ในโฟลเดอร์ที่ลึกกว่า 260 ตัวอักษรจะเก็บเมตาดาต้า
ไว้ด้วย ดู [รูปแบบภาพผลลัพธ์](../output-image-formats.md#index-products).

## การตรวจสอบบันทึกการดีบัก

### ตรวจสอบคำเตือนหรือข้อผิดพลาด

1. เปิดแท็บ **Debug Log** <img src="../.gitbook/assets/icon_log.JPG" alt="" data-size="line">

2. เลื่อนดูข้อความ
3. ค้นหาคำเตือนสีเหลืองหรือข้อผิดพลาดสีแดง
4. อ่านบรรทัด `[RUN-SUMMARY]` และคำแนะนำใดๆ
5. ติดต่อฝ่ายสนับสนุน MAPIR
เพื่อขอความช่วยเหลือ

### การบันทึกไฟล์บันทึก

เพื่อเก็บบันทึกการประมวลผลหรือส่งไปยังทีมสนับสนุน MAPIR
:

1. คลิกปุ่ม **&quot;Copy&quot;**หรือ**&quot;Download&quot;**

2. บันทึกเป็นไฟล์ข้อความในโฟลเดอร์โครงการ
3. แนบไปกับเอกสารโครงการ
4. ส่งไปยังทีมสนับสนุน MAPIR
หากพบปัญหา

เพื่อส่งปัญหาโดยตรงไปยัง MAPIR
ให้ใช้ไอคอนข้อผิดพลาด (**Report a bug**) ที่ด้านบนของแท็บ Debug Log — ดู [รายงานข้อผิดพลาดจากแท็บ log](monitoring-the-processing.md#reporting-a-bug-from-the-log-tab).***

## ปัญหาผลลัพธ์ที่พบบ่อยและวิธีแก้ไข

### ปัญหา: ไฟล์ผลลัพธ์ขาดหาย

**สาเหตุที่อาจเกิดขึ้น:**

* ผลิตภัณฑ์นี้ไม่รองรับกล้องดังกล่าว (เช่น radiance/reflectance สำหรับกล้องRGB
— บันทึกจะระบุไว้)
* ขาดการอ้างอิงที่จำเป็น (เช่น ค่าสะท้อนแสงที่ไม่มีเป้าหมายและไม่มี `.daq` downwelling)
* ช่องทำเครื่องหมายส่งออกของผลิตภัณฑ์ถูกปิดใช้งานใน Project Settings
* พื้นที่ดิสก์ไม่เพียงพอระหว่างการส่งออก

**วิธีแก้ไข:**

1. ตรวจสอบคำแนะนำ `[RUN-SUMMARY]` และบรรทัด `[EXPORT-CHECK]` ในบันทึกการดีบัก — ซึ่งอธิบายการข้ามข้อมูลตามกล้องแต่ละตัว
2. ตรวจสอบช่องทำเครื่องหมายส่งออกผลิตภัณฑ์ใน [การตั้งค่าโครงการ](adjusting-project-settings.md)
3. ตรวจสอบว่าพื้นที่ดิสก์มีเพียงพอ
4. ประมวลผลใหม่หลังจากแก้ไขสาเหตุ

### ปัญหา: ขอบมืดหรือสว่าง (ปรากฏการณ์วิเนตติ้งยังคงเห็นได้)

**สาเหตุที่อาจเกิดขึ้น:**

* การแก้ไข vignetting ถูกปิด
* กล้อง/เลนส์ไม่อยู่ในฐานข้อมูลโปรไฟล์Chloros

* Vignetting รุนแรงเกินขีดความสามารถในการแก้ไข

**วิธีแก้ไข:**

1. ตรวจสอบว่าการแก้ไข vignetting ถูกเปิดใน Project Settings
2. ตรวจสอบว่ารุ่นกล้องถูกตรวจจับอย่างถูกต้อง
3. ติดต่อฝ่ายสนับสนุนMAPIR
หาก vignetting ยังคงปรากฏ

### ปัญหา: สีหรือค่าไม่ถูกต้อง

**สาเหตุที่อาจเกิดขึ้น:**

* ไม่ตรวจพบเป้าหมายการปรับเทียบ
* เลือกแบบเป้าหมายการปรับเทียบผิด
* การปรับเทียบการสะท้อนแสงถูกปิด
* ภาพเป้าหมายมีคุณภาพต่ำ

**วิธีแก้ไข:**

1. ตรวจสอบว่าการปรับเทียบการสะท้อนแสงถูกเปิดใช้งาน
2. ตรวจสอบข้อความ &quot;Target found&quot; ใน Debug Log
3. ตรวจสอบคุณภาพภาพเป้าหมาย
4. ประมวลผลใหม่โดยทำเครื่องหมายเป้าหมายที่ถูกต้อง

### ปัญหา: ค่าNDVI
ดูเหมือนไม่ถูกต้อง

**ช่วงค่าNDVI
ที่คาดการณ์:*** **น้ำ, หิน, ดิน**: -0.1 ถึง 0.2
* **พืชพรรณที่บาง/ไม่แข็งแรง**: 0.2 ถึง 0.4
* **พืชพรรณระดับปานกลาง**: 0.4 ถึง 0.6
* **พืชพรรณที่สมบูรณ์และหนาแน่น**: 0.6 ถึง 0.9**หากค่าอยู่นอกช่วงดังกล่าว:**

1. ตรวจสอบว่าได้ทำการปรับเทียบการสะท้อนแสงแล้ว
2. ตรวจสอบว่าบันทึกข้อมูลเซ็นเซอร์แสงถูกรวมไว้
3. ตรวจสอบว่าเป้าหมายการปรับเทียบถูกตรวจพบ
4. ตรวจสอบว่าได้ตรวจพบรุ่นกล้องที่ถูกต้อง
5. ตรวจสอบเวลาและสภาพการถ่ายภาพเป้าหมาย
6. หากคำนวณดัชนีด้วยตัวเองจากไฟล์การสะท้อนแสง ให้ยืนยันว่าได้หารด้วยค่า `Chloros:PixelScale` ของไฟล์ (ดูข้างบน)

## การใช้ภาพที่ผ่านการประมวลผล

### สำหรับการสร้างภาพโฟโตแกรมเมตรี / ออร์โธโมเสก

**ขั้นตอนการทำงานที่แนะนำ:**

1.**นำเข้าภาพสะท้อนแสงที่ผ่านการปรับเทียบ** เข้าสู่ซอฟต์แวร์โฟโตแกรมเมตรี:
   * Pix4Dmapper
   * Agisoft Metashape
   * DroneDeploy
   * WebODM
2. **รักษาข้อมูลเมตาดาต้า EXIF**: ตรวจสอบให้แน่ใจว่าข้อมูล GPS ถูกรักษาไว้เพื่อการติดแท็กตำแหน่งทางภูมิศาสตร์
3. **ขั้นตอนการทำงานที่ผ่านการปรับเทียบ**: ใช้ภาพสะท้อนแสงเพื่อความแม่นยำทางวิทยาศาสตร์ — ภาพสะท้อนแสง LATTICE มีแท็กการปรับเทียบ XMP ที่ Pix4D สามารถอ่านได้
4. **ประมวลผลภาพโมเสกดัชนี**: สร้างภาพออร์โธโมเสกNDVI
จากภาพดัชนีแต่ละภาพ
5. **ส่งออกไฟล์GeoTIFF
ที่มีการอ้างอิงตำแหน่ง**: เพื่อใช้ในแอปพลิเคชัน GIS

### สำหรับการวิเคราะห์ GIS

**ขั้นตอนการทำงานที่แนะนำ:**

1.**โหลดเข้า QGIS, ArcGIS หรือโปรแกรมที่คล้ายกัน**

2.**ใช้ภาพสะท้อนแสง TIFF
16 บิต** สำหรับการวิเคราะห์หลายแถบ (แบ่งตามค่า `Chloros:PixelScale` ของไฟล์)
3. **ใช้ภาพดัชนี** (NDVI
, NDRE
) เป็นชั้นพืชที่พร้อมใช้งาน
4. **เครื่องคำนวณแรสเตอร์**: รวมแถบเพื่อวิเคราะห์ตามความต้องการ
5. **ส่งออก**: สร้างแผนที่การจัดประเภท, การตรวจจับการเปลี่ยนแปลง, และแผนที่สุขภาพพืช

### สำหรับการวิเคราะห์ / รายงานโดยตรง

**ขั้นตอนการทำงานที่แนะนำ:**

1.**ใช้ภาพดัชนีที่มีสี LUT** สำหรับรายงานแบบภาพ
2. **สกัดข้อมูลสถิติ**: ค่าเฉลี่ยNDVI
ต่อแปลง/พื้นที่
3. **ชุดข้อมูลตามเวลา**: เปรียบเทียบดัชนีระหว่างหลายช่วงเวลา
4. **สร้างรายงาน**: รวมแผนที่ ข้อมูลสถิติ และการแสดงผลแบบภาพ***

## การเก็บรักษาและสำรองข้อมูล

### กลยุทธ์การสำรองข้อมูลที่แนะนำ

**สิ่งที่ควรเก็บ:*** ✅ **ภาพ RAW/JPG ต้นฉบับ หรือภาพดิบ LATTICE** - เก็บไว้ในไดรฟ์/คลาวด์แยกต่างหาก; ภาพดิบเป็นแหล่งข้อมูลของกระบวนการ และข้อมูลอื่น ๆ สามารถสร้างขึ้นใหม่ได้จากภาพดิบนี้
* ✅ **ไฟล์เซ็นเซอร์แสง `.daq` / `.csv`** - จำเป็นสำหรับการคำนวณค่าสะท้อนแสงใหม่ในภายหลัง
* ✅ **ผลลัพธ์ที่ผ่านการประมวลผล** - เก็บภาพที่ผ่านการปรับเทียบและดัชนี
* ✅ **โฟลเดอร์โครงการ** (`project.json` และไฟล์ที่เกี่ยวข้อง) - มีตั้งค่าทั้งหมดสำหรับการประมวลผลใหม่หากจำเป็น
* ✅ **บันทึกการแก้ไขข้อผิดพลาด** - บันทึกรายละเอียดการประมวลผล
* ✅ **ภาพเป้าหมายการปรับเทียบ** - เพื่อการตรวจสอบและประมวลผลใหม่**คำแนะนำในการจัดเก็บ:*** **สำรองข้อมูลทันที**: ฮาร์ดดิสก์ภายนอก
* **เก็บถาวรระยะยาว**: พื้นที่จัดเก็บข้อมูลบนคลาวด์ (Google Drive, Dropbox, เป็นต้น)
* **ข้อมูลสำคัญ**: เก็บสำเนา 2-3 ชุดไว้ในสถานที่ต่างกัน***
