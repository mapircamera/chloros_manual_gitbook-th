# DAQ-E เครือข่ายและการซิงค์เวลา

> การตั้งค่าเครือข่ายทางกายภาพสำหรับเซ็นเซอร์ — การติดตั้งสายเคเบิล, PoE, การกำหนดที่อยู่ IP และการตั้งค่าเครือข่ายของอุปกรณ์ — มีอยู่ใน **[คู่มือผู้ใช้ DAQ](https://mapir.gitbook.io/daq/daq-e/network-setup)**. หน้านี้อธิบายส่วนที่เกี่ยวข้องกับChloros: การเชื่อมต่อ การซิงค์เวลา และวิธีแก้ไขเมื่อการค้นหาไม่พบอุปกรณ์

DAQ-E เป็นสมาชิก Ethernet ในตระกูล DAQ: ใช้พลังงานผ่าน PoE, ถูกค้นพบผ่าน mDNS (บริการ `_daq-e._tcp`), และสามารถระบุที่อยู่ได้โดยใช้ชื่อโฮสต์ที่สร้างจาก ID ของเซ็นเซอร์ — `daq-e-<6 hex>.local`, เช่น `daq-e-def330.local` หน้านี้อธิบายวิธีการส่งข้อมูลบนเครือข่ายและวิธีการเข้าร่วมการซิงค์เวลา PTP

## โหมดการส่งข้อมูล

| โหมด | จุดปลาย | ผู้รับ | หมายเหตุ |
| --- | --- | --- | --- |
| **Multicast** (ค่าเริ่มต้น) | UDP `239.10.10.10:5002` | อุปกรณ์ใดก็ตามใน LAN เดียวกันจะรับสตรีมเดียวกัน | ทุกดาตาแกรมได้รับการตรวจสอบความถูกต้องด้วย CRC-16/CCITT |
| **Raw** | TCP port `5000` | ลูกค้าเพียงหนึ่งเครื่องเท่านั้น (แบบเอกสิทธิ์) | เข้ากันได้กับ DAQ-U ในระดับไบต์ |

Chloros ใช้ multicast เป็นค่าเริ่มต้น ซึ่งทำให้ GUI, CLI และ SDK สามารถติดตามเซ็นเซอร์หนึ่งตัวพร้อมกันได้

## ข้อกำหนดด้านเครือข่าย

* **โดเมนการส่งสัญญาณกระจายเดียวกัน** เครื่องที่รันChloros ต้องอยู่ในเซกเมนต์เครือข่าย L2 เดียวกันกับเซ็นเซอร์ — การค้นหาผ่าน mDNS ไม่สามารถผ่านเราเตอร์ได้
* **ไฟร์วอลล์** บน Windows โปรแกรมติดตั้งจะเพิ่มกฎไฟร์วอลล์ **Chloros Backend (UDP-In)**สำหรับแบ็กเอนด์ ในทุกโปรไฟล์เครือข่าย ซึ่งครอบคลุมข้อมูล DAQ-E (UDP 5002), mDNS (UDP 5353) และ PTP (UDP 319/320) รวมถึงกฎ**Chloros Backend (TCP-In)** ที่จำกัดอยู่ในซับเน็ตท้องถิ่น สำหรับการเชื่อมต่อที่ DAQ-E สร้างกลับไปยังคอมพิวเตอร์ระหว่างการอัปเดตเฟิร์มแวร์ บนระบบLinux, `.deb` จะเปิดพอร์ต UDP ใน `ufw` หรือ `firewalld` เมื่อไฟร์วอลล์ดังกล่าวถูกเปิดใช้งานในช่วงการติดตั้ง ไฟร์วอลล์ของบุคคลที่สาม หรือไฟร์วอลล์ที่เปิดใช้งานในภายหลัง ต้องอนุญาตให้ใช้พอร์ตเดียวกัน
* **แหล่งจ่ายไฟ PoE, ไม่มีไฟ LED แสดงสถานะ** DAQ-E ไม่มีไฟ LED ของตัวเอง — ตรวจสอบสถานะการจ่ายไฟผ่านตัวบ่งชี้ลิงก์/PoE บนสวิตช์หรือพอร์ตอินเจกเตอร์ และรอสักครู่หลังเปิดเครื่องเพื่อให้อุปกรณ์บูตและเชื่อมต่อกับเครือข่าย

## การเชื่อมต่อ

**GUI:** แท็บ Light Sensors → Connect Sensor → ประเภทอุปกรณ์ "DAQ-E (Ethernet)". การค้นหาอุปกรณ์จะทำงานเฉพาะเมื่อหน้าต่างการเชื่อมต่อปรากฏบนหน้าจอ (การค้นหา mDNS พร้อมกับการสแกน ARP บนWindows) โดยทำซ้ำทุก 15 วินาที; ปุ่ม Refresh จะสแกนใหม่ทันที เซ็นเซอร์ที่ตรวจพบจะปรากฏในเมนูแบบเลื่อนลง; เซ็นเซอร์ที่ตรวจพบเป็นเครื่องแรกจะถูกเลือกอัตโนมัติ

<!-- SCREENSHOT-NEEDED: DAQ connect dialog with Device Type set to "DAQ-E (Ethernet)" and at least one discovered sensor listed in the Hostname/IP dropdown (e.g. daq-e-xxxxxx.local), Connect button enabled. -->

**CLI** (ระบบหลังทำงาน):

```bash
chloros-cli daq pool-connect --eth                              # auto-discover on the LAN
chloros-cli daq pool-connect --eth-host daq-e-def330.local      # explicit host — the reliable form
chloros-cli daq pool-connect --eth-host 192.168.1.57            # a plain IP works too
```

DAQ-E ที่อยู่ในกลุ่มแล้วจะถูกระบุทั้งจากชื่อโฮสต์และที่อยู่ IP: การเชื่อมต่อใหม่ด้วยที่อยู่ IP ที่ต่างออกไปจะคืนค่าข้อมูลที่มีอยู่ในกลุ่มแทนที่จะเปิดอุปกรณ์นั้นขึ้นเป็นครั้งที่สอง

### โฮสต์ที่มีหลาย NIC และการเชื่อมต่อครั้งแรกหลังการบูต

บนโฮสต์ที่มีอินเทอร์เฟซเครือข่ายที่ใช้งานอยู่มากกว่าหนึ่งตัว **การเชื่อมต่อครั้งแรก** `pool-connect --eth` หลังการบูตอาจไม่พบอุปกรณ์ แม้เซ็นเซอร์จะอยู่ในสภาพดี — การค้นหาอาจพลาดอินเทอร์เฟซที่เซ็นเซอร์ใช้งานอยู่ เนื่องจากแคช ARP ยังไม่พร้อมใช้งาน วิธีแก้ไขที่เชื่อถือได้คือการข้ามขั้นตอนการค้นหาและระบุที่อยู่โดยตรง:

```bash
chloros-cli daq pool-connect --eth-host daq-e-def330.local
```

`--eth-host` รับชื่อโฮสต์ mDNS หรือ IP ได้เสมอ มุ่งเป้าไปยังเซ็นเซอร์ที่ถูกต้อง และถือเป็นรูปแบบที่แนะนำสำหรับสคริปต์และการติดตั้งแบบไม่มีหน้าจอ ใน GUI ให้ใช้ปุ่ม Refresh ในหน้าต่างเชื่อมต่อและรอให้กระบวนการสแกนใหม่เสร็จสิ้น

## การตั้งค่าอุปกรณ์และเฟิร์มแวร์

เซ็นเซอร์เองจะเก็บการตั้งค่าเครือข่ายไว้: DHCP (การตั้งค่าจากโรงงาน ซึ่งจะกลับไปยังที่อยู่ link-local 169.254.x.x เมื่อไม่มีเซิร์ฟเวอร์ DHCP ตอบกลับ) หรือที่อยู่แบบคงที่ นอกจากนี้ยังเก็บข้อมูลว่าเซ็นเซอร์จะเริ่มสตรีมมิ่งเมื่อเปิดเครื่องหรือไม่ ปรับเปลี่ยนการตั้งค่าเหล่านี้ใน GUI (ในเมนูการตั้งค่ารูปเฟืองของเซ็นเซอร์, **Network**:**Change…**,**Stream at power-on**,**Restart sensor**; ดู [แท็บ DAQ](gui.md)), หรือจาก CLI และ SDK ด้วย `pool-set-network`, `pool-set-auto-stream` และ `pool-reboot` (`DAQSensorSession.set_network()`, `set_auto_stream()`, `reboot()`; ดู [คู่มืออ้างอิง CLI](../reference/cli-reference.md#daq-e-device-settings)). เซ็นเซอร์จะรีสตาร์ทเพื่อปรับใช้การเปลี่ยนแปลงเครือข่าย และChloros จะเชื่อมต่อใหม่กับเซ็นเซอร์นั้น ที่อยู่ IP แบบคงที่ (static address) ต้องอยู่ในเครือข่ายของคอมพิวเตอร์ที่รันChloros: Chloros จะปฏิเสธการเชื่อมต่อหากไม่สามารถเข้าถึงที่อยู่ดังกล่าวได้หลังการรีสตาร์ท ID ของเซ็นเซอร์และชื่อโฮสต์ `daq-e-<id>.local` ของมันจะไม่เปลี่ยนแปลงเลย คุณสมบัติใหม่ในเวอร์ชัน 1.3.0

**การอัปเดตเฟิร์มแวร์ถูกบูรณาการไว้ใน GUI** เมื่อ DAQ-E ที่เชื่อมต่ออยู่ใช้เฟิร์มแวร์เวอร์ชันเก่ากว่าภาพเฟิร์มแวร์ที่มาพร้อมกับChloros ของคุณ แถวเซ็นเซอร์ของมันจะแสดงปุ่ม **Update Available** สีเหลืองอำพัน และหน้าต่างการตั้งค่ารูปเฟืองจะมีปุ่ม "Update to <version>" การอัปเดตจะส่งผ่านเครือข่ายภายในประมาณ 30 วินาที; เซนเซอร์จะรีสตาร์ทและเชื่อมต่อใหม่โดยอัตโนมัติ และการถ่ายโอนที่ถูกขัดจังหวะจะไม่ส่งผลต่อเฟิร์มแวร์ปัจจุบัน จากCLI หรือSDK และบนLinux (ที่ไม่มี GUI) ให้รันคำสั่ง `chloros-cli daq pool-update-firmware --sensor-id <id>` (`DAQSensorSession.update_firmware()`)



<!-- SCREENSHOT-NEEDED: DAQ-E per-sensor settings modal showing the DAQ-E-only rows: Hostname/IP, Firmware row with the "Update to <ver>" button (or "Up to date"), and the PTP Sync row with a live state value. -->## การซิงค์เวลา PTP

เฟิร์มแวร์ DAQ-E เวอร์ชัน 1.2.0 ขึ้นไป สามารถเข้าร่วมใน IEEE 1588 PTPv2 ในฐานะนาฬิกาธรรมดา (เป็นสเลฟเท่านั้น) **ระบบหลังของโฮสต์Chloros เป็น PTP grandmaster** — ทุก DAQ-E และทุกกล้อง LATTICE ใน LAN จะทำงานเป็น slave ต่อมันใน domain 0 โดยรักษาเวลาประทับของทุกอุปกรณ์ให้อยู่ในช่วงความคลาดเคลื่อนประมาณ 1 ms นาฬิกาที่ใช้ร่วมกันนี้คือสิ่งที่ทำให้การอ่านค่าจาก DAQ สามารถจับคู่เวลาได้กับการเปิดรับแสงของกล้อง (ดู [การบันทึกและรูปแบบ .daq](recording.md)).

ตรวจสอบการซิงค์จากCLI:

| คำสั่ง | แสดง |
| --- | --- |
| `chloros-cli time-sync status` | สถานะ grandmaster ของโฮสต์, ลำดับความสำคัญ BMCA, ตัวระบุนาฬิกา, และ `health`: `OK`, หรือ `SENDS_FAILING` / `DEGRADED` / `NO_SOCKETS` / `PEERS_SILENT` พร้อมกับ `health_detail` ที่อธิบายว่าทำไมแพ็กเก็ตของมันไม่ถึงเครือข่าย |
| `chloros-cli time-sync peers` | ทุกอุปกรณ์สเลฟที่ตรวจพบ (เซ็นเซอร์ DAQ-E + กล้อง LATTICE) |
| `chloros-cli time-sync cameras` | สถานะ PTP ของแต่ละกล้อง (`PtpStatus`, `PtpOffsetFromMaster`, `PtpMeanPathDelay`) |
| `chloros-cli time-sync restart` | เริ่มต้นกระบวนการ grandmaster ใหม่ |

ใน GUI หน้าต่างตั้งค่า DAQ-E จะแสดงแถว **PTP Sync** แบบเรียลไทม์ ซึ่งแสดงสถานะ PTP ปัจจุบันของเซ็นเซอร์**อุปกรณ์ DAQ-E ที่ปิด PTP ไว้จะยังคงปิดอยู่** อุปกรณ์จะเก็บการตั้งค่าเปิด/ปิด PTP ไว้ในหน่วยความจำของตัวเอง ดังนั้น อุปกรณ์ที่ PTP ถูกปิดไว้จะยังคงปิดอยู่หลังการเชื่อมต่อใหม่หรือปิดเปิดเครื่อง และเวลาประทับตรา (timestamps) ของมันจะไม่ถูกซิงค์กับ PTP `chloros-cli daq pool-list` จะทำเครื่องหมายหน่วยดังกล่าว (`!! PTP is switched OFF on this unit …`) และแสดงคำสั่งเพื่อแก้ไขปัญหา:

```bash
chloros-cli daq pool-enable-ptp --sensor-id daq-e-def330
```

Chloros ไม่เคยเปิดหน่วยนั้นกลับขึ้นมาเอง เพราะการปิดอาจเป็นการตั้งใจ

รายละเอียดสำหรับผู้ใช้งานที่ต้องการการจัดแนวที่เคร่งครัด:

* ทุกดาตาแกรมที่ส่งผ่านสตรีมจะมีฟิลด์แฟล็ก; **บิตที่ 2 จะถูกตั้งค่าในเฟรมที่มีเวลาประทับที่ซิงค์กับ PTP**. ท่อส่งข้อมูลที่ต้องการการจัดแนวกล้อง/DAQ ที่เคร่งครัดควรใช้บิตนั้นเป็นเงื่อนไขในการกรองข้อมูล
* ก่อนการจับภาพที่ซิงโครไนซ์ ให้ตรวจสอบว่าเซ็นเซอร์ปรากฏใน `chloros-cli time-sync peers` และ `chloros-cli daq pool-list` ไม่ทำเครื่องหมาย PTP ของเซ็นเซอร์ว่าถูกปิด (เครื่องมือฮาร์ดแวร์โดยตรงภายในของ MAPIR ยังสามารถกำหนดเงื่อนไขการบันทึกตามการล็อก PTP ได้ด้วยแฟล็ก `--wait-ptp` ที่รอได้สูงสุด 15 วินาทีจนกว่าเซ็นเซอร์จะเข้าสู่สถานะ SLAVE; เครื่องมือดังกล่าวไม่ได้เป็นส่วนหนึ่งของ CLI ที่จัดส่งมาพร้อมระบบ.)
* เมื่อ PTP อยู่ในสถานะสเลฟอย่างแอคทีฟ เซนเซอร์จะปฏิเสธการส่งสัญญาณนาฬิกาแบบแมนนวล ("PTP กำลังส่งสัญญาณนาฬิกา") นี่เป็นตามการออกแบบ — ให้เชื่อถือ PTP

## หมายเหตุสำหรับLinux

* **พอร์ต PTP ที่ไม่ต้องการสิทธิ์ root** PTP ใช้พอร์ต UDP 319/320 `.deb` จะเขียนค่า `/etc/sysctl.d/60-chloros-ptp.conf` (`net.ipv4.ip_unprivileged_port_start = 319`) ดังนั้น backend จะผูกพอร์ตเหล่านี้และทำงานภายใต้บัญชีผู้ใช้ของคุณ ตั้งแต่เวอร์ชัน 1.3.0 แพ็กเกจนี้ไม่ตั้งค่าความสามารถของไฟล์ (`setcap`) บนแบ็กเอนด์ และไม่ต้องการ `libcap2-bin`; อย่าเพิ่มความสามารถด้วยตัวเอง เพราะแบ็กเอนด์ที่ยังไม่ถูกแพ็กเกจจะไม่สามารถเริ่มต้นได้ หาก PTP ไม่สามารถผูกพอร์ต 319 ได้ ให้ดู [การติดตั้งบน [Linux](../linux/linux-installation.md#ptp-will-not-start--cannot-bind-port-319)

* **Jetson แบบไม่มีหน้าจอ / เครื่องโฮสต์Linux:** แพ็กเกจนี้จะติดตั้งบริการแบ็กเอนด์ แต่ไม่เปิดใช้งานบริการใดทั้งสิ้น สำหรับ PTP ที่ทำงานตลอดเวลา (และความพร้อมใช้งานของ DAQ) โดยไม่ต้องมีผู้ใช้ใดรันคำสั่ง ให้เปิดใช้งานบริการด้วยบัญชีผู้ใช้ของคุณ:

  ```bash
  sudo systemctl enable --now chloros-backend@$USER.service    # $USER expands to your user name
  ```

  หากไม่เปิดบริการนี้ PTP จะทำงานได้เฉพาะเมื่อมีโปรแกรมใดนั้นเริ่มต้นบริการเบื้องหลัง — เช่น คำสั่ง `chloros-cli` หรือสคริปต์ SDK ดู [การติดตั้งบน [Linux]](../linux/linux-installation.md#always-on-ptp-for-headless-hosts) เพื่อทราบเกี่ยวกับ `chloros-backend.service` ในสิทธิ์ root และวิธีเปลี่ยนจากสิทธิ์นั้น
