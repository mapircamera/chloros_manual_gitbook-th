# DAQ-E การเชื่อมต่อเครือข่ายและการซิงค์เวลา

> การตั้งค่าเครือข่ายทางกายภาพสำหรับเซ็นเซอร์ — การติดตั้งสายเคเบิล, PoE, การกำหนดที่อยู่ IP และการตั้งค่าเครือข่ายของอุปกรณ์ — มีอยู่ใน **[คู่มือผู้ใช้ DAQ](https://mapir.gitbook.io/daq/daq-e/network-setup)**. หน้านี้อธิบายเกี่ยวกับด้านของChloros

: การเชื่อมต่อ การซิงค์เวลา และวิธีแก้ไขเมื่อการค้นหาไม่พบอุปกรณ์

DAQ-E เป็นสมาชิก Ethernet ในตระกูล DAQ: ใช้พลังงานผ่าน PoE, ถูกค้นพบผ่าน mDNS (บริการ `_daq-e._tcp`), และสามารถระบุที่อยู่ได้โดยใช้ชื่อโฮสต์ที่สร้างจาก ID ของเซ็นเซอร์ — `daq-e-<6 hex>.local`, เช่น `daq-e-def330.local` หน้านี้อธิบายวิธีการส่งข้อมูลบนเครือข่ายและวิธีการเข้าร่วมการซิงค์เวลา PTP

## ข้อกำหนดด้านเครือข่าย

* **อยู่ในโดเมนการกระจายสัญญาณเดียวกัน** เครื่องที่รันChloros

ต้องอยู่ในเซกเมนต์เครือข่าย L2 เดียวกันกับเซ็นเซอร์ — การค้นหาผ่าน mDNS ไม่สามารถข้ามเราเตอร์ได้
* **ข้อความแจ้งเตือนจากไฟร์วอลล์Windows

: ให้อนุญาต** เมื่อChloros

ผูกซ็อกเก็ตมัลติแคสต์เป็นครั้งแรกWindows

Defender จะขอสิทธิ์หนึ่งครั้ง การอนุญาตจะครอบคลุมข้อมูล DAQ-E (UDP 5002), mDNS (UDP 5353) และ PTP (UDP 319/320) ส่วนบนLinux

กระบวนการนี้จะไม่แสดงข้อความแจ้งเตือน
* **แหล่งจ่ายไฟ PoE, ไม่มีไฟ LED แสดงสถานะ** DAQ-E ไม่มีไฟ LED ของตัวเอง — ตรวจสอบสถานะการจ่ายไฟผ่านตัวบ่งชี้ link/PoE บนสวิตช์หรือพอร์ตอินเจกเตอร์ และรอสักครู่หลังเปิดเครื่องเพื่อให้อุปกรณ์บูตและเชื่อมต่อกับเครือข่าย

## การเชื่อมต่อ

**GUI:** แท็บ Light Sensors → Connect Sensor → ประเภทอุปกรณ์ &quot;DAQ-E (Ethernet)&quot;. การค้นหาจะทำงานเฉพาะเมื่อหน้าต่างการเชื่อมต่อปรากฏบนหน้าจอ (การค้นหา mDNS พร้อมกับการสแกน ARP บนWindows

) โดยทำซ้ำทุก 15 วินาที; ปุ่ม Refresh จะสแกนใหม่ทันที เซ็นเซอร์ที่ตรวจพบจะปรากฏในเมนูแบบเลื่อนลง; เซ็นเซอร์ที่ตรวจพบเป็นเครื่องแรกจะถูกเลือกอัตโนมัติ**CLI

<!-- SCREENSHOT-NEEDED: DAQ connect dialog with Device Type set to "DAQ-E (Ethernet)" and at least one discovered sensor listed in the Hostname/IP dropdown (e.g. daq-e-xxxxxx.local), Connect button enabled. -->

** (ระบบหลังทำงาน):

```bash
chloros-cli daq pool-connect --eth                              # auto-discover on the LAN
chloros-cli daq pool-connect --eth-host daq-e-def330.local      # explicit host — the reliable form
chloros-cli daq pool-connect --eth-host 192.168.1.57            # a plain IP works too
```

### เครื่องโฮสต์ที่มีหลาย NIC และการเชื่อมต่อครั้งแรกหลังการบูต

บนโฮสต์ที่มีอินเทอร์เฟซเครือข่ายที่ใช้งานอยู่มากกว่าหนึ่งตัว **การค้นหา** `pool-connect --eth` ครั้งแรกหลังการบูตอาจไม่พบอะไรเลย แม้เซ็นเซอร์จะอยู่ในสภาพดี — การค้นหาอาจพลาดอินเทอร์เฟซที่เซ็นเซอร์ติดตั้งอยู่ เนื่องจากแคช ARP ยังไม่พร้อมใช้งาน วิธีแก้ไขที่เชื่อถือได้คือการข้ามขั้นตอนการค้นหาและระบุที่อยู่โดยตรง:

```bash
chloros-cli daq pool-connect --eth-host daq-e-def330.local
```

`--eth-host` รับชื่อโฮสต์ mDNS หรือ IP ได้เสมอ มุ่งเป้าไปยังเซ็นเซอร์ที่ถูกต้อง และถือเป็นรูปแบบที่แนะนำสำหรับสคริปต์และการติดตั้งแบบไม่มีหน้าจอ ใน GUI ให้ใช้ปุ่ม Refresh ในหน้าต่างเชื่อมต่อและรอให้กระบวนการสแกนใหม่เสร็จสิ้น

## การตั้งค่าอุปกรณ์และเฟิร์มแวร์

เซ็นเซอร์เองเก็บการตั้งค่าเครือข่าย — IP แบบคงที่ vs. DHCP + การกำหนดที่อยู่แบบ link-local, ชื่ออุปกรณ์, การส่งข้อมูลอัตโนมัติเมื่อเริ่มต้นระบบ, รหัสผ่าน OTA การตั้งค่าด้านอุปกรณ์เหล่านี้ไม่ถูกเปิดเผยเป็นคำสั่งในCLI

ที่จัดส่งมา; แต่ถูกจัดการผ่าน GUI ของChloros

ที่มีการแสดงผล หรือด้วยบริการสนับสนุนMAPIR



**การอัปเดตเฟิร์มแวร์ถูกบูรณาการไว้ใน GUI** เมื่อ DAQ-E ที่เชื่อมต่ออยู่ใช้เฟิร์มแวร์เวอร์ชันเก่ากว่าภาพที่รวมมาพร้อมกับเวอร์ชันChloros

ของคุณ แถวเซ็นเซอร์ของมันจะแสดงปุ่ม **Update Available** สีเหลืองอำพัน และหน้าต่างการตั้งค่าแบบเกียร์จะมีปุ่ม &quot;Update to <version>&quot; การอัปเดตจะส่งผ่านเครือข่ายภายในประมาณ 30 วินาที; เซนเซอร์จะรีสตาร์ทและเชื่อมต่อใหม่โดยอัตโนมัติ และการถ่ายโอนที่ถูกขัดจังหวะจะไม่ส่งผลต่อเฟิร์มแวร์ปัจจุบัน



<!-- SCREENSHOT-NEEDED: DAQ-E per-sensor settings modal showing the DAQ-E-only rows: Hostname/IP, Firmware row with the "Update to <ver>" button (or "Up to date"), and the PTP Sync row with a live state value. -->## การซิงค์เวลา PTP

เฟิร์มแวร์ DAQ-E เวอร์ชัน v1.2.0 ขึ้นไป สามารถเข้าร่วมใน IEEE 1588 PTPv2 ในฐานะนาฬิกาธรรมดา (เป็นสเลฟเท่านั้น) **ระบบหลังของโฮสต์Chlorosคือ PTP grandmaster** — ทุก DAQ-E และทุกกล้อง LATTICE ใน LAN จะทำงานเป็น slave ต่อมันในโดเมน 0 โดยรักษาเวลาประทับของทุกอุปกรณ์ให้อยู่ในช่วงความคลาดเคลื่อนประมาณ 1 มิลลิวินาที นาฬิกาที่ใช้ร่วมกันนี้คือสิ่งที่ทำให้การอ่านค่า DAQ สามารถจับคู่เวลาได้กับการเปิดรับแสงของกล้อง (ดู [การบันทึกและรูปแบบ .daq](recording.md)).

ตรวจสอบการซิงค์จาก CLI:

| คำสั่ง | แสดง |
| --- | --- |
| `chloros-cli time-sync status` | สถานะ grandmaster ของ host, ลำดับความสำคัญ BMCA, ตัวตนของนาฬิกา |
| `chloros-cli time-sync peers` | ทุก slave ที่ตรวจพบ (เซ็นเซอร์ DAQ-E + กล้อง LATTICE) |
| `chloros-cli time-sync cameras` | สถานะ PTP ของแต่ละกล้อง (`PtpStatus`, `PtpOffsetFromMaster`, `PtpMeanPathDelay`) |
| `chloros-cli time-sync restart` | เริ่มต้นกระบวนการ grandmaster ใหม่ |

ใน GUI หน้าต่างตั้งค่า DAQ-E แสดงแถว **PTP Sync** แบบเรียลไทม์ ซึ่งแสดงสถานะ PTP ปัจจุบันของเซ็นเซอร์

รายละเอียดสำหรับผู้ใช้งานที่ต้องการการจัดแนวอย่างเคร่งครัด:

* ทุกดาตาแกรมที่ส่งมาจะมีสนามธง (flags field); **บิตที่ 2 จะถูกตั้งค่าในเฟรมที่มีเวลาประทับ (timestamp) ที่ถูกซิงค์กับ PTP**. ท่อส่งข้อมูล (pipeline) ที่ต้องการการจัดแนวอย่างเคร่งครัดระหว่างกล้อง/DAQ ควรใช้บิตนั้นเป็นเงื่อนไขในการกรองข้อมูล
* ก่อนการจับภาพที่ซิงโครไนซ์ ให้ตรวจสอบว่าเซ็นเซอร์ปรากฏใน `chloros-cli time-sync peers` (เครื่องมือฮาร์ดแวร์โดยตรงภายในของ MAPIR ยังสามารถควบคุมการบันทึกตามการล็อก PTP ได้ด้วยธง `--wait-ptp` ซึ่งจะรอสูงสุด 15 วินาทีจนกว่าเซ็นเซอร์จะเข้าสู่สถานะ SLAVE; เครื่องมือดังกล่าวไม่ได้เป็นส่วนหนึ่งของ CLI ที่จัดส่ง)
* ในขณะที่ PTP กำลังทำงานในโหมดสเลฟ เซ็นเซอร์จะปฏิเสธการส่งสัญญาณนาฬิกาแบบแมนนวล (&quot;PTP is providing clock&quot;) ซึ่งเป็นไปตามการออกแบบ — ให้เชื่อถือ PTP

## หมายเหตุเกี่ยวกับ Linux

* **PTP ต้องการ `libcap2-bin` ในขณะติดตั้ง** สคริปต์ postinst ของ `.deb` จะให้สิทธิ์ `cap_net_bind_service=+ep` บน `/usr/lib/chloros/chloros-backend` เพื่อให้สามารถผูกพอร์ต PTP 319/320 ได้โดยไม่ต้องใช้สิทธิ์ root หาก `libcap2-bin` ไม่ปรากฏขึ้น ขั้นตอนนี้จะถูกข้ามไป และ PTP จะไม่สามารถเริ่มต้นได้ วิธีแก้ไข:

  ```bash
  sudo apt install libcap2-bin
  sudo apt reinstall chloros
  ```

* **Jetson / Raspberry Pi แบบไม่มีหน้าจอ:** ในการติดตั้งครั้งแรก ระบบจะสร้าง unit systemd `chloros-backend.service` แต่ยังไม่เปิดใช้งาน สำหรับ PTP ที่ทำงานตลอดเวลา (และความพร้อมใช้งานของ DAQ) โดยไม่มี GUI:

  ```bash
  sudo systemctl enable --now chloros-backend.service
  ```

  หากไม่เปิดใช้งาน PTP จะทำงานเฉพาะเมื่อ GUI ของChlorosเปิดอยู่เท่านั้น
