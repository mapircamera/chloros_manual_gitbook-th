# การบันทึกข้อมูลและรูปแบบ .daq

ไฟล์ `.daq` เป็นรูปแบบการบันทึกข้อมูลของเซ็นเซอร์แสงChloros: **ฐานข้อมูล SQLite** ที่เก็บเฟรมสเปกตรัมที่ได้รับการปรับเทียบจากเซ็นเซอร์ DAQ ตัวเดียว บันทึกไฟล์นี้หนึ่งไฟล์ระหว่างเซสชันการจับภาพ และระบบประมวลผลความสะท้อนแสง (reflectance pipeline) สามารถแบ่งภาพทุกภาพด้วยค่าความเข้มแสงที่ส่องลง (downwelling irradiance) ที่วัดได้ในขณะนั้นได้

## เนื้อหาของไฟล์ .daq

| คุณสมบัติ | ค่า |
| --- | --- |
| Container | ฐานข้อมูล SQLite, ไฟล์หนึ่งต่อเซ็นเซอร์ต่อการบันทึก |
| Filename | ประกอบด้วย **ID ของเซ็นเซอร์**และ**timestamp**, เช่น `daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| สเปกตรัมต่อเฟรม | 135 จุด, 340–1010 nm ในขั้นตอนละ 5 nm, พร้อมด้วย CIE XYZ tristimulus |
| หน่วย | ความเข้มรังสีสเปกตรัมที่ปรับเทียบแล้ว, **W/m²/nm** (ใช้ชุดปรับเทียบจากโรงงาน + โปรไฟล์ cap ที่ถูกนำไปใช้) |
| ข้อมูลเมตาดาต้าที่บันทึก | ID เซนเซอร์ (กุญแจสำหรับการดึงข้อมูลการปรับเทียบจากโรงงานของหน่วยนั้น) และโปรไฟล์ฝาครอบที่กำลังใช้งาน — ดู [โปรไฟล์ฝาครอบและช่วงที่ปรับเทียบ](caps-and-range.md) |

รูปแบบข้อมูลนี้เหมือนกันสำหรับ DAQ-U, DAQ-M, DAQ-E และ DAQ-E-S ดังนั้นการประมวลผลในขั้นตอนต่อไปจึงไม่จำเป็นต้องทราบว่าอุปกรณ์ส่งข้อมูลใดได้บันทึกข้อมูลนั้น การบันทึกของ DAQ-E-S ยังเก็บข้อมูลมุมเอียง (tilt), มุมหมุน (roll) และมุมก้ม (pitch) ของอุปกรณ์ไว้ข้างๆ ทุกสเปกตรัม

**ข้อมูลบันทึกจะยังคงอยู่แม้เกิดการตัดไฟ (1.3.0)**การบันทึกแบบเรียลไทม์จะถูกเขียนลงในไฟล์บันทึก (journal) และทำการซิงค์ดิสก์แบบเต็มทุกครั้งที่บันทึกข้อมูล ดังนั้นการตัดไฟหรือการยุติกระบวนการจะส่งผลให้ข้อมูลประมาณ 3 วินาทีสุดท้ายสูญหาย แต่ไฟล์บันทึกจะยังคงอยู่ การบันทึกที่ถูกหยุดลงระหว่างการเขียนอาจทิ้งไฟล์ `<name>.daq-journal` ไว้ข้างไฟล์ `.daq`:**เก็บและคัดลอกทั้งสองไฟล์ไว้ด้วยกัน** Chloros จะย้อนบันทึกย้อนกลับเมื่ออ่านไฟล์เป็นครั้งแรก ดิสก์ที่ทำงานหนักจะทำให้การบันทึกไฟล์ล่าช้า แต่ไม่ส่งผลต่อการอ่านค่าจากเซ็นเซอร์

**DAQ-E ที่หยุดส่งข้อมูลจะถูกเชื่อมต่อใหม่ (1.3.0)** เมื่อสตรีมของ DAQ-E หยุดส่งข้อมูล (สวิตช์ถูกปิด-เปิดใหม่ หรือการเชื่อมต่อถูกตัด) ระบบแบ็กเอนด์จะเชื่อมต่อใหม่ด้วยตั้งค่าเดิม และการบันทึกบนอุปกรณ์นั้นจะดำเนินต่อในไฟล์ `.daq` เดิม โดยช่องว่างจะถูกทำเครื่องหมายไว้ในไฟล์

การบันทึกที่ผ่านการปรับเทียบจำเป็นต้องใช้ชุดข้อมูลการปรับเทียบจากโรงงานของเซ็นเซอร์ สำหรับ DAQ-U และ DAQ-M ระบบแบ็กเอนด์จะดึงชุดข้อมูลนี้จากคลาวด์ของ MAPIR โดยใช้ ID ของเซ็นเซอร์ (การบันทึกจะถูกปฏิเสธหากไม่สามารถดึงข้อมูลได้); ส่วนอุปกรณ์ DAQ-E ได้รับการยกเว้น เนื่องจากเก็บข้อมูลการปรับเทียบไว้บนอุปกรณ์เอง

## การบันทึกจาก GUI

การบันทึกใน GUI ต้องมี **โครงการที่เปิดอยู่** (ปุ่มบันทึกจะถูกปิดใช้งานหากไม่มี):

* **บันทึกทั้งหมด / หยุดทั้งหมด** — ด้านบนของแถบข้าง Light Sensors; เริ่มหรือหยุดการบันทึก `.daq` บนทุกเซ็นเซอร์ที่เชื่อมต่อพร้อมกัน
* **บันทึก / หยุดบันทึก** — สำหรับแต่ละเซ็นเซอร์ ในหน้าตั้งค่าแบบโมดัลรูปเฟือง ตัวบ่งชี้ "REC" สีแดงจะปรากฏในแถวข้อมูลสดของเซ็นเซอร์ขณะกำลังบันทึก

ไฟล์จะถูกบันทึกไปยัง `<project>/light_sensor/` และเมื่อการบันทึกหยุดลง — ไม่ว่าจะผ่านปุ่ม Stop, Stop All หรือการตัดการเชื่อมต่อเซ็นเซอร์ที่กำลังบันทึก — ไฟล์ `.daq` ที่เสร็จสิ้นแล้วจะ **ถูกเพิ่มเข้าไปในโครงการที่เปิดอยู่โดยอัตโนมัติ** ไฟล์จะปรากฏในรายการไฟล์ของโครงการโดยไม่ต้องเพิ่มด้วยมือ และพร้อมสำหรับการประมวลผลค่าสะท้อนแสงแล้ว

## การบันทึกจากCLI



CLI บันทึกผ่านกลุ่มเซ็นเซอร์ของแบ็กเอนด์ (แบ็กเอนด์ต้องกำลังทำงานอยู่ — คำสั่งเหล่านี้เป็นไคลเอนต์HTTP แบบบาง):

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

รับค่า `--sensor-id` จาก `chloros-cli daq pool-list` ค่าเริ่มต้นสองค่าที่ควรทราบ:

| ตัวเลือก | ค่าเริ่มต้น |
| --- | --- |
| `--duration` | `0` — บันทึกจนกว่าจะถึง `pool-record --stop` |
| `--output` / `-o` | `~/Documents/DAQ Live View/` บนระบบไฟล์ของ **backend** ไม่ใช่ของ CLI |

การแยกแยะไดเรกทอรีผลลัพธ์มีความสำคัญเมื่อCLI กำหนดเป้าหมายไปยัง backend บนเครื่องอื่น: ไฟล์จะถูกบันทึกไว้ที่ตำแหน่งที่ backend ทำงานอยู่ หาก backend อยู่ในเครื่องเดียวกัน `-o` แบบสัมพัทธ์ (เช่น `./out` ข้างต้น) จะถูกกำหนดตำแหน่งตามโฟลเดอร์ที่คุณรันคำสั่งนั้น

## การบันทึกจากPython

`DAQSensorSession` (ที่ส่งคืนโดย `chloros_sdk.connect_daq_sensor()`) แสดงการบันทึกที่รวมไว้ในกลุ่มเดียวกัน: `record_start(output_dir=None, device_name=None)` คืนค่าเส้นทางไฟล์ ส่วน `record_stop()` คืนค่า `{path, rows}` ดู [SDK Reference](../reference/sdk-reference.md) เพื่อดู API ของเซสชันแบบเต็ม คลาสฮาร์ดแวร์โดยตรงของSDK (สำหรับการติดตั้งบนเดสก์ท็อปเท่านั้น) จะเขียนข้อมูลบันทึกไปยัง `~/Documents/DAQ/` ตามค่าเริ่มต้น; สำหรับเวอร์ชันที่ปล่อยออกมาแล้ว เส้นทางรวมที่กล่าวถึงข้างต้นคือเส้นทางที่ได้รับการสนับสนุน

## การใช้ไฟล์ .daq ในขั้นตอนการประมวลผล

เพื่อสร้างค่าการสะท้อนจากภาพChloros จำเป็นต้องมีค่าความเข้มแสงที่ส่องลง (downwelling irradiance) ที่ตรงกับแต่ละการเปิดรับแสง:

* **เก็บไฟล์ `.daq` ไว้พร้อมกับภาพ**ในขั้นตอนการประมวลผล ระบบจะคำนวณ**ความเข้มแสงที่ส่องลงที่ตรงกับเวลา** โดยอัตโนมัติจากไฟล์ `.daq` ที่บันทึกไว้ (รุ่น DAQ ใดก็ได้) — หรือจากไฟล์ `.csv` แบบเนทีฟของ DAQ-M — ที่พบอยู่ข้างๆ ภาพ การบันทึกผ่าน GUI จะตอบสนองเงื่อนไขนี้โดยอัตโนมัติ เนื่องจากจะถูกเพิ่มเข้าโครงการทันทีที่การบันทึกหยุดลง
* **การปรับเทียบจะถูกดึงมาตามความต้องการ** หากชุดข้อมูลการปรับเทียบจากโรงงานสำหรับกล้องหรือ DAQ แต่ละตัวยังไม่ถูกเก็บไว้ในแคชท้องถิ่น Chloros จะดาวน์โหลดมาโดยอัตโนมัติจากคลาวด์ของ MAPIR เมื่อใช้งานครั้งแรก (ต้องเชื่อมต่ออินเทอร์เน็ตเพียงครั้งเดียว; เก็บไว้ในแคชภายใต้ชื่อไฟล์ `~/.chloros/`)
* **การจับภาพแบบเรียลไทม์จะสร้างไฟล์ sidecar ของตัวเอง** สำหรับเฟรมการสะท้อนแสงที่จับภาพแบบสด ค่าการอ่านจาก DAQ ที่ใช้จริงจะถูกบันทึกเป็นไฟล์ `.daq` ในโฟลเดอร์ `daq/` ของการจับภาพนั้น ทำให้สามารถประมวลผลการจับภาพใหม่ได้ในภายหลังโดยไม่ต้องใช้การบันทึกต้นฉบับ
* **การบันทึกจากเครื่องบันทึก `chloros_scripts` (1.3.0)**ไฟล์ `.daq` ที่ถูกเขียนโดยเครื่องบันทึกสาธารณะ [`chloros_scripts`](https://github.com/mapircamera/chloros_scripts) จะถูกระบุเป็นรุ่น DAQ ที่สร้างไฟล์นั้น และขีดจำกัดของมันสามารถตั้งค่าได้ใน**การตั้งค่าโครงการ → DAQ Light Sensor** ได้เหมือนการบันทึกอื่นๆ เครื่องบันทึกเหล่านี้บันทึกค่าการนับของเซ็นเซอร์แบบดิบ; Chloros จะดึงข้อมูลการปรับเทียบจากโรงงานของเซ็นเซอร์ผ่านพอร์ตอนุกรมและนำไปใช้
* **ค่าการอ่านนี้เป็นของใคร (1.3.0).**ข้างๆ การบันทึกแต่ละครั้ง `.daq`, `.daq.cameras.json` จะระบุชื่อกล้องที่เฟรมในค่าการอ่านนั้นอธิบายถึง และกระบวนการประมวลผลจะ**จับคู่กับภาพจากกล้องเหล่านั้นเท่านั้น** ดังนั้น กล้องแบบสแตนด์อโลนที่ไม่มีเซ็นเซอร์แสงของตัวเอง จึงไม่ใช้ค่าอ่านจากกล้องอื่นอีกต่อไป — ให้ผูกเซ็นเซอร์กับกล้องนั้น หรือบันทึกเซ็นเซอร์เอง การบันทึกที่ทำด้วย DAQ เอง (GUI Record, `daq pool-record`) และ `.daq` ใดก็ตามที่ไม่มีไฟล์นั้น (รวมถึงการจับภาพเก่า) ยังคงให้บริการกล้องทุกตัว

## การดึงค่าความเข้มแสงกลับออกมา

การประมวลผลโครงการจะส่งออกการบันทึกจากเซ็นเซอร์แสงทุกชิ้นที่มันเก็บไว้ ไปยังโฟลเดอร์
`Light Sensor/` ข้างๆ ผลิตภัณฑ์ภาพ สิ่งนี้ **ไม่** จำเป็นต้องมีภาพ:
การบันทึกเซ็นเซอร์แสงที่บันทึกด้วยตัวเองถือเป็นการจับภาพที่สมบูรณ์ และโฟลเดอร์ที่เก็บเฉพาะไฟล์ `.daq`
ถือเป็นข้อมูลนำเข้าที่ถูกต้อง โครงการที่เก็บเฉพาะข้อมูลบันทึกจากเซ็นเซอร์แสงจะแสดงรายการและ
ประมวลผลได้ทั้งจากแอปและCLI และรายการเหล่านั้นจะยังคงอยู่หลังการประมวลผลเสร็จสิ้น การประมวลผล
จะรายงานจำนวนผลิตภัณฑ์จากเซ็นเซอร์แสงที่สร้างขึ้น

| ผลิตภัณฑ์ | อธิบาย |
| --- | --- |
| `<name>_calibrated.daq` | ไฟล์เก็บข้อมูลที่สามารถประมวลผลใหม่ได้ ตามโครงสร้างข้อมูลเดียวกันกับการบันทึกแบบเรียลไทม์ โดยระบุชุดข้อมูลการปรับเทียบที่สร้างไฟล์นี้ขึ้นมา การนำเข้าไฟล์นี้ใหม่ **จะไม่** ปรับเทียบข้อมูลอีกครั้ง |
| `<name>_calibrated.csv` | ความเข้มรังสีสเปกตรัมในหน่วย W/m²/nm บนกริดความยาวคลื่นของเซ็นเซอร์เอง โดยแต่ละแถวแสดงค่าการอ่านหนึ่งครั้ง พร้อมด้วยคอลัมน์โฟโตเมตริก: กำลังรวม, ลักซ์แบบโฟโตปิกและสโคโตปิก, PPFD พร้อมการแบ่งสีฟ้า/เขียว/แดง, และความยาวคลื่นสูงสุด |

DAQ-U หรือ DAQ-M ที่ไม่สามารถดึงชุดข้อมูลการสอบเทียบได้ — คุณกำลังออฟไลน์ หรือ
เซ็นเซอร์นั้นไม่มีข้อมูลการสอบเทียบในไฟล์ — จะ **ถูกข้ามไปพร้อมเหตุผล** และจะไม่ถูกบันทึก
เป็นไฟล์ "ที่สอบเทียบแล้ว" ที่เก็บค่าการนับดิบไว้ ให้เชื่อมต่ออินเทอร์เน็ตและรันใหม่ DAQ-E
มีข้อมูลการปรับเทียบของตัวเอง ดังนั้นจึงต้องการข้อมูลนี้เฉพาะเมื่ออุปกรณ์ไม่เชื่อมต่อและ
ไม่มีข้อมูลใดถูกเก็บไว้ในแคชท้องถิ่น

### DAQ-A: ค่านับดิบ และเหตุผลที่นั่นคือคำตอบที่ถูกต้อง

**DAQ-A** ถูกพัฒนาขึ้นก่อนระบบชุดข้อมูลการปรับเทียบตามพอร์ทซีเรียล และไม่มีชุดข้อมูล
ที่จะดึงมาได้ นี่ไม่ใช่ความผิดพลาด: DAQ-A ได้รับการปรับเทียบในสนามโดยใช้
เป้าหมายการสะท้อนแสง และการปรับเทียบแบบอิงเป้าหมายต้องการเพียงการตอบสนอง *สัมพัทธ์*
ของเซ็นเซอร์ — ซึ่งก็คือค่าการนับดิบของมันนั่นเอง Chloros ใช้ค่าเหล่านี้ในการปรับเทียบในปัจจุบัน

ดังนั้น การบันทึกของ DAQ-A จะถูกส่งออก แต่ภายใต้ชื่อที่ต่างกัน:

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw` ไม่ใช่ `_calibrated` — ชื่อไฟล์ที่ต่างกันแทนที่จะเป็นแฟล็กภายในไฟล์
เนื่องจากข้อมูลนี้ต้องคงอยู่แม้เมื่อไฟล์ถูกส่งต่อทางอีเมลด้วยชื่อไฟล์เปล่าๆ ส่วนหัวของ `.csv`
ระบุว่า `raw spectral sensor counts (NOT irradiance)` และเตือนว่าค่าต่างๆ สามารถ
เปรียบเทียบได้ **ภายใน** ไฟล์เท่านั้น ไม่ใช่ระหว่างเซ็นเซอร์ต่างๆ คอลัมน์ที่มีความหมาย
เฉพาะสำหรับความเข้มรังสีจริง — พลังงานรวม, ลักซ์, PPFD — ถูกทิ้งว่างไว้ แทนที่จะ
คำนวณจากจำนวนการนับ

การบันทึก DAQ-A-SD รุ่นเก่า (schema v1.01 / v1.02) บันทึกเพียงเวลาเขียนไฟล์เท่านั้น ไม่ใช่
เวลาประทับตราสำหรับแต่ละการอ่าน Chloros จะไม่จับคู่ภาพกับข้อมูลเหล่านั้น — การจับคู่เฟรมกับ
เวลาเขียนจะผิดแม้ไม่ปรากฏความผิดพลาด — แต่การส่งออกข้อมูลอ่านข้อมูลเหล่านั้นได้ปกติและ
ไฟล์ CSV ระบุไว้ว่าใช้สัญญาณนาฬิกาใด

สำหรับข้อมูลเกี่ยวกับ reflectance อย่างครบถ้วน — เซ็นเซอร์เดียวพร้อมกล้อง และเซ็นเซอร์คู่สำหรับสภาพแวดล้อม/วัตถุ — ดู [Reflectance Workflows](reflectance.md).
