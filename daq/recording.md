# การบันทึกข้อมูลและรูปแบบ .daq

ไฟล์ `.daq` เป็นรูปแบบการบันทึกข้อมูลจากเซ็นเซอร์แสงของChloros

: **ฐานข้อมูล SQLite** ที่เก็บเฟรมสเปกตรัมที่ได้รับการปรับเทียบจากเซ็นเซอร์ DAQ ตัวเดียว บันทึกไฟล์นี้ระหว่างเซสชันการจับภาพ และระบบประมวลผลความสะท้อนแสง (reflectance pipeline) สามารถแบ่งภาพทุกภาพด้วยค่าความเข้มรังสีที่ตกกระทบ (downwelling irradiance) ที่วัดได้ในขณะนั้น

## เนื้อหาของไฟล์ .daq

| คุณสมบัติ | ค่า |
| --- | --- |
| Container | ฐานข้อมูล SQLite, ไฟล์หนึ่งต่อเซ็นเซอร์ต่อการบันทึก |
| Filename | ประกอบด้วย **ID ของเซ็นเซอร์**และ**timestamp**, เช่น `daq_data_daq-e-def330_2026_04_13_18h30m00.daq` |
| สเปกตรัมต่อเฟรม | 135 จุด, 340–1010 nm ในขั้น 5 nm, พร้อมด้วย CIE XYZ tristimulus |
| หน่วย | ความเข้มรังสีสเปกตรัมที่ปรับเทียบแล้ว, **W/m²/nm** (ใช้ชุดปรับเทียบจากโรงงาน + โปรไฟล์ cap ที่ถูกนำไปใช้) |
| ข้อมูลเมตาดาต้าที่บันทึก | ID เซนเซอร์ (กุญแจสำหรับการดึงข้อมูลการปรับเทียบจากโรงงานของหน่วยนั้น) และโปรไฟล์ฝาครอบที่กำลังใช้งาน — ดู [โปรไฟล์ฝาครอบและช่วงที่ปรับเทียบแล้ว](caps-and-range.md) |

รูปแบบข้อมูลนี้เหมือนกันสำหรับ DAQ-U, DAQ-M และ DAQ-E ดังนั้นการประมวลผลในขั้นตอนต่อไปจึงไม่จำเป็นต้องทราบว่าอุปกรณ์ส่งข้อมูลใดได้บันทึกข้อมูลนี้

การบันทึกที่ผ่านการปรับเทียบจำเป็นต้องใช้ชุดข้อมูลการปรับเทียบจากโรงงานของเซ็นเซอร์ สำหรับ DAQ-U และ DAQ-M ระบบหลังบ้านจะดึงชุดข้อมูลจากคลาวด์ของMAPIR

โดยใช้ ID ของเซ็นเซอร์ (การบันทึกจะถูกปฏิเสธหากไม่สามารถดึงข้อมูลได้); ส่วนอุปกรณ์ DAQ-E ได้รับการยกเว้น เนื่องจากเก็บข้อมูลการปรับเทียบไว้บนอุปกรณ์เอง

## การบันทึกจาก GUI

การบันทึกผ่าน GUI ต้องมี **โครงการที่เปิดอยู่** (ปุ่มบันทึกจะถูกปิดใช้งานหากไม่มี):

* **บันทึกทั้งหมด / หยุดทั้งหมด** — อยู่ที่ส่วนบนของแถบด้านข้างเซ็นเซอร์แสง; เริ่มหรือหยุดการบันทึก `.daq` บนทุกเซ็นเซอร์ที่เชื่อมต่ออยู่พร้อมกัน
* **บันทึก / หยุดบันทึก** — สำหรับแต่ละเซ็นเซอร์ ในหน้าตั้งค่าแบบโมดัลรูปเฟือง ตัวบ่งชี้ &quot;REC&quot; สีแดงจะปรากฏในแถวข้อมูลสดของเซ็นเซอร์ขณะกำลังบันทึก

ไฟล์จะถูกบันทึกไปยัง `<project>/light_sensor/` และเมื่อการบันทึกหยุดลง — ไม่ว่าจะผ่าน Stop, Stop All หรือการตัดการเชื่อมต่อเซ็นเซอร์ที่กำลังบันทึก — ไฟล์ `.daq` ที่เสร็จสิ้นแล้วจะถูก **เพิ่มเข้าไปในโครงการที่เปิดอยู่โดยอัตโนมัติ** ไฟล์ดังกล่าวจะปรากฏในรายการไฟล์ของโครงการโดยไม่ต้องเพิ่มด้วยมือ และพร้อมสำหรับการประมวลผลค่าสะท้อนแสงแล้ว

## การบันทึกจากCLI



CLI

บันทึกผ่านกลุ่มเซ็นเซอร์ของระบบหลัง (ระบบหลังต้องกำลังทำงานอยู่ — คำสั่งเหล่านี้เป็นไคลเอนต์แบบบางHTTP

):

```bash
# Connect the sensor into the backend pool
chloros-cli daq pool-connect --eth-host daq-e-def330.local

# Record for 150 seconds, with a human-friendly device label
chloros-cli daq pool-record --sensor-id daq-e-def330 --duration 150 \
    -o ./out --device-name "rooftop-A"

# Or run open-ended and stop explicitly
chloros-cli daq pool-record --sensor-id daq-e-def330            # --duration defaults to 0 = run until --stop
chloros-cli daq pool-record --sensor-id daq-e-def330 --stop
```

รับค่า `--sensor-id` จาก `chloros-cli daq pool-list` ค่าเริ่มต้นสองค่าที่ควรทราบ:

| ตัวเลือก | ค่าเริ่มต้น |
| --- | --- |
| `--duration` | `0` — บันทึกจนกว่าจะถึง `pool-record --stop` |
| `--output` / `-o` | `~/Documents/DAQ Live View/` ในระบบไฟล์ของ **backend**ไม่ใช่ของ**CLI

** |

การแยกแยะระหว่างไดเรกทอรีผลลัพธ์มีความสำคัญเมื่อCLI

กำหนดเป้าหมายไปยัง backend บนเครื่องอื่น: ไฟล์จะถูกจัดเก็บไว้ที่ตำแหน่งที่ backend ทำงานอยู่

Reference](../reference/sdk-reference.md) เพื่อดูข้อมูลเซสชันAPI

แบบเต็ม คลาสฮาร์ดแวร์โดยตรงของSDK

(สำหรับการติดตั้งบนเดสก์ท็อปเท่านั้น) จะเขียนข้อมูลบันทึกไปยัง `~/Documents/DAQ/` ตามค่าเริ่มต้น; สำหรับเวอร์ชันที่ปล่อยออกมาแล้ว เส้นทางรวมที่กล่าวถึงข้างต้นคือเส้นทางที่ได้รับการสนับสนุน

## การใช้ไฟล์ .daq ในขั้นตอนการประมวลผล

เพื่อสร้างค่าสะท้อนแสงจากภาพChloros

จำเป็นต้องมีค่าความเข้มรังสีลงสู่พื้นดิน (downwelling irradiance) ที่ตรงกับแต่ละการเปิดรับแสง:

* **เก็บไฟล์ `.daq` ไว้พร้อมกับภาพ**ในขั้นตอนการประมวลผล ระบบจะคำนวณ**ความเข้มแสงที่ส่องลงที่ตรงกับเวลา** โดยอัตโนมัติจากไฟล์ `.daq` ที่บันทึกไว้ (รุ่น DAQ ใดก็ได้) — หรือจากไฟล์ `.csv` แบบเนทีฟของ DAQ-M — ที่พบอยู่ร่วมกับภาพถ่าย การบันทึกผ่าน GUI จะตอบสนองเงื่อนไขนี้โดยอัตโนมัติ เนื่องจากไฟล์ดังกล่าวจะถูกเพิ่มเข้าสู่โครงการทันทีที่การบันทึกสิ้นสุดลง
* **การปรับเทียบจะถูกดึงมาตามความต้องการ** หากชุดข้อมูลการปรับเทียบจากโรงงานสำหรับกล้องหรือ DAQ แต่ละตัวยังไม่ได้ถูกเก็บไว้ในแคชท้องถิ่น ระบบChloros

จะดึงข้อมูลนั้นมาโดยอัตโนมัติจากคลาวด์ของMAPIR

เมื่อใช้งานครั้งแรก (ต้องเชื่อมต่ออินเทอร์เน็ตเพียงครั้งเดียว; ข้อมูลจะถูกเก็บไว้ในแคชภายใต้ชื่อ `~/.chloros/`)
* **การจับภาพแบบเรียลไทม์จะสร้างไฟล์ sidecar ของตัวเอง** สำหรับเฟรมการสะท้อนแสงที่จับภาพแบบเรียลไทม์ ค่าการอ่านจาก DAQ ที่ใช้จริงจะถูกบันทึกเป็นไฟล์ sidecar `.daq` ไว้ข้างๆ ภาพ เพื่อให้สามารถประมวลผลภาพที่จับได้ใหม่ในภายหลังโดยไม่ต้องใช้การบันทึกต้นฉบับ

## การดึงค่าความเข้มแสงกลับออกมา

การประมวลผลโครงการจะส่งออกการบันทึกจากเซ็นเซอร์แสงทุกชิ้นที่เก็บไว้ ไปยัง
โฟลเดอร์ `Light Sensor/` ที่อยู่ข้างผลิตภัณฑ์ภาพ สิ่งนี้ **ไม่** จำเป็นต้องมีภาพ:
เซ็นเซอร์แสงที่บินด้วยตัวเองถือเป็นการบันทึกที่สมบูรณ์ และโฟลเดอร์ที่เก็บเฉพาะไฟล์ `.daq`
เท่านั้นก็ถือเป็นข้อมูลนำเข้าที่ถูกต้อง รายงานการรันจะระบุจำนวนผลิตภัณฑ์จากเซ็นเซอร์แสงที่บันทึกไว้

| ผลิตภัณฑ์ | อธิบาย |
| --- | --- |
| `<name>_calibrated.daq` | ไฟล์เก็บข้อมูลที่สามารถประมวลผลใหม่ได้ ตามโครงสร้างเดียวกันกับการบันทึกแบบเรียลไทม์ โดยระบุชุดข้อมูลการปรับเทียบที่สร้างไฟล์นี้ขึ้นมา การนำเข้าไฟล์นี้อีกครั้ง **จะไม่** ทำให้เกิดการปรับเทียบซ้ำ |
| `<name>_calibrated.csv` | ความเข้มรังสีสเปกตรัมในหน่วย W/m²/nm บนกริดความยาวคลื่นของเซ็นเซอร์เอง โดยแต่ละแถวแสดงค่าการอ่านหนึ่งครั้ง พร้อมด้วยคอลัมน์โฟโตเมตริก: กำลังรวม, ลักซ์แบบโฟโตปิกและสโคโตปิก, PPFD พร้อมการแบ่งสีฟ้า/เขียว/แดง, และความยาวคลื่นสูงสุด |

DAQ-U หรือ DAQ-M ที่ไม่สามารถดึงชุดข้อมูลการปรับเทียบได้ — คุณกำลังออฟไลน์ หรือ
เซ็นเซอร์นั้นไม่มีข้อมูลการปรับเทียบในไฟล์ — จะ **ถูกข้ามไปพร้อมเหตุผล** และจะไม่ถูกบันทึก
เป็นไฟล์ &quot;ที่ปรับเทียบแล้ว&quot; ที่เก็บค่าการนับดิบไว้ ให้เชื่อมต่ออินเทอร์เน็ตและรันใหม่ DAQ-E
มีข้อมูลการสอบเทียบของตัวเอง ดังนั้นจึงต้องการข้อมูลนี้เฉพาะเมื่ออุปกรณ์ไม่เชื่อมต่อและ
ไม่มีข้อมูลใดที่เก็บไว้ในแคชท้องถิ่น

### DAQ-A: ค่านับดิบ และเหตุผลที่นั่นคือคำตอบที่ถูกต้อง

**DAQ-A** ถูกพัฒนาขึ้นก่อนระบบชุดข้อมูลการสอบเทียบตามพอร์ตอนุกรม และไม่มีชุดข้อมูล
ที่จะดึงมา นี่ไม่ใช่ความผิดพลาด: DAQ-A ได้รับการปรับเทียบในสนามโดยใช้
เป้าหมายการสะท้อนแสง และการปรับเทียบแบบอิงเป้าหมายต้องการเพียงการตอบสนอง *สัมพัทธ์*
ของเซ็นเซอร์ — ซึ่งก็คือค่าการนับดิบของมันเองChloros

ยังใช้ค่าการนับดิบเหล่านี้ในการปรับเทียบจนถึงปัจจุบัน

ดังนั้น การบันทึกข้อมูลของ DAQ-A สามารถส่งออกได้ แต่ภายใต้ชื่อที่ต่างกัน:

```
<project>/
└── Light Sensor/
    ├── <name>_raw.daq
    └── <name>_raw.csv
```

`_raw` ไม่ใช่ `_calibrated` — ใช้ชื่อไฟล์ที่ต่างกันแทนที่จะใช้แฟล็กภายในไฟล์
เนื่องจากข้อมูลนี้ต้องคงอยู่แม้เมื่อไฟล์ถูกส่งต่อทางอีเมลด้วยชื่อไฟล์เปล่า ส่วนหัวของ `.csv`
ระบุว่า `raw spectral sensor counts (NOT irradiance)` และเตือนว่าค่าต่างๆ สามารถ
เปรียบเทียบได้ **ภายใน** ไฟล์เท่านั้น ไม่ใช่ระหว่างเซ็นเซอร์ต่างๆ คอลัมน์ที่มีความหมาย
เฉพาะสำหรับความเข้มแสงจริง — พลังงานรวม, ลักซ์, PPFD — ถูกทิ้งว่างไว้แทนที่จะ
คำนวณจากจำนวนการนับ

การบันทึก DAQ-A-SD รุ่นเก่า (schema v1.01 / v1.02) บันทึกเพียงเวลาเขียนไฟล์เท่านั้น ไม่ใช่
เวลาประทับตรา (timestamp) สำหรับแต่ละการอ่านChloros

จะไม่จับคู่ภาพกับข้อมูลเหล่านั้น — การจับคู่เฟรมกับ
เวลาเขียนจะผิดพลาดโดยที่ดูไม่ผิด — แต่การส่งออกข้อมูลอ่านข้อมูลเหล่านั้นได้ปกติ และ
CSV

ระบุว่าเป็นนาฬิกาใด
