# กระบวนการทำงานด้านค่าสะท้อนแสง

เซ็นเซอร์แสง DAQ จะแปลงภาพรังสีเป็นค่าสะท้อนแสง มีสองกระบวนการทำงานที่แตกต่างกัน:

1. **เซ็นเซอร์เดียว** — DAQ หนึ่งตัววัดความเข้มรังสีที่ตกสู่พื้นดิน ในขณะที่กล้องถ่ายภาพ และChloros

จะนำค่าความสว่างของกล้องมาหารด้วยค่าอ้างอิงนั้น
2. **เซ็นเซอร์คู่** — เซ็นเซอร์ DAQ สองตัว โดยตัวหนึ่งจับแสงจากท้องฟ้าและอีกตัวจับแสงจากวัตถุ สร้างเส้นโค้งการสะท้อนแสงตามสเปกตรัมแบบเรียลไทม์ โดยไม่ต้องใช้กล้อง

## เซ็นเซอร์ตัวเดียว + กล้อง (ค่าอ้างอิงแสงลง)

DAQ ทำหน้าที่เป็นเซ็นเซอร์แสงลง (DLS): กล้องวัดความส่องสว่างที่ขึ้น **L**(W/m²/sr/nm), DAQ วัดความส่องสว่างที่ลง**E** (W/m²/nm), และChloros

คำนวณค่าการสะท้อนแสงต่อแถบความยาวคลื่นตามสูตร:

> ρ = π · L / E

ค่าที่ DAQ อ่านได้จะ **ตรงกับเวลาการเปิดรับแสง** เสมอ — นี่คือเหตุผลที่ DAQ และกล้องใช้สัญญาณนาฬิกาที่ควบคุมด้วย PTP ร่วมกัน (ดู [DAQ-E Networking &amp; Time Sync](ethernet-ptp.md)) ปรับใช้ Sunshine cosine cap สำหรับการทำงานกลางแจ้งและกำหนดค่าให้ถูกต้อง; การกำหนดค่า cap จะปรับขนาด E โดยตรง (ดู [Cap Profiles &amp; Calibrated Range](caps-and-range.md)). สำหรับงานเชิงปริมาณ ให้จำไว้ว่าคุณสมบัติของเครื่องมือ: ค่าความเข้มแสงเชิงปริมาณได้มาจากการเฉลี่ยค่าการอ่านอย่างน้อย 15 วินาที

### การจับภาพแบบเรียลไทม์

ผูก DAQ กับกล้องในแท็บ Cameras: แผงตั้งค่าของกล้องแต่ละตัวมีเมนูแบบเลื่อนลง **Light Sensor** ที่แสดงรายการ DAQ ทุกตัว (DAQ-U/M/E) ที่เชื่อมต่อจากแท็บ Light Sensors; สำหรับอาร์เรย์ที่ซิงโครไนซ์ การเลือก Light Sensor สำหรับทั้งอาร์เรย์จะส่งต่อไปยังสมาชิกทุกตัว (กล้องแต่ละตัวสามารถตั้งค่าทับได้) เมื่อเชื่อมต่อแล้ว สเปกตรัมของเซ็นเซอร์จะถูกส่งไปยังช่อง DLS ของกล้อง และการส่งออกค่าสะท้อนแสงจะถูกหารด้วยค่าที่ตรงกัน

สองพฤติกรรมที่ควรทราบ:

* **ไม่มีการผูก DAQ → ค่าสะท้อนแสงถูกปฏิเสธ ไม่ใช่ถูกสร้างขึ้น**Chloros

จะปฏิเสธผลิตภัณฑ์ค่าสะท้อนแสงและบันทึกเหตุผลการข้ามไป แทนที่จะส่งคืนผลิตภัณฑ์ที่มีค่าน้อยลงอย่างเงียบๆ
* **ค่าการอ่านที่ใช้จะถูกเก็บรักษาไว้** สำหรับทุกเฟรมค่าสะท้อนแสง ค่าอ่านจาก DAQ ที่ถูกนำไปใช้จริงจะถูกบันทึกเป็น sidecar `.daq` ข้างๆ ภาพ เพื่อให้สามารถประมวลผลข้อมูลที่บันทึกไว้ใหม่ได้ในภายหลัง ([การบันทึกและรูปแบบ .daq](recording.md)).

### การประมวลผลภาพที่บันทึกไว้

สำหรับการประมวลผลหลังการบิน ให้บันทึก `.daq` ระหว่างเซสชันและเก็บไว้พร้อมกับภาพ — ระบบประมวลผลจะแก้ไขข้อมูลการสะท้อนลงที่ตรงกับเวลาอัตโนมัติ และดึงข้อมูลการปรับเทียบจากโรงงานที่ขาดหายไปจากคลาวด์ของMAPIR

เมื่อใช้งานครั้งแรก การบันทึกผ่าน GUI จะถูกเพิ่มเข้าไปในโครงการที่เปิดอยู่โดยอัตโนมัติเมื่อการบันทึกสิ้นสุดลง

สามารถเลือกค่าอ้างอิงการสะท้อนแสงได้ในขั้นตอนการประมวลผล — `--reflectance-source` บน `chloros-cli process` หรือการตั้งค่าแหล่งที่มาของการสะท้อนแสงในส่วน Project Settings ของ GUI:

| ค่า | พฤติกรรม |
| --- | --- |
| `auto` (ค่าเริ่มต้น) | เป้าหมายการปรับเทียบในเฟรมที่ผ่านการตรวจสอบคุณภาพ (QA) เป็นค่าอ้างอิงสัมบูรณ์; การวัดด้วย DAQ แบบลงสู่พื้น (ρ = π·L/E) เป็นค่าสำรอง |
| `daq` | ใช้ข้อมูลจาก DAQ เป็นหลัก |
| `target` | เป้าหมายภายในเฟรมที่เคร่งครัด; ไม่ใช้ข้อมูลจาก DAQ แทน |

ดู [เป้าหมายการปรับเทียบ](../calibration-targets.md) สำหรับขั้นตอนการทำงานของเป้าหมาย และ [บท LATTICE](../lattice/README.md) พร้อมทั้ง [เอกสารอ้างอิงCLI

](../reference/cli-reference.md) เพื่อดูขั้นตอนการประมวลผลทั้งหมด เมื่ออ่านพิกเซลการสะท้อนที่ส่งออก ให้ใช้สเกลที่ระบุไว้ (LATTICE: 32768 = ρ 1.0, XMP `Chloros:PixelScale`;Survey3

: 65535) — ดู [รูปแบบภาพผลลัพธ์](../output-image-formats.md).

### แบนด์ที่อยู่นอกช่วงที่ปรับเทียบของ DAQ

ช่วงที่ DAQ ได้รับการปรับเทียบทางรังสีวัดได้คือ ~374–974 nmChloros

จะปฏิเสธค่าการสะท้อนแสงที่อิงจาก DAQ สำหรับแถบกล้องใดก็ตามที่มีน้ำหนักสเปกตรัมภายในช่วงดังกล่าวน้อยกว่าครึ่งหนึ่ง และรายงานเหตุผลการข้ามค่าเป็น `dls-uncalibrated-band-<nm>`. ในบรรดา SKU ที่จัดส่งอยู่ สิ่งนี้ส่งผลกระทบเฉพาะกับ F988: ค่าสะท้อนแสงของ F988 ได้รับการปรับเทียบโดยใช้แผงสะท้อนแสงในฉาก: ช่วงความยาวคลื่นนี้อยู่นอกช่วงที่ปรับเทียบของเซ็นเซอร์แสง DAQ ดังนั้นChloros

จึงใช้ข้อมูลการจับภาพแผงล่าสุดของคุณและเก็บไว้ระหว่างการตรวจวัดแผงครั้งต่อไป หากกล้อง F988 ทำงานในโหมด DAQ เท่านั้นChloros

จะปฏิเสธค่าการสะท้อนแสงที่อิงจาก DAQ สำหรับแถบความยาวคลื่นนั้น ด้วยเหตุผลการข้าม `dls-uncalibrated-band-988` — กระบวนการทำงานของแผงสะท้อนแสงเป็นวิธีที่ได้รับการสนับสนุน

## เซ็นเซอร์คู่ (แสงรอบตัว + วัตถุ)

เซ็นเซอร์ DAQ สองตัว — คู่ใดก็ได้ ไม่ว่าจะเชื่อมต่อผ่านระบบขนส่งใด — จะให้สเปกตรัมการสะท้อนแบบเรียลไทม์โดยไม่ต้องใช้กล้อง: เซ็นเซอร์หนึ่งตัวหันหน้าไปทางท้องฟ้า (**แหล่งแสงแวดล้อม**), เซ็นเซอร์หนึ่งตัวหันหน้าไปทางวัตถุ (**เครื่องสแกนวัตถุ**), และChloros

คำนวณตามความยาวคลื่น:

> R(λ) = object(λ) / ambient(λ)

(เป็นศูนย์เมื่อ แสงแวดล้อม ≤ 0)

### ใน GUI

เมื่อทั้งสองเซ็นเซอร์ถูกเชื่อมต่อในแท็บ Light Sensors ให้เปิดหน้าต่างเพิ่มเซ็นเซอร์ (ปุ่ม &quot;+&quot; บนไทล์กราฟในมุมมองกริด) และเลือก **Combine Ambient + Object**เลือกเซ็นเซอร์ทั้งสองจากเมนูแบบเลื่อนลง Ambient Light Source และ Object Scanner แล้วคลิก Create กลุ่มนี้จะปรากฏเป็นกราฟแยกต่างหากและในแถวของแถบด้านข้างที่มีป้าย**REF** สีเขียว

### ค่าสะท้อนที่ปรากฏ vs. ค่าสะท้อนสัมพัทธ์ — กฎการตั้งชื่อ

Chloros

ตั้งชื่อผลลัพธ์จากเซ็นเซอร์คู่ตามสิ่งที่คู่เซ็นเซอร์นั้นสามารถอ้างได้จริง:

| คู่เซ็นเซอร์ | ชื่อ |
| --- | --- |
| ทั้งสองเซ็นเซอร์ได้รับการปรับเทียบ — ชุดข้อมูลจากโรงงานถูกโหลด | **ค่าสะท้อนที่ปรากฏ** |
| เซนเซอร์ใดก็ตามที่ยังไม่ได้รับการปรับเทียบ | **ค่าสะท้อนสัมพัทธ์** |

ทั้งสามรุ่นเป็นแบบเรดิโอเมตริก: เมื่อชุดข้อมูลการปรับเทียบจากโรงงานของเซนเซอร์ถูกโหลดแล้ว สเปกตรัมของมันจะเป็นค่าสัมบูรณ์ W/m²/nm ดังนั้น คู่เซนเซอร์ที่ได้รับการปรับเทียบจะให้สัดส่วนที่สอดคล้องกับค่าสะท้อนสัมพัทธ์สัมบูรณ์ — การส่งข้อมูลไม่กำหนดค่านี้ หากเซ็นเซอร์ใดยังคงส่งข้อมูลนับดิบ (ไม่สามารถเข้าถึงชุดข้อมูลได้) ผลลัพธ์จะถูกลดระดับเป็นเส้นโค้งสัมพัทธ์ (รูปทรงสเปกตรัมยังคงถูกต้อง) เซ็นเซอร์ทั้งสองควรมีค่าขีดจำกัด (caps) ที่ประกาศไว้อย่างถูกต้อง ([Cap Profiles &amp; Calibrated Range](caps-and-range.md)).
